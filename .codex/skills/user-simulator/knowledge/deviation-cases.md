# 推奨逸脱の具体事例集（深層）

シミュレーターの価値源泉は「ユーザーが推奨案から逸脱する質問」を当てることにある。
初回シャドー採点（2026-07-28・装備スロット設計28問）で逸脱7問の的中が0だった。その具体事例と検知シグナル。
出典データセット: `datasets/2026-07-27-hotbar-equipment-grill/`（gold.json・runs/は予測時に開いてはならない）。

## 1. プレイヤー操作・UXの幅はYAGNIで削らない

- 割当操作「数字キー長押しか、D&Dか」→ 実回答「**両方（長押し＋D&D）**」。入力導線の複数併存は機能拡張ではなく操作性の基本
- 装備スロット「1スロット（最小）」を蹴って「**複数スロット＋循環キー**」。持ち替え需要（木=斧・鉱脈=石器）が文脈に示されているとき、最小スロットに畳まない
- 同根の preanswer 外し（07-27）: ツール選択は自動マッチ（手数最小）ではなく**手動ホイール循環＋素手**。プレイヤーの主体的操作を残す方向
- **判別法**: 「実装構造の最小化」（クラス・経路・機構を増やさない）はYAGNIで畳んでよい。「プレイヤーの操作・体験の幅の最小化」は逆方向に裁定が出る。質問の主語がコードかプレイヤーかで分ける
- **確信度規律**: 装備構成・操作方式・UI/UX系の予測は、根拠が既存裁定にあっても確信は「中」以下に降格する（07-27/07-28の外し実績。同一ユーザーが枠組み依存で逆回答した前科あり）

## 2. 個数・上限などの定数はマスタ定義へ

- 装備スロット数「3スロット固定（ハードコード）」ではなく「**スロット数はマスタ。個数は固定**」。値が当面固定でも置き場はマスタ。前例 `playerInventorySlotLevels`
- 同根（07-27）: ツールの装備可否も「制限なし」ではなく items.yml の tools 列挙制（概念のマスタ一級市民化）
- 「概念・定数のマスタ一級市民化」はYAGNI対象外。「今は使わないからハードコード」を推奨しない

## 3. 壊れた参照・無効データは消す

- ホットバー参照先の無効化（BP削除・マスタ消失・未解放化）→「保持してグレーアウト」ではなく「**ロード時に無効割当を削除**」
- 開発フェーズ・後方互換考慮不要（AGENTS.md）・フォールバック全排除（PR978）の文化と整合。防御的な残置・復活配慮は選ばれない

## 4. 識別子・キー体系の不揃いは「基盤先行」の枠破りを誘発する

- 「この内容でドキュメントを書いて良いですか？」→ 承認ではなく「**そもそも統合的にビルドメニューに置くもののキー・ID的な仕組みを策定したほうが良いのでは**」と質問の枠自体を破った（→設置対象ID Guid統一・ADR-0001へ発展）
- **検知シグナル**: 設計中に同種概念（ブロック・BP・ツール等）が別々のID/キー/参照方式を持ったまま進行している状態で「先へ進んでいいか」型の質問が来たら、承認ではなくSSOT基盤の先行策定を予測する。既存裁定「プロトコル1ドメイン1本」等の延長

## 5. 決定済み内容の文書化・planは先送りせず一括で書く

- plan分割「3本に分け、まずAだけ書く」ではなく「**3本に分けて全部今書く**」
- adjudications の「将来拡張の裁定は先送り」は**機能スコープ**限定。裁定済み内容の書き下ろし作業には適用されない（分割はするが着手は全部今）

## 6. 過剰逸脱の抑止（FP側の教訓）

- 「スポイトの向きを割当に含めるか」→ 実回答は推奨どおり「**割当はIDのみ、向きは持たない**」。データ最小主義は推奨どおり働く。r1はここで唯一の過剰逸脱（グローバル保持を予測）を犯した
- 上の1〜5の検知シグナルが無い質問で逸脱を予測しない。26問中18問は推奨追従だった
- HUD配置（「右端に置いておく」）のような画面上の好み系は当てにいかず、確信「低」で正直に申告する
