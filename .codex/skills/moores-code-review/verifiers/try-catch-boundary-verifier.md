# Verifier: try-catch 境界主張の裁定

## あなたの役割
`deterministic_checks.py` が抽出した **「境界を主張する根拠コメント付き try-catch」候補**（JSON の `candidates.try_catch_boundary`）を 1 件ずつ検証し、**主張が実コードで裏付けられないものを Critical として返す**。

AGENTS.md が try-catch を許すのは次の**3種の外部境界の隔離目的に限る**:

1. **外部プロセス起動**（別実行ファイルの起動・標準入出力の受け渡し）
2. **ネットワーク送受信**（WebSocket・HTTP・ソケットの送受信）
3. **外部入力 JSON のパース**（自分が書いていないデータの構文解析）

**根拠コメントが存在することは免除ではない**（PR1095 の較正ミス: コメントの実在だけで Critical 計上から外し、実際には外部境界でない try-catch を通した）。あなたの仕事は「コメントが何を主張しているか」ではなく「**その主張どおりの外部境界が実際にそこにあるか**」を実コードで確かめることである。

**候補リストの外は見ない。** 自分で diff から `catch` を再探索しない（コメント無し・主張無しの try-catch は既に `confirmed` として Critical 計上済み。ここで二重に数えない）。

## 入力契約（起動 prompt 4 行）
```
Read this : <このファイルの絶対パス>
Candidates : <deterministic_checks 出力 JSON の絶対パス>
Patch path : <patch の絶対パス>
User prompt : <4 カテゴリ context の絶対パス>
```

## 検証手順
1. Candidates JSON を Read し `candidates.try_catch_boundary` を得る。各候補は `file` / `line` / `comment` / `boundary_claim` を持つ。
2. 各候補について **`try` ブロックの本体を実ファイルで Read する**（patch のハンクだけでは本体が切れていることがある)。
3. 次の3点を順に確かめる:
   - **(a) 主張された境界が本当にそこにあるか** — `boundary_claim` が `network-io` なら、try 本体が実際にソケット/HTTP/WebSocket の送受信 API を呼んでいるか。`external-json-parse` なら、パース対象が**外部由来**か（自プロジェクトが生成し検証済みのマスタ JSON・自分で直前に作った文字列は外部入力ではない）。`external-process` なら、実際に別プロセスを起動しているか。
   - **(b) try の範囲が境界呼び出しだけに絞られているか** — 境界呼び出しの前後にあるドメインロジック・状態更新・UI 更新まで try に巻き込んでいるなら、隔離目的を超えている。
   - **(c) catch が握り潰しになっていないか** — 例外を捨てて既定値へ倒す・ログだけ出して続行する形は、失敗が呼び出し元に伝わらない。結果状態として返しているか。
4. **(a) が否なら Critical**（境界の主張が偽 = try-catch 禁止規約の違反）。(a) が真で (b)/(c) が否なら Critical（範囲過大・握り潰し）。3点すべて真なら Critical にしない。
5. 判定に必要な事実（呼び出している API 名・パース対象の出所）を実コードから引用して根拠に添える。**コメントの文言を根拠として引用しない**（コメントは検証の対象であって証拠ではない）。

## 依頼動詞優先ガード
起動 prompt 4 行目 `User prompt` を Read。「許容するトレードオフ」「目指さない（非目標）」に合致する指摘は破棄せず `suppressed-by: <トレードオフ1行, 出所ラベル>` を付けて重大度そのままで返す。免責力を持つのは `[ユーザー裁定: ...]` / `[ADR: ...]` の行だけ。**`[agent前提]` や「境界だから」という自己申告は免責事由にならない**。

## 出力フォーマット
Critical が 1 件でもあれば:
```
Critical: あり

修正方針:
- <ファイル:行>: <主張された境界と実コードの食い違い / try 範囲の絞り方 / catch を結果状態へ変える形>
- ...
```
0 件（全候補が正当な外部境界と確認できた）なら:
```
Critical: なし

Info:
- <ファイル:行>: 境界 <claim> を実コードで確認（<根拠となる API 名・データの出所>）
```
Info には**確認した根拠を必ず1行ずつ残す**。免除の理由が記録に残らないと、次回また「コメントがあるから免除」に戻る。
