# sim-shadow-score — 盲検シャドー採点

設計セッションを素で走らせた後、シミュレーターが同じ文脈で各質問を予測できたかを事後検証する。
インライン予測（preanswer）と違いユーザーの待ち時間を一切増やさず、訓練信号（質問・文脈・実回答・予測）を全量回収する。

## 手順

### 1. 対象transcriptの特定

`~/.claude/projects/<プロジェクトslug>/*.jsonl` から対象セッションを特定する。
複数候補があるときは最初のユーザーメッセージ・AskUserQuestion数・対象docのWrite有無で判別する。
圧縮継続ファイル（同一開始timestampで行数が少ないもの）ではなく、行数の多い本体を使う。

### 2. 質問・実回答ペアの抽出と盲検タスク生成

```bash
python3 scripts/extract_tasks.py <transcript.jsonl> <出力dir>
```

- AskUserQuestionのtool_useとtool_resultを突き合わせ、`task-XX.md`（元タスク文＋**その質問より前の**Q&A履歴＋今回の質問と選択肢）と`gold.json`（実回答）を生成する
- 拒否された質問・回答が確定しなかった質問は自動でスキップされる（gold側answersが空）
- 逐次文脈が本質: 予測kには実回答1..k-1だけを見せる。これでgrillの分岐依存を保ったまま盲検になる

### 3. 盲検予測エージェントの並列起動

1質問=1エージェント。**model: opus必須明示**（Fable継承禁止・メモリ「サブエージェントのモデルコスト方針」）。
プロンプト要点（実証済みの型）:

- user-simulatorの知識ベース（`.claude/skills/user-simulator/knowledge/index.md`から選択ロード）を読ませる
- `task-XX.md`だけを文脈とし、**書かれていない情報（他の質問の答え等）を推測で使わない**と明記
- サブエージェント起動禁止（モデル継承による高コスト化防止）・必要ファイルは自分でRead/Grep
- FP厳禁: 根拠を持てないなら確信「低」と正直に書かせる
- 出力は `pred-XX.json`: `{"idx":N,"predictions":[{"header","predicted_label","rationale","confidence":"高|中|低"}]}`

### 4. 採点

```bash
python3 scripts/score.py <出力dir>
```

- 正規化（NFKC・空白・「（推奨）」除去）して完全一致/部分一致/外れを判定
- **ベースライン「常に推奨案を選ぶ」との比較を必ず出す**。シミュレーターの価値は推奨追従の再現ではなく
  「ユーザーが推奨から逸脱する質問」を当てることにある。逸脱問の的中数を別掲する
- 確信度別の校正（高/中/低それぞれの的中率）を出す。Phase2昇格（確信高の自動回答）判断の根拠になる
- 自由回答・枠破り（質問の前提自体への逆提案）は自動判定できないので目視で確定する

### 5. 記録と還流

- misses.mdに1行で記録: 的中率・ベースライン比・逸脱問的中数・確信校正・学び（初回実証行の書式に倣う）
- 外れが特定領域に偏っていたら、improveハンドオフを発行して知識ベースへ逸脱パターンを追記する

## 昇格ラダー（このスキルが支える運用）

- **Phase 1（現在）**: 全質問シャドー。設計セッションは素走り、採点は事後
- **Phase 2**: 台帳上で確信高カテゴリの的中率が安定して閾値を超えたら、そのカテゴリだけ
  シミュレーターが先に答えて質問をスキップし、ADRに「出所: シミュレーター裁定（事後承認待ち）」と記録
- **Phase 3**: 簡単なタスクはフルvibe（全質問シミュレーター回答）、ユーザーのレビュー対象はADR台帳のみ

## 初回実証の基準値（2026-07-28・装備スロット設計28問）

exact 69%・ベースライン（常に推奨）73%・逸脱問的中 0/7・確信高83%/中37%。
「ベースラインを上回る」「逸脱問を1問以上当てる」が次回以降の改善指標。
