# 質問は最後にまとめる・実行メモ

SKILL.md「質問は最後にまとめる」の詳細。裁定の出所は `.decisions/2026-09-28-SDDの質問は最後にまとめ後続に係るものだけ途中で聞く.md`。

## 対象

人間にしか決められない設計・仕様の質問すべて。出どころは問わない: 事前計画レビューの矛盾、implementer の NEEDS_CONTEXT・BLOCKED・懸念、タスクレビューの plan-mandated 所見、コンフリクト解消の設計判断。

対象外（従来どおりその場で止まる）: 取り返しのつかない操作の確認、所有者不明の変更の移送、必須ゲートの免除。

## 振り分け

質問が生じたら、まず計画・ADR・`.decisions/`・既存コードの前例で答えが出ないか調べる。出るならそれは質問ではない。出ないときだけ次の2つに振り分ける。

| 判定 | 条件 | 対応 |
| --- | --- | --- |
| 既定で進める | 既定が外れても、直しがその質問の生じた1タスクの変更範囲に閉じる | 推奨案を選んで進め、メモの質問欄へ書く。止まらない |
| 途中で聞く | 答えが、そのタスクより後のタスクの設計・インターフェース・データ形式を決める。既定で進めて外れると、後続タスクごとやり直しになる | 下の「途中で聞くとき」に従って聞く |

迷ったら「外れたとき、やり直すのは何タスクか」を数える。1タスクに閉じるなら既定で進める。着手前（事前計画レビュー）に生じた質問も同じ基準で数える — 全タスクが未着手であることは、途中で聞く理由にならない。

既定で進めた判断は、subagent へ派遣プロンプトの「曖昧さの解消」として渡す。計画の記述と違う側を採った場合も同じで、計画のどの記述をどう読み替えるかを明示する。subagent には「人間に未確認の既定」であることを伝えなくてよい（実装者にとっては確定した要件である）。

## 途中で聞くとき

- 計画上その質問に依存しないことが明らかな未着手タスクがあれば、先に済ませる。依存するタスクしか残っていない時点で聞く。依存の有無が読み取れないなら順序は変えない
- 聞くときは、その時点でメモに溜まっている質問も全部いっしょに出す（止まる回数を減らす）
- 聞く前にメモの現在地へ「回答待ち」と書く。回答を受けたら質問欄へ反映してから再開する

## 最後にまとめて聞く

提示は1回にまとめる。

- 最終レビュー（moores-code-review Step 7）が設計判断を尋ねるなら、溜めた質問も同じ場で出す
- 最終レビューが何も尋ねないなら、PR作成まで済ませてから最終報告で出す
- 未回答が0件なら何も出さない

出し方は、選択肢付きの質問ツール（AskUserQuestion 等）があればそれを使い、無ければ本文に番号付きで並べる。各質問には、採った既定・理由・外れた場合の手戻りを添える。回答が既定と違ったら、完全な変更リストを持った単一の fix subagent を派遣し、コンパイル・関連テストを経てpushする（本体は実装コードを書かない）。回答はメモの質問欄へ反映する。

## 実行メモ

隔離worktree側をcwdにして `scripts/sdd-memo` を実行すると、メモの絶対パスが表示される（無ければ雛形を作る）。置き場所は記録repoの `harness/sdd/<ブランチslug>/memo.md`。

- **worktree内や `/tmp` に置かない。** worktreeは畳むと消え、`/tmp` はOSに掃除される。未回答の質問が残ったままセッションが落ちても、メモから再開できることが目的
- **台帳（`.superpowers/sdd/progress.md`）とは役割が違う。** 台帳は復旧用の追記ログで、逐語の行を機械的に読む。メモは人間がひと目で状況を掴むためのもので、現在地は毎回書き換える。完了タスクの判定にメモを使わない
- 記録repoはStop/SessionEnd hookが自動でcommit・pushする。セッション側で `git commit` しない

### 書式

非常に簡易でよい。整形に時間をかけない。

```markdown
# SDDメモ: <ブランチ>

- 更新: 2026-09-28 18:40
- worktree: <絶対パス>
- 計画: <計画ファイルの絶対パス>
- 台帳: <worktree>/.superpowers/sdd/progress.md

## 現在地

Task 3/6 のタスクレビュー中。次は Task 4 の派遣。

## 質問

### Q1 [未回答] 空の入力を受けたとき、エラーにするか無視するか
- 発生: Task 2（implementer の懸念）
- 採った既定: 無視してログを出す（既存の受信処理がこの形）
- 外れた場合の手戻り: Task 2 の1メソッドと、そのテスト1件

### Q2 [回答済み] 設定の保存先はセーブデータか、クライアント設定か
- 発生: Task 4 着手前（Task 4〜6 の実装が変わるため途中で聞いた）
- 回答: クライアント設定
```

状態は `未回答` / `回答待ち`（途中で聞いて止まっている） / `回答済み` の3つ。

### 更新するタイミング

- subagent を派遣する直前と、結果を受け取った直後
- 質問が生じたとき・回答を受けたとき
- 最終レビュー開始時・PR作成時（PRのURLを現在地へ書く）

compaction やセッション再起動の後は、台帳と併せてメモを読み、未回答の質問を引き継ぐ。
