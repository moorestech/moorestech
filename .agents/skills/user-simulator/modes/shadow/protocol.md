# shadowモード — 盲検シャドー採点

設計セッション（grill等）のtranscriptから質問と実回答を抽出し、「実回答を見せずに」盲検再予測させて採点する
非同期シャドー評価。セッション本体の体感遅延ゼロで育成データを蓄積し、的中率・ベースライン比較・確信度校正を
misses.mdに記録する。発動は (a) user-simulator本体のモード判定表から（「シャドー採点して」等）、
(b) grillセッション終了時の **shadow-gate自動発動**（moores-grill-with-docsのfrontmatter hooks →
`scripts/shadow-gate.sh`。設計doc書き込みで武装し、Stopブロックメッセージに自transcriptパスが渡される。
datasets/への格納で解除）。自動発動時は手順1のtranscript特定が不要（メッセージ内のパスを使う）。

設計セッションを素で走らせた後、シミュレーターが同じ文脈で各質問を予測できたかを事後検証する。
インライン予測（preanswer）と違いユーザーの待ち時間を一切増やさず、訓練信号（質問・文脈・実回答・予測）を全量回収する。

## 手順

### 1. 対象transcriptの特定

`~/.claude/projects/<プロジェクトslug>/*.jsonl` から対象セッションを特定する。
複数候補があるときは最初のユーザーメッセージ・AskUserQuestion数・対象docのWrite有無で判別する。
圧縮継続ファイル（同一開始timestampで行数が少ないもの）ではなく、行数の多い本体を使う。

### 2. 質問・実回答ペアの抽出と盲検タスク生成

出力先は使い捨てのscratchpadではなく、**永続データセットdir** を作ってそこに置く
（tasks/とgold.jsonは凍結データセットとして以後変更しない）。
**置き場は private ログrepo**（moorestechルートからの相対で
`../moorestech_logs/harness/user-simulator/datasets/<YYYY-MM-DD>-<slug>/`）。
コードrepo側の `<このスキルdir>/datasets/` は `.gitignore` 済みで永続しないため使わない。
`misses.md` も同様に `../moorestech_logs/harness/user-simulator/improve/misses.md` が正本:

```bash
python3 <このスキルdir>/modes/shadow/scripts/extract_tasks.py <transcript.jsonl> <データセットdir>
mkdir <データセットdir>/tasks && mv <データセットdir>/task-*.md <データセットdir>/tasks/
```

- AskUserQuestionのtool_useとtool_resultを突き合わせ、`task-XX.md`（元タスク文＋**その質問より前の**Q&A履歴＋今回の質問と選択肢）と`gold.json`（実回答）を生成する
- 拒否された質問・回答が確定しなかった質問は自動でスキップされる（gold側answersが空）
- 逐次文脈が本質: 予測kには実回答1..k-1だけを見せる。これでgrillの分岐依存を保ったまま盲検になる

### 3. 盲検予測エージェントの並列起動

**model: opus を明示指定**。1エージェントに3〜5問を束ねてよい（エージェント数と固定費の節約。知識ベース読み込みが1回で済む）。

**束ねるときは必ず昇順（idxの小さい順）に処理させる。降順・ランダム・任意順は禁止。**
`task-XX.md` は「その質問より前のQ&A実回答」を文脈に含むため、降順に処理すると後続タスクの文脈へ
**これから予測する質問の実回答**が載り、盲検が完全に壊れる。昇順なら各タスクの文脈は前のタスクの文脈の
上位集合であり、未予測の質問の答えは決して現れない。

**昇順の指示だけでは足りない。「1本Readする → その問のpredをWriteする → 次をReadする」の交互実行を明示的に強制する。**
`task-XX.md` は前問の実回答を文脈に含むため、束ね内の複数ファイルを**まとめてRead**した時点で未予測問の正解が見える
（昇順に「処理」しても読み込みが一括なら同じリーク）。プロンプトに「複数のtaskファイルを同時に読むことを禁止する。
1本読んだら必ず pred を書いてから次を読む」と書き、完了報告に読み順の申告（交互だったか一括だったか）を求めること。
**リークすると束ねの末尾問だけが盲検で残り、有効サンプル数が束ね幅の1/Nへ潰れる**（実例: 2026-08-17-webui-hud-face-notification-anim
は束ね5/4/4で13問中3問しか有効にならなかった。3エージェント全員が一括Readした）。

昇順束ねでも残る副作用: エージェントは自分の予測の当否を途中で知る（Q_kを予測した後、task-(k+1)の文脈に
Q_kの実回答が載る）。これは単問エージェントには無い自己フィードバックで、**的中率と確信校正が束ね幅の
異なるrun同士で比較不能になる**。RUN_INFO.txt に**束ね幅を必ず記録**し、確信校正の比較は同一束ね幅の
run同士に限ること。

**盲検性の保全（重要）**: 予測エージェントはリポジトリを探索できるため、**対象セッションの成果物や
実装コミットがリポジトリに既に存在すると答えに触れうる**。設計対話と並行して実装が進んだブランチを
採点する場合は、探索範囲を制限するか対象コミット以前のworktreeで走らせ、毀損した場合は RUN_INFO.txt へ
明記して結果を割り引く（実例: 2026-08-05-alt-free-cursor-spoit の task-06）。

**漏洩は本文を開かなくても起きる。名前だけで漏れる経路を3つとも塞ぐこと。**

1. **データセットdir名（slug）**: 裁定結果の語を入れない。**依頼原文の語で命名する**
   （実例: `right-short-press-grill` の Q0、`placement-default-height-floor` の Q1。
   後者は「-1をデフォルトに」という依頼に対し裁定結果 floor をslugへ入れて漏らした）
2. **成果物のファイル名**: 同一セッションでADRを書くフローでは `docs/adr/0047-...-floor-....md`
   のようにファイル名へ裁定結果が載る。プロンプトで**ディレクトリ一覧の取得そのものを禁じ**、
   既存ADRはパス直指定でReadさせる（`ls docs/adr/` は本文を開かずとも答えを見せる）
3. **git履歴**: `git log` / `git show` / 差分閲覧を明示的に禁じる

いずれも「本文は開いていない」という自己申告では防げないので、**完了報告に読了ファイルと
実行コマンドの申告を求め**、一覧取得の有無まで確認すること。

**質問設計側の要求**: AskUserQuestion の選択肢に「（推奨）」を付けていないと `score.py` の
ベースライン（常に推奨案を選ぶ）が計算できず、全問が「逸脱問」に化けて**その run の情報量が
丸ごと失われる**（実例: 2026-08-30-placement-default-height-minus-one は目視3/3だが
「常に先頭選択肢」ベースラインも3/3で弁別力ゼロ）。grill 側で推奨を明示する運用が前提。

プロンプト要点（実証済みの型）:

- 知識ベース（`<このスキルdir>/knowledge/index.md`から選択ロード）を読ませる
- `task-XX.md`だけを文脈とし、**書かれていない情報（他の質問の答え等）を推測で使わない**と明記
- サブエージェント起動禁止（モデル継承による高コスト化防止）・必要ファイルは自分でRead/Grep
- FP厳禁: 根拠を持てないなら確信「低」と正直に書かせる
- 出力は `pred-XX.json`: `{"idx":N,"predictions":[{"header","predicted_label","rationale","confidence":"高|中|低"}]}`

### 4. 採点

```bash
python3 <このスキルdir>/modes/shadow/scripts/score.py <出力dir>
```

- 正規化（NFKC・空白・「（推奨）」除去）して完全一致/部分一致/外れを判定
- **ベースライン「常に推奨案を選ぶ」との比較を必ず出す**。シミュレーターの価値は推奨追従の再現ではなく
  「ユーザーが推奨から逸脱する質問」を当てることにある。逸脱問の的中数を別掲する
- 確信度別の校正（高/中/低それぞれの的中率）を出す。Phase2昇格（確信高の自動回答）判断の根拠になる
- 自由回答・枠破り（質問の前提自体への逆提案）は自動判定できないので目視で確定する

### 5. 永続化（機械学習的に再チェック可能な形で格納・CRITICAL）

採点結果の要約だけ残して素材を捨てると、後から振り返れず再評価もできない（初期のmisses.md行形式の失敗）。
データセットdirに以下を必ず封入する。**参照ではなくコピー封入**（scratchpad・task出力・transcriptは数日で消える。
リポジトリ内ファイルはgitが持つのでHEAD記録で足りる）:

```
datasets/<YYYY-MM-DD>-<slug>/
  README.md              # 数行: 経緯・予測と実測サマリ・学び・再チェック手順
  tasks/task-XX.md       # 盲検入力（凍結）
  gold.json              # 実回答ラベル（凍結）
  runs/<日付-ラベル>/     # 実行1回分: pred-XX.json + gold.json + score.txt + RUN_INFO.txt。再チェックごとに増える
                         # RUN_INFO.txt必須: model・束ね幅・実行時の知識ベースコミットハッシュ・結果1行
                         # （run間のスコア差を知識変更に帰属させるため。束ね幅が違うrun同士は確信校正を直接比較しない）
  transcripts/*.jsonl    # 匿名化済みセッションログ全量（本体＋圧縮継続。sedで /Users/<name>→/Users/USER・メール置換）
  HEAD.txt               # セッションが見ていたリポジトリ状態（コミット範囲・worktree・期間）
  dirty.patch            # セッション中に未コミットの参照物があった場合のみ（git diff HEAD）
```

- misses.mdには1行だけ記録: 的中率・ベースライン比・逸脱問的中数・確信校正・学び＋**データセットdirへのリンク**
  （misses.mdはインデックス兼スコアボード。実体・考古学はデータセットdirが持つ）
- 外れが特定領域に偏っていたら、improveハンドオフを発行して知識ベースへ逸脱パターンを追記する

### 6. 再チェック（回帰評価）

知識ベース改善後、凍結済みデータセットに対して再予測して改善を測る:

1. `tasks/` の各taskを手順3の型で盲検再予測（実回答遮断は同じ）
2. `runs/<新日付-ラベル>/` に pred-XX.json と gold.json を置き `score.py` で採点
3. 旧runと比較（exact・ベースライン比・逸脱問的中・確信校正）。改善指標は「ベースライン超え」「逸脱問1問以上的中」
4. 比較結果をmisses.mdに1行追記（同一データセットの再評価であることを明記）

## 昇格ラダー（このスキルが支える運用）

- **Phase 1（現在）**: 全質問シャドー。設計セッションは素走り、採点は事後
- **Phase 2**: 台帳上で確信高カテゴリの的中率が安定して閾値を超えたら、そのカテゴリだけ
  シミュレーターが先に答えて質問をスキップし、ADRに「出所: シミュレーター裁定（事後承認待ち）」と記録
- **Phase 3**: 簡単なタスクはフルvibe（全質問シミュレーター回答）、ユーザーのレビュー対象はADR台帳のみ

## 基準値の推移

### 装備スロット設計28問データセット（2026-07-27-hotbar-equipment-grill）

- r1（2026-07-28・改善前）: exact 69%・ベースライン（常に推奨）73%・逸脱問的中 0/7・確信高83%/中37%
- r2（2026-07-28・decision #9 逸脱知識化後・in-sample）: exact 88%（目視込み96%）・逸脱6/7・FP消滅・確信高93%/中92%

### Alt自由カーソル設計15問データセット（2026-08-05-alt-free-cursor-spoit・初のout-of-sample）

- r1（2026-08-05・束ね幅1）: exact 53%（目視込み66%）・ベースライン66%で**未超え**・逸脱問的中 1/5・逸脱FP 2件・確信高66%/中50%
- 判明した弱点: (a) deviation-cases知識化以後の**逸脱の過剰予測**（逸脱シグナルが無い問でも逸脱側へ振れる）
  (b)「**依頼スコープ外のUX改善提案は却下される**」型の逸脱を落とす
- r2の高得点はin-sampleだったため汎化を示していなかったことが、このout-of-sampleで確認された

- 次の指標: **out-of-sampleでベースライン超え＋逸脱2問以上的中＋逸脱FP 0件**

### Web UI画面端HUD是正14問データセット（2026-08-17-webui-screen-edge-polish・上記指標を初達成）

- r1（2026-08-17・束ね幅5/5/4・model opus）: exact 12/14=86%（目視込み）・ベースライン71%を**15pt超え**・
  逸脱問的中 **2/4**・逸脱FP **0件**・確信高86%/中86%
- 達成条件つき: 実行時に `knowledge/adjudications.md` と `deviation-cases.md` が参照できず（パス切れ・後に修正）、
  **逸脱の一次資料なしでの2/4**。index.md修正後の再チェックで上振れの余地がある
- 当てた逸脱の型: 「原則に厳密な側を選ぶ」（仮実装の免責を残さず様式化する／条文どおりトークンで宣言する）
- 落とした逸脱の型: (a) **選択肢の枠自体を作り直す**（浮いている仮UIを本来の所属パネルへ畳む）
  (b) **文脈依存の選好を一般則として適用した誤り**（「git worktree頻用」はUnityの再インポート回避文脈の選好で、
  Web UIのように作成コストが低い領域では単純なブランチが選ばれる）
- このデータセットは AskUserQuestion 不使用（地の文質問）のため `extract_tasks.py` が使えず、
  tasks/gold を手作業で構築した。ラベル粒度が自動抽出runと厳密には同型でない点に注意
