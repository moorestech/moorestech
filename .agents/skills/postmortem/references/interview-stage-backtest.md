# 前段（対話工程）対策のバックテスト手順

Step 5（実測検証）の対話工程版。レビュー系対策の「当時の実入力を凍結→新旧A/B→行動判定→誤爆側確認」という型を、grill・インタビュー・裁定転写などの対話工程の対策に移植する。対話工程の対策を打ったのに本手順（または同等の実測）で検証していなければ、その対策は Step 5-9 の表で **未検証** と申告する。

## 前提: フィクスチャの材料はすべて実記録から採る

- 会話の実記録: セッションtranscript。**探索はまず `../moorestech_logs`**（`map/commit-sessions.tsv` でコミット→session_id を引き、`claude/<slug>/<session>.jsonl` / `codex/` の生ログを開く。手順は同repoのREADME。codexセッションはここにしか無い）。`~/.claude/projects/<slug>/<session>.jsonl` の直読みは同一マシン・session_id既知の近道としてのみ可。AskUserQuestionの提示全文（選択肢・説明・プレビュー）とユーザー回答は `tool_use` / `tool_result` に verbatim で残っている
- 出力の実記録: 当時書かれた台帳・ADR（事故後に修正済みなら `git show <当時sha>:<path>` で当時版を採る。作業ツリーは並行修正で汚染されている前提で扱う）
- 旧版スキルは `git show <対策マージ前sha>:<skill path>` で凍結する

## レシピ1: 決定的瞬間の凍結リプレイ（本命・行動テスト）

事故の決定打となった対話中の1判断を切り出す。

1. **凍結状態の再構成**: transcriptから「その判断の直前」までを1ファイルに再構成する — 元依頼原文・確定済み裁定（採択時のプレビュー含む）・当時の台帳内容・直前に提示した質問の全文。事故の存在や「これはテストである」ことは書かない（リーク管理）
2. **実発言を1発注入**: 当時のユーザー発言（事故ではOther自由記述）をverbatimで与え、「次のターンで取る行動を書き出せ」とだけ指示する。被験体には対象スキル（新版 or 旧版）と凍結状態のみ渡す。較正実例のreference（事故自体が答えとして書いてあるファイル）は渡さない — 渡すと暗記テストになる
3. **blind行動判定**: 合否基準を別ファイルに書き、被験体のどちらの版かを知らない判定者（または基準に対する機械的照合)で判定する。基準は「何を言ったか」でなく「何をしたか」で書く（例: 覆す読みを候補に挙げたか／確定前に再確認へ行ったか／台帳を書いたか）
4. **新旧A/B**: 旧版スキルで同条件を回し、旧版が不合格（=事故を再現・検出できるテストである）ことを確認する。旧版も合格するなら、そのフィクスチャは事故を捉えていない — 凍結時点か判定基準を作り直す
5. **誤爆側**: 「対策が誤発動すると煩くなるケース」（例: 自由記述が提示選択肢と素直に一致する回答）を同じ凍結状態で回し、新版が不要な再確認・再質問をしないことを確認する
6. **n**: 対話は揺れるので正例は新旧とも n≥2。1体でも旧版がPASSしたら「旧版でも防げることがある＝差分は確率的」と正直に記録する

## レシピ2: 台帳転写の単発リプレイ（決定的・出力テスト）

対話の最終段「会話 → 台帳/ADRファイル」だけを file-in/file-out で検査する。

1. **入力**: 会話記録（提示した選択肢・ユーザー実発言・確定した裁定）を1ファイルに整形
2. **実行**: 被験体に「この会話記録から台帳を書け」とだけ指示（対話はさせない）
3. **判定**: 書かれた台帳を会話記録と照合 — (a) 棄却案は実際に提示された案だけか（捏造検出） (b) 引用はverbatimか (c) 決定文は確定した裁定を含意するか
4. 新旧A/Bと誤爆側はレシピ1と同様。転写系は旧版でも合格しやすい（事故は対話の流れの中で起きる）ので、旧版合格＝「このレシピは当該事故の回帰網ではなく転写規則の検証」と役割を限定して記録する

## 常設化（回帰網）

単発バックテストは対策マージ時の1回きり。同じ事故の再発監視は、対話工程に既設の自動採点（例: grillのshadow-gate／user-simulatorのmissesデータセット）へ事故ケースを1件追加して常設回帰に落とす。既設の採点器が「ユーザー回答の予測」しか測れず工程側の行動（転写忠実性等)を測れない場合は、その旨を残課題として Step 5-9 の表に書く — 採点器の測定対象外は「検証済み」に数えない。

## 報告

レシピ実施の結果は Step 5-9 の「対策×検証状態」表の合格根拠として1行で書く（例: `検証済み(凍結リプレイ 新2/2 PASS・旧2/2 FAIL・誤爆0)`）。フィクスチャ・被験体出力・判定はログrepoへ即コミットする（成果物は消える）。
