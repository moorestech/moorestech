# recurrence-registry — 再発照合の累積台帳

再発照合(裁定前)と台帳追記(締め)の詳細規約。SKILL.md 硬い規則 6 の本体。

## 台帳の置き場所

正本の台帳は**コード repo に置かない**。レビュー・skill の実行記録と同じ場所に置く:

- 記録用の logs repo がある場合はそこ(例: moorestech なら `../moorestech_logs/harness/postmortem/registry.md`)。
- 無い場合は `~/.agents/records/postmortem/registry.md`(全プロジェクト共通の 1 冊)。

`~/.agents/records/` は `.md` だけを追跡する(2026-09-09 決定、`records/README.md`)。検証メモ `records/postmortem/verify/<事案>/` に diff 等のフィクスチャを置くときは、README に `git show <sha>` 等の再生成コマンドを必ず書く(それが無い非 .md は `.gitignore` で弾かれる)。

feature ブランチが台帳に触れるとマージ衝突が事案のたびに増えるため、コード repo 内は選ばない。プロジェクトごとに冊子を分けるより、**1 冊に混ぜて系統タグで引く方が照合が効く**(同じ機構の事故は repo を跨いで再発する)。

## 台帳の形式(1 事案 = 1 ブロック・新しい事案ほど上)

```markdown
## YYYY-MM-DD <事案slug>
- repo: <対象リポジトリ名>
- 系統タグ: <カンマ区切り。例: 転写忠実性, プレビュー不完全, 発火条件の代理指標>
- 症状: <一行>
- 裁定類型: <軸違い/枠内最適化/構造的死角/免罪。件別なら列挙。遡及分は「(簡易・遡及)」>
- 対策: <commit sha> <追記先観点・手順名> <一行要約>
- 検証: <合格(単離/フルスケール) / 未検証(理由) / (遡及・不明)>
- 記録: <issue id・記録ファイルパス・PR 番号など一次資料への参照>
```

## 系統タグの運用(照合の要)

- **機構ベースで付ける** — 「なぜ体制がそれを見なかったか」の機構の名前。症状の逆さ書きタグ(「研究UI取り違え」等)は照合に使えないので禁止。症状は事案 slug と症状欄に書く。
- **固定分類にしない**。既存タグで足りなければ新タグを作ってよいが、同じ機構には必ず同じタグを使い回す(照合はタグ grep なので表記ゆれが盲点を作る)。台帳を読んで近いタグがあればそちらへ寄せる。
- 種タグ(SKILL 本文「横断で必ず確認する癖」由来): 転写忠実性 / 発火条件の代理指標 / 自己参照QA。

## 照合手順(裁定前)

1. まず台帳を grep(系統タグ・機構語)。ヒット無しでも今回の機構を 2〜3 通りに言い換えて引き直す(タグの言い換え漏れ対策)。
2. ヒット時の深掘りは**必ず read-only サブエージェントへ委譲する**(本体で一次資料を読み進めない)。入力は今回事案の一行記述＋該当ブロックの「記録」欄の一次資料と「対策」欄のコミット。サブエージェントに**前対策の不発理由を 4 分類で確定**させる:
   - (a) **発火せず** — 発火条件・モード・閾値が今回の入力を系統的に外した
   - (b) **発火したが届かず** — 指摘は出たが降格・注意希釈で防止経路(Critical/設計判断)に到達しなかった
   - (c) **消失・風化** — 後の skill 編集で対策追記が消えた・薄まった(追記行の git blame で確認)
   - (d) **変種枠外** — 対策は兄弟変種のみカバーし今回の変種を包摂していなかった
3. 判定は推測でなく一次資料で取る(SKILL 硬い規則 5 と同じ重み)。「前対策があったのに効かなかった」は裁定の帰責を変えるため、裁定ゲートの提示に「再発判定」行として必ず載せる。
4. 完全な初発でも「初発(照合済み・近縁なし)」と明記する — 照合を省いたのか初発なのかを後から区別できるようにする。

## 追記規約(締め)

- 1 事案 1 ブロックを台帳の先頭側へ追記する。裁定が件別に割れた場合も事案としては 1 ブロック(裁定類型欄に列挙)。
- 対策が複数あれば対策欄を複数行にしてよい。検証欄は報告末尾の「検証」行と整合させる(未検証を合格に見せない)。
- 追記は postmortem の締めの一部であり省略不可。台帳が育たないと次回の照合が盲目になる。

## ブートストラップ(台帳を新設するとき)

初期台帳は 2 層で作る: ①正式な postmortem 実行分は全記録から完全ブロック化、②スキル導入以前の散在「再発防止」コミット(`git log --grep='再発防止\|recurrence\|regression'` 等)は一行要約の遡及簡易ブロック(裁定類型 = 簡易・遡及)。遡及分は当時の裁定が無いため類型・検証欄が粗くてよいが、**系統タグだけは照合可能な精度で付ける**。純粋なバグ修正(体制への手当てが無いもの)は対象外(moorestech では 2026-08-20 にこの手順で初期台帳を構成した)。
