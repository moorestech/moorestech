# UITK I-fix3（integrator 修正 3）Implementation Plan

> **For the controller session (実装を担うsubagentはこのブロックを無視してよい):** この plan は起草したセッション（I-fix3）がそのまま実行する（指揮の指示。Execution Handoff はしない。計画 §5 の独立評価は不要）。ステップはチェックボックス（`- [ ]`）記法で書く。

**Goal:** 先行レーン（C3-b・C4-b・C4-e・I-fix2）が integrator に積んだ共有の道具・トークン・基盤・文書の直しを 1 本の PR で済ませる。

**Architecture:** 共有の式（黒の幕の α・ぼかしの被覆率 Φ）と共有の口（ドラッグの型・画面ポインタ・舞台の倍率）を Foundation に 1 本ずつ置き、使い手（DialogFrameShadow・CrosshairShadowRing・ProgressArrowGlyph・CursorTooltip・GrabOverlay）をそこへ寄せる。文書は設計書・実行計画・台帳・比べ方の手順へ各レーンの「反映する行」を統合する。

**Tech Stack:** Unity UI Toolkit（USS・tss）、C#（Client.Ui・Client.Starter・Client.Tests）、Node（tools/uitk の生成器）、uloop・winunity。

## Requirements

- R-1（黒の幕）: 黒の幕（`rgb(0,0,0)` を全面に敷き地に比を掛けるだけの面。`--modal-backdrop-face`・`--screen-backdrop-face`）だけ暗い半透明の指数を `blackDimExponent` に分け、生成器の formula 行で値を出す。受け入れ: 生成器の照合 0 差分、ランタイムの PanelSettings で参照の地の色を敷いて描いた幕と Web（地×(1−α)）の差を実測し、最大差・平均差を台帳 LX-46 に書く。2 段以内に入らない地があれば理由（Linear 合成で 1 つの α は sRGB の掛け算を全域で再現できない）と実測を残す。S2-hud の画面の幕（4-player-inventory 系の地）も同じ実測の表に並べる
- R-2（Φ の 1 本化）: ぼかした縁の被覆率を `Client.Ui/Foundation/Theme/GaussianEdgeCoverage.cs` の 1 本にし、`DialogFrameShadow.NormalCdf`・`CrosshairShadowRing.CoverageAt` とその表を消す。受け入れ: `grep -rn "NormalCdf\|CoverageAt\|Coverages =" Client.Ui` が 0 件、関係テスト緑
- R-3（ドラッグの型）: `IUiDropTarget` を消し、`IUiDragPayload<in TTarget> where TTarget : class` と `UiDragDrop.MarkSource<TTarget>`・`MarkTarget<TTarget>`・`UnmarkTarget<TTarget>` にする。解放点から最寄りの「同じ型の」落とし先を引く（Web の closest(selector)）。受け入れ: 受け手のキャスト 0、型の違う落とし先を飛ばすテスト 1 本、S3-hotbar-modal・S3-buildmenu の計画の該当箇所が新しい形
- R-4（倍率と座標）: 画面 px（左下原点）→パネル座標の換算とポインタの出所を `Client.Ui/Foundation/Input/Pointer/` の `IUiScreenPointer`・`InputSystemUiScreenPointer` に 1 本化し、`IGrabOverlayPointer`・`InputSystemGrabOverlayPointer` を消す。CursorTooltip の倍率は `StageScaleSource` から読み、`ICursorTooltipScreen.ScreenPixelsPerPanelPixel` を消す。受け入れ: `^Client\.Tests\.Ui\.` 緑、bd moorestech-albof.40 を閉じる
- R-5（CI だけで落ちるテスト）: `UnityCursorTooltipScreenTest.ロックの切替をロック状態を書き換えた後に一度ずつ知らせる` の batchmode の失敗を winunity で再現し、原因を測ってから直す（消す・無視するのは不可）。受け入れ: batchmode（winunity test --class）で緑
- R-6（ギャラリーの固まり）: 部品ギャラリー窓の幅 320 前後で GameTextField の見本が固まらない。本番の狭い親でも起きうるかを実測し、起きるなら部品側で防ぐ。直った後に「Attempted to release an invalid texture」（bd moorestech-p16u1）を再現して直す（再現しなければ実測を bd に残す）
- R-7（PickingIgnore）: 自前の部分木 Ignore の本文が残っていないことを確かめる。ToastHostView・CursorTooltipView・PauseMenuView・ScreenBackdropView を Web の pointer-events と照らして決め、判断記録に書く
- R-8（参照キャプチャ）: 台帳「## 参照キャプチャ」の 2560×1080 の置き場の記帳を確かめる。Web の撮影表への追加をこのブランチで足してよいか規則で確かめ、足せないなら依頼として残す
- R-9（撮影の道具）: 共有の撮影の道具（`UiRuntimePanelCapture`・`GameViewResolution`）が compare-procedure.md と実行計画の「計画に必ず書くこと」から辿れる
- R-10（文書の統合）: C4-b・C4-e 計画末尾の「設計書・実行計画へ反映する行」、C3-b D-47〜D-53（§1.2／§2.2／§2.4）、C4-e の D-29・D-34・D-35・TryMoveItem 廃止と LocalItemMoveResult、旧名（StageColumnsMount・StageColumnsRouting）を設計書・実行計画へ。§2 を変えたらカタログを再生成
- やらないこと: S2-tutorial の持ち物（Screens/Tutorial 系・KeyControlHint・ワールドピン。Tokens.uss の `--world-pin-arrow-shadow`・`--tutorial-drag-guide-shadow` の値も変えない）、PLAN-W3c の持ち物（plans/ の新規計画・設計書 §7.1 の A-115〜A-129）、S4 の計画、Web（`moorestech_web/`）の変更、影（`--modal-shadow-*`・`--progress-arrow-glyph-shadow`）の指数

## 判断記録（ADR）

- D-1 黒の幕だけ指数を分ける（指揮の決定。C3-b 要裁定 1）。対象は「全面に敷く黒の幕」2 行に限る。影（`--modal-shadow-*`・矢印の影）とワールドピン系の黒は Tokens の生成側で値が変わり S2-tutorial の持ち物に触れるので含めない
- D-2 Φ は Foundation/Theme（LinearBlendOpacity と同じ「描画の式」の置き場）。表の補間をやめ erf にする（3σ の外は 0.0013 で、8 bit で見えない）
- D-3 落とし先は型ごとの表で引き、最寄りの「同じ型の」印を取る（Web の elementFromPoint→closest(selector) と同型）。別の型の印は飛ばす
- D-4 画面ポインタの口は Foundation/Input/Pointer。ロック中の中央はツールチップだけの規則なので ICursorTooltipScreen に残す
- D-5 録画: ポインタの換算と幕の値はランタイム挙動に触れるので uitk-grab-overlay と uitk-lifeline を回す
- D-6 Execution Handoff と user-simulator は指揮の指示で省く（このセッションで実行・§5 の独立評価不要）
- D-7 ロック状態の正本は書き手 InputManager の IsCursorLocked。batchmode（-nographics）は Cursor.lockState への代入を捨て None を返し続ける（winunity の batchmode で実測: isBatchMode=True・代入直後も None）。読み手はツールチップと UiPointerHitTest の 2 つとも寄せる（設計書 A-134）
- D-8 GameUiPointerProbe の換算も UiScreenToPanel へ寄せる（設計検査の第 3 バケツだが R-4 の主題そのもの）
- D-9 黒の幕の指数は 2.15（参照画素 400 点で最大 6・平均 2.4 段。2.2 は最大 7・平均 2.8）。2 段以内は Linear 合成の 1 つの α では届かないので LX-46 に残す（設計書 A-130）
- D-10 ギャラリーの固まりは見本の flexShrink=0 で止め、部品側の最小幅は足さない。同じ 2 本を幅 66px に入れた実行時パネルでは固まらない（EditorWindow でだけ起きる）
- D-11 「invalid texture」32 件はギャラリーの窓の型ごとに出る（中身を消しても 32、窓 2 枚で 64、同じ中身の素の EditorWindow では 0）ところまで絞って bd moorestech-p16u1 に記録し、Editor のノイズなので原因の特定は打ち切る
- D-12 Web の撮影表（referenceShots.ts）への 3-modal-backdrop-only・4-player-inventory-grab の追加は、compare-procedure §2「feature/uitk の Web には手を入れない・撮り直しは master の worktree」に当たるのでこのブランチでは足さず integrator への依頼に残す
- D-13 PickingIgnore: 自前の部分木の本文は I-fix2 で 5 画面とも UiPickingIgnore へ寄っていた（grep 0 件）。CursorTooltip・画面の幕は部分木、トースト・ポーズは自要素だけ（設計書 A-135）
