# UITK I-fix2（integrator への依頼の消化）Implementation Plan

> **For the controller session (実装を担うsubagentはこのブロックを無視してよい):** このplanは Execution Handoff をせず、起草したセッションがそのまま実行する（指揮の依頼）。ステップはチェックボックス（`- [ ]`）記法。§5 の独立評価は不要（指揮の依頼）。

**Goal:** C2-b・C3-a・I-fix1・PLAN-W2a/b/c・S2-mode-tooltip が integrator へ積んだ共有の道具・トークン・基盤・文書の直しをまとめて行う。

**Architecture:** ランタイム撮影と Game View の解像度切替は `Client.Ui.Editor/Capture/` に 2 つの静的クラスとして置き、uloop の `execute-dynamic-code` から 1 行で、録画 DSL からは `Client.Playtest` の `PlaytestGameViewOps` 経由で呼ぶ。トークンは生成器（`tools/uitk/convert-web-tokens.mjs`）と手書きの `DerivedTokens.uss`＋`handWrittenDerivedRows.mjs` で直し、α は新しい撮影道具で実測して決める。UiText は辞書の文を引数の有無に関わらず補間の経路へ通し、残った枠は既存の補間器が `Debug.LogError` で知らせる。

**Tech Stack:** Unity UI Toolkit（PanelSettings・RenderTexture）・UnityEditor 反射（GameView）・Node（依存なし）・NUnit（L1）・プレイテスト DSL

土台: `origin/feature/uitk`（d4347f75ef）。

## Requirements

- R-1 ランタイム撮影の道具（A-74 の共有化）: `UiRuntimePanelCapture.Render(content, width, height, ground)` が本番の `GameUiPanelSettings` の複製と sRGB の RenderTexture で `content` を描き、読める `Texture2D` を返す。`CaptureToPng` は PNG に書く。`GameViewResolution.Set(width, height)` が Game View を固定解像度にする（無ければ足す）。uloop は `execute-dynamic-code` の 1 行、DSL は `PlaytestGameViewOps.SetResolution(width, height)`（`Screen.width/height` が変わるまで待つ）で呼べる。受け入れ: L1 で単色の箱と地の画素を読んで一致、1280×720・2560×1080 の両方で `CaptureToPng` が PNG を出す（uloop で実行）、DSL から 2560×1080→1280×720 を切り替える録画 1 本の result が PASS。compare-procedure.md §3 に使い方

## 判断記録（ADR）

| ID | 決定 | 理由 |
|---|---|---|
| D-1 | 撮影道具と解像度切替は `Client.Ui.Editor/Capture/` に置き、DSL は `Client.Playtest` に薄い ops を足して呼ぶ（`PlaytestDriver` は 199 行なので足さない） | 撮影は Editor 専用（反射・AssetDatabase）で、UITK の並べ比べの持ち物。ギャラリー（同 asmdef）の見本をそのまま描ける。DSL の static ops はシナリオから直に呼ぶ前例（`Operations/Ui/PlaytestUiOps`。`Operations/` 直下は .cs が 10 本なので `Ui/` に置く） |
