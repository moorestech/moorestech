## Requirements

- R-1 字間の単位: UITK の `letter-spacing` は px 表記でも「字の大きさ/100 × 値」で効く。生成器は `--*-letter-spacing` の em を ×100、px を「使う字の大きさのトークン」で割って ×100 した値で書く（px の字間に字の大きさの対応が無ければ生成を止める）。受け入れ: `--key-hint-letter-spacing` 5.5px・`--challenge-hud-letter-spacing`／`--operation-hud-letter-spacing` 8.3333px が生成され、`DerivedTokens.uss` の `--hud-label-letter-spacing` は参照のまま同じ値に解ける。ランタイムで 1 つ以上「Web と同じ字幅」を実測（Web の字幅＝字間 0 の幅＋字間 px × 字数）
- R-2 二重補正なし: 手で換算済みの字間（`GamePanel.uss` 題 2px・`Typography.uss` 題 -3.6px）はトークンを経由しておらず、生成器の換算と重ならないことを確かめる。受け入れ: その 2 つの値が変わらず、関係 L1 が緑
- R-3 暗い半透明面の α: 生成器の暗い色の式を `1-(1-α)^1.85`（C2-a のランタイム実測の指数）にし、`--surface-navy`・`--skit-window-face`・`--tooltip-face` 等を再生成。手書きの `--game-panel-craft-face`・`--pause-menu-face`・`--mode-switch-selected-face`・`--panel-action-text-outline` も同じ式の値にし、生成器が式から値を出して照合する。受け入れ: ランタイムの PanelSettings（Linear 合成・`targetTexture`）に描いた色を、Web の sRGB 合成の式と比べた表を作業報告に残す
- R-4 GameScrollView のホイール量: 同じ InputSystem のホイール注入（`SemanticInput.MouseWheel(-120)`）で、Web（CEF）の設定画面が動く px を実測し、`GameScrollView` が同じ px 動くようにする。受け入れ: L1（WheelEvent を送って scrollOffset の変化を検査）が緑、録画 `quality-ui-switching` が全体スイッチ GameUi で PASS
- R-5 文書: compare-procedure.md §3 に「色はランタイムの PanelSettings で比べる」、設計書の `GameScrollView` つまみ 7.2px に整数丸めの注記、§2.6 `TooltipFace` 行に幅ベース折り返しの注記、§3.1 に字間の単位の注記、docs/uitk-migration の F1 前の記述（`UiAssetCatalog`・`ShowRejected`）、component-catalog.md:9 の旧パス、W0-cef の計画逸脱（`BugReportBundleWriter` の ctor・確保時読み）。判断記録は A-70〜A-74、見た目の例外は LX-42〜LX-45
- やらないこと: C2-b の所有（`Components/Controls/` の FormButton・IconButton 等の新規・`Screens/BugReport/`）、`docs/superpowers/plans/` の他の新規計画、設計書 §7.1 の A-50〜A-69。明るい色の α（`α^2.2`）は今回の実測対象外（未確認に書く）

## 判断記録（ADR）

| ID | 決定 | 理由 |
|---|---|---|
| D-1 | 字間の換算は生成器に置き、px の字間は「使う字の大きさ」の対応表で割る。対応の無い px は生成を止める | 字間トークンは使う側の字の大きさを知らないと UITK の値にできない。黙って px のまま出すと C2-c の 1/8 の字間に戻る |
| D-2 | 暗い色の α 補正の指数を 2.2→1.85 | C2-a がゲームの地で測った 4 面（持ち物・チャレンジ HUD・craft・スキット）の合う α が指数 1.79〜1.94。地 30〜180 のどこでも 2.2 は合う α より濃い側に外れる |
| D-3 | 明るい色の式（α^2.2）は据え置き | 今回の依頼は暗い面。明るい色は地が暗い面か世界かで合う値が大きく違い、実測が無い |
| D-4 | ホイール量は「同じ InputSystem のスクロール値で CEF と同じ px」に合わせる | 指揮の決定（ゴールに沿い 1 ノッチを Web 相当に正規化）。CEF には InputSystem の値がそのまま渡るので、UITK 側をその量へ揃えれば実マウスでも DSL でも同じになる |
| D-5 | ランタイム挙動（スクロール量）に触れるので unityプレイ録画テスト `quality-ui-switching` を入れる | AGENTS.md・moores-writing-plans の規則 |
| D-6 | DSL の `SemanticInput.MouseWheel` をノッチ数（実マウスと同じ正規化値）にし、`CefInputForwarder` は 1 ノッチ＝CefUnity の `WheelPixelsPerStep` px で CEF へ送る（実行中に追加） | InputSystem の `scrollDeltaBehavior` は `UniformAcrossAllPlatforms`（実マウス 1 ノッチ＝1）。DSL が -120 を生で入れると UITK では 120 ノッチになり、CEF 転送は 120px（実プレイの CefUnity は 60px/ステップ）で、どちらも実機と違う量を測っていた |
| D-7 | `quality-ui-switching` のパイプを上から地表へ当てた高さに置く（実行中に追加） | 固定 y=96 は今の地形で地表の約 80m 上にあり、影オフの後に水位 Renderer が視野外で `isVisible` が偽になった（影ありの間は影の描画で真だった。推測） |
| D-8 | 暗い色の式は輝度 0.5 未満の判定のまま。純色の赤（`--tutorial-attention-glow`）が外れるのは未対処（実測は台帳） | 使う部品（チュートリアルの強調）がまだ無く、合う式を決める実測の地が無い |
