# 設置照準の占有セル索引を八分木にする設計（2026-11-14）

## 目的
ADR 0100 決定9 の基準（ベースラインワールドで、物理レイが空へ抜ける最悪の向きでも照準1本 0.1ms 以下・Editor）を満たす。照準の結果（当たるかどうか・距離・面）は今の1マスずつの走査と完全に同じにし、距離の上限は置かない（ADR 0100 決定4・9）。

今の実装（16マスのチャンク1段で空チャンクを飛ばす、8aa8912014）は軸方向 0.064〜0.096ms、対角 0.21〜0.25ms で、対角が基準を満たさない。

## 前提にした事実
コードから（読んだだけで実行はしていない）:
- 設置位置に上限が無い。サーバーは重なりしか確かめず（`WorldBlockDatastore.TryAddBlock`）、ワールドの端・高さの上限は無い。座標は負にもなる。
- 照準は設置モード中に毎フレーム1回撃つ（レール接続だけ2回）。削除ツールの箱選択は走査を使わない。
- 照準の後で呼び出し側が「プレイヤーから 100m 以内か」を判定する（`PlacementDistanceRule`）。物理レイ自体は距離無制限。

ベースラインワールドの実測（windows-desktop、Editor の Debug 最適化。生データは `docs/performance/2026-11-13-placement-aim-cell-traversal/index-design/`）:
- ブロック 15,082、占有セル 138,926。1×1×1 が 11,939。縦は y=64〜111 にほぼ集中。範囲 (49,0,−384)〜(1104,113,2485) で、z が 0 をまたぐ。
- 辞書（`Vector3Int` キー）の検索は1回 85〜240ns、配列は 20ns。ただし辞書を使わない形でも、飛ばす・1マス進むの1回に約0.5µs かかる。時間を決めるのは「飛ぶ・進む回数」で、検索の速さはその次。

## 候補の比較（同じレイで測った。結果はすべてセル単位の走査と一致）

| 案 | 最悪のレイ5本（ms） | 実プレイに近い照準1,000本 p99／最大（ms） | 備考 |
|---|---|---|---|
| 今（16マスのチャンク1段） | 0.07〜0.33 | 0.25／0.39 | 対角が基準超え |
| 段ごとの辞書（4・16・64・256） | 0.01〜0.15 | 0.095／0.155 | +Z が今より遅い（下りるたびに辞書を引く） |
| 16マスのブリック（ビット）＋256マスの段 | 0.01〜0.13 | 0.048／0.085 | 対角・低い対角が基準超え |
| **八分木（根を広げる、葉は 4×4×4 の ulong、直前の道からたどり直す）** | **0.006〜0.045** | **0.029／0.049** | 全部が基準内 |
| 八分木（毎回根からたどる） | 0.007〜0.059 | 0.040／0.068 | |
| 八分木（葉の中の 2×2×2 も飛ばす） | 0.006〜0.042 | 0.027／0.043 | 差は誤差の範囲 |

最悪のレイ5本は、全占有セルの外接直方体を最上段で +X・+Z・対角2本、y=90.5 で対角1本、端から端まで何にも当たらずに横切る線。実プレイに近い照準は、ブロックから 20m 以内の地面に立ち、目の高さ（+1.6m）から俯角 −60°〜+15°・方位ランダムに撃ち、物理レイの距離で区切ったもの。結果の突き合わせは、この 1,005本に加え、ワールドの外・中・上からランダムに撃った約3,000本（当たり 2,850本）で、当たるかどうか・距離・面の軸がすべて一致した。

## 決定

### 1. 構造：根を広げる八分木を配列で持つ
- ノードは段 L（大きさ 2^L）の立方体。一番下は段2（4×4×4）の葉で、64マスの占有を ulong 1つのビットで持つ。段3以上は子8つの番号を持つ内部ノード。
- ノードは `int[] children`（ノード番号×8）と `ulong[] leafBits` に詰め、クラスのオブジェクトを作らない。設置・撤去で GC のごみを出さないため。
- 根の位置は、ワールド座標とは別に持つ基準点 `origin` からの相対座標で決める。根は相対座標 [0, 2^rootLevel) を覆う。
  - 理由: ノードを「その大きさの倍数の位置から始まる」と決めると、座標 0 がどの段でも境目になり、0 をまたぐワールド（ベースラインワールドは z が −384〜2485）を1つの根で覆えない。試作でこの形にしたところ、根を広げる処理が止まらなかった。
- 棄却: 段ごとの辞書（下りるたびに辞書を引き、+Z で今より遅い）、16マスのブリック＋256段（対角が基準超え）、ブロックの箱の BVH（隣り合うブロックの境目の同値を今の規則とずらさずに作るのが難しく、設置・撤去で木を組み直す仕組みが要る）、XZ の四分木＋高さ（3次元で空かどうかを持つ八分木に対して利点が無い。実測で 16マスの XZ 柱 658 に対して 3次元のチャンク 826 で、縦方向に分けても数はほぼ同じ）。

### 2. 根の広げ方と段数
- 最初のセルが入ったとき、そのセルを基準点にした段3（8×8×8）を根にする。
- 根の外にセルが入ったら、外れた向きへ根を各軸2倍に広げる。負の側へ広げる軸は基準点を根の大きさだけ下げ、古い根を新しい根の上半分の子に置く。根の中に入るまで繰り返す。ずらす量が根の大きさなので、既存のノードはすべてそのまま使える。
- 段数の上限は決めない。段数は置かれた範囲から決まる（ベースラインワールドで根は段14＝16,384マス、広げた回数11）。最初のセルの位置しだいで、必要な大きさ（段12＝4,096）より最大2段ほど大きくなる。走査では直前の道からたどり直すので、上の段が多くても時間はほとんど変わらない。
- 撤去で根は縮めない（外接直方体と同じく広がるだけ）。全セルが無くなったときだけ木を空に戻す。

### 3. 更新（`BlockOccupiedCellIndex`）
- `セル → ブロック` の辞書は今のまま持つ（照準の始点がブロックの内側のとき、そのブロックの箱を引くため）。
- 「木のビットが立っている ⇔ 辞書にそのセルがある」を常に保つ。`Register` は辞書に新しく入ったセルだけ木に足す（別のブロックのセルを奪うときは足さない）。`Remove` は同じ参照に結ばれたセルを辞書から外したときだけ木から消す。
- 木から消すとき: ビットを消し、葉が0になったら葉を空きに戻して親の欄を空ける。親の子が全部空なら、その親も空きに戻し、根の手前まで同じことを繰り返す。空きにした番号は次の追加で使い直す。
- 今の 16マスのチャンクの数（`_occupiedCountByChunk`、`IsChunkEmpty`、`ChunkShift`）は外す。外接直方体（広がるだけ）は走査の範囲を切るのに残す。

### 4. 走査（`PlacementAimCellTracer`）
- 今の手順を一般化する。毎回「今いるセルを含む空のノードのうち最も大きいもの」とそのセルが埋まっているかを木に問い合わせる。
  - 空のノードがあれば、その出口の時刻を求める。射程を超えるなら外れ。出口の時刻が今の辺・角の組の時刻より後なら、出口の直前のセルへ飛び、組の記録を消す。同じ時刻なら飛ばない。
  - 境界の近い軸へ1マス進む（同値は Y → X → Z）。入ったセルが埋まっていれば、その組の最初の軸の面を返す。
- 当たり方が変わらない理由は今と同じ（空のノードの中のセルはどれも埋まっていない。出口と同じ時刻の越境は先に進めずに残す）。
- 問い合わせは、直前にたどった道（段ごとのノード）のうち今のセルをまだ含む最も深いノードから下りる。毎回根からたどるより最悪で約25%速い（0.059 → 0.045ms）。道は走査の始めに捨てるので、設置・撤去で古くならない。
- 根の外（走査の入口のセルだけで起きる）は、飛ばさずに1マス進む。
- 葉の中の 2×2×2 を飛ばすことはしない（実測で差が無かった）。

### 5. 距離の上限
置かない。構造だけで最悪 0.045ms に収まり、ADR 0100 決定4・9 をそのまま保てる。

## 見込み（試作の実測）
- 照準1本: 最悪 0.006〜0.045ms、実プレイに近い照準で p99 0.029ms・最大 0.049ms。
- 読み込み: 138,926セルで木を作るのに 35ms（Debug の Editor）。今の 16マスのチャンクの数を数える処理はなくなる。
- メモリ: 内部ノード 3,761・葉 7,735 で約180KB。
- 試作は `execute-dynamic-code` のスニペットとして動かした値で、本番のコードに入れると変わりうる。実装後に同じ手順で測り直す。

## テスト
- 索引: 乱数で設置・撤去を繰り返し、木の「埋まっているか」が辞書と常に一致すること（0 をまたいで正負の両側へ根が広がる場合を含む）。全部撤去すると木が空に戻り、また設置できること。撤去で空いたノードの番号が次の設置で使い直されること。
- 走査: 今のテストに加え、正負にまたがる広い範囲（±数千マス、空きが大きい固まり）で、全セルの箱との交差と、当たるかどうか・距離・面を突き合わせること。大きいノードの角ちょうどを通る線で、辺の同値が Y を選ぶこと。
