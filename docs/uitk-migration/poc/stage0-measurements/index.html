結論: 赤信号は出ていない。S1・S3 は合格。S2 は Editor で 3 経路とも写る（配布ビルドでの経路(3)は未確認）。S15 は「action を出さない」は満たすが、pointerOverUi が true のまま残る。
  • S1 合格 — PanelSettings.sortingOrder だけで CEF の前にも後ろにも置ける。1 以上なら前、-1 以下なら後ろ。0（CEF の Canvas と同じ値）のときは UITK が前に出る。Web のインベントリを開いた状態で確認した。
  • S2 Editor で合格／配布ビルドは未確認 — Unity Recorder・PlaytestScreenshot・ScreenFrameReader の 3 経路すべてに UITK と CEF が写り、前後関係も画面どおりだった。Mac の配布ビルド相当は 1 回焼いたが、ディスクが満杯で出力が壊れていて起動しなかった（下記）。
  • S3 合格 — QueueStateEvent で注入したクリックが、InputSystemUIInputModule を通って UITK のボタンに届く（pointerdown 1 回・click 1 回）。画面座標→パネル座標の往復は誤差 0。IsPointerOverGameObject も UITK を拾う。ただしカーソルがロックされている間（通常のゲーム画面）は UITK に届かない。
  • S15 一部不合格 — * { pointer-events: none !important } にすると、当たり判定のある要素が 0 になり action も 0 件になる。html 要素だけを none にする方式では 32 要素が当たったままで、クリックすると action が 1 件出た。どちらの方式でも、CEF 経由の pointerOverUi が true のまま固まる（切替の後に pointermove が来なくなるため）。

S1: UITK パネルと CEF の前後

プローブは 2 枚のパネル。前用のパネル（マゼンタの板とオレンジの「S3 PROBE」ボタン）と、後ろ用のパネル（シアンの帯と左の板）。どちらにも F{frame} t={秒} の透かしを描いている。Tab で Web のインベントリを開き、sortingOrder の組を変えながら撮った。

指揮セッションからの確認: Tab が効かなかった件と、HUD だけで判定していた件

1 回目の撮影（run 20261026_005744）では Tab の後もインベントリが開かず、b_inv〜f_inv はワールドと HUD だけで撮れていた。HUD のホットバーで前後は読めていたものの、全画面の Web パネルでは確かめていなかったので、撮り直した。

  • UITK のフォーカスが Tab を食っていたのではない。撮り直しでは、プローブを出す前の対照で before Tab state=GameScreen → after Tab state=PlayerInventory、プローブを出した後も with probe: after Tab state=PlayerInventory になった（run 20261026_040840）。プローブのボタンは focusable=false で、Editor での実測では IME 画面を出していない。
  • 原因（推測）: Editor が前面にいない間、Input System がデバイスを無効にしていた。同じ時間帯の S3 の実行で focused=False kb=False mouse=False（backgroundBehavior=ResetAndDisableNonBackgroundDevices）を観測している。シナリオの実行中だけ IgnoreFocus／AllDeviceInputAlwaysGoesToGameView に切り替え、終わったら元に戻すようにしてから、注入が届くようになった。1 回目の実行そのものではデバイスの状態を記録していないので、推測と書いておく。

S2: 録画・スクショ・バグ報告動画への写り込み

配布ビルド相当（Mac）での経路(3): 未確認

ローカルで PlayerBuildRequest.ForLocalDevelopment(StandaloneOSX) を焼いた（Addressables のクリーンビルドを含めて 28 分）。Unity は Build Result :Succeeded（TotalSize 3211595421）を返したものの、ディスクの空きが約 100MB しかなく、Contents/Resources/Data には data.unity3d.tmp（29MB）だけが残っていた。起動すると No GlobalGameManagers file was found ... quitting player! で即終了する。ビルドが壊れていても成功として通ってしまうこの問題は、bd moorestech-albof.1.1 に積んだ。再ビルドにはおよそ 4.5GB 要る。同じボリュームで常駐している本番サービスの書き込みを止めないため、空きが 2GB を切っている今は焼いていない。

焼き直す手順（空きが 10GB 以上あるとき）: poc/uitk-stage0-measure の Editor で Client.Editor.Build.UitkStage0PocBuildCli.BuildWithoutExit(BuildTarget.StandaloneOSX, "<出力先>") を呼ぶ。起動は moorestech.app/Contents/MacOS/moorestech --uitkWithCef --uitkProbeAutoCapture --uitkAutoStartLocal。タイトルの「ローカルで開始」を自動で押し、40 秒後に 3 組を撮って persistentDataPath/UitkStage0/<日時>/ へ *_framereader_F*.png を書く。

S3: 入力注入 → UITK

  • EventSystem.IsPointerOverGameObject はボタン（picking=Position）の上で True、picking=Ignore の板の上で False。ゲーム側の UiPointerHitTest は、板の下にある Web のホットバーを拾って True になった（webPointerOverUi=True）。
  • UITK の画面で操作するには、今の Web の画面と同じく、カーソルを解放する状態遷移が要る。

ユーザーに見てほしい判断（agent 既定・ユーザー未裁定）

  1. S15 の受入をどう満たすか。agent 既定: 委譲中は Unity 側が Web の pointerOverUi を読まない（委譲状態を持つ Unity 側の 1 か所で無視する）。Web には * {pointer-events:none !important} を当てる。Web から「委譲に入ったら false を送る」方式は Web の描画タイミングに依存するので採らない。計画 §4.8 の代替案（委譲中は Web の HUD も描かない）は、HUD が消えるので最後の手段に残す。
  2. S2 を段階 1 の関門として通すか。agent 既定: Editor の 3 経路で写ったので S2 は合格として扱い、配布ビルドでの経路(3)は S9 の PoC ビルドを焼くときに同じビルドで確かめる（同じ起動引数で撮れる）。配布ビルドで写らなければ、そのとき赤信号に戻す。
  3. 背面パネル。sortingOrder を負にするだけで CEF の後ろに置けると分かった（追加の仕組みは要らない）。通知層を背面に置くかどうかは、計画どおり段階 1 の担当が決める。

S9（IME）用の PoC ビルド

置けていない。Mac・Windows とも、ディスクの空き（2GB 未満）が 1 本分の出力（約 4.5GB）に足りない。Windows 検証機には Unity も repo も置かない運用なので、mac-mini で焼くしかない。焼く口は実験ブランチに入っている。

  • Mac: Editor の uloop から UitkStage0PocBuildCli.BuildWithoutExit(BuildTarget.StandaloneOSX, dir)。または batchmode で -executeMethod Client.Editor.Build.UitkStage0PocBuildCli.MacLocalRelease（出力先は環境変数 UITK_POC_BUILD_OUTPUT）
  • Windows: batchmode で -buildTarget StandaloneWindows64 -executeMethod Client.Editor.Build.UitkStage0PocBuildCli.WindowsLocalRelease（同じ環境変数）
  • 起動引数を付けなければ CEF を初期化しない。--uitkWithCef で CEF ありの比較になる。ゲーム画面で単行と複数行の TextField、IME の状態（imeCompositionMode・変換中文字列・フォーカス）、イベントのログが出る。F8 で表示を切り替える。手順は bd moorestech-albof.8 に書いた。

実測中の環境の障害

  • dev-server-reaper が実測中の Editor を落とした。~/.local/bin/uloop が素のバイナリで上書きされ、所有 receipt を書くラッパーを経由しなくなっていたため。ラッパーの symlink を戻して復旧した。
  • 別の worktree で CEF のサーバーが動いている間、こちらの CEF が code -6 で初期化に失敗し、Web が白紙になった（同時に動かしたことが原因だというのは推測）。撮り直しは、他に CEF が動いていないことを確かめてから行った。
  • ディスク満杯。Addressables のビルドが SBP の書き込み失敗で落ちた（BuildCache を消して再実行）。その後、プレイヤーが壊れたまま Succeeded になった（上記）。
