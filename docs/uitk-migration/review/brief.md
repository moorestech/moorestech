## 指摘の出し方（厳守）
- **この計画はすでに重い。オーバーエンジニアリングな指摘を出さない。** 新しい仕組み・ゲート・文書・段階・表・検査を足す提案は、それが無いと起きる具体的な故障（どの段階で、何が、どう壊れ、既存のどの手順でも捕まらないか）を示せる場合だけ出す
- 削る・まとめる・単純にする指摘を歓迎する。ただし、削ると具体的に何が壊れるかを考えてから出す
- 推測で事実を断定しない。repo の file:line・計画書の節番号・実測値を根拠に書く。確かめられないものは「推測」と明記する
- 指摘は最大10件。重要な順に並べる。迷ったら出さない
- 各指摘の形:
  - 種別: 誤り（事実・論理）／欠落（無いと壊れるもの）／過剰（削れるもの）／順序（段階や依存の誤り）
  - 対象: 計画書の節番号
  - 根拠: file:line・節番号・実測
  - 何が起きるか: 故障シナリオ、または削ったときに減るもの
  - 最小の直し方: 計画書をどう書き換えるか（1〜3行）
- 最後に「この観点での総評」を3行以内で書く
