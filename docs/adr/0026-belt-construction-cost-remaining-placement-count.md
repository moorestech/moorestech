# 0026. ベルトの建設コストは「残り設置数」の財布で1セットN個にする

日付: 2026-08-21
状態: 採択

## Context

ブロックはアイテム化されておらず、設置は `va:placeBlock` がセル毎に `requiredItems` 全額を消費する（撤去は全額返却）。旧経済ではベルトコンベアは「1クラフトで3個（電気ベルトは5個）」だったため、直接設置化で実効コストが3倍（電気は5倍）になった。2026-07-05にこの端数を長尺ベルト（n連）で吸収する案を採択したが、2026-07-19にn連を撤去し（`docs/superpowers/specs/2026-07-19-remove-multi-cell-belt-conveyors-design.md`）、3倍コストが残っている。ベルトだけ requiredItems を下げると素材粒度（青銅シート1が最小）で割り切れず、全体の数量を3倍にするのも重い。

端数の住所は「永続する隠し状態／1操作内の束ね／価格／アイテム／設置単位」のいずれかにしかない。

## Decision

- blocks に必須フィールド `placementsPerCost`（設置数/1セット）を追加する。全ブロックを一括更新し、既存は1、歯車ベルト（直線・鉄）=3、電気ベルト（ベルトコンベア・高速）=5、分岐器=1。
  出所: ユーザー裁定 2026-08-21（「ベースは1でよくて」＝blocks必須フィールド案／「旧レシピ通り: 歯車系3・電気系5」選択）
- サーバーにプレイヤー×財布の**残り設置数**を持つ `RemainingPlacementCountDataStore` を新設し、セーブに永続する。設置時: 残り>0なら素材消費なしで-1、残り=0なら建設コスト1セット消費→+N→-1。
  出所: ユーザー裁定 2026-08-21 原文「やっぱり、ベルトコンベアで1アイテムあたり3ブロック、を実現したい、もしくは3倍量精算できるようにしたい」「前却下した『コンベア設置のクレジットシステム』みたいなものを実装したいから検討して」→ 選択「永続クレジット台帳」
- 撤去時: 残り+1。Nに達した瞬間に建設コスト1セットへ凝縮して返却（返却不能なら現行どおり撤去失敗）。置く⇄壊すが完全等価。
  出所: ユーザー裁定 2026-08-21「クレジット+1、N貯まったら素材に凝縮して返却」選択
- 財布キーは beltConveyorFamilies 所属なら straightBlockGuid へ正規化（unlock判定 `PlaceBlockProtocol.cs:120` と同じ前例）、非所属は自分の blockGuid。バリデータでファミリー内の requiredItems と placementsPerCost の一致を検証する。
  出所: ユーザー裁定 2026-08-21 原文「クレジットの合算をどう定義するかが迷い中」→ 選択「beltConveyorFamilies をそのまま財布境界に使う」
- 財布キーの解決（`ConstructionWalletUtil`）はベルトファミリーを直接知る。共有単位が2系統目に増えるまではこの据え置きを前提とし、増えた時点で解決規則を汎用化する。
- クライアント同期は規約どおり3点セット（`RemainingPlacementCountChangedEventPacket`＋初期データ＋購読）。UIはビルドメニュー詳細のコスト欄に「この素材でN個」と残り設置数を表示。HUD・カーソルツールチップには出さない。
  出所: ユーザー裁定 2026-08-21「ビルドメニューのコスト欄に『N個分』＋残クレジット」選択
- プレイヤー向け文言・コード・スキーマとも「クレジット」「支払い」を使わず、用語集（CONTEXT.md: 建設コスト／設置数/1セット／残り設置数／財布）に揃える。
  出所: ユーザー裁定 2026-08-21 原文「『支払い』『クレジット』みたいな言葉は出さない。『残り設置数』みたいな感じで出す」＋「コードも用語集に揃える」選択
- `placementsPerCost == 1` のブロックは財布を素通りし現行と同一挙動（agent前提: 既存全ブロックの挙動不変）。
- 財布の永続化は既存のプレイヤー別セーブ（`AssembleSaveJsonText`）に載せ、DebugParameter `FreeBlockPlacement` は財布も素通りする（agent前提: 前例踏襲）。

## Considered Options

- 1操作内だけ束ねる（ceil(n/N)課金・永続状態なし）— 却下: 歯車ベルトに多い1〜2マスの短距離接続でN倍価格が残る。出所: ユーザー裁定 2026-08-21
- 撤去は残り+1のみ／返却なし — 却下: 死に資産化／全額返却方針と不整合。出所: ユーザー裁定 2026-08-21
- 汎用「クレジット共有グループ」マスタ新設／財布をブロックGuid毎／コード内共有リスト — 却下: ファミリーと二重定義／坂込みの短いベルトで複数セット開く／マスタ定義のコード複製。出所: ユーザー裁定 2026-08-21
- 全ベルトN=3 — 却下: 電気ベルトが旧比1.67倍。出所: ユーザー裁定 2026-08-21
- カーソルツールチップにも残数／残数非表示 — 却下。出所: ユーザー裁定 2026-08-21
- （2026-07-05提示・当時採択→撤去）n連長尺ベルト — 再採用せず。

## Consequences

- 新しいプレイヤー別可変状態（財布）がセーブ・同期・UIに増える。ベルト4ファミリー（placementsPerCost>1）だけが実際に使う。
- クライアントの「置ける数」プレビュー（`ConstructionCostPreviewCalculator`）は残り設置数込みで計算し、サーバーのセル毎判定と一致させる必要がある。
- ブループリント貼り付け・Ctrl+Z取消・ドラッグ設置は同じ `va:placeBlock`/撤去経路なので自動的に財布を通る。
- 電気ベルトの電線自動接続の予約コストは「そのセルで実際に消費する建設コスト」を渡す必要がある（残りがあれば0）。
