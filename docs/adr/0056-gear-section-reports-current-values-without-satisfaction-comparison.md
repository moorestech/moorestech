# 0056. 歯車セクションのトルク/RPMは現在値の報告であり充足の比較をしない

日付: 2026-09-11
状態: 採択

## Context

Web UI のブロック詳細に出る歯車セクション（`GearSection.tsx`）は、トルクとRPMを「現在 / 要求」で描き、現在が要求を下回ると赤にしていた。これは旧 uGUI `SetGearText` の移植で、当時の歯車網はトルクを要求比で比例配分していたため「現在 < 要求」が供給不足を意味した。

現行の歯車網に部分供給は無い。需要動力が供給動力を超えると網ごと停止し、動いている間は全消費者の要求が全額通る（`GearNetworkPowerCalculator`）。そのため消費側が state に載せる `CurrentTorque` は「現RPM・待機倍率込みの自分の要求トルク」であり、供給量ではない（`SimpleGearService.CurrentTorque`）。分母にマスタの `BaseTorque` を置くと、待機中（要求倍率 0.2）は常に赤、RPMが基準を超えると永久に黒になる。

ADR 0010 は「実効要求電力に対する充足率」を idlePowerRate を持つ全消費者に適用すると書いたが、歯車には移らない。実効要求トルクを state に足して分母にしても、分子は同じ関数の同じ tick の値なので常に等しく、比較は恒真になる（前セッション案。非本質と裁定）。

発電機3種（SimpleGearGenerator / FuelGearGenerator / ElectricToGearGenerator）は消費要求を持たず、同じセクションで分母 0 の「X / 0.0」が描かれていた。

## Decision

- **消費側のトルク行は「消費トルク: 現在値」のみ。分母（`BaseTorque`）と赤判定を廃止する。**
  出所: ユーザー裁定 2026-09-11 原文「そもそもラベルを消費トルクにかえたほうがいいかな」→ 選択「消費トルク: 現在値のみ」（[[2026-09-11-歯車消費側のトルク行は消費トルクの現在値のみにする]]）
  棄却案: ①「現在 / 基準（赤なし）」で分母だけ残す ②トルク行を削除

- **発電機側のトルク行は「発生トルク: 現在値」とし、ラベルを出し分ける。判別はクライアントがマスタ param で行う（`IGearConsumptionParam` を持つ→消費、持たない→発生）。`GearStateDetail` に発電/消費フラグは足さない。**
  出所: ユーザー裁定 2026-09-11 選択「発生トルク: 現在値のみ」（[[2026-09-11-歯車発電機のトルク行は発生トルクとして出し分ける]]）
  棄却案: ①両者とも中立ラベル「トルク」 ②発電機ではトルク行を出さない

- **消費側のRPM行は「RPM 現在 / 基準RPM」の並記を維持し、赤判定は廃止する。**
  出所: ユーザー裁定 2026-09-11 選択「消費側は現在/基準だが赤なし」（[[2026-09-11-歯車消費側のRPM行は現在と基準を並記し赤判定は付けない]]）
  棄却案: ①現在/基準と赤を維持（RPM不足=遅く動くことを赤で出す） ②全て現在値のみ

- **発電機側のRPM行は「RPM 現在値」のみ。**
  出所: ユーザー裁定 2026-09-11 選択「現在値のみ」（[[2026-09-11-歯車発電機のRPM行は現在値のみにする]]）
  棄却案: 燃料歯車発電機だけ「現在 / 最大RPM」

- **不足を示す赤は歯車網の停止理由行（`GearNetworkSection`）に一本化する。** トルク・RPM行は赤を出さない。
  出所: ユーザー裁定 2026-09-11（上記トルク行の選択肢説明「『不足』の意味は網停止理由に一本化される」を含む案の採択）

- **歯車機械の機械行（稼働状態ラベル＋充足率 `CurrentPower/RequestPower`）は現状維持し、歯車行と両方出す。** 歯車機械では要求電力 = `BaseTorque × BaseRpm` のためこの充足率は `rpm / 基準RPM` に一致し、RPM行と同じ情報の二重表示になるが許容する。電力機械と歯車機械で機械行の形を揃えたままにする。
  出所: ユーザー裁定 2026-09-11 選択「両方残す（現状維持）」（[[2026-09-11-歯車機械の充足率行は歯車行と重複しても両方残す]]）
  棄却案: ①歯車機械は充足率%行を消し稼働状態ラベルだけ残す ②両方残すが歯車機械だけ%行のラベルを「速度」に変える

- **稼働状態ラベルを持たない歯車消費者（歯車ベルト・歯車採掘機等）で、待機中であることを歯車行では示さない。** 消費トルクの実値だけを出し、サーバー state は拡張しない。待機中の低い値は赤にならず、不足は網停止理由行で別途出るため「不足か待機か判別不能」は起きない。
  出所: ユーザー裁定 2026-09-11 選択「示さない。消費トルクの実値だけ」（[[2026-09-11-機械以外の歯車消費者に待機表示は出さない]]）
  棄却案: ①稼働状態ラベルを歯車消費者全種に出す（サーバーが待機フラグを送る） ②「消費トルク 0.1（待機 20%）」のように要求倍率を併記する

- **純伝達ブロック（歯車・シャフト・チェーンポール）も消費側と同じ行構成で出す。** チェーンポールは基準トルク0のため「消費トルク 0.0」とそのまま出る。回転方向（時計/反時計）は表示しない。
  出所: ユーザー裁定 2026-09-11 選択「全ブロック同じ行構成（0.0でもそのまま）」（[[2026-09-11-純伝達ブロックも歯車消費側と同じ行構成で出す]]）
  棄却案: ①基準トルク0のブロックはトルク行を出さずRPM行のみ ②同じ行構成に加えて回転方向の行を足す

- **歯車網の負荷率（需要動力/供給動力）の表示は本件のスコープに含めない。** 網集約行は「供給 / 要求」の実数のまま。
  出所: ユーザー裁定 2026-09-11 選択「今回は出さない（GearSectionの是正に絞る）」（[[2026-09-11-歯車網の負荷率表示は今回のスコープに含めない]]）
  棄却案: `GearNetworkDto` に負荷率を追加し「供給 300 / 要求 180（負荷率 60%）」と併記する

- **ADR 0010 との関係: 本ADRを新設し、ADR 0010 には歯車セクションを除外する旨の追記だけ行う。** ADR 0010 の本文は電力の裁定として維持する。
  出所: ユーザー裁定 2026-09-11 選択「新ADR 0056＋ADR-0010に除外の追記」
  棄却案: ADR 0010 本文を改訂して歯車の扱いを同居させる

- **データ形状: `GearStateDetail`（サーバー）は変えない。クライアント dto は発電/消費の役割と `BaseRpm` を持ち、`BaseTorque` は落とす。**
  出所: agent前提（設計原則「判断は具体側で行い基盤に業務語彙を持ち込まない」。役割はクライアントがマスタ param から導出できるため state 拡張不要）

## Consequences

- ローカライズ: `ui.blockInventory.gearTorqueSummary` / `gearRpmSummary` は「消費トルク」「発生トルク」「RPM 現在 / 基準」「RPM 現在」の4文言に分かれる（4言語列すべて）。
- `blockDetails.spec.ts` の「トルク」テキスト断言と目視QA撮影スクリプトは新文言へ追従する。
- `WireContractBlockDetailTest` の `GearDetailDto` 契約は新形状へ更新する。
