# 0070. プレイテストの許可リストと起動時照合を撤去し、報告者の追跡は取り込み時のSteam表示名解決で担う

日付: 2026-09-25
状態: 採択（ADR 0065 の識別の出どころ「受け口の検証済みID」を撤回し、ADR 0061 の「起動時にWorkerの許可リストでSteamIDを照合し不許可ならタイトルで止める／Workerに届かなければ止める（オンライン必須）」を撤回する）

## Context

ADR 0061 は、個別に参加停止できるようにするため、起動時にWorkerの許可SteamID一覧と照合し、届かなければタイトルで止める設計にした。運用を始めると、キーを配るたびに `allowlist.sh add` が要り、開発者本人の配布ビルドも "This Steam account is not on the playtest list" で止まった。参加者の絞り込み自体は、パスワード付きベータブランチとキー配布が既に担っている。

報告と進行記録には、Workerが検証したSteamIDが今も付いている（`uploadsAuthorize.ts`・R2キー `reports/<steamId>/<id>/`）。ただし日次ダイジェストに出るのはSteamIDだけで、誰の報告かを人が読んで分かる形にはなっていない。

## Decision

- **許可リストをまるごと撤去する。** Workerの許可リスト照合・管理API（`/v1/allowlist`）・R2の `config/allowlist.json`・`scripts/playtest/allowlist.sh` を消す。`/v1/session` は Steam 認証チケットの検証だけでトークンを発行する。
  出所: ユーザー裁定 2026-09-25 原文「そもそもこのリスト自体まるっと消す」（直前の質問「このチェック機構って必要？」への回答として。提示していた選択肢は拒否リストへの反転・照合をまるごとやめる・現状維持で、原文はこのうち「照合をまるごとやめる」にあたる）
  棄却案: 拒否リストに反転する（個別停止は残し追加の手間を無くす）／現状維持

- **起動時ゲートとオンライン必須も撤去する。** 起動は常に通し、オフラインでも遊べる。トークンは報告・進行記録の送信時に取りに行き、送れなければ既存の outbox に溜めて後で送る。
  出所: ユーザー裁定 2026-09-25 質問「許可リストを消すとき、起動時のゲート自体（Workerに届かなければタイトルで止まる＝オンライン必須）も消しますか？」→ 選択「A：ゲートごと消す」
  棄却案: 照合だけ外し起動時の通信は残すが止めない／照合だけ外しオンライン必須は残す

- **報告者の名前は、Mac miniの取り込み時にSteam Web API（`GetPlayerSummaries`）で解決する。** SteamIDから表示名とプロフィールURLを引き、報告のメタ情報に「取り込み時点の名前」として保存する。日次ダイジェストは `名前（SteamID・プロフィールリンク）` で出す。ゲーム本体とWorkerには名前を扱わせない。
  出所: ユーザー裁定 2026-09-25 原文「FBやバグ報告時、steamユーザー名などをとれるようにして追跡出るようにしておきたい」→ 質問「『誰の報告か』を、どこでSteamユーザー名に結びつけますか？」→ 選択「A：取り込み時にMac miniがSteam Web APIで名前を引く」
  棄却案: ゲームが送信時に自分の表示名を報告に書く（本人申告）／Workerが発行・アップロード時にWeb APIを引きR2メタに書く

- **初回起動の同意ポップアップ（`ui.playtest.consent.body`）に、報告がSteamアカウント（SteamIDと公開表示名）に紐づけて記録される旨の1文を英日独で足す。** 末尾の「これ以外はPCから送信されません」との食い違いを無くすため。
  出所: ユーザー裁定 2026-09-25 質問「初回起動時の同意文に、Steamアカウントが紐づくことを書き足しますか？」→ 選択「A：1文足す」
  棄却案: 文面はそのまま、キー配布時の案内で伝える

- **報告・進行記録・異常終了箱に書く `steamId` は、配布版の起動時にローカルの Steam API（`SteamUser.GetSteamID()`）で読んで `PlaytestSessionIdentityProvider` へ差し込む。** 照合の撤去で ADR 0065 の出どころ（受け口の検証済みID）が無くなるため。追跡の正は R2 の置き場所（トークン由来の検証済み SteamID）で、記録内の値は参考情報にとどまる。
  出所: ユーザー裁定 2026-09-25 質問「報告・進行記録・異常終了箱に書くSteamIDは、どこから取りますか？」→ 選択「A：ローカルのSteam API（SteamUser.GetSteamID()）で起動時に読む」（ADR 0065 の棄却案を採り直す）
  棄却案: 記録内の steamId 欄をやめ R2 の置き場所に一本化する／初回アップロードの認証成功時に検証済みIDを差し込む

- **同意ポップアップの文言追加後も、既読のテスターへは再表示しない。** 表示規則（保存先ごとに初回1回）は ADR 0065 のまま。既存テスターへはキー配布時の案内などで個別に伝える。
  出所: ユーザー裁定 2026-09-25 質問「同意ポップアップに1文足したあと、既に『了解』を押したテスターにもう一度見せますか？」→ 選択「B：再表示しない」
  棄却案: 同意の版を上げ既読の人にも1回再表示する

- 名前解決の対象は報告（バグ報告・感想）と進行記録の両方とする。
  出所: ユーザー裁定 2026-09-25 質問「名前を付ける対象に、自動送信の進行記録も含めますか？」→ 選択「A：進行記録にも付ける」
  棄却案: 報告だけに付け、進行記録はSteamIDのみ

- 保存するのは取り込み時点の名前とプロフィールリンクまでとし、閲覧時に現在名を引き直さない。同一人物の判定はSteamIDが担う。
  出所: ユーザー裁定 2026-09-25 質問「過去の報告を読むとき、保存された名前で足りますか？」→ 選択「A：保存された名前とプロフィールリンクで足りる」
  棄却案: ダイジェスト生成ごとに現在名を引き直し「旧名 → 現在名」で並べる

- Steamの情報とは別の連絡先（Discord ID等）は集めない。
  出所: ユーザー裁定 2026-09-25 質問「報告時に、Steamの情報とは別の連絡先も集めますか？」→ 選択「A：集めない」
  棄却案: 報告画面に任意の連絡先欄を足す

- 名前解決に失敗したとき（Web API不達・キー未設定）は取り込みを止めず、SteamIDのみで保存し、理由をログに出す。次回以降の取り込みで同じSteamIDを解決できたら使う。
  出所: agent前提（AGENTS.md「fail-closed経路は理由をログへ必ず出す」／取り込みを名前のために止めると報告自体が滞るため）

## Consequences

- 個別の参加停止手段が無くなる。止めたい人が出たら、ベータパスワードを変えて残る全員へ配り直す。2026-09-18 に「許可済みテスターが箱を大量に作る行為は運用で許可リストから外す」と裁定していた対策も、同じくこの手段へ退く。
- Workerに届かなくても遊べるため、Worker障害がプレイを止めなくなる。代わりに送信が遅れ、outbox に溜まる。
- 表示名はテスターが変えられる。追跡の同一性はSteamIDが担い、名前は取り込み時点の読みやすさのためのラベルにとどまる。
- 関連ADR: 0061（本ADRが部分撤回）、0064（R2直接PUT。トークンの用途はそのまま残る）
