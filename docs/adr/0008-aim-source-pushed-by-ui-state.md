# 0008: 照準ソースはUIステートがプッシュし、通常モードの三人称は左Alt押下中だけ自由カーソルにする

日付: 2026-08-05
状態: 採択

## 背景

通常モード（GameScreenState）はカーソルをロックしてカメラ回転を有効にしている。一方 `AimPointProvider` は視点モードだけを見て、一人称なら画面中央・三人称ならマウス座標を照準点として返す。三人称の通常モードではカーソルがロックされているため、返るマウス座標はUnityのロック実装が返す固定値であり、「意図して画面中央」ではなく「ロックの副作用で動かない一点」になっていた。

この照準点はスポイト（`PlacementTargetPickService`）だけでなく、ブロックを開く判定（`GameScreenSubInventoryInteractService`）・採掘（`MapObjectMiningController`）・設置系（`PlaceSystemUtil`）が共有している。結果として三人称の通常モードでは、画面上の任意の位置にある設置物をスポイトできない。

この不具合がテストをすり抜けていた理由も判明した。unityプレイ録画テストの `SemanticInput` はマウス絶対座標を `QueueStateEvent` で注入するため `Mouse.current.position` を直接書き換え、**カーソルロックを迂回する**。`block-eyedropper-via-ui` と `placement-pick-wire-and-train-via-ui` は通常モード中のスポイトを検証して通っていたが、実プレイヤーには再現できない操作を検証していた。

前例として、同ブランチ（`fix/fps-build-mode-camera`）には `UiStateCameraPolicyService` が既にある。Gameplay / Menu / Build の3ゾーンでカーソル/回転ポリシーを一元所有し、`OnViewModeChanged` を常設購読し、Buildゾーンの三人称では既定で自由カーソル・右ドラッグ押下中だけ `CameraLook` へ切り替える。`IPlayerCameraInteractionApplier` は `CameraInteractionMode`（`PointerFree` / `CameraLook`）の単一メソッド契約に畳まれている。

## 決定

1. **通常モードの三人称では、左Alt押下中だけ自由カーソルにする。** カーソルを解放してカメラ回転を止め、離した瞬間に元へ戻すホールド判定とする。トグルにはしない。
   出所: ユーザー裁定 2026-08-05（[[2026-08-05-Alt自由カーソルはホールド判定にする]]）
   実装はGetKey毎フレーム導出ではなくGetKeyDown/GetKeyUpのエッジ検出ラッチ（`_isGameplayAltHeld`）で保持し、ゾーン遷移・視点切替・フォーカス復帰では残留状態の破棄を許容する。Alt+Tabでフォーカスを失うとGetKeyUpが届かず押しっぱなしが固着するため、割り込みで明示的に破棄できる保持形を採る。
   出所: 独立レビュー裁定 2026-08-16（PR #1137 F14=案A）
2. **Altが解放するのは照準そのものであり、スポイト専用の抜け道にはしない。** Alt中は照準点を共有する全機能（スポイト・ブロックを開く・採掘）がカーソル位置に追従する。
   出所: ユーザー裁定 2026-08-05（[[2026-08-05-Alt自由カーソルは照準全体を解放する]]）
3. **一人称では左Altを受け付けない。** 一人称はクロスヘア＋画面中央照準で一貫させる。
   出所: ユーザー裁定 2026-08-05（[[2026-08-05-Alt自由カーソルはTPS時のみ有効にする]]）
4. **`AimPointProvider` は「視点モード」と「三人称時の照準ソース」の2入力を保持して照準点を導出する。** 照準ソースは基盤側で判断せず、各UIステートのカメラ操作サービスがプッシュする。通常モードはAlt押下中だけカーソル、設置・破壊モードは右ドラッグ中も含め常にカーソル。一人称は照準ソースに関わらず常に画面中央。
   出所: ユーザー裁定 2026-08-05（[[2026-08-05-照準ソースはUIステート側からプッシュする]]・[[2026-08-05-AimPointProviderは視点と照準ソースの2入力にする]]）
5. **Alt非押下中の三人称照準は明示的に画面中央とする。** ロック中のマウス座標に依存させない。
   出所: ユーザー裁定 2026-08-05（[[2026-08-05-非Alt時のTPS照準は明示的に画面中央とする]]）
6. **Alt押下でカーソルを解放する瞬間、カーソルを画面中央へ明示ワープする。** 決定5と連続し、Alt前後で照準が飛ばない。
   出所: ユーザー裁定 2026-08-05（[[2026-08-05-Alt押下時にカーソルを画面中央へワープする]]）
7. **制御は `UiStateCameraPolicyService` が担う。新規サービスは作らない。** Gameplayゾーンの修飾入力として、Buildゾーンの `UpdateRotationInput`（右ドラッグ）と同形に足す。同サービスが照準ソースのプッシュも併せて担う。
   出所: agent前提（[[2026-08-05-Alt自由カーソルはUiStateCameraPolicyServiceが担う]]）。設計対話中は削除済みの `BuildModeCameraInteractionService` を参照して「兄弟サービスを新設」と裁定していたが（[[2026-08-05-GameScreenのAlt自由カーソルは兄弟サービスに切る]]）、同ブランチのより新しいレビュー裁定 [[2026-08-05-カメラポリシーは単一サービスがUIState側で所有する]] がAlt実装を見越して単一所有へ統合していたため、そちらを優先して覆した
8. **修飾キーは左Altのみ。** `HybridInput` の KeyCode→Key マップに LeftAlt を追加する。WindowsのAlt+TabがOSに奪われる件は受け入れる。
   出所: ユーザー裁定 2026-08-05（[[2026-08-05-自由カーソルの修飾キーは左Altのみとする]]）
9. **Alt中もカーソルがWeb UI要素の上にあるときはスポイトを不成立とする。** 既存の `UiPointerHitTest` をそのまま通し、追加コードを書かない。
   出所: ユーザー裁定 2026-08-05（[[2026-08-05-Alt中もHUD上ではスポイト不成立とする]]）
10. **クロスヘアの表示条件は従来どおり一人称限定のまま変えない。** 三人称の非Alt時に照準が見えない件は別問題として切り分ける。
    出所: ユーザー裁定 2026-08-05（[[2026-08-05-TPS非Alt時もクロスヘアは出さない]]）

## 却下した選択肢

- **スポイトだけ実カーソル座標で独自にレイを飛ばす** — 照準系が二重化するため却下。出所: ユーザー裁定 2026-08-05（AskUserQuestion「Altの意味」）
- **`AimPointProvider` が `Cursor.lockState` を読んで照準ソースを自動導出する** — 設置・破壊モードの右ドラッグ中だけ照準が画面中央へ跳ねてプレビューが飛ぶ。AGENTS「汎用基盤は判断せず具体側が `SetHoge(値)` でプッシュする」にも反するため却下。出所: ユーザー裁定 2026-08-05（AskUserQuestion「照準ソースの所有」）
- **`SetAimPointMode` の単一入力にして `PlayerViewApplier` からの呼び出しを削除する** — インベントリ・SubInventory・ポーズなど照準をプッシュしないステート滞在中に古いモードが残り、常時 `Update` する採掘コントローラがそれを読むため却下。出所: ユーザー裁定 2026-08-05（AskUserQuestion「AimPointProviderのAPI」）
- **Gameplay用のカメラ操作サービスを別クラスとして新設する** — カメラポリシーの所有者が2箇所に割れ、直前のレビュー裁定（単一サービス所有）を打ち消すため却下。出所: [[2026-08-05-Alt自由カーソルはUiStateCameraPolicyServiceが担う]]
- **Alt中はUIヒットテストをスキップしHUDに被った位置でもスポイトできるようにする** — 何も足さない側が「UI上では不成立」であり、スキップ分岐を足すとスポイトだけ他モードと挙動が分かれるため却下。出所: ユーザー裁定 2026-08-05（当初は「被っても取れる」と裁定されたが、複雑性の方向が逆である事実を提示して再裁定）
- **クロスヘアの表示条件を「照準が画面中央のとき」へ変える** — 今回の依頼から外れるため却下。出所: ユーザー裁定 2026-08-05（AskUserQuestion「TPSの照準表示」）

## 帰結

- 通常モードの三人称で、Altを押さない限り照準は画面中央に固定される。三人称にはクロスヘアが無いため、狙点が画面に出ないまま「仕様として」画面中央になる。決定10でこれは受け入れた。
- unityプレイ録画テストのマウス座標注入は、非Alt時の通常モードでは照準に効かなくなる。これはハーネスがカーソルロックを迂回していた穴を塞ぐ効果があるが、既存の `block-eyedropper-via-ui` と `placement-pick-wire-and-train-via-ui` の通常モード照準箇所にAltホールドを追加しないと落ちる。この2本の書き換えは今回のスコープに含む。
- Alt中はWindowsのAlt+Tabが奪われるため、自由カーソル中にTabでインベントリを開けない。Altを離してから押す運用とする。
- `KeyControlDescription` の通常モード文言に左Altの説明を追加する。
