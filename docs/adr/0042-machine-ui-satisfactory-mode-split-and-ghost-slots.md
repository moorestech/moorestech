# 0042. 機械UIをレシピ選択/インベントリの2モードへ分け、スロット固定とゴーストスロットを入れる

日付: 2026-08-30
状態: 採択

## Context

機械UIは Web UI（`moorestech_web/webui/src/features/blockInventory/details/MachineSection.tsx`）で、レシピを持つ機械は `ModeSwitch` の「レシピ選択 / インベントリ」2タブ切替（§8.7、ADR 0010セッション由来）。未選択で開くとレシピタブ、選択直後にインベントリタブへ自動遷移、右クリックで選択解除。レシピ選択タブは「ホバー詳細プレビュー + 代表出力アイコンの9列グリッド」。uGUI版は退役済みで対象外（裁定 2026-08-17）。

サーバーの機械入力インベントリ（`VanillaMachineInputInventory`）は汎用 `OpenableInventoryItemDataStoreService` で、レシピ素材とスロット番号に対応が無い（投入順で任意スロットへ入る）。出力も同様。レシピ未選択の機械は加工しない（`IdleMachineProcessState`）が入力は受け入れる。レシピ選択・解除は `IMachineRecipeSelectorComponent`（`machine_recipe.select` set/clear）で、変更時の入力返却処理（`MachineRecipeRefundUtil`）が既にある。

実マスタ（server_v8）では機械のスロット数はレシピの素材数・生産物数より多いのが普通（入力3/出力3〜4に対しレシピは素材1〜2・生産物1）。液体レシピは61件中入力7・出力3。

## Decision

- **タブを廃止し、レシピ選択モードとインベントリモードをSatisfactory方式で往復する。** 未選択で開く→レシピ選択モード。行を選ぶ→インベントリモードへ自動遷移。インベントリモード上部の選択中レシピ表示（出力アイコン＋レシピ名＋秒数）をクリック→レシピ選択モードへ戻る。
  出所: ユーザー裁定 2026-08-30 原文「レシピ選択モードとインベントリモードを明確に分けるのと、タブを無くして、インベントリ画面はレシピ選択しないと出ないようにする」→ 選択「Satisfactory方式」（[[2026-08-30-機械UIはタブを廃しレシピ選択とインベントリをSatisfactory方式で往復する]]）
  棄却案: ①選択画面へ戻れない一方向 ②選択中表示は情報表示のままで「レシピ変更」ボタンを別置き

- **スロット固定をサーバーで強制する。** 選択中は入力スロットiに素材iのみ受け入れ（ベルト・手投入・シフト移動）、出力スロットjに生産物jのみ排出。
  出所: ユーザー裁定 2026-08-30 原文「インベントリのスロットに半透明のアイテムプレビューをおいて、どのアイテムが配置されるべきかわかりやすくしたい」→ 選択「サーバーもスロット固定にする」（[[2026-08-30-機械入力スロットはサーバー側でもレシピ素材順に固定する]]）
  棄却案: ①表示だけゴーストでサーバーは任意受入のまま ②スロット対応を持たず入力欄全体に未投入素材を並べる

- **レシピ未選択の機械は入力を一切受け入れない。**
  出所: ユーザー裁定 2026-08-30 選択「一切受け入れない」（[[2026-08-30-レシピ未選択の機械は入力を一切受け入れない]]）
  棄却案: 現状通り受け入れ、選択時に不整合分を返却

- **インベントリモードはレシピ分のスロットだけ描き、余剰スロットは非表示。** 入力＝素材数、出力＝生産物数、液体も同様。
  出所: ユーザー裁定 2026-08-30 選択「レシピ分だけ表示し余剰は非表示」（[[2026-08-30-機械UIは選択レシピ分のスロットだけ描き余剰スロットは非表示にする]]）
  棄却案: ①全スロット表示で余剰は空枠 ②余剰をロック風減光で残す

- **ゴーストスロットは入力・出力・液体の全スロットに置き、実物があるスロットでは出さない。**
  出所: ユーザー裁定 2026-08-30 選択「入力・出力・液体の全スロット」（[[2026-08-30-ゴーストは入力出力液体の全スロットに置く]]）
  棄却案: ①アイテムスロットのみ ②入力スロットのみ

- **レシピ選択モードはレシピ名付きの行リスト。** 各行は共有 `RecipeRow` を流用し、中央列は秒数＋静止矢印のみ、レシピ名（出力アイテム名）を行の上辺に置く。行全体クリックで選択。ホバー詳細プレビューと9列アイコングリッドは廃止。
  出所: ユーザー裁定 2026-08-30 原文「satisfactoryの機械レシピを参考にしつつ」→ 選択「Satisfactory風のレシピ名付き行リストへ変更」＋「共有RecipeRowを流用し行上にレシピ名を付ける」（[[2026-08-30-機械レシピ選択画面はレシピ名付きの行リストにする]] [[2026-08-30-機械レシピ選択行は共有RecipeRowを流用し行上にレシピ名を置く]]）
  棄却案: ①現行のアイコングリッド＋ホバー詳細を維持 ②機械専用コンパクト1行の新設

- **レシピ解除の導線は設けない。** UIからは `clear` を発行しない（ブループリント適用等のためプロトコルは残す）。
  出所: ユーザー裁定 2026-08-30 選択「解除導線は設けない」（[[2026-08-30-機械UIにレシピ解除の導線は設けない]]）
  棄却案: 選択画面に「レシピを解除」行/ボタン

- **代表出力（レシピ選択行の名前・アイコン／選択中レシピ表示のアイコン・名前の出所）はアイテム優先・無ければ液体へ拡張する。** 出力アイテムが無くボイラー・石油蒸留機のように液体のみ出力するレシピも選択リストへ残し、代表を出力液体の先頭へフォールバックする。R2（選択中レシピ表示）・R3（行リスト）の「出力アイコン＋レシピ名」はこの代表出力を指す。
  出所: moores-code-review 2026-08-30-1020 C2/D2裁定（[[2026-08-30-機械スロット束縛のレビュー裁定8件]]）。液体のみ出力のフィルタ漏れでWeb UIから恒久的に選択不能になっていた不具合の是正
  棄却案: ①出力アイテム0件のレシピをリストから除外したまま ②`outputItems[0] ?? inputItems[0]` の入力名フォールバックへ復元 ③レシピ名をマスタ側の新規ローカライズキーにする

- agent前提（ユーザー確認済みだが裁定ではない）:
  1. ゴーストは `SlotFrame` の新 data 属性 `data-ghost` と不透明度トークンで描き、個数バッジはレシピ必要数（§4「新しい状態は data 属性を追加」）
  2. 選択中レシピ表示は「出力アイコン＋レシピ名＋秒数」で現行 `machine-selected-product` バッジを置き換える（[[2026-08-17-機械レシピエントリはブロックアイコン名前秒数を表示]] の情報要素に準拠）
  3. モジュールスロット・進捗矢印・分間生産数・稼働状態フッタ・大型パネルレイアウトは現状維持
  4. レシピ0件の機械は現状の小型表示のまま
  5. スロット固定はサーバーの入力/出力インベントリで実装し、既存セーブの不整合は考慮しない（AGENTS.md 後方互換不要）
  6. uGUI側は触らない（[[2026-08-17-クラフトUI改修はWebUI専任でuGUIは今後見ない]]）

## Consequences

- サーバー: `VanillaMachineInputInventory` / `VanillaMachineOutputInventory` に選択レシピ由来のスロット束縛が入る。`InsertItem` / `InsertionCheck` はレシピ素材iのスロットiへのみ入れ、未選択は全拒否。ベルト接続からの投入は不一致時にベルト側で滞留する。レシピ変更時の返却は既存 `MachineRecipeRefundUtil` を通す。出力の `CanStoreOutputs` / 排出も生産物jのスロットjに限定。機械系テストの「任意スロットへ投入」前提が変わる。
- ワイヤ: `MachineDetailDto` は選択レシピGUIDを既に持つため、ゴースト内容（素材・生産物・液体・必要数）はクライアントが `crafting.machine_recipes` トピックから解決する。スロット表示数はレシピから決まる。
- Web UI: `MachineSection` からタブを除去し2モードの状態機械へ。`MachineRecipeSelectionTab`（ホバー詳細＋グリッド）は行リストへ置換。`MachineInventoryBody` はレシピ分スロット＋ゴースト描画。`SlotFrame` に `data-ghost`。`webui-design` §8.7 を実装より先に改訂。e2e `machineRecipe.spec.ts` / `machineGestures.spec.ts` とunitテストを新仕様へ更新。
- チュートリアル: 機械UIをアンカーする誘導（`inventory.item-` 等）があればtestId変更に追従。
