# ADR 0081: ベルトのドラッグ経路は地形を下限として乗り越える

- Status: Accepted
- Date: 2026-10-15
- Related: ADR 0047（既定設置Yは地形最高点を含むセル）、ADR 0080（地形接触ゲート）、bd moorestech-5wy86

## Context

通常ベルト（直線・自動坂）のドラッグは、始点とカーソル点をL字（1コーナー）で結ぶ。
既存ブロックは `ConveyorObstacleScanner` が経路セル直上の積み上がりを下限Yにし、`ConveyorVerticalEnvelope` が
隣接差≤1・端点固定・コーナー踊り場・狭い谷の橋渡しで高さプロファイルを解いて自動で跨ぐ。
地形はこの下限に入っていない。端点Yだけが地形最高点を含むセル（ADR 0047）になり、中間セルは地形を見ないため、
経路途中の丘にベルトが埋まる。

地形めり込みによる設置不可判定は全設置系で入れない方針（`.decisions/2026-10-15-地形めり込み判定は全設置系で入れない.md`）で、
接続線（電線等）が地形に埋まるのは許容する。ベルトだけは埋まらない経路を自動で作りたい。

## Decision

**通常ベルトのドラッグ経路は、L字の形を保ったまま、地形を各セルの下限Yとして既存ブロックと同じ高さプロファイル計算で乗り越える。**

1. 経路の水平形状（L字・1コーナー）は変えない。水平に回り込む経路探索はしない
   - 出所: ユーザー裁定 2026-10-15 原文「ベルトは地形を迂回して最適なルート計算をしたいけど、電線が埋まるのは許容（うまっても埋まってない範囲で切断できるので」→ 選択「A. 上下に乗り越える（L字の経路はそのまま、丘の部分だけ坂で登って越えて降りる。既存ブロックの高架と同じ仕組みで地形も障害物として扱う）」
2. 地形は「これより下に置かない」下限としてだけ効く。経路途中が谷でもベルトは降りず、経路本来の高さで水平に渡る
   - 出所: ユーザー裁定 2026-10-15 提示「経路の途中が谷（両端より低い）のとき、ベルトは降りるか」→ 選択「a. 降りない（水平を保つ）」
3. 地形込みでは高さプロファイルが解けない（急な地形で固定端点へ戻れない等）ときに限り、地形を無視した現行の経路（丘には埋まる）で設置する。既存ブロック起因の立体交差不能（`ImpossibleOverpass` による設置不可）はそのまま残す
   - 出所: ユーザー裁定 2026-10-15 提示「地形が急すぎて、乗り越えたあと端点の高さまで戻れないとき」→ 選択「ii. 地形だけ諦めて今の挙動に戻す（地形込みで解けないときだけ地形を無視した今の経路で置く。既存ブロック起因の設置不可は残す）」
4. 坂ベルトを手持ちにした一定勾配のドラッグ（`BeltConveyorSlopePathBuilder`）には適用しない
   - 出所: ユーザー裁定 2026-10-15 提示「坂ベルトを手に持ってドラッグしたときにも地形の乗り越えを効かせるか」→ 選択「x. 効かせない（通常ベルトだけ）」

5. 各中間セルの地形下限Yは端点と同じ「そのセルの地形最高点を含むセル」（`PlacementGroundCellResolver` / `GroundHeightProbe`、ADR 0047）。斜面で搬送面が部分的に沈むのは許す
   - 出所: ユーザー裁定 2026-10-15 提示「丘を乗り越えるとき、ベルトが地形にどこまで食い込むのを許すか」→ 選択「1. 端点と同じ基準（セル内の地形最高点を含むセル）」
6. 越え方が複数あるとき（丘が続く等）は既存ブロックの高架と同じ規則に従う。地形下限は既存ブロック下限と `max` で合成して1本の下限列にし、`ConveyorVerticalEnvelope` をそのまま解く（基本は最低高さ、降りて平坦区間を作れない狭い隙間だけ橋渡し）
   - 出所: ユーザー裁定 2026-10-15 提示「越え方が複数ある場合どちらを優先するか（推奨: α 既存ブロックの高架と同じ規則）」に対し原文「ok」→ 推奨αの採択と解釈し復唱した
7. 決定3で地形を諦めて戻したときは、カーソルツールチップに設置を妨げない案内（地形が急なため乗り越えられない旨）を出す。セルは赤にしない
   - 出所: ユーザー裁定 2026-10-15 提示「乗り越えられず埋まる経路へ自動で戻したとき、プレイヤーに知らせるか」→ 選択「q. 設置を妨げない案内を出す」

### agent前提（ユーザー裁定ではない）

- 決定3の「解けない」は、合成下限で解いた結果に端点の不可（`feasible` が偽）が出たことを指す。そのときは既存ブロック下限だけで解き直し、その結果（`ImpossibleOverpass` 含む）を採用する。出所: agent前提（決定3の「既存ブロック起因の設置不可は残す」を満たす最小の形）
- 決定7の案内は、カーソルセルに関係なく列全体が縮退したときに1行出す。出所: agent前提（縮退は列単位の判断のため）
- 地表が取れないセル（プローブ失敗）はそのセルの地形下限を付けない（経路本来の高さのまま）。出所: agent前提（決定3と同じく地形は軟らかい下限で、置けなくする理由にしない）
- 地形高さの問い合わせは高架ソルバーへ interface で注入し、純粋ロジック（Envelope）は Physics を知らない。出所: agent前提（`Func<>` 禁止規約と `ConveyorVerticalEnvelope` が純粋ロジックである前例）
- 変更はクライアントの設置プレビュー・送信列だけ。サーバー・セーブ形式は変えない。出所: agent前提（経路はクライアントが計算して PlaceInfo 列で送る現行構造）

## Considered Options

### B. 丘を避けて水平に回り込む経路探索（棄却）
A* 等でコーナー複数の経路を探す。ドラッグで経路形状を決める操作の意味が変わる。棄却: ユーザー裁定 2026-10-15 選択A。

### C. 3D経路探索で回り込みと乗り越えをコストで選ぶ（棄却）
棄却: ユーザー裁定 2026-10-15 選択A。

### 谷にも降りて地形にぴったり沿う／沿うが狭いくぼみは橋渡しする（棄却）
棄却: ユーザー裁定 2026-10-15 選択a（降りない）。

### 解けないときは設置不可にする／端点を持ち上げる（棄却）
棄却: ユーザー裁定 2026-10-15 選択ii。

### 坂ベルト手持ちのドラッグにも効かせる（棄却）
棄却: ユーザー裁定 2026-10-15 選択x。

### 搬送面だけ地表に出す／本体全体を地表に出す（棄却）
棄却: ユーザー裁定 2026-10-15 選択1。

### 坂を減らす優先／常に最低高さ（棄却）
棄却: ユーザー裁定 2026-10-15 原文「ok」（推奨α採択）。

### 縮退時に何も出さない（棄却）
棄却: ユーザー裁定 2026-10-15 選択q。

## Consequences

- 丘を横切るドラッグは、丘の手前で坂を登り、越えて降りる。坂ブロックの数だけ建設コストが変わる（坂も同ファミリーで同コスト）
- 谷の上では宙に浮いたベルトが続く。広く深い谷では高い位置を長く渡る
- 端点のすぐ隣が崖などで解けないと、従来どおり丘に埋まる。設置は通るが、ツールチップに乗り越えられない旨の案内が出る
- 地形めり込みの設置不可判定は引き続きどの設置系にも無い
- 裁定記録: `.decisions/2026-10-15-ベルトの地形迂回はL字のまま上下に乗り越える.md` / `…谷には降りず水平を保つ.md` / `…解けないときは地形を無視した経路に戻す.md` / `…坂ベルト手持ちのドラッグには地形乗り越えを効かせない.md`
