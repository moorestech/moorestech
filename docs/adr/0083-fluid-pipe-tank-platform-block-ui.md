# 0083 パイプ・タンク・液体PFのブロックUIはWebUIに液体の量表示だけ足す

日付: 2026-10-18

## 背景
パイプ・タンク（blockType FluidPipe）はUIが開かず、液体プラットフォーム（TrainFluidPlatform）のUIは積む/降ろすの切り替えと容量しか出さない。中に何がどれだけ入っているかを見る手段が無い。

## 決定
1. UIは既存WebUIのBlockDetailに作る。UI Toolkitへの移行時に作り直す前提。
   出所: ユーザー裁定 2026-10-18 原文「パイプ、タンク、液体PFのUIが欲しい とりあえずサクッと作る。」→ 選択「WebUIで作る」
   棄却: UI Toolkitで作る（ブロックUIの土台作りからになる）
2. 出すのは液体のアイコン・名前・量/容量だけ。操作は付けない。
   出所: ユーザー裁定 2026-10-18 選択「液体名・量/容量だけ」
   棄却: 中身を捨てる操作も付ける
3. 液体PFが表示するのは、PF自身が持つ液体バッファ。停車中の貨車のタンクは出さない。
   出所: ユーザー裁定 2026-10-18 選択「PF自身の液体だけ」
   棄却: PFと停車中の貨車を並べる
4. 液体の表示は機械UIの液体スロット（dto.FluidSlots）と同じ部品を使う。
   出所: agent前提（BlockDetailDtoBuilder.AppendFluidSlots の前例）

5. パイプ・タンクはクリックでブロックUIを開いて中身を見る（マスタの openable を true にする）。ホバー表示は作らない。
   出所: ユーザー裁定 2026-10-18 選択「クリックで画面を開く」
   棄却: ホバーだけで見る、クリックとホバーの両方

6. 液体貨車をFで開いたときの貨車インベントリ画面に、貨車の液体のアイコン・名前・量/容量を出す（液体PFの画面は決定3のまま）。
   出所: ユーザー裁定 2026-10-18 原文「貨車に液体が乗ってる時も対応したい」→ 復唱して選択「1（貨車をFで開いたら液体を出す）」
   棄却: 液体PFの画面に停車中の貨車を並べる、両方
7. 貨車の液体は、開いたときの在庫要求の応答に載せる（初期データ）。貨車の液体が変わったとき・容器が付け外しされたときは統合在庫イベントに「取り直し」通知を足して加入者へ送り、クライアントは開いたときと同じ要求を出し直す。
   出所: agent前提（サーバー状態同期の3点セット＝イベント・初期データ・購読。既存の統合在庫イベントと在庫要求の応答に相乗りする。貨車の液体は液体PFの受け渡しでしか変わらず頻度が低いため、差分ではなく取り直しにする）
