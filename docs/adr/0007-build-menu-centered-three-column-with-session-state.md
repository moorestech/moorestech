# ビルドメニューはstage水平中央の3列パネルとし、閉じても状態を丸ごと保持する

Web UIのstageは持ち物画面の正本合わせで左詰め固定アンカー（`justify-content: start`）だが、ビルドメニューはこのgrid配置から離脱し、ホットバーと同族のstage絶対配置で**水平センター固定**にする（縦は現状維持: 上端=持ち物パネル同高、下端=ホットバー手前）。stageはレターボックスで常に画面中央にあるため、これで全解像度で画面中央に一致する。パネルは1枚のGamePanel内で「カテゴリ | 検索+グリッド | 詳細サイドバー」の3列構成とし、グリッド8列を維持するため総幅を新固定幅トークンへ拡張する。カテゴリボタンはflex伸縮をやめ固定高トークンで統一する。

閉じて開き直したときは、選択タブ・検索文字列・スクロール位置・詳細sticky表示をセッション内ストアで丸ごと復元する（研究ツリーviewport保持と同族・リロードで消える・永続化なし）。

## Considered Options

- 左詰めgrid維持 — 棄却。ユーザーが全解像度での中央表示を要求。
  出所: ユーザー裁定 2026-08-05「UI全体が中心に来ていない・どの解像度でも中心に来ない」
- 縦横完全中央 — 棄却。上部安全帯・ホットバーとの余白が非対称になり他メニューの上端揃えと不一致。
  出所: ユーザー裁定 2026-08-05（AskUserQuestionで「水平のみ中央・縦は現状」を選択）
- 詳細を別GamePanel(craft)フロートにする — 棄却。面が2枚に分かれ単一UIとしてのまとまりが弱い。
  出所: ユーザー裁定 2026-08-05（「同一パネル内で3列・総幅拡張」を選択）
- 保持はタブのみ — 棄却。検索・スクロールも含め閉じた時点の状態を丸ごと復元する。
  出所: ユーザー裁定 2026-08-05（推奨のタブのみ案を棄却し「タブ+検索+スクロールも保持」を選択）
- 詳細サイドバーへの説明文表示 — 今回スコープ外。blocks.yml/items.ymlに説明文フィールド自体が無く、スキーマ拡張＋全マスタ入力が必要な別機能のため。
  出所: agent前提（VanillaSchema・Localization/content_keys.csv の実地調査）

## Consequences

- webui-design §8.11（建設メニュー様式）の改定が必須（大型2列→中央3列・固定高カテゴリボタン・sticky詳細・状態保持）。様式が先、実装が後。
- ModeSwitchの縦利用時の伸縮挙動は共有側で抑止するため、他の縦利用が現れた場合も上詰め固定高が既定になる。
