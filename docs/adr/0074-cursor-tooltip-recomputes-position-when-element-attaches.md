# 0074. カーソルツールチップは要素が付いた時点で表示位置を計算する

日付: 2026-10-01
状態: 採択（ADR 0020「実装後の実測」節のスキット経路の因果説明を訂正する。0020 の決定そのものは維持）

## Context

新規ワールドをストーリーから始め、開幕スキットをスキップして最初にカーソルツールチップを出すと、ツールチップが画面左上（12,12）に固定される。Tab メニューを開閉してマウスを動かすと正しい位置に戻る（ユーザー報告 2026-10-01）。

実カーソル（cliclick による OS 入力）で再現して計測した結果、Web 側の `pointer` はクロスヘア位置（640,360）を正しく受け取っていたのに、表示位置の `position` state が初期値（12,12）のままだった。マウス位置の経路（OS → `Input.mousePosition` → CefUnity の `SendMouseMove` → DOM `pointermove` → `pointer`）は全段で正常に動いていた。

原因は `CursorTooltip.tsx` の位置計算にある。

- ツールチップは Mantine の `Portal` 内に描かれる。`Portal` は初回描画で `null` を返し、layout effect でマウントフラグを立ててから次の描画で子を出す。
- 位置計算の `useLayoutEffect`（依存 `[pointer, data, text, locale]`）は、表示に切り替わった描画で `elementRef.current` が `null` のため何もせず終わる。
- `Portal` が子を出した後の描画では依存が変わらないので、計算は再実行されない。カーソルロック中は `pointermove` も来ないため、`position` は初期値か前回値のまま固まる。

この欠陥はツールチップ基盤の導入時（`1e0ab754b`, 2026-07-18）からある。単体テスト `CursorTooltip.test.ts` が `Portal` を「その場で子を出す」モックに差し替えていたため、テストでは発生しなかった。

ADR 0020 の「実装後の実測」は、スキット経路の症状を「Web 側が一度も座標を受け取っていない」と説明していた。これは誤りだった。根拠の実測はプレイテストの注入マウスで取られていたが、注入マウスは実プレイの経路（legacy `Input.mousePosition`）を通らない。さらに、計測に使った座標換算 `CefScreenMapper.TryBrowserToScreen` の結果は上下が逆転していた（実 CSS 位置 (12,666)＝左下を、Unity 座標 (124,687)＝左上と報告した）。

## Decision

- **表示位置は、ツールチップ要素が DOM に付いた時点でも計算する。** 位置計算のきっかけに「要素の付与」を加え、`Portal` の1描画遅れに左右されないようにする。ロック中の表示位置は従来どおり、`pointer`（ワープ後のクロスヘア座標）を基準にする。
  出所: ユーザー裁定 2026-10-01 原文「ok」（「要素が付いた時点で位置計算を走らせる（callback ref 等）」の修正方針の提示に対して）

- **単体テストの `Portal` モックを本物と同じ遅延マウントにし、初回表示で位置が計算されることを回帰テストで固定する。**
  出所: ユーザー裁定 2026-10-01 原文「ok」（「単体テストの Portal の偽物を本物と同じく1描画遅れて子を出す形にして回帰テストを足す」の提示に対して）

- **プレイテスト基盤の不具合は本件に含めず、別の bead に積む。** 対象は、注入マウスが実プレイの経路を通らない問題と、`TryBrowserToScreen` の上下逆転の2つ。
  出所: ユーザー裁定 2026-10-01 原文「ok」（「プレイテスト基盤の2つの問題は別件として bead に積む」の提示に対して）

- **ADR 0020 の決定（ロックする遷移でカーソルをクロスヘアへワープする）は維持する。** スキット経路の因果説明だけを本 ADR で訂正する。
  出所: agent前提（実測でワープ後の中央座標が Web へ届いていることを確認済み。0020 の決定は本件の原因でない）

## Consequences

- 開幕スキット直後を含め、初回表示でもツールチップがクロスヘア基準に出る。
- 位置計算は Web 側の1ファイルで完結し、Unity 側・wire 契約の変更は無い。
- `Portal` の遅延マウントを再現しないテストモックは、同種の DOM 計測バグを再び隠しうる。モックは本物の描画タイミングに揃えておく。
