# 0079. 駅の既定名は周辺の特徴から構造で付け、表示時に翻訳する

日付: 2026-10-13
状態: 採択

## Context

PR #1415（ADR 0067）で駅名の改名UIが入ったが、新設駅の名前は空文字で、UIでは全駅が「駅」（`ui.blockInventory.timetableUnnamedStation`）と表示され時刻表で区別できない。master 由来の既存セーブの駅名は全て "test"。時刻表は駅名でなく個々の駅ブロックを指し、駅名は表示専用（[[2026-09-24-時刻表は駅名でなく個々の駅ブロックを指す]]）。ゲーム実行中のサーバーが参照できる周辺情報は鉱脈（`IItemMapVeinDatastore` / 液体鉱脈）・マップオブジェクト（`IMapObjectDatastore`）・設置ブロックで、バイオームはマップ生成時にしか存在しない。

## Decision

- **新設駅には周辺の特徴から既定名を付ける（OpenTTD型）。**
  出所: ユーザー裁定 2026-10-13 原文「駅のデフォルト名の命名システムを作りたい」→ 選択「周辺の特徴から付ける (Recommended)」
  棄却案: ワールド通し連番／地名風ランダム生成／座標ベース（[[2026-10-13-駅の既定名は周辺の特徴から付ける]]）

- **特徴は鉱脈（アイテム・液体）を優先し、無ければ最も多いマップオブジェクト種、どちらも無ければ代替名。**
  出所: ユーザー裁定 2026-10-13 選択「鉱脈優先→地物→代替 (Recommended)」
  棄却案: 鉱脈だけ／周辺の自分のブロックも使う（[[2026-10-13-駅の既定名は鉱脈を優先し次に地物を使う]]）

- **既定名は「特徴の種類＋GUID＋番号」の構造で保持し、UIが表示言語で組み立てる。** 改名した駅は文字列を保持する。駅名のセーブ形式と `TrainStationNameStateDetail` が変わるため、セーブマイグレーションを伴う。
  出所: ユーザー裁定 2026-10-13 選択「構造で保存し表示時に翻訳 (Recommended)」
  棄却案: 設置時に文字列で固定／英語固定の文字列（[[2026-10-13-駅の既定名は構造で保存し表示時に翻訳する]]）

- **番号は特徴ごとの連番で、撤去しても再利用しない。** 1つ目は番号なし、2つ目から「… 2」。特徴ごとの次番号をワールドのセーブに保存する。
  出所: ユーザー裁定 2026-10-13 選択「特徴ごとに連番・再利用しない (Recommended)」
  棄却案: 空いた番号を再利用／番号を付けず重複を許す（[[2026-10-13-駅の既定名の番号は特徴ごとの連番で再利用しない]]）

- **設置時に、マスタ原文name（日本語）で既定名を仮に組み立てて既存の全駅名（手動名・他の既定名）と比較し、重なれば番号を進める。** 保存は構造のまま、表示は言語に従う。言語ごとの重複（英語表示だけで重なる等）は拾わない。カウンタは「次に試す番号」であり、比較で飛ばした番号も再利用しない。
  出所: ユーザー裁定 2026-10-13 原文「他の駅名を全部比較して、重複しそうならその時重複しないような名前にする、とかがいいんじゃないですかね」→ 選択「設置時に原文名で比較 (Recommended)」
  棄却案: 特徴ごとの連番だけで重複は許す／手動名とも全言語で照合／表示時にクライアントで比較／既定名を文字列で保存に切替（[[2026-10-13-駅の既定名は設置時に原文名で全駅名と比較し重複を避ける]]）

- **既定名は新設駅だけに付ける。既存セーブの駅名（"test"・空文字を含む）は文字列のまま保持する。** マイグレーションは既存の `stationName` を「改名済みの文字列」へ写すだけで、名前を変えない。
  出所: ユーザー裁定 2026-10-13 選択「新設駅だけ」
  棄却案: testと空を既定名へ置換／空だけ置換しtestは残す（[[2026-10-13-駅の既定名は新設駅だけに付け既存駅は触らない]]）

### agent前提（ユーザー裁定ではない）

- **既定名は設置時（`VanillaTrainStationTemplate.New`）に1回だけ決めて固定する。** 後から鉱脈を掘り尽くしたり木を伐っても変わらない。ロード（`Load`）では決めない。
  出所: agent前提（「周辺の自分のブロックも使う」案の帰結説明で「設置時に固定」を提示済み。設置時固定は既存駅を触らない裁定とも整合）
- **走査範囲は駅ブロックの中心から水平半径32ブロック。** 鉱脈は範囲内で中心に最も近いもの（アイテム・液体を区別せず、AABBまでの距離）。マップオブジェクトは範囲内で破壊されていないものを種類（MapObjectGuid）ごとに数え、最多の種類。同数なら GUID の文字列順で先のもの。
  出所: agent前提（前例となる既存定数なし。決定性を優先し乱数を使わない）
- **代替名は「駅」で、番号は代替名用の1系列で振る**（「駅」「駅 2」…）。
  出所: agent前提（PR1415の未命名表示 `timetableUnnamedStation` と同じ語）
- **表示形式は「{特徴名}の駅」「{特徴名}の駅 {番号}」（英語 "{name} Station" / "{name} Station {n}"）。** 特徴名はアイテム・液体・マップオブジェクトの既存ローカライズ名（ADR 0006 の GUID 由来キー）。
  出所: agent前提
- **サーバーは原文比較用に原文の書式（「{0}の駅」「{0}の駅 {1}」、代替名「駅」）を定数で持つ。** localization.csv の Source 列と同じ文字列にし、一致をテストで確かめる。
  出所: agent前提（ADR 0006 によりサーバーは辞書を持たないため）
- **対象は `TrainStationComponent` を持つ駅ブロック（蒸気機関車駅）だけ。** 貨物・液体プラットフォームは駅名を持たない（ADR 0067）。
  出所: agent前提（現行コードで `TrainStationComponent` を作るのは `VanillaTrainStationTemplate` のみ）
- **改名欄の初期値は表示中の既定名。** 内容を変えずに確定しても送信しない（既定名のまま保つ）。空文字の改名は従来どおり拒否し、「既定名へ戻す」操作は作らない。
  出所: agent前提
- **番号カウンタは特徴キー（種類＋GUID、代替名は専用キー）ごとの次番号で、ワールド単位の datastore としてセーブする。** `WorldSaveAllInfo.CurrentVersion` を 5→6 に上げる。
  出所: agent前提（AGENTS.md のセーブ形式規約）

## Consequences

- 既存テスターのワールドの駅は "test" / 「駅」のまま残る。新しく置いた駅だけが「鉄鉱石の駅」などになる。
- 言語を切り替えると、既定名の駅は名前も切り替わる。改名した駅は変わらない。
- 同じ特徴の駅を撤去して置き直すと番号が進む（「鉄鉱石の駅 3」など）。番号の欠番は許容する。
