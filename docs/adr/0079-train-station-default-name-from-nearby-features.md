# 0079. 駅の既定名は周辺の特徴から設置時に英語の文字列で付ける

日付: 2026-10-13
状態: 採択

## Context

PR #1415（ADR 0067）で駅名の改名UIが入ったが、新設駅の名前は空文字で、UIでは全駅が「駅」（`ui.blockInventory.timetableUnnamedStation`）と表示され時刻表で区別できない。master 由来の既存セーブの駅名は全て "test"。時刻表は駅名でなく個々の駅ブロックを指し、駅名は表示専用（[[2026-09-24-時刻表は駅名でなく個々の駅ブロックを指す]]）。ゲーム実行中のサーバーが参照できる周辺情報は鉱脈（`IItemMapVeinDatastore` / `IFluidMapVeinDatastore`）・マップオブジェクト（`IMapObjectDatastore`）・設置ブロックで、バイオームはマップ生成時にしか存在しない。v8 マスタのマップオブジェクト195種は名前の多くがアセット名（BirchTree01 等）で、翻訳キーも無い。サーバーは翻訳辞書を持たない（ADR 0006）が、mod の `localization/localization.csv` には英語のアイテム名・液体名がある。

## Decision

- **新設駅には周辺の特徴から既定名を付ける（OpenTTD型）。**
  出所: ユーザー裁定 2026-10-13 原文「駅のデフォルト名の命名システムを作りたい」→ 選択「周辺の特徴から付ける (Recommended)」
  棄却案: ワールド通し連番／地名風ランダム生成／座標ベース（[[2026-10-13-駅の既定名は周辺の特徴から付ける]]）

- **特徴は鉱脈（アイテム・液体）を優先し、無ければ地物、どちらも無ければ代替名。**
  出所: ユーザー裁定 2026-10-13 選択「鉱脈優先→地物→代替 (Recommended)」
  棄却案: 鉱脈だけ／周辺の自分のブロックも使う（[[2026-10-13-駅の既定名は鉱脈を優先し次に地物を使う]]）

- **地物は採掘で得る最初の earnItems のアイテムで数え、最多のアイテム名で名付ける。** 採掘できない飾りは数えない。
  出所: ユーザー裁定 2026-10-13 選択「採掘で得るアイテム名で集計 (Recommended)」（帰結「v8では原木93種・石59種・小石4種の3系列に縮退」を明記して提示）
  棄却案: マスタの地物名を整備する／地物は使わない（[[2026-10-13-駅の既定名の地物は採掘で得るアイテム名で集計する]]）

- **既定名は設置時にサーバーが英語の文字列で作り、既存の駅名欄（`stationName`）へ入れる。** 改名と同じ扱いで構造は持たない。セーブ形式・同期・Web UI は変えない。英語名は mod の localization.csv の english 列（`item.<guid>.name` / `fluid.<guid>.name`）から取り、欠けていればマスタの name。
  出所: ユーザー裁定 2026-10-13 原文「そもそも名前は自動で一回つけたら文字列として登録されるもので、その構造時代まで保持する必要はないと思ってたんだけど、それは変に複雑過ぎませんか」「たかが自動名前付けでそんなに色々考える必要ある？」→ 復唱「設置時に文字列で付ける最小構成。言語切替で翻訳されない」への回答「1がそうなら、英語固定とかにできない？」
  棄却案: 構造で保存し表示時に翻訳（同日先行裁定を覆した）／日本語（マスタ name）で固定（[[2026-10-13-駅の既定名は設置時に英語の文字列で確定する]]）

- **番号は、設置時に全駅名と比べて重ならない最小の番号。** 番号なし→「 2」→「 3」…。カウンタは持たず、撤去後に同じ番号が再利用されうる。
  出所: ユーザー裁定 2026-10-13 原文「他の駅名を全部比較して、重複しそうならその時重複しないような名前にする、とかがいいんじゃないですかね」、および復唱「撤去後に同じ番号が再利用されうる」への回答「2はok」
  棄却案: 特徴ごとの連番で再利用しない（同日先行裁定を覆した）／番号を付けず重複を許す（[[2026-10-13-駅の既定名の番号は全駅名と比べ空いている最小番号にする]]・[[2026-10-13-駅の既定名は設置時に原文名で全駅名と比較し重複を避ける]]）

- **既定名は新設駅だけに付ける。既存セーブの駅名（"test"・空文字を含む）はそのまま。**
  出所: ユーザー裁定 2026-10-13 選択「新設駅だけ」
  棄却案: testと空を既定名へ置換／空だけ置換しtestは残す（[[2026-10-13-駅の既定名は新設駅だけに付け既存駅は触らない]]）

### agent前提（ユーザー裁定ではない）

- **既定名は `VanillaTrainStationTemplate.New` で1回だけ決める。** 後から鉱脈を掘り尽くしたり木を伐っても変わらない。`Load` では決めない。
  出所: agent前提（設置時固定は「周辺の自分のブロックも使う」案の帰結説明で提示済み）
- **走査範囲は駅ブロックの水平中心（XZ）から半径32ブロック。** 鉱脈は範囲内で中心に最も近いもの（XZ平面でのAABBまでの距離）。同距離ならアイテムを液体より先、次にGUID文字列の順。地物は範囲内（XZ）で破壊されていない採掘可能なものを数え、最多のアイテム。同数ならGUID文字列の順。どれを選んでも下流は名前の文字列だけで、構造に差は出ない。
  出所: agent前提（前例となる既存定数なし。乱数を使わず決定的にする）
- **書式は "{name} Station" / "{name} Station {number}" / 代替 "Station" / "Station {number}"。**
  出所: agent前提
- **サーバーは起動時に全 mod の `localization/localization.csv` を共通パーサー（`mooresmaster.LocalizationCsv`）で読み、english 列の `item.*.name` / `fluid.*.name` だけを持つ。** 後の mod が前の mod を上書きする（クライアント `ModLocalizationMerger` と同じ順）。CSV が読めない mod はエラーログを出して飛ばす。これは ADR 0006 決定4「サーバーは辞書に非関与」の例外で、用途は既定名の生成に限る。
  出所: agent前提（英語固定裁定の実現手段）
- **地物の採掘アイテムは既存の `IMinableMapObjectParam.EarnItems` と `MapObjectMaster.IsDecoration` で取り、取り出し役を新設しない。**
  出所: ユーザー裁定 2026-10-13 選択「採掘アイテムは既存APIで取る (Recommended)」（計画の型検査の弱い指摘への回答）
- **対象は `TrainStationComponent` を持つ駅ブロック（蒸気機関車駅）だけ。**
  出所: agent前提（現行コードで `TrainStationComponent` を作るのは `VanillaTrainStationTemplate` のみ）

## Consequences

- 既定名は英語の文字列で、表示言語を切り替えても変わらない。改名した名前と区別しない。
- 工場側の駅は v8 では実質「Log Station N」「Stone Station N」になる。
- 既存テスターのワールドの駅は "test" / 「駅」のまま残る。
- 同じ特徴の駅を撤去して置き直すと、空いた番号が再び使われる。
