# イベント出展モードは「終了＝リセット」の再起動ループで運用する

gamescom出展（2026-08-25・展示1台・mac・スタッフ基本常駐だが不在も想定・試遊は新規ワールドから最大20分程度）に向けて、
展示用の仕組みを最小構成で入れる。核となる設計は「アプリ終了がそのままリセットになる」こと。
起動スクリプトが環境変数（`MOORESTECH_EVENT_MODE=1`）を立てて無限ループでアプリを再起動し、
イベントモードのクライアントは起動時に既定ワールド（world_1）を削除して新規生成し、
メインメニューを経由せず自動でゲーム内まで進む。言語は起動ごとに英語へ強制リセットする。
これにより誤終了・途中離脱・異常終了のすべてが「数十秒後に新規ワールドで復帰」に収束し、
ゲーム側の追加UIはゼロで済む。

あわせて、ポーズメニューの「メインメニューへ戻る」ボタンは「セーブして終了」へ恒久的に差し替える（イベントモードに限らない永続変更）。
既知の制約「ゲームは起動後メインメニューへ戻らない（mod書き換えにより再開時の状態を保証できない）」に反して残存していたボタンを設計へ整合させるもので、
通常プレイヤーの正規終了経路（セーブflush済みの終了）もこれで確保される。

無操作自動リセット（イベントモード時のみ、一定時間キーマウ入力なしで `Application.Quit`）も入れる。
終了すればループが新規ワールドで再起動するため、タイマー1本で「前の来場者の工場が次の人に渡る」穴が塞がる。

## Considered Options

- 途中まで工場が動いているマスターセーブをコピーして開始 — 20分で自動化の魅力に届く利点を提示したが、新規ワールド開始を裁定（ユーザー裁定 2026-08-23）
- メニューに「セーブ削除して終了」ボタンを追加 — 起動時削除方式ならUI追加ゼロで済むため棄却（同上）
- イベントモード時に終了ボタンを非表示化（単独/ループ併用） — 「終了＝リセット」なら誤終了が無害でありスタッフ操作も簡単なため棄却（同上）
- 再起動後メインメニューで待機 — ワールド生成の待ち時間を次の来場者が払う形になるため、自動でゲーム内まで進む案を採択（同上）
- 以下は開発せず運用対応と裁定: アトラクトモード・終了画面・QR/Wishlist・DEMO表記（紙/ポスターで）、計測ログ、高速起動、アクセシビリティ、コントローラー対応（キーマウ専用）、スタッフ用チート（既存DebugParametersで足りる）、グラフィック実機確認（出発前チェック）

## Consequences

- ウィンドウ×・Cmd+Q・クラッシュ等のflush待ちを通らない終了経路はイベントモードでは無害（次回起動で必ず削除されるため）。通常プレイでは従来どおりの残存リスクだが本決定の範囲外
- オフライン動作は追加作業なし（全通信がlocalhost内蔵サーバー。SteamManagerはSteam未起動時にエラーログを吐くのみで続行する）
- 英語ローカライズの品質確認はユーザーが別途実施する
- 無操作タイムアウトの既定値は180秒とし環境変数で調整可能にする（agent前提）
