# 0085: ベルト上アイテムの表示物はカメラ範囲内の segment だけ具現化する

日付: 2026-10-18
状態: 採択（仮実装、feature/belt-segment-client-sync に同梱）

## 文脈

ベルトの segment 化(ADR 0083 / 0084 と同じ PR)で、クライアントは搬送の複製を全体で持ち、`BeltItemObjectPresenter` が tick ごとに全 segment を走査して走行中アイテム全部に GameObject を持たせるようになった。旧方式はサーバーがプレイヤー周囲のエンティティだけを送っていたため、クライアント CPU は「周囲の個数」比例だった。新方式では「ワールド全体の個数」比例になり、見積りでは tick のあるフレームで約 2 µs/個(Transform 書き込みが主)、毎フレームで 0.3〜0.5 µs/個(prefab の Update とカリング)。2 万個で 60 fps を割る。

出所: ユーザー 2026-10-18「今回のPRでクライアントでgameobject全部表示になったじゃないですか、旧では周囲のみ表示でした、これによる"cpu"負荷が以前とどうかわりそうかって予想つく？」→ 予想を提示 → 「可視範囲だけ具現化する を今仮実装しちゃおう」「面倒なのでこのPRにまとめます」

## 決定

- 複製は全体を持ったまま(同期とハッシュ照合に必要)、**GameObject を持つのは基準点(メインカメラ)から範囲内の segment 上のアイテムだけ**にする。範囲外の segment のアイテムは「見かけなかった」扱いで即破棄し、戻れば作り直す。
- 判定は **segment 単位**。複製の組み立てごとに各 segment の中心と半径をマス座標から 1 回求め(`BeltSegmentVisibleRange`)、tick ごとに基準点との距離で内外を決める。アイテム数ではなく segment 数比例。
  出所: ユーザー裁定 2026-10-18 質問「可視範囲の判定はどの機構で行いますか?」→ 選択「tick ごとに距離を自前計算」
- 距離は **入る側 340 m / 出る側 350 m**(マップオブジェクトの `MapObjectDistanceVisibilityController` と同じ値、ヒステリシス付き)。
  出所: ユーザー裁定 2026-10-18 質問「具現化する距離はどれにしますか?」→ 選択「340 m / 350 m(マップオブジェクトと同じ)」
- 範囲外に出た表示物は **即 Destroy、プールなし**。
  出所: ユーザー裁定 2026-10-18 質問「範囲外に出た segment の表示物はどうしますか?」→ 選択「即 Destroy(プールなし)」
- 基準点は `IBeltItemViewpoint` で注入し、本番は `CameraBeltItemViewpoint`(`CameraManager.MainCamera`)、テストは固定座標。カメラが無い間は何も具現化しない。
  出所: agent前提（前例 `MapObjectGameObjectDatastore` がカメラを基準にしている。EditMode テストで視点を差し替えるため interface にした）

## 棄却案（実提示したもの）

- 前例どおり CullingGroup に segment の球を登録する: native 判定で速いが、複製の組み直しのたびに球の再登録が要り、EditMode では Camera が無く範囲判定のテストが書けない。判定は segment 数 × 距離 1 回なので自前計算で十分。
- 距離 160 m / 176 m、100 m / 110 m: 負荷削減は大きいが、遠景でベルトの流れが止まって見える。ユーザーは前例と同じ 340 / 350 を選択。
- 範囲外の表示物をプールへ戻す: 境界付近の生成・破棄の連打を避けられるが、ユーザーは実装最小の即 Destroy を選択。

## 影響と残課題

- 1 tick あたりの費用は「範囲内の segment のアイテム数」比例になる。範囲外の工場は複製の搬送 tick(Core、600 万個で 16 ms)だけを払う。
- 毎フレームの費用(prefab 部品の `Update` の lerp、Renderer ごとのカリング)も範囲内の個数に絞られる。lerp を外す・tick 間補間へ置き換える・instance 描画にするのは別 PR(順番: 可視範囲 → 補間 → instance)。
- 範囲内で 2 万個規模になる配置(超大型工場の中心に立つ)では効果が無い。そのときは距離を下げるか instance 描画へ。
- 実測は未取得。録画プレイテストに 2,000 個と 2 万個を流す配置を足して 1 個あたりの µs を取るのは別 PR の最初に置く。
