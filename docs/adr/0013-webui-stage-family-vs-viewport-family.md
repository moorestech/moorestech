# Web UI の表示要素は stage族 と viewport族 のいずれかに属する

Web UI は 1280×720 基準の `.stage` をレターボックス中央へ一様拡縮して描くため、**stage の四辺は実画面の四辺ではない**。それを意識せず画面端HUD（インベントリ/研究のキーヒント・装備HUD）を stage 絶対配置で置いたため、横長画面ほど画面の角から離れる不具合が入った。今後は全ての表示要素が「stage族（1280×720基準で一様拡縮し、形はアスペクト比で変わらない。パネル・グリッド・詳細）」か「viewport族（実画面の辺へ位置が追従し、内容寸法だけは stage 拡縮に従う。常時表示HUD・画面端の案内）」のどちらに属するかを、実装前に宣言する。常時表示HUD族（キーヒント・装備HUD・ホットバー・採掘プログレスバー）は viewport族として `.viewportOverlay` 配下へ置く。

出所: ユーザー裁定 2026-08-17（Q2「A」＝常時表示HUD族をまとめて `.viewportOverlay` へ移す／Q11「A」＝この二分法をデザイン哲学 §1.5 として明文化する）

## Considered Options

- **stage内に留めたまま `calc()` で viewport 補正する**（却下）: 補正式が画面端HUDの数だけ増殖し、次に足す要素が必ず補正を忘れる。破綻源。
- **装備HUDだけを viewport 右下角へ移す**（却下）: `--equipment-bottom: var(--hotbar-bottom)` で共有していたホットバーとの「同じ床」が、縦に余る画面で崩れる。HUD族は床を共有する単位なのでまとめて動かす。
  出所: ユーザー裁定 2026-08-17（Q2 で B・C を却下）

## Consequences

- 基準解像度 1280×720 では stage と viewport が一致するため**描画結果は完全に不変**で、uGUI正本合わせのスクリーンショット回帰は無傷。
- `.viewportOverlay` は `pointer-events: none` のため、移設するホットバー（D&D・クリック）と装備HUD（クリック選択）には `pointer-events: auto` の明示が必須。忘れると操作が死ぬ。
- 極端な横長では装備HUD（実画面右端）が `ItemListPanel`（stage右端）から大きく離れる。これは「画面の角に沿う」要求の当然の帰結として受け入れる。
  出所: ユーザー裁定 2026-08-17（Q13-6）
- stage は `z-index: var(--z-viewport-stage)`（=2）で独自スタッキングコンテキストを作るため、stage内部の層序は Portal 層（モーダル `z=200` / トースト `z=300` / 再接続 `z=2000`）へ影響しない。stage内部の前後関係は `--z-stage-*` トークンで明示する（DOM順への暗黙依存をやめる）。
  出所: ユーザー裁定 2026-08-17（Q7 は当初 B＝DOM順だったが、モーダルへの影響が無いと確認した上で A＝トークン明示へ変更）
- `.viewport` 直下は `--z-viewport-backdrop`(0) / `--z-viewport-behind-stage`(1) / `--z-viewport-stage`(2) の3値で層序を明示する（ADR 0017）。
