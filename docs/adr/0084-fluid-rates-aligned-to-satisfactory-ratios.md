# 0084. 液体の数値は原油系を水・蒸気の桁へ縮め、パイプ律速の比率にそろえる

日付: 2026-10-19
状態: 採択（液体の数量の単位は ADR 0086 で×10。比率はこのADRのまま）

## Context

v8 マスタの液体流量は桁がそろっていない。水・蒸気は歯車ポンプ 2/秒・ボイラー 5/秒なのに、原油は油井 60/秒・蒸留機 41.7/秒と20〜30倍大きい。貨車 `fluidCapacity` は 0（moorestech-qwz1）で、パイプ・貨車が原油の桁に追いついていない。Satisfactory の比率（採掘機1台で精製機2台、細いパイプで精製機5台、貨車は採掘機20分ぶん）を目標にする。変更は v8 マスタ（`blocks.json`・`machineRecipes.json`・`train.json`）の数値だけで、コード・セーブ形式は変えない。

## Decision

- **石油蒸留機レシピは 原油10 → ナフサ2 / ガソリン3 / 残油5、5秒（原油2/秒）。油井は 原油2 / 0.5秒（4/秒、蒸留機2台ぶん）。**
  出所: ユーザー裁定 2026-10-19 質問「たたき台のうち触れられていない値はこのまま採ってよいか」→ 選択「このままでよい」（たたき台の根拠: 原油系を約1/21に縮め出力比をほぼ保つ。Satisfactory の採掘機1台＝精製機2台）

- **鉄のパイプは 10/秒（蒸留機5台ぶん）、鋼鉄のパイプは 30/秒（鉄の3倍、蒸留機15台ぶん）。**
  出所: 鉄は ユーザー裁定 2026-10-19 質問「たたき台のうち触れられていない値はこのまま採ってよいか」→ 選択「このままでよい」（ボイラーは鉄パイプ1本で6台→2台になる帰結を提示済み）。鋼鉄は ユーザー裁定 2026-10-19 原文「鋼鉄流量は30/sにしたい（3倍は維持」（[[2026-10-19-液体流量はパイプ鉄10鋼鉄30接続口60でパイプ律速にする]]）
  棄却案: 鋼鉄 20/秒（Satisfactory Mk2＝精製機10台）

- **液体の接続口を持つ機械はすべて flowCapacity 60/秒。対象: 油井・石油蒸留機・液体タンク・液体プラットフォーム・ガソリンエンジン発電機・化学プラント・ボイラー・蒸気機関・クリーンルームパイプコネクタ・歯車ポンプ。ボイドパイプ（1000）は対象外。上限はつながるパイプで決まる。**
  出所: ユーザー裁定 2026-10-19 原文「接続口は60/s（今後の開発も考慮しある程度の余剰を持たせておく。1ポートしかないので流量はそのパイプに規定される」→ 選択「液体の機械すべて60」（[[2026-10-19-液体の機械の接続口はすべて60にそろえる]]）
  棄却案: 接続口 20/秒（鋼鉄パイプと同値）／原油系と輸送系の4種だけ60にし他は据え置き

- **貨車 `fluidCapacity` 5,000、液体プラットフォーム `capacity` 5,000、液体タンク 5,000 据え置き。**
  出所: ユーザー裁定 2026-10-19 質問「たたき台のうち触れられていない値はこのまま採ってよいか」→ 選択「このままでよい」（根拠: 油井4/秒×20分＝4,800、蒸留機2/秒×40分＝4,800 を丸めた値。プラットフォームは貨車と同値にしてロード時の切り詰めを防ぐ）
  棄却案: 貨車 10,000（手元の未コミット値）— ユーザー裁定 2026-10-19 で 5,000 に上書き（[[2026-10-19-master手元の未コミット調整は液体PRに同梱する]]）

- **ガソリンエンジン発電機は ガソリン1 / 4秒（0.25/秒）、power 1000 据え置き。蒸留機1台（ガソリン0.6/秒）で2.4台がフル稼働し、蒸留機1台あたりの発電量は約667→2,400。**
  出所: ユーザー裁定 2026-10-19 原文「ガソリン発電機は、蒸留器1台で2.4台までフルで賄えるようにしたい」、選択「1台1000のまま」（[[2026-10-19-ガソリン発電機は1台1000のまま消費を4秒1に下げる]]）
  棄却案: 蒸留機1台あたり約0.6台／1台約280に下げて蒸留機1台あたり発電量を今と同じにする

- **化学プラントは時間と出力を据え置き、液体量だけ減らす。ゴム＝ナフサ0.5/5秒→1（4台）、プラスチック＝ナフサ0.5/4秒→2（3.2台）、アスファルト＝残油2/5秒→1（2.5台）、固形燃料＝残油1/2秒→3（2台）。台数は蒸留機1台の出力を全量そのレシピへ回した値（各レシピ単独で2〜4台。両系統を同時に動かすと合計4.5〜8台）。アスファルト収量は蒸留機1台あたり2.17/秒→0.5/秒に減る。**
  出所: ユーザー裁定 2026-10-19 原文「化学プラントは蒸留器1台あたり2〜4台程度にしたい」→ 選択「時間と出力はそのまま、液体だけ減らす」（[[2026-10-19-化学プラントは時間と出力を据え置き液体量だけ減らす]]）
  棄却案: 1〜2程度／整数にそろえる（プラスチック時間4→5秒、台数ほぼ2台）／両系統の合計で2〜4台（選択「各レシピ単独で2〜4台」）

- **原油系機械の内部タンクを縮める: 油井 200→30、石油蒸留機 300→30、化学プラント 300→30（innerTankCapacity）、ガソリンエンジン発電機 fuelFluidTankCapacity 400→20。パイプ容量50と水・蒸気系は据え置き。**
  出所: ユーザー裁定 2026-10-19 原文「減らす」「もう少しだけ多くする」→ 選択「約2倍（30 / 30 / 30 / 20）」（[[2026-10-19-原油系機械の内部タンクは油井蒸留機化学30発電機20に縮める]]）
  棄却案: 今の値を維持／今とほぼ同じため時間（15/15/15/10）／約3倍（50/50/50/30）／パイプ容量も縮める

- **既存セーブの原油・ナフサ・ガソリン・残油は数量のまま引き継ぐ。超過分はロード時の切り詰めに従い、CurrentVersion は上げない。**
  出所: ユーザー裁定 2026-10-19 選択「数量をそのまま引き継ぐ」（[[2026-10-19-既存セーブの原油系在庫は数量のまま引き継ぐ]]）
  棄却案: マイグレーションで約1/20に換算する

- **蒸気機関の蒸気消費（0.1/秒）は今回変えない。**
  出所: ユーザー裁定 2026-10-19 選択「今回は触らず別タスクに」（[[2026-10-19-蒸気機関の蒸気消費は液体桁あわせと切り離す]]）

- **moorestech_master 手元の未コミット調整（液体プラットフォームのプレハブ Station_Fluid_Cargo 化・建設コスト変更・パイプ placementsPerCost 1→3）を同じPRに含める。nodeGraph の視点変更はPRに含めない（手元の未コミット差分は消さない）。**
  出所: ユーザー裁定 2026-10-19 選択「液体以外もPRに含める」（[[2026-10-19-master手元の未コミット調整は液体PRに同梱する]]）

## Consequences

- 鉄のパイプ1本で動くボイラーは6台→2台（ボイラー水5/秒）。歯車ポンプ（2/秒）なら5台ぶん
- 液体プラットフォームは鋼鉄パイプ2本（60/秒）で5,000を約83秒でためる
- 既存セーブは、新しい容量を超えた分（縮めた機械タンクの中身など）がロード時に切り詰められて消える。タンク・パイプに残った在庫は消費量が約1/20になるぶん一時的に得になる（ガソリン5,000で発電機約5.5時間）
- 貨車容量0のバグ moorestech-qwz1 は、貨車5,000で実害が消える（コード側の根治は別）
