# 0013. ローカルプレイは必ず内蔵サーバーを起動する（接続試行フォールバックの廃止）

日付: 2026-08-17
状態: 採択

## 文脈

現行の `ServerConnectionInitializer` は全起動経路共通で「まず設定ポート(既定11564)へ接続試行 → SocketException で内蔵サーバー(port 0)を起動」という probe→フォールバック構造を持つ。`InitializeProprieties` は常に `ServerIp/ServerPort` を持ち、「ローカルプレイ」と「外部サーバー接続」の意図を区別しない。

このため、ポート未指定のスタンドアロンサーバーが11564に居ると、並列worktreeのPlayModeやプレイテストDSLが自前サーバーを起動せずそこへ誤接続する事故が起きる。フォールバックによる意図の吸収は「設計の敗北」原則にも反する。

## 決定

1. **モードはファクトリ2本で明示する。** `InitializeProprieties.CreateLocalServer(...)` / `CreateRemoteConnection(ip, port, playerId)` の2本に絞り、内部にモードを保持する。暗黙にリモート試行する `CreateDefault()` は廃止し、全呼び出し側（StartLocal・プレイテストDSL・StandaloneQa・EditModeInPlayingTestUtil）をローカル明示へ一括更新する。
   - 出所: ユーザー裁定 2026-08-17（Q1でA案を採択。型分割B案は却下）
2. **ローカルモードは接続試行なしで必ず内蔵サーバーを起動する。** `CreateLocalServerArgs` に明示ポートがあれば尊重し、無ければ port 0（OS自動採番）で起動し `BoundPort` へ接続する。SocketException 捕捉によるフォールバック try-catch は削除する。
   - 出所: ユーザー裁定 2026-08-17（bd moorestech-kjp の反転案を承認）
   - port 0既定・明示ポート尊重の細部は agent前提（現行 `Port ??= 0` の維持）
3. **外部サーバー接続はConnectServerメニューの明示指定のみ。** エディタ用の外部接続先指定手段は追加しない（必要になった時点で後付け）。
   - 出所: ユーザー裁定 2026-08-17（Q2でA案を採択。エディタ用接続設定B案は却下）
4. **失敗時は両モードともフォールバックせずエラー表示→メインメニューへ戻る。** リモート接続失敗で内蔵へ落ちない。try-catch はネットワーク/プロセス境界の隔離（エラー表示と復帰）用途のみ残す。
   - 出所: ユーザー裁定 2026-08-17（Q3で承認。リトライ・ダイアログ案はスコープ外）
5. **11564の残骸を同時掃除する。** クライアント側 `ServerConst.LocalServerPort` の暗黙参照と、`MainGameStarter` の未使用フィールド（`IPAddress`/`Port`/`isLocal`/`localServerProcess`/`PlayerId`）を削除する。スタンドアロンサーバー自体の既定ポート11564はサーバー側の話で本ADRの対象外。
   - 出所: ユーザー裁定 2026-08-17（Q4でA案を採択。掃除先送りB案は却下）

## 検証

コンパイル＋既存テスト（Playtest系・Boot系）に加え、unityプレイ録画テストで「11564にダミーサーバーが居る状態でもそこへ繋がらず自前の内蔵サーバーを起動する」ことを実証する。
- 出所: ユーザー裁定 2026-08-17（Q5でB案を採択）

## 影響

- 「スタンドアロンサーバーを11564に立てておけばローカル開始ボタンで繋がる」暗黙のサーバー開発フローは廃止。外部接続はConnectServerメニューが唯一の受け皿。
- CLAUDE.local.md の「スタンドアロンサーバーは `--port` 明示」運用注意は、本反転後はPlayMode誤接続の観点では不要になる（クライアントが11564を見に行かなくなるため）。
