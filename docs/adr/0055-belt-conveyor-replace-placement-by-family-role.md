# 0055. ベルトコンベアの張替え設置はファミリーのロール対応で行う

日付: 2026-09-10
状態: 採択

## Context

2026-07-22 に「ベルトコンベア リプレース設置」が一度実装され（旧spec a02c76b8c）、翌日 PR #1050 の整理のため全て revert された（bf5fe7eea / 9847f3d1c）。宣言された後続PRは出ていない。

当時の方式は「ドラッグで計算した経路座標にたまたま同ファミリーのブロックがあれば張り替える」もので、経路のYは新規設置と同じ計算だった。坂や立体交差で持ち上がった既設ラインとは座標が合わず、坂・分岐器が絡むと張替えが外れる。

マスタの `beltConveyorFamilies` は 歯車 / 鉄歯車 / 通常 / 高速 の4ティア×（直線+上り+下り）に加え、各ティアの分岐器が「直線だけの単独ファミリー」として計8行ある。分岐器は同ティアの直線と結び付いておらず、「分岐器を同ティアの分岐器へ差し替える」ことをマスタから導けない。

## Decision

- **ファミリーに分岐器ロールを足し、分岐器の単独行を吸収する。** `beltConveyorFamilies` の各行に `splitterBlockGuid`（optional）を追加し、分岐器4行を直線側の行へ統合して4行にする。ロールは 直線 / 上り / 下り / 分岐器 の4つ。
  出所: ユーザー裁定 2026-09-10 原文「何が何に対して張替え可能なのか、というのを定義出来るようにしておきたい」「これで分岐器とかも張替えが可能になる」→ マスタ形状の提示に対し「ベルコンファミリーはそれぞれ無制限にリプレース出来るようにしたい。だからreplaceableFamiliesはなくていいかな」
  棄却案: ①ファミリーは触らず tierKey 文字列と別配列の張替えグループで束ねる ②ブロック単位で replaceableBlockGuids を列挙する（提示のみ、いずれも未採択）

- **ファミリー同士は無制限に相互張替え可。張替え可否の関係はマスタに持たない。** 有向の `replaceableFamilies` は不採用。
  出所: ユーザー裁定 2026-09-10 原文「ベルコンファミリーはそれぞれ無制限にリプレース出来るようにしたい。だからreplaceableFamiliesはなくていいかな」
  棄却案: 有向の張替え関係（各ファミリーに replaceableFamilies を書く）／対称の張替えグループ

- **張替えは形状維持のティア差し替え。** 既設の座標・向き・坂・分岐器ロールを維持し、BlockId だけを手持ちファミリーの同ロールへ差し替える。ドラッグは範囲指定にだけ使い、向きの引き直しは張替えでは行わない（撤去→再設置で行う）。手持ちが坂や分岐器でも「ファミリーの指定」として扱う。
  出所: ユーザー裁定 2026-09-10 原文「ドラッグしたら、分岐器とか坂とか、そのへんもいい感じに自動で張替えできるようになったら差に理想的」→ 選択「形状維持（ティア差し替えのみ）」
  棄却案: ①同ファミリーは引き直し・別ファミリーは形状維持 ②常に引き直し（ロールだけ維持）

- **既設ベルトの無いセルは飛ばして続行する。** 空セル・別種ブロックのセルは何もせず次へ進み、終点までの既設ベルトを全て張り替える。離れた平行ラインを横断ドラッグでまとめて張り替えられる代わりに、意図しない隣のラインも巻き込む。
  出所: ユーザー裁定 2026-09-10 選択「飛ばして続行」
  棄却案: ①途切れたセルで打ち切る ②空セルは手持ち直線の新規設置で埋める

- **サーバー側は 2026-07-22 の裁定を引き継ぐ。** (1) 搬送中アイテムは進行率維持で新ブロックへ引き継ぎ、収まらない分はプレイヤーインベントリへ、それも満杯ならそのセルは失敗（ロスト・地面ドロップ禁止） (2) コストは「旧ブロックの撤去返却→新ブロックの設置消費」の順で、両方とも財布（ADR 0026）を通す (3) `PlaceBlockProtocol` にセル単位の isReplace を足してサーバーがアトミックに処理し、既設がベルトファミリーでなければ拒否ログを出してスキップ。
  出所: ユーザー裁定 2026-09-10 選択「引き継ぐ」
  棄却案: ①搬送中アイテムは全てプレイヤーへ返却する簡略化 ②コスト精算なし

- **フィルター分岐器は含めない。** blockType FilterSplitter はどのファミリーにも属さず、張替えドラッグでは「既設ベルトの無いセル」として飛ばされる。
  出所: ユーザー裁定 2026-09-10 選択「含めない」
  棄却案: ①全ファミリー共通ロールとして含める ②旧specどおり直線との相互差し替えを単クリック特例で許す

- **発動条件は「起点セルに既設ベルトファミリーブロックがある」ことのみ。** 空き地起点の通常ドラッグが途中で既設ベルトに重なっても張り替えず、今どおり設置不可で飛ばす。単クリックは起点=終点の張替え。
  出所: ユーザー裁定 2026-09-10 選択「既設ベルト起点のときだけ」
  棄却案: 起点に関係なく重なった既設ベルトは張り替える

- **既設ラインの高さは自動で追従する。** XZ は現行のドラッグ経路（L字可）。各セルの Y は直前に見つけた既設ベルトの Y±1 の範囲で探し、見つからないセルは直前の Y を保って次へ進む。張替え中はカーソルの高さオフセット・`ConveyorOverpassRaiser`・坂の自動判定を使わない。
  出所: ユーザー裁定 2026-09-10 選択「自動で追従する」
  棄却案: 今の新規設置と同じ経路計算で座標を作り、重なる既設ベルトだけを対象にする

- **不可セル・失敗セルはそのセルだけ残して後続を続行する。** 手持ちファミリーに対応ロールが無いセルはプレビューで不可色＋理由ツールチップにし送信しない。素材不足・返却不能で失敗したセルはサーバーがそのセルだけスキップする。
  出所: ユーザー裁定 2026-09-10 選択「そのセルだけ残して後続は続行」
  棄却案: 不可セルが1つでもあればドラッグ全体を実行しない

- **Undo は逆張替えとして含める。** 張替えレコードを既存の設置/撤去レコードと同型で積み、Undo で同じセルを旧 BlockId へ張り戻す。搬送品は巻き戻さずその時点のものを引き継ぎ、コストは通常の張替えとして精算する。既に別ブロックへ変わっているセルは触らない。
  出所: ユーザー裁定 2026-09-10 選択「含める（逆張替え）」
  棄却案: 張替えは Undo 履歴に積まない

### agent前提（ユーザー裁定ではない）

- 既設が手持ちと同ファミリー同ロールのセルは no-op（送信しない）。出所: agent前提（旧spec の冪等規則）
- 財布・解放の直線代表への正規化は坂ロール（上り/下り）に限定し、分岐器ロールは自身の財布・解放を保つ。分岐器は建設コストが直線と異なるため。出所: agent前提（ADR 0026、実マスタのコスト差）
- プレビューは既存の設置可否色に張替え色を1色足して区別する。出所: agent前提（旧spec）
- `BlockRemoveReason` に Replace を足し、撤去演出・購読側が張替えを区別できるようにする。出所: agent前提（旧spec）
- 対応ロール無しの理由は `BeltConveyorPlacementBlockReason` に追加する。出所: agent前提（設置不可理由ツールチップの既存規約）
- 立体交差の上下2段のラインは起点の高さの方を追う（Y±1 探索の帰結）。出所: agent前提（高さ追従規則からの導出）

### 呼び出し側の線引き

- クライアントの張替え経路生成は「既設セルのロール → 手持ちファミリーの同ロール BlockId」の写像だけを行い、コスト・搬送品・財布は一切見ない。
- サーバーの張替え処理は「同一セルでの撤去＋設置」を一体で行う1つのサービスとし、撤去返却・設置消費・財布は既存の `ConstructionWalletService` / `ConstructionCostService` へ指示を問い合わせる。`PlaceBlockProtocol` はセルごとに isReplace で分岐して呼び分けるだけで、精算の段取りを知らない。

## Consequences

- `BeltConveyorPlaceFamilyUtil` のメンバー判定に分岐器ロールが加わる。`ConstructionWalletUtil.ResolveWalletBlockId` と `BeltConveyorPlacementUnlockSourceMap` は「坂ロールのみ直線へ」と判定を明示する必要がある。
- `BeltConveyorFamily` に SplitterBlockId と「BlockId → ロール」「ロール → BlockId」の解決が要る。
- `BeltConveyorPlaceSystem` は「起点に既設ファミリーブロックがあるか」で張替え経路生成へ分岐する。ADR 0050 の坂選択経路とは排他で、張替えが優先。
- 全 mod の blocks.json（moorestech_master と TestMod）で分岐器の単独ファミリー行を直線側へ統合する。moorestech_master 側も push + PR が必要。
- FilterSplitter は張替え対象外なので、フィルター分岐器を挟んだラインは前後だけ張り替わりフィルター分岐器はそのまま残る。
