# 0086. 液体の数量はすべて10倍の単位にそろえる

日付: 2026-10-20
状態: 採択

## Context

ADR 0084 で液体を Satisfactory 比率にそろえた結果、原油系の数量が小さくなり、ナフサ0.5・蒸気0.1 のような小数が残った。比率はそのままに、液体の数量の単位を10倍にする。対象は v8 マスタ（`moorestech_master` の `blocks.json`・`machineRecipes.json`・`train.json`）。

## Decision

- **液体すべて（原油・ナフサ・ガソリン・残油・水・蒸気）の数量を×10にする。対象: レシピの液体入出力量、油井・歯車ポンプの生成量、ガソリン発電機・蒸気機関の消費量、パイプの流量と容量、機械の接続口 flowCapacity、内部タンク（innerTankCapacity・fuelFluidTankCapacity・蒸気機関 fluidCapacity）、液体タンク・液体プラットフォーム capacity、液体貨車 fluidCapacity。比率は ADR 0084 のまま（鉄パイプ1本で蒸留機5台・ボイラー2台）。**
  出所: ユーザー裁定 2026-10-20 原文「石油の消費/生産の単位系を1単位に今はなっていると思うけど、全体的に10単位にしたい」→ 選択「液体すべて×10」（[[2026-10-20-液体の数量はすべて10倍の単位にそろえる]]）
  棄却案: 原油系＋共用設備だけ×10（水・蒸気レシピ据え置き）／原油系の数量だけ×10（パイプ・タンク・貨車据え置き）

- **処理時間・アイテムの入出力数・発電量（power）は変えない。** 液体の単位だけを変える。
  出所: ユーザー裁定 2026-10-20 質問「処理時間・アイテムの入出力数・発電量は今のままでよいか」→ 選択「すべて今のまま」
  棄却案: 液体以外も変える

- **ボイドパイプの flowCapacity 1000→10000 も×10。容量0の機械は0のまま。**
  出所: agent前提（「液体すべて×10」の範囲に含まれる液体量のため）

- **クリーンルームのパイプハッチ容量（`VanillaCleanRoomBoundaryTemplate.PipeHatchFluidCapacity` 100f の直書き）は本変更で触らず、値の追従とマスタ化をまとめて別タスクにする。**
  出所: ユーザー裁定 2026-10-20 原文「別タスクに送るからそのためのプロンプトを書いて」（[[2026-10-20-パイプハッチ容量の10倍化とマスタ化は別タスクにする]]）
  棄却案: 値だけ×10しマスタ化は別タスク／このPRでマスタ化／値だけ×10しタスクも積まない

- **既存セーブの液体在庫は数量のまま引き継ぐ（実質1/10）。セーブ形式・CurrentVersion は変えない。**
  出所: ユーザー裁定 2026-10-20 選択「数量のまま引き継ぐ」（[[2026-10-20-液体10倍化で既存セーブの液体在庫は数量のまま引き継ぐ]]）
  棄却案: マイグレーションで液体量を×10に換算する

- **テスト用マスタ（moorestech_server のテスト mod）は変えない。** v8 の数値に依存するテストが無い限り対象外。
  出所: agent前提（テスト mod は v8 バランスと独立）

## Consequences

- 現行値の×10: 油井 原油20/0.5秒、蒸留機 原油100→ナフサ20/ガソリン30/残油50、化学プラント ナフサ5・ナフサ5・残油20・残油10、ガソリン発電機 ガソリン10/4秒、歯車ポンプ 水10/0.5秒、ボイラー 水100→蒸気100・水100→蒸気300、蒸気機関 蒸気1/秒、鉄パイプ 100/秒・鋼鉄パイプ 300/秒・容量500、接続口600、内部タンク 油井・蒸留機・化学300・発電機200・ボイラー2000・歯車ポンプ1000・蒸気機関100、液体タンク・PF・貨車50,000
- 既存ワールドのタンク・貨車の中身は実質1/10に目減りする。容量は広がるので切り詰めは起きない
- recipe-chain-machine-count スキル等に液体の数値例があれば合わせて直す
