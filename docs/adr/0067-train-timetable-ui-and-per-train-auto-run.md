# 0067. 時刻表は丸ごと置換で編集し、自動運転は列車ごとにUIから切り替える

日付: 2026-09-24
状態: 採択

## Context

サーバーには `TrainDiagram`（レールノードの循環リスト＋出発条件）と `TrainUnit.TurnOnAutoRun/TurnOffAutoRun` があるが、中身を入れる経路はデバッグシートの `trainAutoRun on|off`（全駅を全列車へ一括投入し全列車をON）だけだった。時刻表も自動運転フラグもクライアントへ同期されず、駅名は `TrainStationComponent.StationName` が "test" 固定で設定手段が無い。Factorio・Satisfactory の調査（2026-09-24）では、両者とも「駅の順序リスト＋各駅の出発条件」であり実時間の発車時刻は持たない。本プロジェクトではこの構造を「時刻表」と呼ぶ（CONTEXT.md「列車の運行」）。

## Decision

- **出発条件は変えない。エントリは固定で「着駅後1秒（`GameUpdater.TicksPerSecond`）待って発車」だけを持ち、UIは条件を見せない。** 現行のデバッグ経路が全エントリに付けている値をそのまま正式化する。「移し終わったら発車」等の条件は将来の鉄道改修で扱う。
  出所: ユーザー裁定 2026-09-24 原文「出発条件はいまの方式で全く変えないにしたい」「とりあえずいまは固定1秒待機だけ設定するようにして。移し終わったら、みたいなのは今後鉄道周りの回収をする時に行う」
  棄却案: 「転送完了」条件の新設（実装調査で現状は1秒待機であり転送完了条件は存在しないと確認済み）

- **時刻表の編集操作は「丸ごと置換」1つ。** `TrainDiagram.ReplaceEntries(駅ノード列)` を設け、Remove/Move/Insert は公開しない。UIはローカル配列を編集して適用時に全体を送る。
  出所: ユーザー裁定 2026-09-24 原文「Entryという物自体、『置き換える』だけでいいんじゃないの？MoveやInsert、削除みたいな操作系を公開する必要ある？作る側が作って置き換え、それだけでよいのでは」
  棄却案: RemoveEntry/MoveEntry の操作API（提示したがユーザーが置換一本へ修正）

- **置換後の現在地は常に先頭。** 既存デバッグ経路（全削除→追加で -1→0）と同じ。
  出所: ユーザー裁定 2026-09-24 原文「それって実装時点の挙動はどうなるの。下手に変えなくて良い。」→ 実装時点の挙動＝常に先頭へ
  棄却案: 同じ駅が残っていれば維持／置換後は自動運転を解除（[[2026-09-24-時刻表の置換は現在地を先頭へ戻す既存挙動を維持する]]）

- **空の時刻表での自動運転ONはUIで塞ぎ、サーバーは現状維持。** `TurnOnAutoRun` は受理後の検証で目的地が無ければ即OFFに戻す挙動のまま。UIは時刻表が空のときONを無効化し理由を添える。
  出所: ユーザー裁定 2026-09-24 原文「即OFFと、UI側でオンにできないようにして追う」→ 復唱確認「合っている」
  棄却案: サーバーが拒否し失敗理由を返す（[[2026-09-24-空の時刻表での自動運転ONはUI側で塞ぎサーバーは現状維持]]）

- **時刻表タブはUI側で追加・削除・↑↓並べ替えを持ち、「適用」で1回送信する。** 適用前に閉じたら破棄。
  出所: ユーザー裁定 2026-09-24 選択「追加・削除・上下移動 (Recommended)」
  棄却案: 追加・削除のみで操作ごとに即送信（[[2026-09-24-時刻表タブは追加削除上下移動をローカル編集し適用で丸ごと送る]]）

- **時刻表タブの置き場は、機関車を含む列車車両をFで開く車両インベントリ画面。** 自動運転ON/OFFトグルも同じタブに置く。
  出所: ユーザー裁定 2026-09-24 原文「UIまで実装し、ランタイムプレイテストで駅と鉄道を起き、UI経由で鉄道の自動運転のオンオフ、時刻表の設定ができるようになっていることを確認してほしい」／grill引数「UIはwebuiで機関車の車両インベントリに時刻表タブ」

- **「インベントリ / 時刻表」のタブ切替を Web UI の新様式として webui-design に追記してから実装する。**
  出所: ユーザー裁定 2026-09-24 選択「タブを新設する」
  棄却案: インベントリの下に縦積み（[[2026-09-24-列車インベントリに時刻表タブを新設する]]）

- **駅名の変更UIは駅ブロックのUIに名前欄として置く。** 時刻表タブは駅名を表示するだけ。プラットフォームには出さない。
  出所: ユーザー裁定 2026-09-24 選択「駅ブロックの UI に名前欄 (Recommended)」
  棄却案: 時刻表タブからも改名（[[2026-09-24-駅名の変更UIは駅ブロックのUIに置く]]）

- **時刻表は駅名でなく個々の駅ブロックを指す。** 改名しても行き先は変わらず、同名駅があっても区別される。駅名は表示専用で、同名駅グループ・train limit は作らない。
  出所: ユーザー裁定 2026-09-24 選択「個々の駅を指定 (Recommended)」
  棄却案: 駅名で指定し同名駅のいずれかへ（[[2026-09-24-時刻表は駅名でなく個々の駅ブロックを指す]]）

- **適用後も自動運転フラグは ON のまま。** 列車は新しい先頭駅へ向かう。
  出所: ユーザー裁定 2026-09-24 選択「ON のまま新しい先頭へ向かう (Recommended)」
  棄却案: OFF にして手で再開

- **線路が未接続の駅も登録できる。** サーバーは経路成立を検証せず受理し、到達不能なら既存の `DiagramValidation` が自動運転を OFF に戻す。UI は初版では理由表示を作らない。
  出所: ユーザー裁定 2026-09-24 選択「登録できる (Recommended)」
  棄却案: 経路が成立する時刻表だけ適用できる（[[2026-09-24-未接続の駅も時刻表に登録できる]]）

- **同時編集は後勝ち。** バージョン照合はしない。
  出所: ユーザー裁定 2026-09-24 選択「後から適用した内容を優先（後勝ち）(Recommended)」
  棄却案: 上書きせず最新を確認して再適用（[[2026-09-24-時刻表の同時編集は後勝ち]]）

- **デバッグ経路は撤去する。** `TrainUpdateService.TurnOnorOffTrainAutoRun`・`TrainDiagramManager.ResetAndNotifyNodeAddition`・`CommandProtocol` の `trainAutoRun`・クライアントのデバッグトグル送信を削除する。
  出所: ユーザー裁定 2026-09-24 grill引数「デバッグ経路撤去」（サーバー変更一覧の提示に対し「じゃあ、それでこれの作成に取り掛かりたい」）

### agent前提（ユーザー裁定ではない）

- **時刻表に載せられるのは蒸気機関車駅（`BlockTypeConst.TrainStation`）だけ。登録ノードは Back側 Exit。** 出所: agent前提（`docs/train/StationPlatformComponentRefactoring.md`「Station = Diagram が認識する駅のマーカー」、既存デバッグ規則 `IsDebugAutoRunStationNode` と同一）
- **列車への操作は1プロトコル `va:trainScheduleEdit` に Operation enum（ReplaceTimetable / SetAutoRun）で束ね、static factory で Request を作る。駅名は別プロトコル `va:setTrainStationName`。** 出所: agent前提（moorestech-principles「1プロトコル＝1ドメイン」、`FilterSplitterStateProtocol`・`RailConnectionEditRequest` 前例）
- **同期は既存 snapshot 経路に同乗。** `TrainSimulationSnapshotMessagePack` に自動運転フラグと時刻表（駅ブロック座標の列＋現在インデックス）を追加し、編集適用時と到着で次エントリへ進んだ時に `NotifySnapshot` を呼ぶ。初期データは `va:event:trainUnitFullSnapshot` が兼ねる。ハッシュには含めない。出所: agent前提（creating-server-protocol 3点セットを既存経路で満たす。`TrainPlatformItemContainerComponent` が `NotifySnapshotByCar` を呼ぶ前例）
- **駅名の配信はブロック状態（`IBlockStateObservable`）で行い、既存の `TrainPlatformDetailDtoBuilder` に載せる。** 出所: agent前提（`TrainPlatformTransferComponent` と同型）
- **セーブ形式は変えない。** エントリはノード参照のまま。駅名は既に永続化済み。出所: agent前提（AGENTS.md セーブ形式変更時のマイグレーション規約を回避できる）
- **駅の座標が駅でない・不明なら置換全体を失敗理由付きで拒否しログに出す。** 出所: agent前提（fail-closed 無音縮退禁止）
- **playerId は自己申告のまま。** 出所: agent前提（[[2026-08-14-プロトコルのplayerId自己申告は既存多数派として放置する]]）

## Consequences

- `TrainDiagram.AddEntry(node, type, waitTicks)` のデフォルト引数（`waitTicks = 0`）は規約違反なので `ReplaceEntries` 実装時に呼び出し側を明示に直す。
- 時刻表と自動運転フラグの変更で snapshot が飛ぶため、頻度は「編集時＋到着時」に限る。
