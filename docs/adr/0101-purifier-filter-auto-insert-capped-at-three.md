# 空気清浄機のフィルターの自動搬入は3個で止める

通常機械は 2026-10-18 の裁定で「ブロックからの自動搬入はレシピ要求数×3で止め、手動はスタック上限まで」になったが、空気清浄機（CleanRoomAirFilter）のフィルタースロットには上限が無く、ベルトからスタック上限まで溜め込まれていた。これを機械の入力と同じ考え方で止める。

## 決定

- **ブロックからの自動搬入（`IBlockInventory.InsertItem(stack, context)` 経由すべて。ベルト・チェスト直結・フィルター分岐器等）は、フィルタースロットが3個になったら受け入れを止める。** 入りきらない分は搬入元に残る。
  出所: ユーザー裁定 2026-11-16 原文「空気清浄機の入力個数を機械のインプットとかと同じように3つまでに制限する」→ 選択「自動搬入だけ3個」
- **プレイヤーの手動投入は従来どおりスタック上限まで。**
  出所: ユーザー裁定 2026-11-16 選択「自動搬入だけ3個」（「手で入れる分はスタック上限まで入る」と明示した選択肢）
- **3個は使用中のフィルターを含めたスロットの表示数で数える。** 使用中1個＋予備2個で止まる。
  出所: ユーザー裁定 2026-11-16 選択「スロット表示で3個」
- ベルトの振り分け判定（`IBlockInventory.InsertionCheck` の明示実装）も実挿入と同じ上限で判定する。`IOpenableInventory` 側の `InsertItem(IItemStack)`・`InsertItem(List)`・`InsertionCheck` はプレイヤー操作の経路なので上限を掛けない。
  出所: agent前提（機械側 `VanillaMachineBlockInventoryComponent` が `IBlockInventory.InsertionCheck` だけを明示実装で自動搬入上限にし、`InsertItem(List)` は上限無しにしている前例）
- 上限値は機械側の倍率定数 `MachineInputSlotBinding.AutoInsertCraftCount`（現在3）を参照し、別の数値リテラルを置かない。フィルターの要求数は1個なので 1×3=3 と同じ意味になる。
  出所: agent前提（既存定数と同じ意味の閾値は既存を参照する規約）

## Considered Options

- 手動投入も含めスロット上限を3個にする: 機械と挙動が違う。不採用（ユーザー裁定 2026-11-16）
- 使用中とは別に予備3個（表示は最大4個）: 機械の「使用中とは別に3回分」と揃うが、UIの数字と上限がずれる。不採用（ユーザー裁定 2026-11-16）
