# ADR 0100: ベルト経路は探索箱を持たず、重み付き探索で上限なしに引く

- Status: Accepted
- Date: 2026-11-09
- Related: ADR 0097（2クリック設置。本ADRが「探索範囲と障害物」「探索の作り方」「経路なし」「C キー」の各項を置き換える）
- Supersedes: ADR 0097 の X64×Z64 の探索箱・高さ上限・経路なしの理由分け・C キーの同コスト候補送り

## Context

ADR 0097 の探索は、始点クリック時に X64×Z64 の箱を固定し、全列の地形を1回測り、箱の全状態を配列で持つ A* だった。箱の外の終点は「範囲外」、高さの上限は地形最高点＋3。ユーザーから「64×64 のサイズ制限と高さの制限を撤廃したい」「最短じゃなくていいので障害物よけて y 方向も無限で、横方向も」という要望が出た（2026-11-09）。箱を大きくするだけでは、始点クリックの地形計測と経路なし時の全探索が面積に比例して重くなる（実測: 64×64・高さ24の経路なしで約105 ms）。

## Decision

本ADRの各項の出所は、特記がなければユーザー裁定 2026-11-09 原文「ダメです。最短じゃなくていいので障害物よけてy方向も無限でできるように横方向も、なんかかんがえられない」と、その後の提案への回答「1 ok 2ok Cキー一旦撤廃で」。

### 探索箱を持たない

- 探索は「触ったセルだけをその場で調べる」。地形は列ごとに初めて触れたときに測って覚え（`BeltRouteLiveWorld`）、既存ブロックの占有・坂の真上・入出力辺は、始点を決める前は、ブロックの改訂番号が変わったときだけ全ブロックから作り直す（箱の周囲で絞らないので、今までの作り直しより費用は増える。全ブロックの足跡を辞書へ写す1回の走査）。始点を決めた後は作り直しも再探索もせず、終点を確定した瞬間に世界を読み直して経路の全セル（分岐なら分岐器の向きと出口も）が置けるかを検査し、置けなければ送らずに理由行「周りが変わりました。始点から選び直してください」を出して始点選びへ戻す（ユーザー裁定 2026-11-09）。世界（`BeltRouteLiveWorld`）は設置システムが1つ持ち、始点を決める前の端点判定もセッションの探索も同じ `BeltRouteCellJudge.Judge` を通す。
- 横・縦ともに範囲の上限は無い。「範囲外」の理由行は無くなる。始点と終点は建築射程（`PlacementDistanceRule`）の内側に限るが、経路の途中のセルは射程の外へ出てよい（ユーザー裁定 2026-11-09）。範囲の上限は探索量の上限だけ。
- 始点クリック時の全列計測は無くなる（引っかかりが消える）。

### 最短ではなく、ゴールへ強く向かう探索

- A* の評価値を `f = g + W × h`（W = 2、agent前提: 一般的な重み付き A* の値。開けた場所では最短のまま、障害物の周りだけ遠回りを許す）にする。h は今までの下限見積もり（残り水平距離と高低差）。
- 開けた場所では最短と同じ形になる。障害物の周りでは最大で最短の W 倍までの遠回りを許す（出所: ユーザー裁定 2026-11-09「2ok」＝「開けた場所では最短、障害物の周りは多少遠回りでよい」）。
- 状態（セル・出る向き・種別）のコスト表は辞書、待ち行列は二分ヒープ（f 昇順・同じ f なら g の大きい方を先）。入出力辺の面ビットは書き込み時にセルごとの辞書へ立て（`BeltRouteFaceBits`）、探索の1問い合わせは辞書1回の参照にする。
- 経路の組み立て（`BeltRouteRecovery`）の中身は今までのまま。終点から始点へ、探索が触った状態だけをたどり、同じセルを2度使わない・自分の坂の真上を空ける規則を守る。予算は探索が終点に着いたときの g、組めなければ探索を少し進めて（追加の展開数）g＋余裕20 で組み直す（余裕20は ADR 0097 の裁定のまま）。
- 組み立ての前提は変わる: ADR 0097 では「終点と同じ f の状態を全て確定」「余裕の範囲を正確に確定」してから組んでいたが、重み付きでは g は真の最短の上界で、終点を取り出した時点で止める。探索がたどった親の列は、組み立ての枝刈り（最短コスト＋置いた分が予算以下）を必ず通る（best(親) ≤ best(子) − 一歩のコスト が常に成り立つため）。同じセルの再使用や自分の坂の真上で親の列が弾かれる配置だけが追加の展開と余裕に頼る。
- 組み立ての候補順は固定（直進・左・右の順、種別は直線・上り・下り）。C キーの優先順は無い。

### 経路なしは探索量の上限だけで決める

- 探索の展開数が上限（`MaxExpansions` = 20,000。agent前提: 1展開あたり辞書参照が十数回で、Mono で約 100 ms に収まる見込み。実機の囲まれた終点で測り、100 ms を大きく超えるなら下げる。実測は Consequences に記す）に達したら経路なし。遠すぎる終点・囲いの大きい終点はここで止まる。
- 本探索の前に終点から空きセルを 512 セルまで塗りつぶし、先に尽きたら囲まれた終点として即経路なしにする（囲いの中でカーソルを動かすたびに上限まで探索しないため。ユーザー裁定 2026-11-09）。理由分けのための塗りつぶし（地形／ブロック）は廃止のまま。塗りつぶしの近傍は経路の隣り合うセルの関係（水平に1歩・高さ差±1以内。真上・真下へは進まない。終点の手前は同じ高さか1つ下だけ）に合わせ、始点の列か隣の列（高さ差±1以内）に着いたら開いているとみなす。経路があれば必ず開いていると判定されるので、始点と同じ小部屋の終点を囲まれと誤らない（agent前提: 6近傍の塗りつぶしでは上の開いた輪の中の終点を囲まれと判定できなかったため）。
- 経路なしになったときは、利用者向けの理由行とは別に、開発者向けログへ出どころ（囲まれた終点／上限到達／待ち行列の枯渇／組み立て失敗）と展開数を1行出す（fail-closed の経路はログへ出す規約。同じ問い合わせは使い回すので毎フレームは出ない）。
- 理由行は「経路が見つかりません」（`ui.tooltip.placeBeltRouteNotFound`）の1つ。地形／既存ブロックの区別（塗りつぶし判定）は廃止（出所: ユーザー裁定 2026-11-09「1 ok」）。
- 同じ終点を指し続けている間は再探索しない（`BeltRouteSession` の同一問い合わせの使い回しはそのまま）。

### C キーの廃止

- 同コスト候補を送る C キー（ADR 0097「操作」）を無くす。`BeltRouteStepPriority` と `BeltRouteQuery.Priority` を削除する（出所: ユーザー裁定 2026-11-09「Cキー一旦撤廃で」）。
- `HybridInput` のキー対応表の C（ADR 0097 で足したもの）も外す。C を使う機能は他に無い（`Key.C` の参照なし）。

### 変えないもの

- 経路の形の規則（直線は前・左・右、坂は曲がらない、山谷なし、坂の真上を空ける、既存の出力口を横取りしない、終点の前は空ける）、分岐、分岐器手持ち、建設コストの判定、2段の置き換え送信。
- 始点・終点のセルの可否（既存ブロック・地形・坂の真上）。

## Considered Options

- 探索の持ち方（箱の配列を置き換える機構）:
  - 辞書＋二分ヒープ＋その場問い合わせ（採用）: 範囲の上限が要らず、触った状態の数だけ費用がかかる。Mono の辞書参照は配列より遅いが、重み付きで触る状態が少ないので釣り合う。
  - 必要な所だけ確保するチャンク配列（整数添字を保つ）: 添字の速さは保てるが、チャンクの確保と添字の変換が複雑で、範囲の上限が無いことの検査が増える。不採用（agent前提）。
  - f 値のバケットを据え置く（Count を増やすか辞書化）: 重み付きの f は距離に比例して大きくなり、バケットの線形走査（FirstActive）が f の大きさに比例して遅くなる。二分ヒープは f の大きさに依らない。不採用（agent前提）。

- 箱をカーソル追従で動かし、上限を建築射程にする: 最短は保てるが、遠い経路なしで箱全体を舐めて重く、始点クリックや箱の作り直しで地形計測が引っかかる。ユーザー裁定で不採用（「ダメです」）。
- 箱の数字（64）を大きくするだけ: 面積に比例して遅くなる。不採用。
- 探索量の上限なし: 囲まれた終点で止まらない。不採用（agent前提）。

## Consequences

- 本番は `BeltRouteLiveWorld` を使う。`BeltRouteGrid`（配列の箱）はテストアセンブリへ移してテスト用の世界にし、本番には残さない（デバッグ/テスト専用 public を本番に残さない規約）。分岐判定が隣の辺を写す1セル箱は `BeltRouteNeighbourEdges`（辺の有無だけ）に置き換える。両世界は `IBeltRouteWorld`（地形・占有・坂の真上・入出力辺の面ビット）を実装し、面ビットの立て方は `BeltRouteFaceBits` の1本に集める。
- `BeltRouteTerrainProfile`・`BeltRouteWorldScanner`・`BeltRouteReachability`・`BeltRouteCostBuckets`・`BeltRouteStateCodec`・`BeltRouteObstacleMask`・`BeltRouteStepPriority`・`BeltRouteEdgeTable` を削除する。
- 参照ソルバ突き合わせ（`BeltRouteReferenceCrossCheckTest`）は「最短性」ではなく「存在」（参照が見つけたら本番も見つける）と「コストが参照の W 倍＋余裕以内」を確かめる形に変わる。余裕なしの比較は意味を失うので本番の余裕だけで回す。
- 実測（2026-11-09。計画 Task 4 で記入）: 手元 EditMode（`BeltRoutePlanner.Plan` を10回回した中央値）で、開けた平地 120×3×120 の (2,0,2)→(110,0,100)（207 セル）が 0.44 ms・展開 207、同じ平地の x=60 列に高さ3の壁（z=0〜110）を置いた遠回り（231 セル）が 8.71 ms・展開 6,457、囲まれた終点（40×3×40）は囲まれ判定で止まり 0.44 ms・展開 0、200×3×200 の x=100 列を高さ3の壁で全て塞いだ (2,0,2)→(190,0,190)（囲まれ判定は開いている）が上限到達で 28.80 ms・展開 20,000（2026-11-09 再計測）。録画シナリオ `belt-route-two-click-via-ui`（録画あり）の探索フレームの最悪時間は、開けた遠距離（4 終点 × R 4回）で 49.3 ms、実機で囲まれた終点（E/Q 4回、毎回囲まれ判定で止まりログは `end enclosed expansions:0`）で 34.9 ms（2026-11-09 再計測。旧値は上限到達時の 90.0 / 65.3 ms）。録画の値は、R（面ヒットで向きが決まる囲まれた終点では E/Q で高さを切り替え）で再探索を起こした直後の数フレームの unscaledDeltaTime の最大で、録画の書き出しを含むため回ごとに揺れる（録画なしの試走では 74.5 / 36.5 ms と 22.4 / 31.9 ms）。150 ms を下回ったので `MaxExpansions` = 20,000 は据え置く。
- 録画シナリオ `belt-route-two-click-via-ui.cs` の C キーのフェーズは、旧箱（±32）を超える遠距離の経路のフェーズに置き換える。
