# ADR 0082: 地形への埋まりは底面から1/3mまで許容し、既定の設置高さはそれを超えない最も低いセルにする

- Status: Accepted
- Date: 2026-10-16
- Supersedes: ADR 0047 の既定設置Y「地形最高点を含むセル（浮くくらいなら埋める）」、ADR 0081（preview-no-collider）決定1の基準「底から1セルより深い沈みを不可」と決定2の境界「ResolveCellY の許容誤差で比べる」
- Keeps: ADR 0081（preview-no-collider）の適用範囲・高さサンプル方式・BP除外の送り方、ADR 0081（belt-drag-climbs-over-terrain）の途中セル下限の組み立て（既定セル＋Q/E補正）

## Context

プレイヤー直下の直線歯車ベルトコンベア列が全体に埋まって見えた。
原因: 実測（証拠: macbook-pro の PlayMode・既存の大規模セーブ。ベルト列 (798,68,2424〜2432) の設置Yは68、GroundHeightProbe の最高点は 68.627〜68.682（step=0.0183）、ベルトの当たり判定上面は Raycast で ClickCollider@68.40。実機で `PlacementGroundCellResolver.TryResolveCellFromGround` は y=68 を返した）。
既定Y = floor(地形最高点＋許容誤差) なので沈む量は地表の小数部分（0〜1m）そのものになり、厚さ0.4mのベルトは0.6m沈んで全体が隠れる。
埋まり判定（#1513）のしきい値は「底から1セルより深い沈み」なので、既定Yでは一度も働かない。

## Decision

### 1. 埋まり量と許容量

**埋まり量 = 占有セルの地形最高点（GroundHeightProbe）− ブロック底面Y**。これが **1/3m（＋浮動小数余裕0.001m）以下なら許容**、超えたら埋まり。
全ブロック共通の固定距離で、見た目の高さや blockSize.y に比例させない。

出所: ユーザー裁定 2026-10-16 原文「埋まりは0.333までのみ許容して、0.3333以上埋まる場合に埋まり判定にしたい。」
出所（単位）: ユーザー裁定 2026-10-16 提示「底面から固定0.333m（推奨）／見た目の高さに対する割合／blockSize.yに対する割合」→ 選択「底面から固定0.333m (推奨)」
出所（境界）: ユーザー裁定 2026-10-16 提示「1/3以下を許容＋浮動小数余裕（推奨）／0.333以下を許容（文字どおり）／パッド用許容誤差も残す」→ 選択「1/3以下を許容＋浮動小数余裕 (推奨)」

### 2. 既定の設置高さは自動で1段上げる

既定設置Y = **埋まり量が許容量以下になる最も低い整数セル**（= ceil(地形最高点 − 1/3 − 0.001)）。
地表の小数部分が1/3mを超えるときは、従来（地形最高点を含むセル）より1段上がる。通常の1mブロックは「最大1m沈む」から「最大1/3m沈む／最大2/3m浮く」へ変わる。
鉱脈パッドのように整数より数cm下に格納された地表は、この規則で自然にその整数へ置かれるため、パッド用の許容誤差（格子1段＋採掘底面クリアランス）は撤去する。

出所: ユーザー裁定 2026-10-16 提示「置けない（埋まり判定）／自動で1段上げる（推奨）」→ 選択「自動で1段上げる（推奨）」。続けて原文「埋まり判定で設置不可+自動一段上げ」
出所（パッド許容誤差の撤去）: ユーザー裁定 2026-10-16 境界の質問に同記して選択「1/3以下を許容＋浮動小数余裕 (推奨)」

### 3. それでも許容量を超える配置は設置不可

Q で下げたとき・複数セルのブロックで内側の地形が盛り上がっているとき・ブロック面へ積んだ配置が丘へ食い込むときなど、決定1の埋まり量が許容量を超える配置は既存の「地形に埋まっています」で設置不可（赤表示）。BPは超えるブロックだけ飛ばす（ADR 0081 決定4のまま）。
ベルトのドラッグで Q を下げた列（ADR 0081 belt 決定8）は、途中セルも端点も1段以上沈むため不可になる（従来の1セル基準でも不可だったので挙動は変わらない）。

出所: ユーザー裁定 2026-10-16 解釈の復唱「(1) 既定の高さを決めるとき、埋まり量が0.333mを超えるなら自動で1段上げる (2) それでも0.333mを超えて埋まる配置（Qで下げたとき・複数セルのブロックで内側の地形が盛り上がっているとき等）は『地形に埋まっています』で設置不可」に原文「ベースokなんだけど、それってすでに覆さなかったっけ。埋まり判定の実装完了してないの？」→ ベースOK

### 4. 適用範囲

全設置系: 通常設置（単体・ドラッグ）、BP貼り付けの各ブロック、ベルト（ドラッグ途中セル含む）、レール橋脚、電柱、歯車チェーンポール。既定Yの決定（`ResolveCellY`）と埋まり判定（`IsSunkAbove`）を同じ1つの規則から出す。

出所: ユーザー裁定 2026-10-16 提示「全設置系（推奨）／ベルト系だけ」→ 選択「全設置系（推奨）」

### 5. 届け先と変えないもの

master へのPRだけ（次回のプレイテスト配布で入る）。
出所: ユーザー裁定 2026-10-16 提示「masterへのPRだけ（推奨）／マージ後にプレイテスト版へも反映」→ 選択「masterへのPRだけ (推奨)」

クライアントの設置Y決定と埋まり判定だけを変え、セーブ形式・サーバーは変えない。既に置いたブロックは動かさない。
出所: agent前提（地形判定はクライアントのみ。BP除外もクライアントが判定して送る＝ADR 0081 決定4）

## Considered Options

- 超えたら置けないだけにする（自動で上げない）: 棄却。ユーザー裁定 2026-10-16 選択「自動で1段上げる（推奨）」
- 見た目の高さ／blockSize.y に対する割合: 棄却。ユーザー裁定 2026-10-16 選択「底面から固定0.333m (推奨)」
- 0.333 を文字どおりの境界にする／パッド用許容誤差を残す: 棄却。ユーザー裁定 2026-10-16 選択「1/3以下を許容＋浮動小数余裕 (推奨)」
- ベルト系だけに適用: 棄却。ユーザー裁定 2026-10-16 選択「全設置系（推奨）」

## Consequences

- 地面へ普通に置いたブロックは最大1/3mしか沈まず、代わりに最大2/3m浮く
- 既定位置では埋まり判定に当たらない（既定Yと判定が同じ規則から出るため）
- 同じ場所でも従来より1段上に置かれる場合があり、既存の設備と高さがずれることがある（既存ブロックは動かない）
