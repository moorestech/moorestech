# 0081: 開発者のバグ報告も受け口へ送り、機材ごとの開発者トークンで認証する

日付: 2026-10-16
状態: Accepted（ADR 0057 の運搬・自動投入の部分を置き換える）

## Context

Editor・開発ビルドのバグ報告は outbox に置かれ、運搬スクリプト（Tailscale経由rsync）が Mac mini の inbox へ運ぶ設計だった。MacBook ではこのスクリプトが未設定のまま、開発者報告が約1か月届いていなかった。ゲーム側は開発者モードでは旧運搬経路に残す旨のログを1行出すだけで、誰も気づけなかった（原因: 実測（証拠: MacBook に 旧運搬の設定ファイル と launchd 登録が無い／outbox に 2026-10-12 と 2026-10-15 の箱が READY のまま残っていた／`PlaytestUploadRunner.RequestUpload` の配布版ゲート））。rsync を選んだときの前提「HTTPの受け口が無い」は、ADR 0061 で受け口ができた時点で消えている。

調査の手間も大きかった。報告の在処（受け口・取り込み済み・inbox・開発機の outbox）を順に探し、箱の外にある列車同期の停滞診断を scp で取り、箱の中身は使い捨てのスクリプトで読んだ。

## Decision

- 出所: ユーザー裁定 2026-10-16 原文「この辺を進めたい」→ 選択「CFへ一本化しrsync廃止」。開発者のバグ報告も配布版と同じ受け口へ送る。運搬スクリプトは廃止する。
- 出所: ユーザー裁定 2026-10-16 選択「開発者トークンを機材ごとに発行」＋原文「エディタ拡張でセットできるようにして」。Mac mini の管理コマンドで機材名つきの開発者トークンを発行する。受け口はそれを検証し、`dev-<機材名>` を識別子とする通常のセッショントークンを出す。漏れたら機材単位で失効できる。開発機へのトークン設定はエディタ拡張から行う。
- 出所: ユーザー裁定 2026-10-16 選択「テスター報告と同じく人が選ぶ」。開発者報告も取り込みは保存までで止める。自動修正ランへの投入は人が行う。
- 出所: ユーザー裁定 2026-10-16 原文「それで」（推奨7点に対して）。
  - 報告の確保時に、Editor が未pushコミットの git bundle（moorestech と moorestech_master）を作って箱へ入れる。
  - 停滞診断の同梱、Unity不要のトリアージスクリプト、報告の所在一覧も同じ流れで作る。
  - 送り先は本番の受け口。
  - 開発者トークンで送るのはバグ報告と感想だけ。進行記録は送らない。
  - 溜まっている箱は、トークン設定後の起動でそのまま送る。
  - 配布版は Steam 認証のまま。開発者トークンは Editor と開発ビルドだけで使う。
  - 所在一覧は受け口と Mac mini だけを見る。送れない機材はゲーム内に「ローカル保存のみ」を出す。
- 出所: ユーザー裁定 2026-10-16 選択「Mac・Windows両方」。Mac と Windows の両方の Editor で、送信から取り込みまでを実機で確かめて完成とする。
- 出所: ユーザー裁定 2026-10-16 選択「次回再生時に再送」。再生停止で中断した送信は次の再生で再送する。バグ報告画面では送信待ちと送信完了を区別する。
- 出所: ユーザー裁定 2026-10-16 選択「失効を即時に効かせる」。`dev-` の sub の prepare・complete ごとに台帳を確かめ、失効済みなら 401 にする。
- 出所: ユーザー裁定 2026-10-16 選択「置いたままにする」。Mac mini には機材名 macmini のトークンを常設し、Mac mini 上の全 worktree の Editor が共通の outbox から送る。
- 出所: agent前提（受け口が既に持つ R2 を状態置き場として使う。新しい binding を足さない）。開発者トークンはランダム値とし、R2 にはそのハッシュと機材名だけを置く。失効は R2 からの削除で行う。
- 出所: agent前提（ADR 0070 で manifest の steamId はローカルの値になり、受け口では token の sub が置き場を決める）。開発者モードの箱の manifest の steamId は今どおり空（欠損理由つき）のままにし、開発機の識別は受け口の置き場 `dev-<機材名>` が担う。
- 出所: シミュレーター予測（確信高・拒否権つき前提宣言）2026-10-16。異常終了箱（kind=crash）も開発者トークンで送る。送らないのは進行記録だけ（異常終了箱はバグ報告と同じ outbox・同じ中身で、開発機に箱があるのは開発者がタイトルで「送る」と答えたときだけ）。
- 出所: agent前提（Windows の検証機 winbuild に Unity 6000.3.8f1 と `C:\dev\moorestech` が実在する。ユーザーへ提示した前提「winbuild の Editor」は実測で正しかった）。Windows の実機確認は winbuild の Editor で行う。
- 出所: agent前提（enqueue-autofix.sh が inbox を自動修正ランの投入口として使っている）。inbox と inbox 監視は投入口として残し、廃止するのは開発機からの運搬だけにする。

## Consequences

- 開発者報告も取り込み・日次ダイジェスト・enqueue-autofix.sh の導線に乗り、機材を足しても Mac mini 側の設定は要らない。
- 未コミット差分と未pushコミットが R2（非公開バケット）を通る。閲覧範囲は [[2026-09-11-バグ報告バンドルの閲覧は本人とエージェントに限り公開PRには説明とパスだけ載せる]] のまま。
- トークン未設定の開発機は送らず、その理由をバグ報告画面に出す。ログだけの縮退はしない。
