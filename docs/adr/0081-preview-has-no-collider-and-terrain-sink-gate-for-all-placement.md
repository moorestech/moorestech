# ADR 0081: 設置プレビューは当たり判定を持たず、地形めり込みは全設置系で高さサンプルにより判定する

- Status: Accepted
- Date: 2026-10-15
- Supersedes: ADR 0047 の「通常ブロック設置から地形重なりゲートを外す」、ADR 0080 の判定箱方式と「高さ1は判定箱を作らない」
- Keeps: ADR 0047 の既定設置Y（地形最高点を含むセル）、ADR 0080 の「4設置系の設置Yも占有範囲の最高点を含むセル」

## Context

設置プレビューは `PreviewBlockCreator.Create` が実ブロックPrefabを複製して作り、Collider が生きたまま残っていた。
#1499 前はTrigger化するだけで、設置レイがベルト系Prefabの子Collider（Defaultレイヤー）に当たり、BP貼り付けが点滅した。

#1499 はプレビューの Collider を残したまま BlockLayer へ移し、さらに「ベルト・レール橋脚・電柱・歯車チェーンポールは
`GroundCollisionDetector` で地形めり込みを判定している」前提で、検出器の無いPrefabへ判定箱・kinematic Rigidbody・
検出器を自動生成した。この前提は agent 前提で、実Prefabに検出器は無く、4設置系のゲートはそれまで一度も働いていなかった。
#1499 で初めて働き、端数地形でポール・橋脚がほぼ置けない退行になった（ADR 0080 で最下段セルを除外して緩和）。

4設置系だけにゲートがある状態は設計判断ではない。2024-07 に通常設置へ入れた接触判定の API（`SetPreviewAndGroundDetect`）を、
後から作った専用設置系がそのまま呼んだだけで、ADR 0047 で通常設置からだけ外したときに名目上残った。
BP貼り付けは一度もゲートを持っていない。

## Decision

### 1. 地形めり込み判定を全設置系へ同じ基準で入れる

**フットプリント内のどこかで、地表がブロックの底面から1セルの高さを超えていたら設置不可**（底から1セルより深く沈んだら不可）。

- 対象: 通常設置（単体・ドラッグ）、BP貼り付けの各ブロック、ベルト、電線ツールの電柱、歯車チェーンポール、レール橋脚
- 高さ2以上は ADR 0080 と同じ結果。高さ1は地表が上面を超えたら不可（ADR 0080 では無判定だった）
- 既定設置Yが「地形最高点を含むセル」なので、地面へ普通に置く限りこの基準には当たらない。当たるのは Q/E で下げたとき・ブロック面へ積んだ配置が丘へ食い込むとき・崖ぎわ
- 電線・歯車チェーン・レールの接続線は判定しない（埋まってよい）
- 不可の表示は既存の「地形に埋まっています」（`PlacementFeedback.AddBlockedByTerrain`）と赤表示を使う

出所: ユーザー裁定 2026-10-15 原文「地形のめり込み判定ってなんでポール等にだけはいってるの？それ自体がおかしくない？全体で入れるか全体で入れないかのどっちかじゃない？」「ちょっとぐらいなら埋まっていいと思ってる」「（④ 高さ1を地中へ下げた／案A 可）←なんでこれだけ案A化なの？これも負荷であるべきでは？ベースは案Aでok」→ 提示「案A'（底から1セルより深く沈んだら不可。全設置系・BPの各ブロックに適用）でよいか」に原文「hai」
出所（接続線）: ユーザー裁定 2026-10-15 原文「電線が埋まるのは許容（うまっても埋まってない範囲で切断できるので」
出所（表示）: agent前提（既存の設置不可理由の経路を流用）

### 2. 判定は GroundHeightProbe の高さサンプルで測る

`GroundHeightProbe.TryGetFootprintMaxGroundHeight`（占有セル4隅への下向きレイ。設置Yの決定と同じ）でフットプリント最高点を取り、
`底Y + 1` と比べる。物理の重なり問い合わせは使わない。
境界は設置Yの決定と同じ許容誤差で比べる（`PlacementGroundCellResolver.ResolveCellY(地形最高点, 格子1段, 0) > 底Y` なら不可）。整数のつもりの地表が数mm下に格納される分だけ厳しい側にずれるが、既定設置位置では必ず可になる。

出所（境界の許容誤差）: ユーザー裁定 2026-10-15 提示「ADRをplanに合わせる（推奨）」に選択「ADRをplanに合わせる (推奨)」

出所: ユーザー裁定 2026-10-15 提示「高さサンプル（推奨）／計算した箱で物理問い合わせ」→ 選択「高さサンプル (推奨)」

### 3. 設置プレビューは当たり判定を持たない

プレビュー生成時に全 Collider を `enabled = false` にする（`TrainCarPreviewController` と同型）。これに伴い次を撤去する。

- `BlockPreviewObject.ConfigurePlacementColliders`（Trigger化・BlockLayer移動）、`ConfigureTerrainContact`・`SetTerrainContactEnabled`・`DetectCurrentGroundOverlap`
- `PlacementGroundContactQuery`、`IPlacementPreviewBlockGameObjectController.DetectGroundOverlaps` と `SetPreview` の地形接触フラグ
- 歯車チェーンポールで選択レイの前に前フレームのゴーストを隠す処理
- `BlockClickDetectUtil`・`DeleteTargetRaycaster` のプレビュー命中スキップ
- `GroundCollisionDetector` と、それを付けている5Prefab（Charcoal_Kiln / Primitive_Blast_Furnace / Sieve / campfier / press machine）の部品、`BlockGameObject` 側の無効化処理

出所: ユーザー裁定 2026-10-15 依頼原文「そもそも、bpって当たり判定ないよね、だとすると、より本質で変な変更をしてない、修正のPRを出したい」／撤去範囲の一覧を提示し原文「ok」
出所（無効化の手段）: agent前提（`TrainCarPreviewController` の前例。Collider を消さず無効化するのは IPreviewOnlyObject 等の依存を plan で確認するため）

### 4. BP貼り付けは埋まるブロックだけ飛ばし、除外をクライアントが送る

- 不可のブロックだけ赤くして飛ばし、残りは置く（既存の重なりスキップ `NonOverlapFlags` と同じ扱い。全ブロック不可ならBP不可）
- クライアントが判定し、飛ばすブロックの貼付先ワールド位置の列をBPリクエストに載せる（1リクエストが複数の貼付原点を持つため番号でなく位置。出所: ユーザー裁定 2026-10-15 選択「ADRをplanに合わせる (推奨)」）。サーバーはそれを重なりと同じく飛ばし素材も請求しない。サーバーは地形を検証しない
- 飛ばしたブロックにつながる接続線は、重なりで飛ばしたときと同じ扱いにする

出所: ユーザー裁定 2026-10-15 提示「クライアントが除外を送る（推奨）／サーバーも地形を判定」→ 選択「クライアントが除外を送る (推奨)」
出所（部分設置・接続線）: agent前提（既存の重なりスキップと同型）。範囲一覧を提示し原文「ok」

### スコープ外

ベルト設置で地形を迂回する最適ルート計算（bd moorestech-5wy86）。
出所: ユーザー裁定 2026-10-15 提示「今回のPRに入れるか（推奨: 別タスクに切る）」に原文「別で切る。」

## Considered Options

### 1. 全体で地形めり込み判定を入れない（ADR 0047 へ揃える）

提示した選択肢。ユーザーは「全体で入れる」前提で基準の質問へ進み、案A'を選んだ。

### 2. 案A: 最下段1セルは見ず、それより上に触れたら不可（棄却）

高さ1のブロックが完全に地中でも通る。棄却理由: ユーザー裁定 2026-10-15 原文「これも負荷であるべきでは？」。

### 3. 案B: ブロックが全部埋まったら不可（棄却）

ポールが9割埋まっても通る。棄却理由: ユーザー裁定 2026-10-15「ベースは案Aでok」。

### 4. 占有サイズから計算した箱で TerrainCollider へ物理問い合わせ（棄却）

4隅の間の尖りも拾えるが、高さ1に上面より上の箱が要り、完全地中の検出は未実測、設置Yの決定と別データになる。
棄却理由: ユーザー裁定 2026-10-15 選択「高さサンプル (推奨)」。

### 5. サーバーも地形の高さを引いて BP planner で判定（棄却）

棄却理由: ユーザー裁定 2026-10-15 選択「クライアントが除外を送る (推奨)」。

## Consequences

- 通常設置・BP・高さ1のブロックで、Q/E で地中へ下げた配置や崖に刺さる配置が置けなくなる。普通に地面へ置く場所は変わらない
- セル4隅の間にある尖った盛り上がりは拾わない（そこは置ける）
- サーバーは地形を検証しない。改造クライアントなら埋まった配置も通る（通常設置も同じ）
- BPリクエストに除外ブロックの項目が増える。セーブ形式は変えない。既存セーブで地中にあるブロックはそのまま
- プレビューがレイ・物理に一切現れないため、プレビュー自己命中による点滅・誤選択の類は構造的に起きない
