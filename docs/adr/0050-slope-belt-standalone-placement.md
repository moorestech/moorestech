# 0050. 上り・下り坂ベルトコンベアを単体で設置できるようにする

日付: 2026-09-05
状態: 採択

## Context

坂ベルト（上り・下り）は `blocks.json` の `beltConveyorFamilies` で直線ブロックと束ねられており、次の3点で「プレイヤーが直接選べないブロック」として扱われてきた。

- `PlacementTargetCatalog` が `BeltConveyorPlaceFamilyUtil.IsSlopeBlock` で坂をカタログから除外する（ビルドメニュー・ホットバー割当の両方に出ない）
- 坂が実際に置かれるのは `BeltConveyorPlaceSystem` のドラッグ経路に高低差が出たときか、`ConveyorOverpassRaiser` が障害物を跨いで持ち上げたときだけ。単クリックは `VerticalDirection = Horizontal` なので坂は原理的に出ない
- `BlockPickResolver`（スポイト）は坂を拾っても直線へ正規化する

このため「段差の坂を1個だけ壊してしまった」ときに、その1マスを直すには直線を選んで高低差をまたぐドラッグをやり直すしかない。ブロックとして存在するのにメニューに無いこと自体も不自然である。

坂を持つファミリーは 歯車 / 鉄歯車 / 通常 / 高速 の4つで、単体化するとビルドメニューのエントリは8個増える。

## Decision

- **上り・下りをビルドメニュー・ホットバーの個別エントリとして出し、単体で設置できるようにする。** `PlacementTargetCatalog` の坂除外を撤廃する。並び順は既存の `sortPriority`（直線→上り→下り）に従う。
  出所: ユーザー裁定 2026-09-05 原文「上下の坂ベルトコンベアも単体で設置できるようにしてほしい」→ 選択「個別エントリとして追加」（プレビュー: 直線／上り／下り／分岐機が並ぶビルドメニュー・計8エントリ増）／動機の選択「1個だけ直したい」「メニューに無いのが不自然」
  棄却案: ①直線を持ったまま切替キーで直線→上り→下りを回す ②エントリも切替キーも増やさず単クリック時に足元の高低差から坂を自動選択する

- **坂選択中のドラッグは経路の全セルを選択中の坂で埋める。** 3マスなら上り／上り／上りとなり、中途に直線は一切入らない。
  出所: ユーザー裁定 2026-09-05 選択「ドラッグで坂を並べる」（プレビュー: `y+0 → y+1 → y+2`・「中途の直線は一切入らない」）
  棄却案: ①1クリック1個のみでドラッグ無効 ②ドラッグ時は直線と同じ自動判定に戻す

- **ドラッグ中の高さは選択ブロックだけで決める。** 起点から毎セル +1（上り）／ -1（下り）で進み、カーソル先の地形高さは一切参照しない。上りを伸ばせば終端は空中へ伸びる。
  出所: ユーザー裁定 2026-09-05 選択「選択ブロックだけで決める」（プレビュー: 地形が平らでも `y+0 y+1 y+2 y+3`・「空中に伸びる」）
  棄却案: カーソル位置の地形高さに到達したらそこで打ち切る

- **曲がり角のセルにも坂を置く。** L字ドラッグを許し、現行の「角のブロックは必ず水平」規則を坂選択時だけ外す。角のセルも `y` は毎セル ±1 で進む。
  出所: ユーザー裁定 2026-09-05 選択「角も坂にする」（プレビュー: 角セルも上り）
  棄却案: ①坂選択中はドラッグを1軸直線に制限しL字を作らせない ②角のセルだけ直線ブロックを入れる
  補足: 角で搬送の接続や見た目が繋がらない可能性は裁定時に選択肢へ明示済み。破綻したらこの裁定を更新する。

- **設置可否は共通ルールのままとし、坂単体に地形条件を追加しない。** 平地でも坂を置ける。ただし地面と重なるセルは従来どおり設置不可（共通の地面重なり判定を使う）。平地で下りをドラッグすると2セル目以降は地中になるため置けず、崖の上からなら並ぶ。
  出所: ユーザー裁定 2026-09-05 選択「どこにでも置ける」＋「従来どおり設置不可」（プレビュー: 平地の下り3マスで1個目のみ設置可）
  棄却案: ①前方のマスに段差があるときだけ設置可にする ②坂選択中は地形との重なり判定を外して地中も許す

- **坂選択中は立体交差の自動持ち上げを無効にする。** 全セルが一定勾配で上下しているところに持ち上げが重なると高さが跳ねるため。障害物と重なるセルは従来どおり「既存ブロックあり」で設置不可になるだけ。
  出所: ユーザー裁定 2026-09-05 選択「坂選択中は無効」
  棄却案: 従来どおり `ConveyorOverpassRaiser` を効かせる

- **解放と建設コストは直線代表を維持する。** 坂の unlock 判定は直線ブロックの解放状態へ委譲し、財布（3個1セット・ADR 0026）も直線と共有する。research.json とコストマスタは変更しない。直線が解放された瞬間に直線・上り・下りの3エントリが同時にメニューへ並ぶ。
  出所: ユーザー裁定 2026-09-05 選択「直線代表を維持」
  棄却案: research.json に坂を別ノードとして追加し財布も坂ごとに分ける

- **スポイトは坂を拾ったら坂そのものを手持ちにする。** `BlockPickResolver` の直線正規化を坂については撤廃する（未解放ブロックを拾わせない規則は直線の解放状態で判定するため維持）。
  出所: ユーザー裁定 2026-09-05 選択「坂そのものを持つ」
  棄却案: 従来どおり直線へ正規化する

- **直線選択時の既存の自動坂挿入は現状のまま残す。** 坂単体はその上に足される選択肢であり、既存のドラッグ体験は変えない。
  出所: ユーザー裁定 2026-09-05 選択「現状のまま残す」
  棄却案: 自動挿入を廃し坂は常に明示選択にする

## Consequences

- `PlacementTargetCatalog` の Guid 一意検証はそのまま通る（坂 Guid は他種別と衝突しない）。ホットバーへ坂を割り当てた既存セーブは無い（従来は割当不可）ため移行は不要。
- `BeltConveyorPlaceSystem` は「選択が直線か坂か」で経路生成の分岐を持つことになる。直線選択時は現行の `BeltConveyorPathBuilder` ＋ `ConveyorOverpassRaiser` ＋ `BeltConveyorCellBlockResolver`、坂選択時は一定勾配のプロファイルで全セルを選択ブロックにする経路。
- `holdingBlockMaster` に直線ブロックを使っている箇所（プレビュー・地面重なり判定・建設コスト代表）は、坂選択時に選択中の坂を指す必要がある。財布キーは `ConstructionWalletUtil.ResolveWalletBlockId` が直線へ正規化するため変更不要。
- 坂を選んで平地に単発で置くと、接続先の無い坂ブロックが世界に残る。これはプレイヤーの自由として許容する。
