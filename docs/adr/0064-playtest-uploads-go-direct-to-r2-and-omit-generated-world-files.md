# 0064. プレイテストの報告は R2 へ直接アップロードし、生成ワールドの地形は送らない

日付: 2026-09-18
状態: 採択（ADR 0061 の「受け口は Cloudflare Worker + R2 で、ゲーム本体が直接アップロードする」の実装形を改訂する。plan D の「Worker が PUT を中継し Content-Length を縛る」を置き換える）

## Context

plan E の人手検証（配布ビルド → steamcmd → 検証機 smoke）を 2026-09-18 に初めて通したところ、phase1（起動時照合・新規ワールド・セーブ）と進行記録の送信は通ったが、phase2 のバグ報告アップロードが受け口で HTTP 503（Cloudflare 1102）になった。`wrangler tail` で outcome=exceededCpu を確認した。受け口の moorestech アカウントは Workers 無料プラン（CPU 10ms/リクエスト）で、Worker がバイト列を R2 へストリーミング中継する現行の実装は約 17ms/MB の CPU 時間を使う（8.4MB の地形で 120〜170ms、12.7MB の map.json で 210〜234ms）。取り締まりはバースト許容で不定期なため、通ったり落ちたりに見えた。

報告の箱は約 100MB で、そのうち約 88MB は `world/map.json` と `world/terrain/height_*.r16`（9枚）だった。新規ワールドは生成マップで seed 196 固定（ADR 0035）、配布ビルドには生成済みワールドのスナップショットが同梱されており、テスターの地形は同梱物と同一である。`map.json` はプレイ中に書き換えられず、プレイ中の変化はスナップショット（`tick_*.json`）側にある。

また、アップローダーは一過性の失敗（Retryable）を同一走行内で再試行せず次回起動へ持ち越すため、503 を1回受けただけで smoke の phase2（300秒）が必ず落ちた。

## Decision

- **Cloudflare Workers は無料プランのまま運用し、受け口 Worker はアップロードのバイト列を中継しない。** Worker は認証（Steam チケット検証・許可リスト照合・セッショントークン）のあと、箱の宣言（相対パスと長さの一覧）を受けてファイルごとの署名付き R2 PUT URL を発行し、クライアントは R2 へ直接 PUT する。署名にはファイルごとの Content-Length を含め、R2 に長さ不一致を拒否させる（1ファイル 100MB の上限は維持）。URL 発行時に箱全体のファイル数と合計バイト数の上限を検査し、超過は 413 で拒否して理由をログへ出す。`complete` では R2 の実オブジェクトを列挙し、発行した一覧と照合してから READY を書く。
  出所: ユーザー裁定 2026-09-18 原文「単に時間がかかるからってほぼ使われないサービスに安易に課金するその判断ってどうなの」「R2直接アップロードで変なことされたりはしない？」→ 質問「R2 への直接 PUT にすると Worker はバイト列を見なくなります。サイズの縛りはどこまでやりますか？」→ 選択「ファイル単位に加えて箱単位も縛る」（[[2026-09-18-受け口はR2直接PUTにしWorkerは署名付きURLの発行と箱単位の上限だけを持つ.md]]）
  棄却案: Workers Paid（月額 $5、CPU 30秒）にしてコードを変えない／ファイル単位の上限だけ／テスターごとの累計上限も足す

- **生成ワールドのバグ報告は `world.json` だけを入れ、`map.json` と `terrain/*.r16` は入れない。** 判定は `world.json` の `mapMode` が `generated` かどうかで行う。手作りワールドは従来どおり全部入れる。開発側は `world.json`（seed・generatorVersion・マスタ指紋・配置台帳ダイジェスト）と同じビルドから地形を引き当てる。
  出所: ユーザー裁定 2026-09-18 原文「それと、map.jsonとかhegihtとか送るひつようある？」→ 質問「バグ報告バンドルから map.json と地形を外す条件はどれにしますか？」→ 選択「生成ワールドなら常に外す」（[[2026-09-18-生成ワールドのバグ報告はmap.jsonと地形を送らずworld.jsonだけで再現する.md]]）
  棄却案: 同梱スナップショットと一致するときだけ外す／常に外す

- **アップローダーは Retryable の失敗を同一走行内で有限回、間隔を広げながら再試行し、送れたファイルは飛ばして続きから送る。** 上限を超えたときだけ従来どおり次回起動へ持ち越す（回数は数えない）。
  出所: ユーザー裁定 2026-09-18 質問「アップローダーが一過性の失敗を同じセッション内で再試行しない件は、今回の変更に含めますか？」→ 選択「含める：同一走行内で有限回のバックオフ再試行」（[[2026-09-18-アップローダーの一過性失敗は同一走行内で有限回再試行する.md]]）
  棄却案: 別タスクのまま

- **取り込み（ACK）済みの箱も R2 から消さない。保存量が無料枠（10GB）を超えて生じる少額の従量課金は許容する。** Workers の固定費を付けない裁定とは別で、使った分だけの課金は受け入れる（月額の目安は未指定）。
  出所: ユーザー裁定 2026-09-18 質問「R2 の保存量が無料枠（10GB）を超えたときの扱いはどうしますか？」→ 選択「少額の従量課金は許容し、R2 にも残す」（[[2026-09-18-R2の従量課金は少額なら許容し取り込み済みの箱もR2に残す.md]]）
  棄却案: 取り込み済み・未完了の箱をライフサイクル規則で自動削除して無料枠に収める／無料枠に近づいたら新規受付を止める

- **許可済みテスターが箱を大量に作る行為への対策は今回含めない。** 運用（日次ダイジェストで件数を見て `allowlist.sh remove` で外す）で対応する。署名付き URL の再利用は同じキーへの上書きで保存量は増えない。
  出所: ユーザー裁定 2026-09-18 質問「許可済みテスターが箱を大量に作る行為への対策は今回含めますか？」→ 選択「含めない：運用（許可リストから外す）で対応」（[[2026-09-18-アップロードの期限はサイズ比例ではなく進捗が止まったときのアイドル期限にする.md]]）
  棄却案: SteamID ごとの発行頻度を Worker で数えて 429 で拒否する

- **クライアントのアップロード期限は「一定時間バイトが進まないとき」に切るアイドル期限にする。** 遅くても進んでいれば送り続け、回線断だけを Retryable の失敗にする。plan D の「60秒＋128KiB/秒換算（上限900秒）」を置き換える。アイドル時間の具体値は plan 側で決める。
  出所: ユーザー裁定 2026-09-18 原文「低速回線でアップロードが30sを超える可能性を考慮してなくない？」→ 質問「この期限はどうしますか？」→ 選択「進捗がある間は切らないアイドル期限に変える」（[[2026-09-18-アップロードの期限はサイズ比例ではなく進捗が止まったときのアイドル期限にする.md]]）
  棄却案: 今の期限を維持する

- complete まで届かなかった箱も自動削除しない（次回起動の再送で同じキーへ上書きされる）。R2 のライフサイクル規則は設定しない。
  出所: agent前提（「R2 にも残す」裁定との整合。未完了分の保存量は上限内で有界）

- 地形を省いた報告の復元元は別途保存しない。生成ワールドは seed と generatorVersion から決定的に再生成でき、`world.json` の `placementLedgerDigest` で一致を検証できる。同じコミットの配布ビルド（`runs/<label>/build/game/worldSnapshots`）にも同梱物が残る。
  出所: agent前提（ADR 0035 の決定論的生成。Codex 独立質問 Q5 の消し込み）

- クラッシュ報告（`CrashBundleWriter`）は今もワールド定義を入れておらず、今回の除外規則の対象外。変更しない。
  出所: agent前提（コード事実。Codex 独立質問 Q7 の消し込み）

- 署名付き URL の発行はファイルごとでなく箱ごとのバッチ（`prepare` に宣言一覧を送り、全ファイルの URL をまとめて受ける）。再試行のたびに取り直す（URL の期限切れも再試行で解ける）。有効期限はセッショントークンと同じ1時間。進行記録も同じ経路を使う（経路を2本持たない）。応答の判別は `outcome` キー一本（`prepared` / `acked`）。
  出所: 箱ごとのバッチは agent前提（Worker のリクエスト数をファイル数でなく試行数に比例させる）。「試行ごとに取り直す」「判別は列挙型一本」はユーザー裁定 2026-09-18（plan の型検査で提示 → 選択「ADR の言葉を直す」「畳む：結果は列挙型一本で判別する」）

- 署名は R2 の S3 互換 API の SigV4 で作り、アクセスキーは Worker のシークレット（`R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY`）に置く。テスターに渡るのは署名だけで、キーは渡らない。署名はテスター・箱 ID・相対パス・PUT・Content-Length・期限に固定される。
  出所: agent前提（R2 は Workers バインディングから署名付き URL を作れないため S3 API を使う）

- 再試行の回数と間隔の具体値（例: 3回、10s/30s/60s）は plan 側で決める。
  出所: agent前提

## Consequences

- Worker のデプロイ前に、moorestech アカウントで R2 の API トークン（オブジェクト読み書き、対象バケット `moorestech-playtest` 限定）を作り、シークレットとして入れる作業がユーザーに要る。
- クライアントの `PlaytestUploader` は Worker への PUT をやめ、発行された URL への PUT に変わる。契約（`contract.json`）とクライアント側の定数テストを更新する。
- Worker の `putUpload`（ストリーミング中継）は削除する。`complete` は R2 の列挙を行うため、Worker の CPU はファイル数に比例するが1ファイルあたり数十 µs で無料枠に収まる。
- PUT されたが `complete` まで届かなかったオブジェクトは、次回起動の再送で同じキーへ上書きされる。自動削除はしない。
- 開発者モード（Editor）の rsync 経路でも `world/` の除外規則は同じ（判定は `mapMode`）。
- Mac mini 側の取り込み（`scripts/playtest/ingest.sh`）は READY の一覧を読むだけなので変更しない。再現時に地形が要る場合は、`world.json` と同じビルドの同梱スナップショットから引き当てる。
- クライアントの送信期限がアイドル期限に変わるため、`PlaytestReceiverConfig.UploadTimeout`（サイズ比例）と `contract.json` の対応定数・テストを置き換える。
- 検証機の smoke（`run-smoke.ps1` phase2）は、報告の箱が約 17MB になり、再試行も入るため 300 秒の待ちで完了する見込み。
