# 0082. クライアントの行き止まり停止をサーバーに合わせる

日付: 2026-10-16
状態: 採択

## 決定と出所

- クライアントもレール端で移動距離が余り、接続先がない場合に速度を0にする。
  出所: ユーザー裁定 2026-10-16「じゃあおなじのをクライアントに実装すればいいね、ブランチきってできる？」。
- 端へのちょうどの到達では速度を維持し、小数の移動距離を保持する。ドッキング通知による停止は速度と小数の移動距離を0にする既存処理を優先する。
  出所: agent前提（`TrainUnit.UpdateTrainByDistance` の手動運転停止条件とドッキング処理に一致させる）。
- ローカルコミットまで行い、pushしない。
  出所: ユーザー裁定 2026-10-16「はあ、すすめて pushしないで」。同発言により、見つからない `codex-audit` の独立質問チェックを省略する。

## 原因と検証範囲

原因: 推測（根拠: サーバーは接続先がない超過時に速度を0にするが、クライアントは目標到着後に警告を出して速度を保持していた。速度は同期ハッシュの対象）。実プレイの同期破綻はこの環境では再現していない。

`ClientTrainDeadEndStopTest` は既存のテスト用ノードと公開スナップショット入口から本番のクライアント移動処理を呼ぶ。到達前・一致・超過、次の移動での停止、接続先のある目標、ドッキング、期待する停止状態とのハッシュ一致を検証する。サーバーとの通信を含むテストではない。

Unityコンパイルと対象テストの実行を試みたが、`uloop` がPATH上になく、両方とも実行できなかった。テストの成功・実プレイでの解消は未確認。セーブ形式と通信形式は変更しない。
