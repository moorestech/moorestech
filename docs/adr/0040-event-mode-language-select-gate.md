# 出展モードは言語選択画面を開始ゲートにし、無操作タイマーは言語選択で武装する

gamescom出展の無人キオスク運用（ADR 0030「終了＝リセット」の再起動ループ）で2つの穴が残っていた。
1つは、無操作180秒タイマーがロード完了時点から無条件に走るため、来場者が誰も居ない時間帯でも
3分ごとにアプリが落ちて再起動し、無人のブースで数十秒の起動画面が定期的に挟まること。
もう1つは、言語が起動ごとに英語へ強制リセットされるだけで、来場者が母国語を選ぶ手段がないこと。

これを、**言語選択画面を「プレイ開始のゲート」として据える**ことで一度に解く。
出展モードでは MainGame のロード完了後・オープニングスキット再生前に、
WebUI の全画面言語選択画面を出して**永久に待機する**。無操作タイマーはこの間まったく武装せず、
来場者が言語ボタンを押した瞬間に初めて武装する。押下と同時に保留していたスキット・チュートリアル発火が
選ばれた言語で流れ、プレイが始まる。以後3分間の無操作でこれまでどおり `Application.Quit` し、
起動スクリプトが新規ワールドで再起動して、また言語選択画面で次の来場者を待つ。

これにより無人時はブースの画面が「Select Language」で静止し続け、
来場者が来た瞬間だけ起動コストゼロでプレイに入れる。

## 画面をロード完了後に置く理由（構造上の制約）

CEF ブラウザは `MainGameUI.prefab` にしか存在せず、WebUI が画面へ出るのは MainGame シーンのロード後である
（`WebUiHost` の Kestrel/Vite 自体は `InitializeScenePipeline.cs` 冒頭で起動するが、それを映すブラウザが無い）。
uGUI は `docs/webui/ugui-retirement-plan.md` Phase 1 で廃止済み（`WebUiScreenGate.IsWebUiMode => true` 恒久ON）であり、
出展モードのために uGUI を復活させる選択肢は取らない。
よって「ワールド生成前に選ばせる」には CEF をブートシーケンス側へ立ち上げる構造改修が要るため、
ロード完了後に置く。副産物として、来場者は言語を選んだ瞬間に遅延ゼロで遊び始められる。

## 決定

- 出展モード（`MOORESTECH_EVENT_MODE=1`）のとき、MainGame ロード完了後・オープニングスキット再生前に
  WebUI の全画面言語選択画面を出し、言語が確定するまで永久に待機する
- 選択肢は `LanguageCatalog.Languages` の DisplayName（English / 日本語 / Deutsch）。見出しは英語固定 `Select Language`
- 背景は不透明の暗幕でゲーム画面を完全に隠す
- 言語ボタンの押下だけが「最初の操作」。待機中のキーマウ入力（マウス移動・空白クリック）は一切カウントしない
- 押下で言語を適用し、保留していたスキット・チュートリアル発火をキューから流す
- 無操作タイマーは押下時点で初めて武装する。武装後の挙動は従来どおり（180秒無操作で `Application.Quit`）
- 選び直しの導線は設けない。誤選択はスタッフの Cmd+Q か3分待機で回収する（どちらも新規ワールドで再起動する）
- メインメニューは出展モードで一切使わないため、置き場・流用の検討対象から外す

出所:
- 無操作タイマーを最初の操作まで武装しない: ユーザー裁定 2026-08-28 原文「3分間無操作リセットは最初何らかの操作があってから操作に移りたい」→ 選択「言語選択画面での最初の入力から」
- 言語選択UIの新設: ユーザー裁定 2026-08-28 原文「言語選択UIを出しておいて、どの言語でやるか選ばせたい」→ 選択「出展モード専用の全画面3ボタン」
- 選択ボタン押下で即開始: ユーザー裁定 2026-08-28 選択「選択ボタン押下で即ゲーム開始」
- 待機画面での放置は永久待機: ユーザー裁定 2026-08-28 選択「永久に待機する」
- 画面をロード完了後・スキット前に置く: ユーザー裁定 2026-08-28 選択「ロード完了後・スキット前に全画面モーダル」
- 「最初の入力」は言語ボタン押下のみ: ユーザー裁定 2026-08-28 選択「言語ボタンの押下のみ」
- スキット・チュートリアル発火の保留: ユーザー裁定 2026-08-28 選択「スキット・チュートリアル発火を保留」
- 背景は不透明の暗幕: ユーザー裁定 2026-08-28 選択「不透明の暗幕で完全に隠す」
- 見出しは英語固定 `Select Language`: ユーザー裁定 2026-08-28 選択「英語固定 "Select Language"」
- 選び直し導線を設けない: ユーザー裁定 2026-08-28 選択「用意しない」
- メインメニューを検討対象から外す: ユーザー裁定 2026-08-28 原文「メインメニューは使ってないって」「出展者モードで使ってないんだから検討項目に挙げないで」「終了してから自動再起動するモードで少なくともユーザーはメインメニューに一切触らない」
- UIをWebUIで作ること: ユーザー裁定 2026-08-28 原文「WebUIでつくるuguiはどこも使ってない」
- 起動ごとの英語強制リセットを維持すること（ロード画面の言語であり、選択画面は毎回必ず出る）: agent前提（ADR 0030 の既存挙動を変える理由が無い）

## Considered Options

- 既存 MainMenu をそのまま表示して既存の LanguageSetting ドロップダウンで選ばせる — ConnectServer・SetPlayerId・ResetAllData 等の開発向けボタンが来場者に見えるため棄却。加えて出展モードでメインメニューは使わないとユーザーが明言（ユーザー裁定 2026-08-28）
- ロード前に出す（CEF をブートシーケンス側にも用意する） — CEF をシーンをまたいで立ち上げる構造改修が必要で、かつ選択後に来場者が数十秒のロードを待つため棄却（同上）
- 「最初の入力」を任意のキーマウ入力とする — 現行判定が `mouse.delta` の1px微動も拾うため、机の揺れや通りすがりで待機が打ち切られる。棄却（同上）
- 見た目だけ全画面オーバーレイで覆い、スキットは裏で英語のまま進める — 言語を選んだ頃にはオープニングを見逃しているため棄却（同上）
- 見出しを3言語併記 / 見出しなし — ボタンが母国語表記のため英語1行で足りると裁定（同上）
- 選び直し導線（ポーズメニューの既存言語設定への案内） — 画面に余分な要素が増えるため棄却。誤選択は Cmd+Q か3分待機で回収する（同上）

## Consequences

- 無人時はプロセスが落ちずに走り続ける（ロード済みの MainGame と内蔵サーバーの tick が回り続ける）。
  ワールドは無人で空のため負荷は軽いが、長時間の連続稼働を初めて踏むことになる
- 前の来場者のワールドが次の人に渡る穴は塞がったまま。Quit → 再起動 → 起動時 world_1 削除 → 新規生成の順序は不変
- 待機中に内蔵サーバーの tick が進むため、ワールド作成日時と実プレイ開始時刻がずれる（記録用途のみで実害なし）
- スキット・チュートリアル発火の保留は出展モード固有の概念であり、`SkitFireManager` のような汎用基盤へ
  「出展モード」の語彙を持ち込まないこと（判断は具体側で行い、基盤へは値をプッシュする）
