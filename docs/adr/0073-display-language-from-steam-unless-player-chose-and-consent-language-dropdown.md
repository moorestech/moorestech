# 0073. 表示言語は選んだ言語が無ければSteam言語から決め、参加同意に言語ドロップダウンを置く

日付: 2026-09-28
状態: 採択

## Context

表示言語は `Client.Localization.Localize` が PlayerPrefs `LanguageCode` の保存値から決め、保存値が無ければ english 固定で始まる（`Localize.cs:14,33-38`）。保存値は明示的な選択（タイトルのドロップダウン `LanguageSetting`・設定画面の `localization.setLocale`・出展モードの言語ゲートと起動言語env）でしか書かれない。Steam の言語はどこでも読んでいない。言語一覧 `Localization/localization_settings.csv` には `steam_api_lang_code` 列（en/ja/de）が既にあるが、クライアントから参照されていない。値は Steam の Web API 言語コード形式で、`SteamApps.GetCurrentGameLanguage()` が返す API 言語コード（english/japanese/german）とは形が違う。

参加同意ポップアップ（ADR 0065、タイトルに uGUI で初回だけ出る「各種データを送ります」の画面）は、初回起動なので必ず english で表示される。英語を読めないテスターは、何を送るのかを読めないまま了解することになる。

対応言語は今後18以上に増える見込み（ユーザー発言 2026-09-28「言語は今後18以上になることを想定して」）。

## Decision

- **起動時の表示言語は、選んだ言語があればそれ、無ければSteam言語とする。** Steam言語は保存しない。選んだ言語を持たない人は、Steam側の言語を変えればそれに追従する。一度自分で選べば、以後はSteam言語に追従しない。
  出所: ユーザー裁定 2026-09-28 原文「言語設定をSteamから自動取得、自動適用にする」→ 質問「Steamの言語と、プレイヤーが自分で選んだ言語が食い違うとき、どちらを優先しますか？」→ 選択「自分で選んだ言語を優先」
  棄却案: 毎回Steamに合わせる（ゲーム内の選択はそのセッション限り）／Steamが変わったときだけ追従（前回のSteam言語を覚えて差分で上書き）

- **Steam言語がゲームの対応外のとき、または取得できないとき（Steam未起動・エディタ）は english で始める。** OS の言語は見ない。
  出所: ユーザー裁定 2026-09-28 質問「Steamの言語をゲームが対応していないとき、またはSteamを起動せずに遊んでいて言語が取れないとき、どの言語で始めますか？」→ 選択「Englishで始める」
  棄却案: OSの言語を次に試す（Steam→OS→English）

- **言語一覧CSVで、ゲームの1言語に複数のSteam言語を対応づけられるようにする**（例: spanish ← spanish, latam）。どこへ寄せるかは言語を足すときにCSVで決める。簡体字と繁体字のように寄せたくない組は、対応づけなければよい。
  出所: ユーザー裁定 2026-09-28 質問「Steam側の地域差のある言語（中南米スペイン語・ブラジルポルトガル語・簡体字/繁体字など）の人をどう扱いますか？」→ 選択「近い言語へ寄せられる」
  棄却案: 完全一致だけ（1言語につきSteam言語1つ）

- **参加同意ポップアップに言語ドロップダウンを置く。** 選んだ瞬間に、ポップアップの本文と背後のタイトルがその言語へ切り替わる。ここで選べば選んだ言語として保存される。何も触らずに了解した人は、Steam言語のまま。
  出所: ユーザー裁定 2026-09-28 原文「最初の各種データを送るよ、といっているところの画面で言語選択をもうできるようにしたい」→ 質問「同意ポップアップに置く言語選択は、どんな形にしますか？」→ 選択「ドロップダウン」。前提 原文「言語は今後18以上になることを想定して」
  棄却案: 母国語表記のボタンを横並び

- **Steam言語は、Steamのゲーム個別の言語設定から読む。** Steam は Steamworks に登録した対応言語へ丸めて返すので、地域差の言語を近い言語へ寄せるには、その地域言語を Steamworks の対応言語にも登録する。
  出所: ユーザー裁定 2026-09-28 質問「「Steam言語」をどこから読みますか？」→ 選択「ゲーム個別の言語」
  棄却案: Steam本体の表示言語

### agent前提（実装方針。ユーザー裁定ではない）

- 「選んだ言語がある」とは PlayerPrefs `LanguageCode` が存在すること。現状も保存は明示選択でしか起きないため、既存テスターの保存値をそのまま選んだ言語として扱う。移行処理は置かない。出所: agent前提（`TrySetLanguage` 以外に PlayerPrefs への書き込みが無いことを確認）
- Steam言語の読み取りは、`PlaytestLocalSteamIdReader` と同じ形の境界にする（ネイティブ呼び出しを try/catch で理由付きの失敗に畳む）。その結果を `Localize` へ、保存しない経路で渡す。`Localize` は Steam を知らない。出所: agent前提（`PlaytestLocalSteamIdReader` の前例。汎用基盤にドメイン語彙を持ち込まない原則）
- `Localize.Initialize` は SteamAPI 初期化（MainMenu の `SteamManager.Awake`）より前に走る。Steam言語は Steam 初期化の直後に当て、`OnLanguageChanged` で既存の表示を追従させる。出所: agent前提（言語変更は即時反映で、購読側が揃っている）
- CSV の `steam_api_lang_code` 列を Steam の API 言語コード（`GetCurrentGameLanguage` の戻り値の形: english/latam/schinese…）に改め、複数値を持てる形にする。ソースジェネレーターが生成する `LanguageInfo` も追従させる。出所: agent前提（Steamworks の言語コード表）
- 同意ポップアップとタイトルのドロップダウンは、言語コード（english）ではなく CSV の `display_name`（母国語表記）を並べる。18言語でも収まるようスクロールさせる。タイトルの既存ドロップダウンも同じ表示に揃える。出所: agent前提（ユーザー発言「18以上」からの帰結。選択の形そのものは裁定済み）
- 出展モードの起動言語env（ADR 0042）は明示選択として今までどおり保存し、Steam言語より優先される。出所: agent前提（既存の保存経路を変えない）
- 同意ポップアップの表示規則（保存先ごとに初回1回）は変えない。既に了解済みのテスターには言語ドロップダウンを出し直さない。出所: agent前提（ADR 0065 裁定「表示規則は変えない」の維持）
