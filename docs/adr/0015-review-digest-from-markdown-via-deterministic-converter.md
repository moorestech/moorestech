# レビューダイジェストはMarkdown正本を決定論コンバータでHTML化する

`pr-independent-review` の成果物 `digest.html` は、sonnet subagent が951行のテンプレートを土台に**HTMLを丸ごと手書き**している。これをやめ、AIは所定フォーマットの `digest.md` **1枚だけ**を書き、決定論コンバータが `digest.html` と `findings.json` の**両方**を生成する構成へ移す。

出所: ユーザー裁定 2026-08-18「特定のマークダウンフォーマットで書けば自動でhtmlに変換される仕組みにする」

## 背景: 規約が破れても出荷される構図

PR #1155 の裁定サイトで、11件すべての案ボタンが各カードの直下ではなく「章の末尾」にまとめて落ちる不具合が出た。原因は、SKILL.md が「`data-finding-id` はカードのルート要素（`section.verdict-card`）へ付ける」と規定しているのに、生成subagentが外側の `.figure` ラッパへ付けたこと。裁定サイト側は前者を前提に `closest("section")` していたため、内側のカードを飛び越して外側の章セクションに解決していた。

これは単発のミスではなく構図の問題である:

- SKILL.md は HTML を正しく書かせるために**約60行の注意書き**（エスケープ順序・h1は1個・絵文字禁止・プレースホルダ置換・`data-verdict` 手設定・`data-finding-id` 付与先・生成後検査4点）を積み上げている。守るのは毎回AIで、破れても出荷される
- `digest.html` と `findings.json` が**二重入力**になっており、両者の一致は「単一ソース原則」という人手の約束でしか担保されていない
- 実際に生成後検査4点は `data-finding-id` の件数と重複しか見ておらず、**どの要素に付いたか**は検査していなかった。今回の破れはここを素通りした

## 決定

### 1. 正本は digest.md 1枚（findings.json は導出物）

AIは `digest.md` だけを書く。コンバータが `digest.html` と `findings.json` を生成する。id採番・`data-finding-id` の付与先・案キー・`recommended`・HTMLエスケープはすべてコンバータの責務になり、SKILL.md からは対応する規約群が消える。

棄却: `findings.json` を正本にする案（長文の散文をJSON文字列に埋めることになり可読性と編集性が落ちる）／`digest.md` と `findings.json` の2本立て（現状の二重入力をそのまま温存する）。

### 2. ページ骨格はコンバータが自動生成する

AIは finding カードをフラットに列挙するだけとし、セクション分け・並び順（必読の設計判断→残りの設計判断→suppressed→新形→Critical要点）・「あなたが判断すること」インデックスのアンカーリンク・0件セクションの「該当なし（0件）」行は、カードの `severity` / `category` / `must_read` からコンバータが導出する。SKILL.md の並び順規定（約40行）は不要になる。

棄却: AIがMarkdownの見出しでセクションを並べる案（並び順と0件セクション存置の遵守がAI任せのまま残る）。

### 3. カード記法は「見出し＋YAMLブロック＋自由本文」

見出しがタイトル、直下のYAML fence が機械可読キー（`category` / `severity` / `must_read` / `summary` / `files` / `options`）、その下は自由Markdown。`options` はリスト順がそのまま案キー A / B / C になる。

棄却: 小見出し規約のみでYAMLを持たない案（`severity` 等の値を散文から拾うことになりパースがもろい）／本文までYAMLの値にする案（長文とコードブロックをYAML文字列に埋めるとインデント事故が増え人が読めない）。

### 4. 推奨案の欠落を構造的に不可能にする

コンバータは `options` の先頭を必ず `key: "A"` ・`recommended: true` として出力する。AI側の規約は「推奨案を先頭に書く」だけになり、フラグの付け忘れが起きる余地が無くなる。あわせて裁定サイト側の「`recommended` が欠けていたら黙って先頭案を採用する」フォールバックを削除し、欠けている場合は一括採用をエラーで拒否する。

これは「私が明示的に選択したもの以外は、少なくともおすすめが選択されるようにしたい」（ユーザー裁定 2026-08-18）への回答である。現行は完了ボタンが未裁定分を推奨で一括採用する一方、フラグが欠けると**AIのおすすめではなく、たまたま先頭にあった案**が無言で通る。

棄却: コンバータ側だけで保証しサイトのフォールバックは互換のため残す案（手書き `findings.json` が混ざった瞬間に黙りフォールバックが復活する）／未裁定の一括採用自体をやめる案（指摘11件のPRで全件クリックが必須になり、裁定の手数が実用の範囲を超える）。

### 5. 変換エンジンは標準ライブラリのみの限定サブセット自前実装

`python3` に `markdown` / `markdown-it-py` / `pyyaml` はいずれも入っておらず、レビューは使い捨てworktreeで無人headless実行される。digestが実際に使う記法（見出し・段落・箇条書き・コードフェンス・diffフェンス・強調・インラインcode・リンク）だけを実装し、未知記法はエラーで落とす。汎用Markdownを通さないことは「見た目が勝手に変わる道を塞ぐ」ことでもある。

棄却: pipで変換ライブラリを導入する案（無人実行環境にパッケージが無いと黙って死ぬ／標準変換は現行CSSが想定しないタグも出す）／node側で変換する案（既存 `scripts/` が全てpythonで言語が混ざり、webuiの `node_modules` にレビュー基盤が依存する）。

### 6. 見た目はPR #1155をゴールデンに据えて担保する

**見た目を今までとほぼ変えないことが最優先制約**（ユーザー裁定 2026-08-18）。現行の `pr-1155-r2/digest.html` をMarkdownへ書き戻し、コンバータ再生成版と現行版を同一幅でレンダリングしてスクリーンショット比較する。そのmdと期待HTMLは `tests/` へゴールデンとして残し、以後コンバータを触ったときに見た目が動いたら即座に割れるようにする。

棄却: DOM構造とclass語彙の一致検査のみ（CSSが同じでも余白・改行・順序の差で見た目が変わるケースを見逃す）／目視1回で完了とする案（後からコンバータをいじった時に見た目が黙って崩れるのを防げない）。

## 適用範囲と移行

- `digest-template.html` を使うスキルは `pr-independent-review` のみ。他スキルへの波及は無い
- Step 7 のテンプレ手書き経路は**完全廃止**する。コンバータが落ちたらAIが `digest.md` を直す。逃げ道を残すと「規約が破れても出荷される」構図が復活する（出所: agent前提。本ADRの背景と裁定4の一貫性から）
- `data-finding-id` はカード要素へコンバータが付ける。2026-08-18に裁定サイト `inject.py` へ入れた両対応（`closest("section.verdict-card") || byId`）は、過去runのdigestを開くために残す（出所: agent前提）
- 過去runのdigestは再生成しない。成果物は当時のまま保存する（出所: agent前提。既存の「$RUNDIRの成果物はlogs repoへ保存し後から見返す」方針に従う）
- `digest.md` も `$RUNDIR` へ保存し、logs repoへpushされる成果物に含める（出所: agent前提）
- 触る箱は2つ: moorestech repo（SKILL.md・コンバータ・tests）と hermes 側 `data/services/pr-review/site`（`recommended` 欠落時の黙りフォールバック削除）
