# 接続線の切断は削除ツールへ一本化し、削除ツールのUndoは撤去物を同じ抽象で復元する

電線と歯車チェーン（まとめて「接続線」）を削除ツールで切断できるようにし、電線ツールにあった「起点未選択で電線をクリックして切断」は廃止する。接続線の切断手段は削除ツールだけになる。歯車チェーンは2026-07-03（71609bc91）に到達不能としてサーバーの切断経路ごと削除されていたため、返却付きの切断経路を復活させる。

削除ツールの中で接続線はブロックと別の破壊カテゴリーとして扱う。ホバーとドラッグ開始は最前面の対象を取り、ドラッグ中は固定したカテゴリーに属する対象のうち最も手前のものを拾う。電柱・橋脚などのブロックをホバー／選択したときは、一緒に消える電線・チェーン・レールも赤プレビューで示す（選択には入れない）。

削除ツールのUndoは、撤去したもの（ブロック・電線・歯車チェーン・レール）を同じ抽象度で1バッチに記録し、Ctrl+Zでいずれも復元する。直接切った接続線・レールに加えて、ブロック撤去に巻き込まれて消えた接続線・レールも同じバッチに入り、ブロック再設置の後に引き直す。Undoの再設置では電線の自動接続を発動させず、記録した線だけを引き直して撤去前と同じ配線に戻す。

## Considered Options

- 対象を電線のみにし、歯車チェーンは現状のまま — 棄却。
  出所: ユーザー裁定 2026-10-04 原文「電線を削除ツールで切断できるようにしたい」→ 自由記述「歯車チェーンも、適切に共通化する」
- 接続線をブロックと混在でドラッグ選択できるようにする（レールと同じ） — 棄却。
  出所: ユーザー裁定 2026-10-04 選択「接続線は別カテゴリー」
- 接続線は単体クリックのみでドラッグ選択に入れない — 棄却。
  出所: ユーザー裁定 2026-10-04 選択「接続線は別カテゴリー」
- 切った接続線をUndoで復元しない（レールの現状と同じ） — 棄却。
  出所: ユーザー裁定 2026-10-04 自由記述「復元したい。本質的に同じ抽象度で保持するようにしたい」
- 接続線だけブロックと同形で復元し、レールは触らない — 棄却。
  出所: ユーザー裁定 2026-10-04 自由記述「本質的に同じ抽象度で保持するようにしたい」→ 解釈確認で選択「レールも含めて統一」
- 電線ツールのクリック切断を残す／チェーンツールにも足す — 棄却。Undoできない切断経路を残さない。
  出所: ユーザー裁定 2026-10-04 選択「廃止し削除ツールに一本化」
- 照準で接続線を常に優先／常に最前面のみ — 棄却。
  出所: ユーザー裁定 2026-10-04 選択「最前面＋ドラッグ中は同カテゴリー」
- ブロック撤去のUndoではブロックだけ再設置し、巻き込まれた線は戻さない — 棄却。
  出所: ユーザー裁定 2026-10-04 選択「復元する」
- 橋脚・駅の撤去で巻き込まれたレールは戻さない — 棄却。
  出所: ユーザー裁定 2026-10-04 選択「引き直す」
- Undoの再設置で自動接続も走らせ、未接続分だけ追加で引く — 棄却。撤去前に無かった線が増え得る。
  出所: ユーザー裁定 2026-10-04 選択「止めて記録どおりだけ引く」
- ブロック撤去時、巻き込まれる線は赤くせずブロックだけ赤くする — 棄却。
  出所: ユーザー裁定 2026-10-04 選択「赤くする」
- 電線と歯車チェーンは同じ「接続線」カテゴリーに属し、同じドラッグで一緒に選べる。
  出所: ユーザー裁定 2026-10-04 選択「接続線は別カテゴリー」（選択肢が「接続線（電線・チェーン）」を1カテゴリーとして提示）
- レールは従来どおりブロックと同じ（default）カテゴリーに留める。
  出所: agent前提（照準の裁定で「ブロック（レール含む）」と提示し採択された／DeleteTargetRail の既存カテゴリー）
- Undoで線を引き直すときは通常の接続経路を通り、建設コストを再消費する。素材不足・未解放・端点不在などで失敗した分は開発者ログとプレイヤー通知に出して残りを続行する。
  出所: agent前提（ブロックUndoの再設置が通常設置経路で素材を再消費する前例 RemoveOperationRecord／AGENTS.md の無音縮退禁止）
- Undoの記録は端点をワールド座標で持ち、BlockInstanceIdは持たない（再設置でInstanceIdが変わるため）。
  出所: agent前提（ElectricWireDisconnectRequest が座標で端点を指す前例）
- 電線・歯車チェーンの種類は保存せず、Undo時に自動接続と同じ規則（解放済み・賄える種類のうち最優先）で選ぶ — 棄却。元と別の種類に変わり得る。採択: 接続ごとに引いた種類（ConnectToolGuid）をレールと同じく保存・同期し、セーブ形式変更に伴いCurrentVersionを上げ、旧セーブは線種別ごとの固定の種類を割り当てる移行ステップを足す（次項）。
  出所: ユーザー裁定 2026-10-04 選択「接続ごとに種類を保存」
- 旧セーブの移行で素材から種類を逆引きし、空・未知素材の線があれば移行失敗にする — 棄却。採択: 旧版の電線は全て「電線」、チェーンは全て「歯車チェーン」の種類を割り当てる（固定定数・マスタ非参照・失敗しない）。
  出所: ユーザー裁定 2026-10-04 選択「線種別ごとの唯一の種類を割り当て」
- 橋脚・駅の撤去で付いていたレールの素材を返却しないまま、Undoの引き直しを無償にする／再消費する（二重払い） — 棄却。採択: 撤去でレールも電線・チェーンと同じく返却し（入りきらなければ撤去拒否）、Undoは通常どおり再消費する。
  出所: ユーザー裁定 2026-10-04 選択「撤去でレールも返却する」
- Undoの引き直しは既存の接続経路を再利用する（電線: va:electricWireExtend の既存ブロック接続、チェーン: va:gearChainConnectionEdit の接続）。レールは再設置でノードGuidが振り直されるため、座標同定（ConnectionDestination）で接続する要求を新設する。ブロック再設置は設置要求に指定を足して電線の自動接続を止める（駅隣接のレール自動接続は止めない。ユーザー裁定 2026-10-05「止めない（電線だけ止める）」）。
  出所: agent判断（RailComponent.cs で設置ごとにNodeGuidを新規発行・RailNodeIdAllocatorがId再利用する事実／サーバーのパケット処理がFIFO単一スレッドである事実 TickEndPacketQueue.cs）
- 列車車両の撤去のUndo復元は本件の範囲外。
  出所: agent前提（ユーザーへの提示範囲がブロック・接続線・レールに限られていた）

## Consequences

- サーバー: 歯車チェーンの切断（返却付き）を復活させる。Undo再設置用に自動接続を発動させない設置経路が要る。
- クライアント: 接続線のクリック判定（チェーンにも当たり判定を追加）・赤プレビュー・IDeleteTarget実装を電線/チェーンで共通化する。電線ツールから切断経路を除去する。Undoレコードは撤去物の種類を問わない形へ作り直す。
- CONTEXT.md「電線ツール」から切断を外し、「接続線」「削除ツール」の項を足す。
- 関連裁定: .decisions/2026-10-04-*.md 一式
