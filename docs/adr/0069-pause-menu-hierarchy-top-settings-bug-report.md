# 0069. ポーズメニューをトップ・設定・バグ報告の階層にする

日付: 2026-09-24
状態: 採択（`.decisions/2026-09-11-バグ報告の入口はポーズメニューへ記述欄と送信を直置きする.md` を覆す）

## Context

ポーズメニュー（Web UI の `PauseMenuPanel`）には、セーブ・セーブして終了・バグ報告フォーム（種別・説明文・送信）・言語選択が1枚に並んでいる。項目が増えるほど1枚が縦に伸びる。2026-09-11 には「クリックが1つ増える」ことを理由に、バグ報告フォームをポーズメニューへ直接置くと決めていた。

ポーズメニューは3か所から開く。通常の画面（`UIStateEnum.PauseMenu`）、列車HUD、スキット（どちらも `NestedPauseSubStateEnum.PauseMenuScreen`）。3か所とも Escape の判定を `PauseMenuStateService.IsClosePause()` 1つに頼っている。ポーズを開いた瞬間（`OnPauseMenuOpened`）には、バグ報告用に Escape 時点の記録を確保する（ADR 0057）。

## Decision

- **トップは「セーブ／セーブして終了／設定→／バグ報告→」の4ボタンにする。** 切断表示はトップに残す。言語選択は設定画面へ、バグ報告フォームはバグ報告画面へ移す。バグ報告は今より1クリック増えるが、2026-09-11 の直置き裁定はこれで覆す。Escape 時点の記録を確保するタイミング（ポーズを開いた瞬間）は変えない。
  出所: ユーザー裁定 2026-09-24 原文「ポーズ画面 > 設定画面,バグ報告 みたいな感じで、今ポーズ画面に集約されてるものを全部階層化したい」→ 選択「4ボタン並び」
  棄却案: セーブ系も子画面へまとめ、トップを「再開／設定／バグ報告／セーブ・終了」に絞る／階層ではなく同じパネル内のタブで切り替える

- **子画面で Escape を押すとトップへ1段戻り、トップで押すとポーズを閉じる。** 子画面には「戻る」ボタンも置く。
  出所: ユーザー裁定 2026-09-24 質問「設定画面・バグ報告画面を開いているときにEscapeを押したらどうなりますか？」→ 選択「1段戻る」
  棄却案: どの階層でも Escape 1回でゲームへ戻り、トップへは「戻る」ボタンでだけ戻る

- **バグ報告画面で送信が成功したら、入力を空にしてトップへ戻る（ポーズは閉じない）。** トーストは今どおり出す。送信が失敗したらバグ報告画面に留まり、入力も残す。
  出所: ユーザー裁定 2026-09-24 質問「バグ報告画面で送信が成功したあと、画面はどこへ行きますか？（現状はポーズ画面に留まって入力欄を空にし、トーストで「送信しました」と出す）」→ 選択「ポーズのトップへ戻る」
  注記: 質問文の「現状は留まる」は誤りで、実際の現状は C# の `BugReportSubmitActionHandler` が送信成功でポーズを閉じてゲームへ戻していた。提示した3案（トップへ戻る／留まる／ゲームへ戻る）自体は正しく並んでおり、選ばれた「トップへ戻る」は現状とも異なる変更として扱う。
  失敗時に留まって入力を残す扱いは agent前提（現状の `BugReportForm` が失敗時に入力を消さない挙動を引き継ぐ）。
  棄却案: バグ報告画面に留まる／ポーズごと閉じてゲームへ戻る

- **送信成功後にトップへ戻すのは C# の `BugReportSubmitActionHandler` が行う。** 今ポーズを閉じている箇所を、`PauseMenuStateService` へのトップ遷移要求に置き換える。
  出所: agent前提（今どの画面にいるかの持ち主が C# なので、遷移も C# 側の同じ箇所で起こす）

- **設定画面の中身は、今回は言語選択の移設だけにする。** 新しい設定項目は別タスクで足す。
  出所: ユーザー裁定 2026-09-24 質問「今回の設定画面は、今ある言語選択を移すだけですか？」→ 選択「言語選択の移設だけ」
  棄却案: 新しい設定項目（音量・感度など）も今回足す

- **今どの画面にいるか（トップ・設定・バグ報告）は Unity 側の `PauseMenuStateService` が持ち、pauseMenu トピックで Web へ配る。** Web は子画面へ進む・戻るをアクションで要求する。Escape を処理するのは Unity なので、Web だけが画面を持つと「子画面なら1段戻る」を Unity が判定できない。`PauseMenuStateService` は通常ポーズ・列車HUD・スキットの3か所で共有されているので、ここ1か所を直せば3か所とも同じ階層になる。
  出所: agent前提（Escape が `PauseMenuStateService.IsClosePause()` 1口に集まっている構造と、AGENTS.md の「イベントパケット＋初期データ＋購読」前例）

- **子画面は同じパネルの中身を差し替えて見せる。親の一覧は残さず、重ねもしない。**
  出所: agent前提（現行パネルの幅420pxのまま、依頼の「階層」を最小の構成で満たす）

- **ポーズを開くたびにトップから始める。ポーズを閉じたらバグ報告の書きかけは捨てる。同じポーズの中でトップと子画面を行き来する間は書きかけを残す。**
  出所: agent前提（Escape 時点の記録はポーズを開くたびに上書きされる（ADR 0057）ので、書きかけを次のポーズへ持ち越すと別の瞬間の記録に付いてしまう）

- **チュートリアルアンカー `pause.save`・`pause.back`（セーブ・セーブして終了）はトップに残るので、そのまま使う。** 設定ボタン・バグ報告ボタン・戻るボタンにもアンカーを足す。
  出所: agent前提（既存アンカーの参照先を壊さない）

## Consequences

- バグ報告は Escape → バグ報告 → 記入 → 送信 となり、1クリック増える。
- ポーズメニューの pauseMenu トピックに「今の画面」が増えるので、Web と C# の契約テスト（WireContract）を更新する。
- 今後の設定項目は設定画面に足していく。
