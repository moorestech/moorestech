# 0061. 選定テスター向けSteamプレイテストは報告受け口をCloudflareに置き、セーブ互換をゲーム内マイグレーションで保つ

日付: 2026-09-13
状態: 採択（ADR 0057 の「送り手は開発者本人のみ」「HTTP受け口は作らない」「クラッシュは対象外」を改訂する）。起動時の許可リスト照合とオンライン必須は ADR 0070 で撤回

## Context

選定した限られた人にプレイしてもらうプレイテストを始めたい。前回の壁打ち（本セッション冒頭）で、対象PFはWindows・経路はSteamキー・報告UIを作る・セーブ互換は極力保つ・人数は10人から最終100人規模・期間は設けない・見るのは全体のバランスとプレイ感、と裁定された。

既存資産: Steamworks.NET同梱（app 1958160、`SteamManager`）、macOS向けRelease固定ビルドメニュー（ADR 0036）、gamescom展示のA4プレイガイド（日英独）、バグ報告システムの設計（ADR 0057、plan A/B/C は未実装）、Mac miniの cloudflared / Hermes / 内蔵cron。無いもの: Windows向けRelease固定入口、Steamへのアップロード経路、配布版からの報告経路、テレメトリ、セーブ互換コード、Windows検証機の自動運転。

## Decision

- **配布版（Steamテスター）も報告の送り手に加える。受け口は Cloudflare Worker + R2 で、ゲーム本体が直接アップロードする。Mac mini の inbox 監視は R2 の定期ポーリング取り込みに変わり、それ以降（自動修正ラン）は ADR 0057 のまま。開発者本人の Tailscale rsync 経路は残す。**
  出所: ユーザー裁定 2026-09-13 原文「報告経路 →報告UIを作る」「http受付口を作るとして、もっと安定した口はない？CFとか」→ 選択「Cloudflare Worker + R2」（[[2026-09-13-プレイテスト報告の受け口はCloudflare Worker+R2としMac miniは取り込むだけにする]]）
  棄却案: Worker+R2 に加え Mac mini へ Webhook 即時通知／Mac mini 直受け（cloudflared経由）

- **受け口の認証は Steam の Web API 用認証チケットを Worker が Steam Web API で検証する。報告・進行記録には SteamID を付ける。Steam未起動の自作ビルドからは送れないので開発者は rsync 経路を使う。**
  出所: ユーザー裁定 2026-09-13 質問「R2受け口の認証と、報告へのテスター識別はどうしますか？」→ 選択「Steam認証チケットをWorkerがSteam Web APIで検証し、SteamIDを報告に付ける」（[[2026-09-13-報告受け口はSteam認証チケットをWorkerで検証しSteamIDを報告に付ける]]）
  棄却案: ビルド焼き込みの共有トークン＋インストールごとのランダムID／検証はするが報告にはハッシュだけ

- **テスターのバンドルは開発者版と同じ中身（スナップショットリング・パケットログ・120秒録画・Unityログ・スクショ・説明文）。未コミット差分の代わりにビルド時の BuildInfo（コミット・master dataピン・Steamビルド識別）を入れる。Windows配布ビルドに ffmpeg.exe を同梱する。**
  出所: ユーザー裁定 2026-09-13 質問「テスターからの報告バンドルは、開発者向け（ADR 0057）と同じ中身にしますか？」→ 選択「同じ中身。リポジトリ差分だけ BuildInfo に置き換える」（[[2026-09-13-テスター報告バンドルは開発者版と同じ中身で差分だけBuildInfoに置き換える]]）
  棄却案: 動画を外す／説明文＋スクショ＋セーブ＋ログの軽量版

- **ポーズメニューの報告UIに種別（バグ／感想）を足し、どちらも同じバンドルを送る。自動修正ランはバグ種別だけ起動する。感想は人間が読む。用語は「プレイ報告」を上位語にし、その下に「バグ報告」「感想」を置く。**
  出所: ユーザー裁定 2026-09-13 原文「何を見るか　ゲーム全体的なバランス、プレイ感等」→ 質問「バランス・プレイ感の感想は、バグ報告と同じポーズメニューのUIで受けますか？」→ 選択「同じUIで「バグ／感想」の種別を選ばせる」（[[2026-09-13-感想もポーズメニューの報告UIで受け種別バグと感想を選ばせる]]）
  棄却案: ゲーム内はバグ専用で感想はDiscord等／種別なし自由記述のみ

- **クラッシュ・フリーズ・起動失敗は、次回起動時に前回正常終了マーカーの欠落で検知し、タイトルで説明欄付きの送信確認を出す。送るのは前回のスナップショットリング・パケットログ・録画リングの残骸・Player.log・クラッシュダンプ。常時記録のリングは終了時に消さず次回起動まで残す。起動自体ができない場合は Player.log の場所を手順書に書く。**
  出所: ユーザー裁定 2026-09-13 質問「クラッシュ・フリーズ・起動失敗の報告はどう扱いますか？」→ 選択「次回起動時に前回の異常終了を検知し、前回の記録を送るか聞く」（[[2026-09-13-クラッシュは次回起動時に前回の異常終了を検知し記録を送るか聞く]]）
  棄却案: 確認なしで自動送信／初版は手動報告のみでクラッシュはPlayer.logをDiscordでもらう

- **報告操作とは別に、セッション終了時（送れなければ次回起動時）に進行記録を同じ受け口へ送る。内容はセッションサマリ（プレイ時間・到達チャレンジ/研究・設置ブロック数・クラフト数・終了時の画面/UI）と、プレイ中のイベント列（研究完了・チャレンジ達成・UI開閉・ビルドモードキャンセル等、時刻付き）。ワールドも録画も送らない。**
  出所: ユーザー裁定 2026-09-13 質問「報告操作とは別に、プレイ状況を自動収集しますか？」→ 選択「セッションサマリに加えてプレイ中のイベント列も送る」（[[2026-09-13-プレイ状況はセッションサマリとイベント列を自動送信する]]）
  棄却案: セッションサマリだけ／自動収集なし

- **取り込んだ報告・進行記録は moorestech_logs へ保存し、Hermes内蔵cronが1日1回、新着の感想全文・進行記録の集計（人数・平均プレイ時間・到達段階分布・離脱地点上位）・自動修正ランのdraft PR一覧をDiscordへ投稿する。ダッシュボードは作らない。**
  出所: ユーザー裁定 2026-09-13 質問「感想・テレメトリ・自動修正ランの結果を、人間はどこで読みますか？」→ 選択「Mac miniが取り込み時に集計し、日次ダイジェストをHermes経由でDiscordへ投稿」（[[2026-09-13-感想とテレメトリは日次ダイジェストをHermes経由でDiscordへ投稿して読む]]）
  棄却案: tar-atari.com配下に閲覧サイト／集計せずmoorestech_logsを直接読む

- **セーブ互換はゲーム内のロード時マイグレーション連鎖で保つ。worldVersion を上げる形式変更ごとに V(n)→V(n+1) の変換ステップをコードに足し、ロード時に順に適用する。開発規約「旧セーブ互換不要・ファイルを手変換」は反転し、形式変更PRはマイグレーションステップとテストを同梱する。**
  出所: ユーザー裁定 2026-09-13 原文「セーブ互換 極力保つ」→ 質問「テスターのセーブ互換を「極力保つ」仕組みはどれにしますか？」→ 選択「ゲーム内のロード時マイグレーション連鎖を導入」（[[2026-09-13-テスターのセーブ互換はゲーム内ロード時マイグレーション連鎖で保つ]]）
  棄却案: 互換コードを書かず壊れるビルドでは作り直しを告知／Mac mini側で変換

- **マスタに無いブロック・アイテム・研究ノードはロード時に除去してワールドを続行し、除去件数をプレイヤーへ一度知らせ、理由をログとバンドルに残す。除去したデータと、コード側マイグレーション前の元セーブは世代付きでセーブと並べて保持し、後から置換・返金のマイグレーションを足したとき遡って適用できる形にする。レシピ・コスト改変は何もしない。**
  出所: ユーザー裁定 2026-09-13 質問「マスタデータ変更に対してテスターの既存ワールドはどう扱いますか？」→ 原文「ベース1にしつつ、将来的なものも含めてマイグレーション前を保持するようなやり方が良い」→ 復唱確認「その読みで合っている」（[[2026-09-13-マスタ削除はロード時除去で続行し除去データとマイグレーション前セーブを保持する]]）
  棄却案: マスタ変更ごとに置換・返金のマイグレーションを書く／マスタの破壊的変更は作り直しを告知

- **Steam配布は app 1958160 のパスワード付きベータブランチ＋キー配布。「選定した人だけ」はキーを渡す運用で担う。更新はSteamの自動配信。**
  出所: ユーザー裁定 2026-09-13 原文「経路 Steamキー」→ 質問「Steamでの配布形はどれにしますか？」→ 選択「本体appのパスワード付きベータブランチ＋キー配布」（[[2026-09-13-Steam配布は本体appのパスワード付きベータブランチとキー配布で行う]]）
  棄却案: Steam Playtest（別app）／defaultブランチへ直接

- **配布ビルドは Mac mini がコマンド1つで、masterの指定コミットから使い捨てworktreeを切り、Release固定のWindowsビルド入口（ADR 0036のMac版と同型を新設）をbatchmodeで焼き、BuildInfoを焼き込み、steamcmdでベータブランチへ上げる。Steam資格情報はMac miniの封じ込めenvに置く。起動は手動コマンド。**
  出所: ユーザー裁定 2026-09-13 質問「Windows配布ビルドの生成とSteamベータブランチへのアップロードはどこで行いますか？」→ 選択「Mac miniがコマンド1つでビルド→steamcmdアップロードまで無人で行う」（[[2026-09-13-配布ビルドはMac miniがコマンド1つでビルドからsteamcmdアップロードまで無人で行う]]）
  棄却案: 開発機のMacでGUIメニューからビルド／GitHub Actionsに非公開assetsのdeploy key

- **配布前検証は既存の自宅Windows PC（Tailscale接続済み・常時起動ではない）で行う。アップロード後にSteamクライアントでベータブランチを更新し、起動→新規ワールド→チュートリアル開始→セーブ→終了→ロード→報告送信の通しをプレイテストDSLで自動実行し、合格したビルドだけテスターへ告知する。**
  出所: ユーザー裁定 2026-09-13 質問「配布前のWindows実機検証はどう行いますか？」→ 選択「Windows PCを1台用意しTailscaleに入れ、Mac miniから起動検証を回す」＋原文「自宅PCがある。それでいい。tailscaleも通している。今は起動してないが」（[[2026-09-13-配布前のWindows検証は自宅PCをTailscale経由でMac miniから回す]]）
  棄却案: 手元のWindows機で手動確認／最初のテスター数人を先行ブランチの検証役にする

- **初回配布のゲートは上記の通し検証だけ。gamescomの導線問題・P1は既知バグ一覧としてテスターへ渡し、優先度は報告と進行記録で決める。**
  出所: ユーザー裁定 2026-09-13 質問「最初の10人に渡す前に、既知の問題をどこまで直しますか？」→ 選択「通し検証が通ることだけ。既知バグはリストにして渡す」（[[2026-09-13-初回配布のゲートは通し検証だけとし既知バグは一覧で渡す]]）
  棄却案: 通し検証＋チュートリアル導線修正のマージまで／通し検証＋gamescomのバグ項目を全部潰す

- **テスター向け文言（報告UI・クラッシュ送信確認・トースト・手順書・既知バグ一覧）は日本語・英語・ドイツ語で用意する。**
  出所: ユーザー裁定 2026-09-13 質問「テスター向け文言はどの言語を必須にしますか？」→ 選択「日英独すべて」（[[2026-09-13-テスター向け文言は日英独すべて必須とする]]）
  棄却案: 日本語と英語／日本語のみ

- **人数の増やし方は10人から段階的に100人規模へ。ラウンド期間は設けない。テスターは全員が新規ワールドから通常進行する（中盤以降の用意済みワールドは配らない）。**
  出所: ユーザー裁定 2026-09-13 原文「人数 最初は10人程度、徐々に増え、最終的には100人規模 期間→ひとまず設けない。」／質問「テスターにはどの状態から遊んでもらいますか？」→ 選択「全員が新規ワールドから通常進行」
  棄却案: 担当を分け新規開始と中盤以降の用意済みワールドを並行評価／各自が開始地点を自由に選ぶ

- **報告ごとの添付選択は設けない。同意はキー配布時の案内と初回起動時の表示で包括的に取る。進行記録の自動送信は参加条件とし、断る設定トグルは作らない。**
  出所: ユーザー裁定 2026-09-13 質問「報告ごとに添付を外せるようにしますか？」→ 選択「外せない。参加時の包括同意で一式送る」（[[2026-09-13-報告の添付は外せず参加時の包括同意で一式送る]]）／質問「進行記録の自動送信を断ってもプレイできますか？」→ 選択「参加条件にする。断る選択肢は作らない」（[[2026-09-13-進行記録の自動送信は参加条件とし断る選択肢を作らない]]）
  棄却案: 録画だけチェックで外せる／設定でオフにできる（既定オン）

- **起動時に受け口のWorkerが持つ許可SteamID一覧と照合し、不許可なら タイトルで止める。Workerに届かないときも止める（オンライン必須）。止めた理由はタイトルに表示しログに残す。**
  出所: ユーザー裁定 2026-09-13 質問「起動時にも承認済み本人かを照合し、個別に参加停止できる必要はありますか？」→ 選択「必要。起動時にWorkerの許可リストでSteamIDを照合する」（[[2026-09-13-起動時にWorkerの許可リストでSteamIDを照合し個別に参加停止できるようにする]]）／質問「Workerに届かないときは？」→ 選択「届かなければタイトルで止める（オンライン必須）」（[[2026-09-13-起動時照合はオンライン必須でWorkerに届かなければタイトルで止める]]）
  棄却案: 照合不要でキーとパスワードの配布管理で十分／前回の照合結果で通す／照合なしで通す

- **テスターからのバグ報告は自動修正ランへ自動投入しない。取り込みは moorestech_logs への保存までで止め、日次ダイジェストを見て人が手動コマンドで plan C の inbox へ投入する。ADR 0057 の inbox 監視→自動ランは開発者本人の rsync 経路にだけ残る。**
  出所: ユーザー裁定 2026-09-13 質問「テスターのバグ報告は、ADR 0057どおり取り込み即自動修正ランに投入しますか？」→ 選択「自動投入はしない。日次ダイジェストを見て人が選んで投入」（[[2026-09-13-テスター報告は自動投入せず日次ダイジェストを見て人が自動修正ランへ投入する]]）
  棄却案: 全件自動投入し類似はラン内で既存PRへ寄せる／自動投入だが1日の上限件数

- **Windows の CEF raw input 奪取の応急処置は配布ビルドに入れない。通し検証に「マウスで視点回転しつつWebUIを開閉」を含め、再現したら既知バグ一覧に載せて別タスクで根治する。**
  出所: ユーザー裁定 2026-09-13 質問「CEF raw input奪取の応急処置を配布ビルドでどうしますか？」→ 選択「応急処置は入れず、検証機の通し検証で実害を確かめてから決める」（[[2026-09-13-CEF raw input応急処置は入れず検証機の通し検証で実害を確かめてから決める]]）
  棄却案: 応急処置をmasterへ取り込んでから配布／根治を初回配布のゲートに入れる

- **メインメニューの開発者向け操作（ConnectServer・SetPlayerId・ResetAllData 等）は本ADRの範囲で隠さない。メインメニューの作り変えを別タスクとして起票し、別の設計インタビューで決める。**
  出所: ユーザー裁定 2026-09-13 原文「メインメニューをちゃんと作り変える。そのあたりの機能は別途検討する」（[[2026-09-13-配布ビルドのメインメニューは作り変え開発者向け操作は別途検討する]]）
  棄却案: 配布ビルドでは非表示／そのまま出す／ResetAllDataだけ残す

- **Steam Cloud 同期は有効化しない（セーブはローカルのみ）。配布ビルドでの通し検証はプレイテストDSL（Editor専用アセンブリ）では成立しないため、既存の Player 自動運転前例（`Client.Starter/StandaloneQa`）と同型の起動引数駆動で同じ手順を通す。**
  出所: agent前提（Steam Cloud は比較採点で挙がった取りこぼし。DSL 非成立は plan E 起草時の調査結果: `Client.Playtest.asmdef` が Editor 限定）

- **運用事項として未裁定（作るものが変わらないため本ADRでは決めない）: テスターへの事前説明の程度、マイグレーションで扱えない更新が出たときの配布判断、更新を全員同時に届けるか段階配信か、テスターによる配信・公開の可否、増員の判断基準。**
  出所: ユーザー裁定 2026-09-13 原文「別に今検討する事項じゃなくない？」（事前説明の質問に対して）。他4件はagent前提で同じ基準により保留

- **R2からMac miniへの取り込みは定期ポーリングで moorestech_logs への保存までを行い、自動修正ランへの投入は人の手動コマンドに限る（上の裁定）。ランは直列のまま。**
  出所: agent前提（受け口裁定と自動投入しない裁定からの帰結）

- **進行記録のイベント列はサーバー既存状態の変化通知（研究完了・チャレンジ達成）とクライアントのUIステート遷移から購読で取り、`Update()` 内の判定は足さない。**
  出所: agent前提（moorestech-principles「状態変化の検知は購読で」）

- **Windows検証機の電源投入は Wake-on-LAN を工程に含め、起こせなければ検証失敗として告知しない。**
  出所: agent前提（原文「今は起動してないが」への対応）

## Consequences

- ADR 0057 の送り手・運搬・クラッシュ対象外の3裁定が改訂される。plan A/B/C は実装前なので本ADRを織り込んで計画し直す（受け口・BuildInfo・種別・クラッシュ検知・進行記録）。
- 開発規約「旧セーブ互換不要」が反転する。moorestech-save-migration スキルは「テスター配布前の一度きり変換」から「マイグレーションステップの書き方」へ役割が変わる。AGENTS.md への規約追記が要る。
- Windows配布ビルドに ffmpeg.exe が同梱される（ライセンス表記が必要）。
- Cloudflare アカウントに Worker と R2 バケットが増え、Steam Web API の publisher key を Worker secret として管理する。
- Mac mini に steamcmd と Steam ビルド資格情報が置かれる。
- テスターのセーブに除去データと世代付き元セーブが並ぶため、セーブディレクトリの容量が増える。
