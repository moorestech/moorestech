# 地形生成システムの外に出るのは結果だけ（見た目はクライアントが同じロジックで焼く）

地形の見た目（スプラット・surround・草detail）は **転送せず**、生成ロジックを `Game.MapGeneration`（生成システム）に閉じ、クライアントはそのファサードを呼んで手元で焼く。生成システムの外が触れるのは生成の**結果**だけで、実際に生成したのか固定値（template）を返しただけなのか、外は知り得ない。

ADR-0012 は同じ目標（生成はサーバーに閉じる）を「焼いた見た目データをチャンク配信する」で達成しようとしたが、コスト欄の見積もり（512²×8層≒50MB）は誤りで、実データは `resolutionPreset=_2048`・alphamap 19層・detail 24枚＝**1タイル281MB・25タイル6.6GB（gzip後でも約430MB）**。転送で閉じる線は捨て、**コードの所有権（アセンブリ境界）で閉じる**線に差し替える。

## 境界の定義

- **外に出る結果（全量）**: 表示用高さの2次元マップ／どのテクスチャがどの重みで塗られるかの2次元マップ＋テクスチャ並び（アドレス列）／detail 密度マップ＋プロトタイプ並び／mapObject（GUID＋Transform）／鉱脈（AABB）／スポーン地点／メタ情報（ワールド同一性。外は解釈せず生成システムへ戻すだけ）／将来枠: mapObject にならない木・岩（Unity Terrain tree 想定、現状は存在せず枠のみ）
- **外に出ないもの**: バイオーム（index も型も）・岩クラスタ・分類重み・ノイズ窓原点の意味・generate系フラグ・TerrainGenerationConfig・キャッシュの鍵と形式・木摂動の幅/量・距離場
- クライアントから `Game.MapGeneration.Pipeline.*` の using を全廃し、参照してよいのはファサードと結果型（と転送路 `Transfer`）だけ
- template（オーサリング済み地形）も同じファサードの裏に置き、結果型の種別（配列か、アセットのアドレス＋原点か）で外が受ける

## 帰結

- 岩クラスタ（ClusterId/ClusterCenter）は配置器の内部に閉じ、`PlacedMapObject`・map.json 必須3キー・`MapObjectLayoutMessagePack` Key 8〜10・クライアント消費の4段すべてを削除する。クライアントは配置ステージまで含めて同じコード・同じパラメータ・同じ seed で回し、クラスタ重心 surround は内部で塗る（決定論で同じ結果になる）
- `biome_x_z.bin` は中間値なので転送もファイル出力も廃止。永続・転送される地形バイナリは高さのみ
- `terrainSurroundEffectType`（map.yml）は配置器が出自を知っているため不要になり、`MapObjectKindSplitter` ごと削除（裁定 2026-08-18 のとおり）
- 高さの転送（TerrainChunk＋SHA256）は維持する。高さは mapObject の Y・スポーンの正本で、Burst の浮動小数差を許せない。見た目は許せる
- 見た目・高さのディスクキャッシュは生成システム内部の共有基盤として残す。ヒットの有無は外から不可視。同一PCでサーバーとクライアントを起動する場合、サーバー生成分のキャッシュをクライアントが再利用できるようワールド同一性で引く
- `generateTexture/generateDetail` は削除せず `generateObject/generateOre` と同じパイプラインのステージ有効化フラグとして内側に残す
- 移設は見た目を1ピクセルも変えない。完了条件は「同一 seed で移設前後の alphamap・detail・表示高さがバイト同値」

## 決定論の留保（agent前提）

分類段は Burst の浮動小数なので CPU 世代差で末尾ビットが揺れ、境界画素の勝者が1px変わって配置の採否が1個ずれる可能性は理論上ある。起きても「裸地があるのに岩が無い」程度の見た目限定の不整合で、高さのようにゲームプレイに効かないため許容する。

## 出所

- 「データの送信はしないが、ロジックはサーバー側においておく（前はクライアントにおいてしまって変なことになっていた）」: ユーザー裁定 2026-08-21
- 「サーバーとクライアントで同じコード、同じパラメーター、同じseedで生成しているんだったら、決定論的になるからすべてを生成ロジックの中に収めても転送なしで同じ結果を得られるでしょ？」: ユーザー裁定 2026-08-21（クラスタ内部化）
- 「生成ロジックの内容、ドメインを生成システムの外に出さないで。生成システムの外が触るのは生成した結果だけ。だから、生成システムが実際に生成を行うか、それとも固定者を返すだけなのか、精製の外は知り得ない」: ユーザー裁定 2026-08-21（境界定義）
- 「バイオームindexはいらなくない？高さ、どのタイルにどのテクスチャが塗られるべきかを決める2次元マップ、mapobject、鉱脈、スポーン地点、メタ情報、detailの配置、mapObjectにならないTreeや岩等 この辺だけが外にでるべきじゃない？」「biome_x_z.bin ←だとしたらこれって送る必要なくない？」: ユーザー裁定 2026-08-21（結果の全量・biome廃止）
- 「生成システム内部に共通基盤として残す。生成システムを使う側は、キャッシュヒットしたかどうかは知り得ない。これにより、同じPCでサーバーとクライアント両方起動する場合、サーバーで生成したキャッシュをクライアント側で利用することが出来る」: ユーザー裁定 2026-08-21（キャッシュ）
- 高さ転送維持・草 parity の別タスク化: ユーザー裁定 2026-08-21（AskUserQuestion で推奨案を採択）
- template を同じファサード裏に置く・generate系フラグ温存・GeneratorVersion bump・バイト同値の完了条件・決定論の留保: agent前提（ユーザーは「進めてよい」で黙認。裁定ではない）
