# ベルト接続をedge単位で解き、ワールド更新の前後差分を反映する

## 決定

物理的な水平edgeを共有する4voxelを判定単位にする。edgeに接しないベルトは候補に含めず、左右の各列で上側の接触ベルトを先に選ぶ。その後、選んだペアの出力・入力方向とコネクタ形状を評価する。山(Up→Down)・谷(Down→Up)は接続しない。不成立でも下側へ候補を戻さない。各edgeの結果は有向接続0本または1本。

出所: ユーザー裁定 2026-09-30「上にあるコンベアが基本優先となります。edgeに接しないマスは空と同義となります。右上ななめと左下斜めは接続しません」、続く画像確認「ok」。承認済み画像の具体的な接続結果（7状態2401配置、画像repo belt-edge-patterns-20260930 commit c94c979）は、上側選択後に下側へ戻らない境界例も含む。選択順とfallbackの扱いはこの承認済み期待結果に基づく。

平行ベルトは底面4edge、斜めベルトは高低2端点edgeを更新する。ブロック変更前後の判定結果を送出ブロック・送出ポート・受入ブロック・受入ポートで比較し、古い接続を解除して新しい接続を設定する。変更したブロック以外の送出側も更新する。設置・撤去・ロードはWorldBlockDatastoreの更新に明示的に連動させる。

出所: ユーザー裁定 2026-09-30「ok -> okでも相手が変わることもあります。その場合に_connectedTargetsをいじることになります」「平行コンベアのonplaceのときは4つのedgeが、斜めなら2つのedge」「はい、それで実装してもらっていい？」。

World更新から明示的に駆動する方向はD6のユーザー提案と実装承認に基づく。ロードも同じ変更境界へ通す具体策は、既存LoadBlockDataListがTryAddBlockを使う前例からの実装判断であり、ユーザー発言の直接引用ではない。

PR1134のTConnectContext/GetOverrideの役割（周辺を調べ、自己と相手以外の接続変更も返せる）を実装の出発点にする。汎用コネクターは接続適用を担い、ベルト幾何・優先順位は具体のinventory contextに置く。ワールドは汎用ライフサイクル契約経由で駆動し、Game.Blockへの参照を増やさない。

出所: ユーザー裁定 2026-09-30「これをもとにベルコン接続判定をやっていく必要があります。これは依頼者の決定です」「GetOverride() が肝になるのはそうです。ようは自分相手だけじゃなくて、それ以外にも接続を解除する必要があるってことです」。層分割の具体はagent前提（Game.World.asmdefの既存依存方向、moores-reviewer-digest）。

水平姿勢（North/East/South/West）のベルトだけが共有edgeを持つ。真上・真下姿勢（Up*/Down*）のベルト間接続は成立させず、除外理由を開発者ログへ記録する。対象分類は全姿勢で維持し、機械との接続は既存のコネクタ判定に従う。

出所: ユーザー裁定 2026-09-30 D12「真上・真下姿勢はベルト間接続を成立させない」。空edgeリストでこの仕様を表すこととログ位置は実装判断。

## 範囲

ベルトの接続だけを変更する。機械とコンベアの接続・機械同士の接続は既存の判定を維持する。segment搬送・フィルタ・速度・セーブ形式は変更しない。通常・高速・歯車ベルトと分岐器に同じ物理ルールを適用し、水平ベルトの側面は既存の入力/出力コネクター方向で評価する。出所: ユーザー裁定2026-09-30「全種類・分岐器にも共通で適用」。

出所: ユーザー裁定 2026-09-30「接続パターンのみの全部の実装」「機械とコンベアの接続はあとで考えるので大きくかえないで」。手前/奥の質問に続く裁定「とにかくedgeを中心に考えます」「受け取る側のコンベアが適切な方向を向いている」。

## 前例と帰結

既存BlockConnectorComponentは出力先のplace/removeイベントを購読するが、remove通知はワールド削除前なので、その時点での再判定では下側への復帰を解けない。IPostBlockLoadのようにWorldがinterfaceを通してcomponentを明示駆動する既存方式に沿い、変更前の情報取得と変更後の反映を組にする。機械や歯車の既存イベント購読は維持する。ctorではselfをワールドから解決しない。
