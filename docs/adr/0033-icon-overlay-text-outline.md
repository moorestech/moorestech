# 0033. アイコンに重なるテキストは反対色の縁で浮かせる

日付: 2026-08-25
状態: 採択

## Context

黒っぽいアイテムアイコンの上で個数バッジが沈み、数量が読めないことがある。

`ItemSlot` の個数バッジは `--count-text: #111`（黒）で、これは2026-08-17のユーザー裁定「バッジが出るのは**明色面のみが前提**」として一元化された値である（`app/tokens.css:361`）。アイコン自体が暗い場合はこの前提が成り立たず、黒い数字が黒い絵の上に載る。

現状、アイコンに重なるテキストは5系統あり、縁取りの様式が3通りに割れている:

| 箇所 | 文字色 | 現状の縁 |
| --- | --- | --- |
| `shared/ui/ItemSlot/style.module.css:23` `.count`（個数） | 黒 | 4方向 `text-shadow` 白 0.25px / 75% |
| `features/recipe/views/RecipeBox.module.css:83` `.materialCount`（所持/必要） | 黒 | 1方向ぼかし影 `0 1px 2px` 白 |
| `features/research/style.module.css:111` `.consumeCount`（消費数） | 黒 | 1方向ぼかし影 `0 1px 2px` 白 |
| `shared/ui/FluidSlot/style.module.css:36` `.amount`（液体量） | 白 | 1方向ぼかし影 `0 1px 2px` 黒 |
| `features/hotbar/HotbarPanel/style.module.css:93` `.num`（キー番号） | 白 | 4方向 `text-shadow` 黒 0.3px / 80% |

`ItemSlot .count` は個数バッジの正本で、呼び出し側は `--count-bottom` / `--count-font-size` / `--count-letter-spacing` の3変数だけで調整している（`ItemSlot` を使う約20箇所はすべてこのバッジを継承する）。一方で残り4系統は各featureに個別実装されており、縁の手法も太さも揃っていない。

uGUI 側（`CommonSlotView` + `ItemSlotView.prefab` の TMP Outline マテリアル）は2026-08-17裁定で恒久停止済みのため対象外。

## Decision

- **アイコンに重なるテキストは、文字色の反対色の縁で浮かせる。** 黒文字には白縁、白文字には黒縁を付け、**太さは全系統で1つに揃える**。文字色自体は現状維持（`--count-text: #111` と白文字系はそのまま）。対象は上表の5系統すべて。
  出所: ユーザー裁定 2026-08-25 原文「黒っぽいアイコンだと数量と重なって見えないことがあるから、アイコン全体のテキストに白縁をつけて視認性を向上させる」→ 選択「アイコンに重なる全テキストを白縁へ統一」＋「白文字系は白縁ではなく黒縁を太くする」（`.decisions/2026-08-25-アイコンに重なる全テキストへ反対色の縁を付ける.md`）
- **縁は `-webkit-text-stroke` ＋ `paint-order: stroke fill` の真のストロークで描く。** 太さは固定長トークン1本、色は白縁用・黒縁用の2本。既存の4方向 `text-shadow` と1方向ぼかし影はすべて撤去してこれへ置き換える。
  出所: ユーザー裁定 2026-08-25「それで進める（推奨）」（`.decisions/2026-08-25-アイコンテキストの縁は真のストロークで実装する.md`）
- **縁の様式は1宣言に畳んで5箇所が共有する。** 各featureのCSSは位置決めと文字色だけを持つ（前例: `:where(.keyHintText)` が3画面のキーヒント文字様式を1宣言で共有している）。
  出所: agent前提（前例 `keyHintText` の共有宣言）
- **太さはまず一律1トークンで実装し、実画面で小さい文字（11px系）が潰れていた場合にのみ小字用トークンを足す。** 先に場合分けを発明しない。
  出所: agent前提（ユーザー「CSSよくわかんないからそこら辺もう全部いい感じにしておいて」により委任。webui-design §「視覚寸法は固定長トークンが既定・比例指定は破綻源」に従い `em` 比例指定は採らない）
- **uGUI（`CommonSlotView` / `ItemSlotView.prefab` の TMP Outline）は触らない。**
  出所: agent前提（2026-08-17裁定「uGUI移植を終了しWeb UIは独自調整へ移る」）

## Consequences

- 縁の様式が3通り→1通りになり、以後アイコン上へ文字を足すときは共有宣言を当てるだけになる。
- 白文字系（Hotbarキー番号・液体量）は黒縁が太くなるため、現状より輪郭がはっきりする。文字色が変わらないので明色面での読みは悪化しない。
- 個数バッジはスロット下端から実測5pxはみ出しており、`--item-list-count-bleed: 5px` で溢れを吸収している（2026-08-17裁定の追補）。縁が太くなるとはみ出し量が増えるため、アイテム一覧のスクロール溢れが再発しないことを実測で確認する必要がある。
- 縁の見た目を固定する既存テストは無い（`ItemSlot/index.test.ts` はバッジの有無のみ、`e2e/tests/challenge/hudLayout.spec.ts` の `text-shadow` 断言は対象外のチャレンジHUD）。
- `webui-design` スキルはホワイトリストであるため、新しい縁の様式を SKILL.md へ追記してから実装する。
