# 0032. 操作ヒントの正はUIStateが持ち、Web UIの左下HUDへtopicで配る

日付: 2026-08-23
状態: 採択

## Context

画面左下の操作説明は uGUI 時代の `KeyControlDescription` が担っていた。各 `IUIState` の `OnEnter` で改行区切りの生文字列を `SetText` する方式で、10 stateぶんがハードコードされている。uGUI廃止Phase1（`WebUiScreenGate.IsWebUiMode => true` 固定）以降このビューは恒久非表示となり、Web UI 側には代替が用意されなかった。

その結果:

- **ゲーム画面・配置モード・破壊モード・ビルドメニュー・チャレンジ一覧・ポーズ・デバッグには操作説明が一切表示されない。** 左下ヒントが実在するのは `InventoryScreenChrome.tsx` と `ResearchScreenChrome.tsx` の2画面だけで、いずれもTSX内にキーと文言をハードコードしている。
- 表示されなくなった uGUI 文字列は腐った: `PlayerInventoryState` は `Tab/ECS`（ESCの誤記）、`PlaceBlockState` は「Q: 設置高さ上げる / E: ブロック高さ下げる」と実装（Q=`--`／E=`++`）に対して上下が逆、`ResearchTreeState` は `SetText` 自体が無く前画面の文字列が残る。

実プレイ（PlayMode録画・`scenarios/misc/ui-state-transition-matrix.cs`）で遷移18ケースを検証した結果、`PlayerInventory + R → ResearchTree` を含め**全ケースPASS**。壊れているのは遷移ロジックではなく表記だけであることが確定している。

腐った原因は構造的で、「遷移を判定する `if` を書く場所」と「その遷移を告知する文言を持つ場所」が離れていたことにある。

## Decision

- **操作ヒントのSSOTは各 `IUIState` 実装（C#）に置く。** 各stateがキー名＋翻訳キーの一覧を宣言し、`UiStateTopic` 経由でWeb UIへ配る。Web UIは受け取った配列を描画するだけで、画面名からヒント内容を再導出しない。遷移判定の `if` とヒント宣言が同一ファイルに並ぶため、遷移を触ればヒントも視界に入る。
  出所: ユーザー裁定 2026-08-23 原文「常に左下に出てる操作方法の表記が全体的に正しくなかったりヌケモレがある感じだから調べて補正したい」→ 選択「C#のUIStateが宣言しtopicで配る」（`.decisions/2026-08-23-操作ヒントの正はC#のUIStateに置きtopicで配る.md`）
- **その画面の対象項目は全部、左下へ常時積む**（ゲーム画面で行数が増えても畳まない）。
  出所: ユーザー裁定 2026-08-23「基本1, T,Eは出さない」（`.decisions/2026-08-23-操作ヒントは全項目を左下に常時積む.md`）
- **自明な操作は載せない。** 移動系（WASD / Space / Shift）・左クリックの主行為（採掘・設置）・**ESCは全画面で一切載せない**・デバッグ向けキー（F3 / Ctrl+U / F1・F2）を除外する。ESC除外の結果、ポーズメニューは左下ヒントごと空になる。
  出所: ユーザー裁定 2026-08-23「WASD space shift クリック ESC不要。」／「全画面で一切載せない」（`.decisions/2026-08-23-操作ヒントは自明な操作を載せない.md`）
- **T（チャレンジ一覧）は載せない**（機能停止中）。**E（列車に乗る）も左下には載せない**（列車接近時の専用HUDへ回す。そのHUDは今回スコープ外・`moorestech-*` で別タスク化）。
  出所: ユーザー裁定 2026-08-23「Tは現在機能を停止しているため今出さない。列車は列車が近づいた時にHUDで出す（今後対応」
- **配置モードのQ/Eは実装（Q=下げる／E=上げる）を正とし、腐った文言の側を直す。** キー割当は変更しない。
  出所: ユーザー裁定 2026-08-23「実装が正。表記をQ=下げる/E=上げるへ直す」（`.decisions/2026-08-23-配置モードのQEは実装を正としヒント表記を直す.md`）
- **インベントリ系画面ではアイテム操作も載せる**（Shift+左クリック 一括移動／右クリック 半分取る・1個置く／左ドラッグ 均等分配／ダブルクリック かき集め）。修飾キー・右クリック・ドラッグ・ダブルクリックは「知らないと辿り着けない操作」で、自明除外基準に当たらない。
  出所: ユーザー裁定 2026-08-23「載せる」（`.decisions/2026-08-23-インベントリのアイテム操作もヒントに載せる.md`）
- **列車乗車中の操作説明は列車HUD内の1行（`ui.trainHud.controls`）をやめ、左下ヒントへ統合する。** 列車HUDは速度・分岐候補などの状態表示だけを持つ。
  出所: ユーザー裁定 2026-08-23「左下ヒントへ統合する」（`.decisions/2026-08-23-列車操作表示を左下ヒントへ統合する.md`）
- **文言のカッコ表記は「長押し」以外すべて使わない。** 「1~9 建築ショートカット（同キーで解除）」→「1~9 建築ショートカット」、「カーソル解放（三人称のみ）」→「カーソル解放」、「まとめて選択（離して削除）」→「まとめて選択」。「左Alt（長押し）」のカッコだけ残す。**配置モードの `Shift+R 縦回転` は載せない。**
  出所: ユーザー裁定 2026-08-23 原文「長押し以外の文言のカッコ表記はすべて不要。 配置モードシフト＋Rも不要。」
- **uGUI の `KeyControlDescription` は完全削除する**（C#クラス／全10箇所の `SetText` 呼び出し／`MainGameUI.prefab` 上のオブジェクト／`Client.Tests` の生成・WebUiゲート分類ルール）。
  出所: ユーザー裁定 2026-08-23「完全削除する」（`.decisions/2026-08-23-KeyControlDescriptionを完全削除する.md`）
- 既存の `InventoryScreenChrome.tsx` / `ResearchScreenChrome.tsx` のハードコードヒントは新機構へ寄せて削除する（agent前提: SSOT裁定の当然の帰結。2箇所目の正を残さない）。
- 表示位置・文字様式は既存の左下ヒント（`InventoryScreenChrome.module.css` の `.keyHints` と共有の `keyHintText`）をそのまま踏襲する（agent前提: 前例踏襲）。中央下のチュートリアル `KeyControlHintHud`（master由来）は別枠のまま触らない。
- 文言は `Localization/localization.csv` に `ui.keyHint.*` を新設して3言語ぶん持つ（agent前提: 既存 `ui.inventory.closeHint` 等と同型）。
- チャレンジ一覧画面には左下ヒントを置かない（agent前提: Tが機能停止で入口が無いため）。

## Considered Options

- **Web側にuiState→ヒントの静的テーブルを持つ** — 却下: C#に触れず実装は軽いが、遷移判定と文言が再び離れ、今回腐った構造を場所だけ変えて再現する。出所: ユーザー裁定 2026-08-23
- **マスタデータ（JSON）に持つ** — 却下: キー割当の正はコード側にしかなく、正とデータが別repoへ分裂する。出所: ユーザー裁定 2026-08-23
- **既定は折りたたみ、F1で全展開** — 却下: 視界を食わないが、初見が押さなければ何も知れず「抜けを直す」目的に対して露出が下がる。出所: ユーザー裁定 2026-08-23
- **画面ごとに主要4〜5個へ厳選** — 却下: 何を落とすかの判断が入り、目的と正面衝突する。出所: ユーザー裁定 2026-08-23
- **プレイ操作を全部載せる／デバッグキーも載せる／画面遷移だけに絞る** — いずれも却下。出所: ユーザー裁定 2026-08-23
- **ESCはゲーム画面だけ載せない** — 却下: 全画面除外に一本化。出所: ユーザー裁定 2026-08-23
- **旧表記を正として実装をQ=上げる/E=下げるへ反転** — 却下: 体で覚えた操作感が壊れる。出所: ユーザー裁定 2026-08-23
- **インベントリのアイテム操作は載せない** — 却下。出所: ユーザー裁定 2026-08-23
- **列車HUD内の1行のまま残す** — 却下: 操作説明の置き場所が2つに割れる。出所: ユーザー裁定 2026-08-23
- **KeyControlDescription はC#呼び出しだけ消してprefabは残す／今回は触らず放置** — 却下: 前者はMissing ScriptのGameObjectが残り、後者は腐った文字列がリポジトリに残る。出所: ユーザー裁定 2026-08-23

## Consequences

- `IUIState` の契約に「この画面の操作ヒント」が加わる。全10 state（+ TrainHUDのサブstate）が宣言を持つか、明示的に空を返す。
- `UiStateTopic` のペイロード（`UiStateDataSchema`）が拡張され、wire contract テスト（`Client.Tests/WebUi/WireContractTest.cs` と `bridge/contract/wireContract.test.ts`）の更新が必要。
- ポーズメニューは左下ヒントが空になる（ESC全画面除外の帰結）。
- 列車HUDから `ui.trainHud.controls` が消えるため、同キーはlocalization.csvから削除する。
- `MainGameUI.prefab` の変更が入るため、Unity Editor経由（`uloop execute-dynamic-code`）でのオブジェクト削除が必要。テキストエディタでの直接編集は禁止。
- 回帰検証の手段として `scenarios/misc/ui-state-transition-matrix.cs` が残る。ヒント内容の検証もこのシナリオへ足せる。
