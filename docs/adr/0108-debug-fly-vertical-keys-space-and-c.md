# 0108. デバッグ用フライの上下は Space と C にする

日付: 2026-11-28
状態: 採択（ADR 0075 の「Q/E で上下」「Q で下降、E で上昇」を置き換える）

## Context

ADR 0075 ではフライの上下を Q/E にした。Q/E は建築の設置高さ±1・E の列車乗車とも重なり、同時に効いていた。ユーザー依頼 2026-11-28 原文「サクッとフライモードのときの上下をQ,E以外にしたい。ただシフトが被るからどうにかしたい」。

調査で確認した事実:

- 上下は `PlayerFlyModeController.ReadVerticalInput` が `HybridInput.GetKey(KeyCode.E/Q)` を直書きで読んでいる。
- Shift は走り（`InputManager.Player.Sprint`）。トグル式が既定で、Shift 単独の押し離しで走/歩が反転する。フライ中の速度は走り状態で×6/×2。
- Space は `InputManager.Player.Jump`（キーボード space・ゲームパッド buttonSouth）。フライ中はジャンプしない。Space 2連打で解除する。
- C キーはどこにも使われていない。

## Decision

- **上昇は Space を押している間、下降は C を押している間。Q/E ではもう上下しない。Shift は今までどおり走り（フライの高速）。**
  出所: ユーザー裁定 2026-11-28 原文「サクッとフライモードのときの上下をQ,E以外にしたい。ただシフトが被るからどうにかしたい」→ 質問「新しい上下キーはどれにしますか？」→ 回答「下降cで」（提示案 B「上昇=Space／下降=C。Shiftは今のまま走り」）。棄却: 上昇=Space／下降=Shift（[[2026-11-28-フライの上下はSpace上昇C下降でShiftは高速のまま]]）
- **上昇は Jump アクション（Space とゲームパッドの南ボタン）を読む。下降の C はキーボードだけ。** Space と C の同時押しは相殺する。
  出所: agent前提（Space は既に連打判定で Jump アクションを読んでいるので同じ口に揃える。ゲームパッドの下降は今も無いので足さない）
- **Q/E の建築の設置高さ・E の乗車は変えない。** フライが Q/E を読まなくなるため、重なりが消える。
  出所: agent前提（依頼外の既存挙動に手を入れない）

## Consequences

- フライ中に建築しても Q/E で高度が変わらなくなる。
- C を押して下降するとき Shift の走り状態は変わらないので、高速のまま下降できる。
