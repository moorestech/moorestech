# GPU を消し、ICチップをそのまま軌道へ運んで計算データを得る

半導体製造の後の本線は、GPU設計・金属超精密加工の2研究、GPU・GPU衛星の製造、データセンター、GPULv2〜5 の研究を挟んでいた。工程と研究の種類が多いので、GPU に関わるものを丸ごと消し、ICチップをロケットに積めば計算データが出る形に単純化する。[[0095-ground-data-center-consumes-gpu-for-compute-data]] と、GPU衛星を積荷にする部分の [[0091-orbital-arrival-service-shared-by-launch-sites]] を覆す。

## 決定

- **研究の前提を次の形にする。** 半導体製造 →（品質モジュールLv1 から始まるモジュールの枝）／半導体製造 → ロケット技術 →（軌道エレベーターの建設・核融合炉）→ 反物質爆弾 → 最終研究。研究「金属超精密加工」「GPU設計」「GPULv2〜5」を消す。
  出所: ユーザー裁定 2026-11-16 原文「金属超精密加工、GPU設計と、各種GPU関連の研究とアイテムは消したい。GPU関連を消してもっとシンプルな構成にする」「半導体製造 →品質モジュールlv1を起点とするモジュール関連の研究 ↓ ロケット　解放：ロケット関連、計算データ、ICチップを乗せたらそのまま計算データが手に入る ↓ ↘ 軌道エレベーター　核融合 ↓ ↙ 反物質爆弾」
- **アイテム GPULv1〜5・GPU衛星Lv1〜5 と、それらのレシピを消す。**
  出所: 同上の原文「各種GPU関連の研究とアイテムは消したい」
- **金属3Dプリンタは機械ごと消す。** ICチップからコンピュータ・制御モータを作るレシピ2本も消す。
  出所: ユーザー裁定 2026-11-17 選択「機械ごと消す」
- **データセンターを消す。** 計算データを得る手段は、打ち上げ口に ICチップを入れることだけにする。
  出所: ユーザー裁定 2026-11-17 選択「消す (推奨)」
- **積荷は ICチップLv1〜5、1便20個。** 打ち上げ成果の計算データは Lv1:20 / Lv2:40 / Lv3:80 / Lv4:160 / Lv5:320（GPU衛星1機と同じ。ICチップあたりの量は変わらない）。
  出所: ユーザー裁定 2026-11-17 選択「1便20個、今と同じ量 (推奨)」
- **宇宙エレベーター拠点も ICチップを20個ずつ運ぶ。** 筐体素材・燃料・コンピュータが要らない代わりに1回 240 秒かかる役割は変えない。
  出所: ユーザー裁定 2026-11-18 選択「ICチップ20個を運ぶ設備にする (推奨)」
- **品質モジュールLv1 の研究から計算データを外し、品質モジュールLv2 の前提にロケット技術を足す。** Lv2〜5 の計算データ（400 / 4,000 / 40,000 / 400,000）は変えない。
  出所: ユーザー裁定 2026-11-17 選択「Lv1だけ外し、Lv2の前提にロケット (推奨)」
- **消した研究のコストは他へ上乗せしない。** ロケット技術の計算データ200 も外すだけにする（ICチップLv1 2000・鋼鉄板1000・コンピュータ300）。
  出所: ユーザー裁定 2026-11-18 選択「上乗せしない」
- 品質モジュールLv1 の前提は半導体製造、ロケット技術の前提は半導体製造、核融合炉の前提はロケット技術にする。品質モジュールLv3 の前提のロケット技術は、Lv2 で満たすので外す。
  出所: agent前提（原文の図をそのまま前提関係に写した。Lv3 は冗長になる辺の整理）
- ロケット技術の解放物は、ロケット筐体素材・ロケット燃料・ロケット発射台と、計算データのレシピ表示にする。
  出所: agent前提（原文「解放：ロケット関連、計算データ」）
- 昇降機が1回に運ぶ個数を「1個」固定から、積荷表の1便の個数に変える。マスタ検証の「運ぶ積荷は1便1個」を外し、発射台と同じ「1便の個数は Lv1 のスタック上限以下」で足りるものとする。セーブ形式は変えない（昇降中の積荷は個数つきのアイテムとして既に保存している）。
  出所: agent前提（「ICチップ20個を運ぶ設備にする」を実装へ写した。積荷表を両方の打ち上げ口が共有する 0091 の作りを保つ）
- 消したアイテム・ブロック・研究を持つセーブ済みワールドは手当てしない。
  出所: agent前提（[[2026-11-02-旧研究完了とスタック上限超過のワールドは手当てしない]] と同じ扱い）
- **ロード時、昇降中の積荷のうち昇らせない分（運ぶ積荷でない・1便に足りない・1便より多い余り）は、入口 → 出口の空きの順に戻し、どちらにも入らない分は消してロードを続ける。** 退避・消去のたびにアイテムID・個数・理由をエラーログへ出す。ロードを例外で止めることはしない。理由: セーブデータをロードできない状態にするほうが、積荷が消えるより悪い。
  出所: ユーザー裁定 2026-11-18 原文「1で、出口も満杯のときは消す.セーブデータをロードできない状態にするほうがまずい」

## Considered Options

- 金属3Dプリンタを残して半導体製造で解放する／ロケット技術で解放する: ユーザー棄却。
- 1便100個で計算データ5倍／ICチップLv1 だけ積める: ユーザー棄却。
- 品質Lv1 だけ計算データを外し前提は足さない／品質Lv1〜5 の全部から外す: ユーザー棄却。
- データセンターを ICチップを入れる機械として残す: ユーザー棄却。
- 計算データはロケットだけにして拠点は ICチップを運ばない／拠点のブロックも消す: ユーザー棄却。
- 消した分をロケット技術に上乗せ／軌道エレベーターと反物質爆弾に上乗せ: ユーザー棄却。
- 昇降中の積荷を戻せないときはロードを止めたまま手順で避ける／戻せなかった積荷の保持枠を足す: ユーザー棄却（出口へ退避し、無理なら消す）。
