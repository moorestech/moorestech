# 0101: 設置モードのプレビュー専用部品は、描画するプレイヤー半径内だけ有効にする

Status: Accepted
日付: 2026-11-14

## 背景
ADR 0083 決定4 は「半径外でも PreviewOnlyObject の GameObject と面コライダーは有効のまま残し、レンダラーだけを切る」とした。理由は、設置照準が枠の面コライダーに当てて隣接設置を解決していたため。ADR 0099 で面コライダーは `BlockPlacementHitFaces` へ移ったが、これも同じ表示切り替え（`IPreviewOnlyObject`）に乗っていた。ADR 0100 で照準はコライダーを使わず占有セルをたどる形になり、決定4 の理由は無くなった。それでも `BlockPreviewOnlyObjectsView.Apply` は、設置モード中は半径に関係なく全部品を有効にしていた。

ベースラインワールド（15,082ブロック、半径内177ブロック）で、設置モードに入る遷移の中身を測った（実測。`docs/performance/2026-11-14-build-mode-preview-radius-activation/README.md`）。
- 遷移のほぼすべてがプレビュー表示（`PlaceBlockPreviewDisplay.OnEnter`）で、前の画面を閉じる処理・カメラ・状態変更の通知は合わせて 1ms 未満。
- 入ったときに新しく有効になる Transform は、ブロックの向きを示す矢印（`PreviewOnlyObject`）41,059、枠の辺 4,425、歯車の接続線 44。
- 歯車の接続線（`GearConnectorView`）は `SetEnableRenderers(false)` が `SetActive(false)` なので、半径外では「有効にしてすぐ無効に戻す」ことになり、有効化の分（約14ms）が丸ごと無駄だった。
- 本番と同じ部品への指示をスニペットで再現して比べると、今の作り 172.4ms に対し、全部品を半径内だけ有効にして半径外のブロックには何も呼ばない形で 6.5ms。全ブロックをたどる繰り返しそのものは約0.1ms。

## 決定
1. プレビュー専用部品（矢印・搬入出口の線・歯車の接続線・枠の借り口）は、描画する時だけ有効にする。設置モード中はプレイヤー半径内のブロックだけ、デバッグのホバーは半径に関係なく、それ以外は無効。ADR 0083 決定4 を置き換える。
   出所: ユーザー裁定 2026-11-14 原文「じゃあ今のprから派生する形で別のprとして作る形で 別ブランチで進めて」（上の比較を提示したうえで）
   棄却: 矢印だけ半径内にする（43.9ms）／矢印と歯車の線だけ（27.3ms）

2. 表示の切り替えは、部品へ最後に指示した描画状態と同じなら何も呼ばない。半径外で隠れたままのブロックには、設置モードの出入りで指示を出さない。
   出所: agent前提（実測で、隠れたままの部品への指示だけで約13ms かかっていた）

3. 設置アニメーション中の「当たり判定だけ残す」表示モード（`CollidersOnly`）は無くし、アニメーション中は隠す。完了後に半径に従って描画する（ADR 0083 決定5 の後半はそのまま）。
   出所: agent前提（アニメーション中のブロックの横に置くための当たり判定で、照準がコライダーを使わなくなった今は要らない）

4. 半径外の矢印のコライダー（`Block` レイヤー）が無くなることは受け入れる。設置モード中に `Block` レイヤーへ撃つのは中クリックのスポイト（`PlacementTargetPickService`）だけで、半径外ではブロック本体のコライダーに当たり、拾うブロックは変わらない。搬入出口・歯車の線は `Default` レイヤーの線だけでコライダーが無い。
   出所: agent前提（コードの確認による）

## 見込み
設置モードに入る遷移は、ベースラインワールドでプレビュー表示の分が約170ms から約7ms になる見込み（再現の実測。本番の遷移では実装後に測り直す）。出る遷移も、矢印の無効化（約54ms）が無くなる。プレイヤーが動いて半径に出入りした部品を、その都度有効・無効にする負担が移動中に出る（1m 移動ごとの再評価で、チャンク 4m 単位。移動中の負担は実装後に測る）。
