# ADR 0097: ベルトは2クリックで最短経路を探して置く

- Status: Accepted
- Date: 2026-11-06
- Superseded in part by: ADR 0100（探索箱・高さ上限・経路なしの理由分け・C キーは 2026-11-09 に置き換え。該当節の冒頭に注記）
- Related: ADR 0081（ベルトのドラッグ経路は地形を乗り越える・本ADRで廃止）、ADR 0083（合流マスの分岐器モデル）、ADR 0095（向きは水平4方向のみ）
- 参考実装: ParamegaFactory `Road/Djk.cs`（A*）・`Road/DJKSetRoad.cs`（経路の組み立て）

## Context

ベルトのドラッグ設置は、始点とカーソルをL字で結び、既存ブロックと地形を高さプロファイル（`ConveyorOverpassRaiser` / `ConveyorVerticalEnvelope`）で跨いでいた。水平に回り込めず、坂ベルトのドラッグは一定勾配の別経路で、分岐は手で分岐器を置き換える必要があった。
前回の試作では A* の親を1本たどるだけで経路を復元したため、Uターンで輪になる経路や自分の坂の真上を通る経路が緑（置ける）で表示された。

## Decision

本ADRの各項は 2026-11-06 のユーザー裁定（仕様書「ベルトコンベアの設置を『2クリックで最短経路を探して置く』方式に置き換えてください」）を出所とする。

### 操作

- 始点をクリックし、向きは R で水平4方向に回す。Shift+R の縦置き回転は廃止（ADR 0095 で向き自体が水平4方向になっている）。
- 始点を決めたあとは、カーソルのセルを終点として毎フレーム最短経路をプレビューし、終点のクリックで置く。
- 終点の向きはふだん R。カーソルが既存ブロックの側面に当たっているときだけ、そのブロックへ差し込む向きにする。終点にできるのは空のセルだけで、ブロックの面に当てているときはその面の手前のセルが終点。
- （2026-11-09 廃止・ADR 0100）同コストの経路が複数あるときは C で切り替える。X/Y/Z のどの軸の一歩を先に試すかの6通りを順に送り、今どれかは画面に出さない。
- 始点のセルをもう一度クリックするとベルトを1個だけ置く。向きと可否の判定は終点と同じ。
- 右クリックの短押しか Esc で始点を解除する（建築モードには留まる）。
- agent前提: 持ち替え直後（`Enable`）の向きは北から始める。プレイテストDSLが向きを R の回転回数で合わせるため、起点を固定する必要がある。

### 探索範囲と障害物

> 2026-11-09: 箱と高さ上限は ADR 0100 で廃止。以下の「範囲」「始点確定時の地形計測」「箱の作り直し」は旧仕様。障害物の扱い（地面・既存ブロック・既存の出力口・坂の真上・終点の前）は ADR 0100 でもそのまま。


- 範囲は始点を中心にした X64×Z64 の箱で、始点を決めた時点で固定する。Y の下限は箱の中の地形の最低点と始点の低い方、上限は地形の最高点と始点の高い方に3を足した高さ。箱の外の終点は「範囲外」。
- 障害物は地面と既存ブロックのセル。地面の境界は既存の設置判定（`PlacementGroundCellResolver`）と同じ（沈み許容 1/3m）。地形は始点確定時に箱の全列を1回だけ測る（`BeltRouteTerrainProfile`）。
- 始点を決めたあと、箱と重なるところでブロックが置かれたり撤去されたりしたら占有を作り直す（`BeltRouteWorldScanner`）。それで始点が使えなくなったら始点の選び直しに戻す。
- 既存ラインを勝手につなぎ替えないため、次のセルは経路の途中で使わない（始点と終点には使える）:
  - 既存の出力口（ベルトの末端・機械の搬出口）が向いていて、新しく置くセルの入口がその出力を受け取ってしまうセル。辺はサーバーの `BeltEdgeEndpoint` / `MachineInventoryEdgePorts` と同じ面と高さで照合する（`BeltRouteEdge`）。
  - 既存の坂の真上のセル。ここは始点と終点にも使わない。
- 終点の前のセル（終点が流す先）は最初から途中で使えない。ただし始点がそのセルに来るのは許す。経路は始点→…→終点→始点の輪になり荷物が回り続けるだけで、壊れるものは無い（出所: ユーザー裁定 2026-11-07 原文「終点の前が始点になる輪の配置 ってなんでダメなの？」）。

### 経路の形（サーバーの接続規則に合わせる。サーバーは変えない）

- 直線セルは前・左・右へ進める（Uターンだけ不可）。坂セルは曲がれず、上り→下り・下り→上りの隣接は作らない。
- 坂の真上に何か置くとサーバーは上を優先してつなぐので、自分の坂の真上も空ける。
- 始点と終点は必ず置くので、真上が始点か終点になる坂は探索（`BeltRouteTransitionRule`）でも弾く。組み立てだけが弾いていたときは、終点の真下を上りにする形が最短コストになり、同コストに組める経路が無くて「経路なし」になっていた（原因: 実測 `BeltRoutePlannerBasicTest.EndAboveStartDetoursInsteadOfRisingUnderTheEnd` の配置で探索の終点コスト 27／32、組み立て null、直線始点だけなら 37 で組めた）。出所: ユーザー裁定 2026-11-06 原文「開始からy+1が終了 で方角は180度反転 外側で適切に斜めを配置すれば絶対にあるはず」。直し方は agent前提（組み立てが既に持つ規則を探索へ写す）。
- コストは直線5・坂7。始点セルを直線にするか上りにするかも探索が決める。手持ちが坂でも直線でも動きは同じ（ファミリーの直線を手持ちとして扱い、各セルの種別は経路が決める）。
- 分岐器を手持ちにしたときは水平の経路だけで、全セルを分岐器にする。分岐器は背面入力・3方向出力なので、曲がりは出口側で起きる（`TurnByOutput`）。使わない出口の先に既存の受け手があるセルは途中で使わない。

### 探索の作り方

> 2026-11-09: 1. の A*（箱全体の配列・f 値のバケット）と 3. の余裕の確定は ADR 0100 で「辞書と二分ヒープの重み付き A*（f = g + 2h）」に置き換え。2. の組み立て（BeltRouteRecovery）はそのまま。


- ParamegaFactory と同じ2段構え:
  1. A*（`BeltRouteSearch`）で、各状態（置いたセル・出る向き・セル種別）の最短コストを求める。整数コストなので f 値ごとのバケットで処理し、終点と同じ f の状態まで全て確定させる。
  2. 終点から始点へ、コストが1セルぶんずつ減る状態を深さ優先でたどって経路を組み立てる（`BeltRouteRecovery`）。使ったセルと自分の坂の真上を作業用の地図に書き、同じセルの再使用か坂の真上の通過にぶつかったら一歩戻って別候補を試す。候補を試す順は C の優先順。組めなかった状態は、その失敗が自分より先に置いたセル（終点を除く）に依存していないときだけ「残り予算がこれ以下なら組めない」と記憶して二度と試さない（`BeltRouteRecoveryMap`）。これが無いと、終点と衝突箇所の間に広場があるだけで同コスト経路を全部数え（実測: 囲いと幅1の廊下の配置で約 300 ms）、歩数上限で諦めていた。記憶ありでは同じ配置が 2〜5 ms。歩数上限は 2 万の保険として残す。
  3. 最短コストで組めないときは予算を余裕 20 まで広げ、その範囲の状態を A* で確定させてから組み直す。最短で組めたときは追加の確定をしないので通常ケースの時間は変わらない。爆発配置で 11〜38 ms（実測 2026-11-07）。
- 最短コストで組めないときは予算を余裕 20（直線4セル分、`BeltRoutePlanner.DefaultRecoverySlack`）まで広げて組み直し、それでも組めなければ経路なし。ParamegaFactory は最短で組めなければ経路なし（`Road/DJKSetRoad.cs` の Recover）で、2026-11-06 は一度それに揃えたが、組み立ての列挙で本番の最悪が約 300 ms になると分かり、記憶つきの組み立てと余裕 20 へ差し替えた。残る穴は余裕を超える遠回りが要る配置（袋小路の先で向きを変えるしかない形）で、参照ソルバ突き合わせ（6×3×6、1461 問）では 0 件。余裕で見つかる経路は最短とは限らない（1 件が参照より 10 長い）。出所: ユーザー裁定 2026-11-07 原文「200ms 300msは重いのでそもそもダメ」「1. 余裕 20 を本番に入れる」。棄却: 経路なしのまま残す、GPU の BFS 全探索。
- 探索はカーソル・向き・優先順・占有が変わったフレームだけメインスレッドで回す（`BeltRouteSession` が同じ問い合わせの結果を使い回す）。

### 経路なし・コスト不足

> 2026-11-09: 経路なしの理由分け（地形／既存ブロック／両方／範囲外）と塗りつぶし判定は ADR 0100 で廃止。理由行は「経路が見つかりません」の1つ、判定は探索量の上限。建設コスト不足の扱いはそのまま。


- 経路が無いときは始点と終点のゴーストだけを赤にし、理由を1行出す。理由は「地形が障害」「既存ブロックが障害」「両方」「範囲外」。
- 理由は、始点から空きセルをベルトの歩幅（水平1歩、坂ありなら高さ±1を伴う水平1歩）で塗りつぶす到達判定（`BeltRouteReachability`）を、地形を無視・既存ブロックを無視で回して分ける。片方だけ届けばそれ、両方届く（坂の真上・山谷・曲がり・既存の入出力口の規則だけで届かない）・両方届かないは「両方」。到達判定は経路なしになったときだけ回す。
  - 出所: ユーザー裁定 2026-11-06（選択「セル単位の塗りつぶしで判定する」）。当初の「地形無視・ブロック無視の本探索を2回追加する」方式は、経路なしのたびに箱全体の探索が3回走り、カーソルを動かした1フレームが 200 ms〜1 s 止まった（`BeltRouteNoRoutePerformanceTest` で実測）。
- 塗りつぶしで届かない終点は本探索を回さずに経路なしにする（agent前提: 塗りつぶしは必要条件なので結果は変わらず、囲われた終点で箱全体を舐めるのを避けられる）。
- 塗りつぶしは届くが規則で届かない終点（例: 台座の上で上り坂の真上が塞がる）は本探索が箱全体を舐める。この最悪はフレーム分割ではなく探索の内側の高速化で抑える（出所: ユーザー裁定 2026-11-06 選択「内側の高速化だけ」。棄却: フレーム予算で分割し「探索中」表示、塗りつぶしで弾くだけ）。内側は辺の HashSet 照合をセルごとの面ビット（`BeltRouteEdgeTable`）へ、探索と途中セル判定を Vector3Int から整数添字へ変えた。
- 建設コストが足りないときは経路の全セルを赤にし、不足を出して置かない（`BeltRouteCostGate`）。

### 既存ベルトからの分岐

- Ctrl を押したまま既存の直線ベルト（直線のブロック。坂と分岐器は不可。向きが直角に変わる L字の角も直線のブロックなので対象）をクリックすると分岐の始点になる。手持ちは同じファミリーの分岐器ではないベルトに限る。
- そのベルトは同じファミリーの分岐器（`BeltSplitterCounterpart`）に置き換わる。分岐器の向きは「そのベルトへアイテムが入ってくる向き」（`BeltRouteBranchGeometry`）。横から受けていない直線ならベルトと同じ向き。L字の角（左右どちらか一方の面だけから受けていて、背面からは受けていない）なら、流し込んでくる隣の向き。分岐器は背面からしか受けないので、角のベルトと同じ向きに置くと流れが切れる（2026-11-09 までは角を「横から荷物を受けています」として分岐不可にしていた）。
- 出口は分岐器の3つ（正面・左・右）のうち、元のベルトの向き（既存の続きが流れる出口）を除いた2つが候補。直線なら右が既定で R で左。角なら正面（入ってくる向きの先）が既定で R で空いている横。置き換えは撤去要求が受理されてから設置要求を送る2段（`BeltRouteBranchReplaceSender`）。
  - 出所: ユーザー裁定 2026-11-09 原文「今更だけどL字で1本になってる部分ってL字のところをctrlで上書き分岐化ってできないんだっけ　理論上はできるよね？」「じゃあ分岐化について入力を考慮した配置でブロック置換してなにか問題あるの？」。既定の出口は原文「あってます、規定はまっすぐです」（提示した2案: 正面／空いている横）。
- 次の場合は分岐にせず赤と理由を出す: そのベルトが2方向以上から受けている（背面と横、または両横。分岐器の入口は背面1つなので、どの向きに置いても片方の入力が切れる）／使わない出口の隣に受け手がいる（分岐器は使わない出口にも流す）。
- agent前提: 置き換えた元のベルトは Undo 履歴に残さない（Ctrl+Z は分岐器と経路を外すだけで、元の直線ベルトは戻らない）。
- 既知の不具合（別 PR）: 分岐の最初のセルが横の出口の直後で曲がると、歯車ベルトでは回転が繋がらずアイテムが止まる（本番マスタの `conveyorSide` 同士は非接続。原因: 推測、根拠はマスタの接続対応表の読み）。出所: ユーザー裁定 2026-11-09 選択「別 PR にする」。

### 置き換える範囲

- ドラッグ設置（L字、`ConveyorOverpassRaiser` / `ConveyorVerticalEnvelope` の立体交差、地形の乗り越え、坂のドラッグ）とそのテスト・シナリオ（`belt-terrain-climb-via-ui.cs`）を削除。
- プレイテストの `DragPlaceViaUi` は `RoutePlaceViaUi` / `BranchPlaceViaUi` に置き換え、録画オーバーレイにログ欄と入力欄を隠す切り替え（`SetOverlayPanels`）を足す。

## Considered Options

- L字ドラッグのまま高さプロファイルで跨ぐ（従来）: 水平に回り込めず、坂や分岐が別操作になる。不採用（ユーザー裁定）。
- A* の親を1本たどる復元（前回の試作）: Uターンの輪や自分の坂の真上を通る経路が緑で出る。不採用（ユーザー裁定で2段構えを指定）。
- 始点確定時に到達可否をまとめて求める: 始点クリックで引っかかる。不採用（ユーザー裁定）。

## Consequences

- 経路の正しさは、種を固定した50回のランダム試験（重複なし・自分の坂の真上なし・終点の前なし・山谷なし・隣接接続）と、テスト用サーバーに経路を置いて流れを確かめる試験（障害越え・分岐）で守る。経路の存在と最短性は、小さな箱で全経路を総当たりする参照ソルバとの突き合わせ（`BeltRouteReferenceCrossCheckTest`、終点の半分を始点の±2以内に置く）で守る。ランダム試験は見つけた経路の形しか見ないので「経路なし」は常に通り、始点の真上の終点を見落とした不具合（2026-11-06）はこの試験でしか捕まらない。余裕なしでは既知の穴（100 問中 1 件）が見えることを、余裕あり（本番値）では穴ゼロを要求する。試験の回数は「PR で足したテストは合計 1 秒以内」の裁定（2026-11-07）で 3000 回・1500 問から 50 回・100 問へ下げた（下げる前の 1461 問では穴 5 件）。
- 速さは壁時計の閾値テストでは守らない（ユーザー裁定 2026-11-07。CI の共有ランナーは手元の 10〜35 倍遅く、同じテストが再実行の間で 2.4 倍ぶれて PR 1616 が落ちた）。`BeltRouteSearchPerformanceTest`・`BeltRouteNoRoutePerformanceTest`・組み直しが苦手な配置の試験は削除した（余裕ありで既知の穴が消えることは参照ソルバ突き合わせが見る）。以下は削除前の手元の実測（2026-11-06〜07）で、参考値として残す。
  - EditMode で X64×Z64×Y12・障害2割の箱を端から端へ探索して最悪 4.6 ms（内側の高速化前は 12.5 ms）。
  - 経路なし（X64×Z64、箱の高さ 6/12/24）: 塗りつぶしで弾ける配置（囲われた終点・地形の尾根・真上だけ開いた縦穴）は 1〜8 ms。規則だけで届かない台座の配置は本探索が箱全体を舐めて 15/45/105 ms（探索単体、5回の実測）。高速化前は囲われた終点で 206/484/1063 ms だった。録画シナリオ `belt-route-two-click-via-ui.cs` が終点を4か所振って測った Editor 実機のフレーム時間は最悪 19.3〜23.0 ms（3回の実行、描画込みの1フレーム全体）。
- プレイテストDSLへの波及: 録画で設置物を写すため `HideMapObjects()`（スキットと同じ `MapObjectGameObjectDatastore.SetActive(false)` 経路）を足した。足場 y=32 は地形の山の中にあり、隠さないとベルトが写らない。
- `HybridInput` のキー対応表に C を足した。対応表に無いキーは legacy Input へ落ちるため、プレイテストの注入では C が押されたことにならず、実機でだけ動く状態だった。
- 角の分岐は、周囲の入出力辺だけで向きと出口を決める幾何（`BeltRouteBranchGeometryTest`）、テスト用サーバーで角を分岐器に置き換えて両方へ流れる試験（`BeltRouteConveyanceTest`）、録画シナリオ `belt-route-branch-via-ui.cs` の角のフェーズで守る。プレイテストDSLの `BranchPlaceViaUi` は「右か左か」ではなく「既定の出口か R で切り替えた出口か」と、経路が出る向きを受ける形に変わる（2026-11-09）。
- 坂なしのファミリー（分岐器）は水平経路のみ。上り・下りが片方しか無いファミリーも坂を使わない。
