# 常時表示HUDに面を許可し GamePanel の hud variant で供給する

デザイン哲学 §1 は「常時表示HUD（ホットバー・クロスヘア・キーヒント等）は浮いている表現であること。面で塗らない」と定め、§8.14 はチャレンジHUD（左上の目標表示）を「面・枠・角丸を持たず」と明記していた。今回、左上の目標にインベントリ同様の背景を入れたいという要望を受け、**目標HUDを「面を持つ初の常時表示HUD」として §1・§8.14 の例外に据える**。面の供給元は §2 の規定どおり `GamePanel` に新variant `"hud"` を追加して1箇所へ集約し、面色はパレットを増やさずインベントリパネル面と同値の半透明ネイビー `rgb(10 14 27 / 80%)` を流用する。境界フェードは全4辺を固定長トークンで行い、面の外形は実viewport左上24pxに据えて、フェード帯に文字が載らないよう安全帯paddingで文字を内側（画面端から約44px）へ寄せる。

出所: ユーザー裁定 2026-08-17（依頼「左上の目標に簡単な背景を入れておきたい。インベントリみたいな感じで、グレー+境界フェード」／面色=既存の半透明ネイビー流用／部品=`GamePanel` に `variant="hud"` 追加／面幅=固定520px維持／面は現位置で文字を内寄せ／文字影=通知同族へ弱める）

## Considered Options

- **HUD側CSSへトークン化した面を直接描く**（却下）: `NotificationHost` と world-pin ラベル面という前例はあるが、§2 の「GamePanel の外で独自CSSのパネル面を作るのは禁止」へHUD例外を切る必要があり、面表現の供給元が分散する。
- **既存 `variant="default"` を流用する**（却下）: インベントリ面と完全一致するが、下向き三角3個・左28pxの非対称padding・正本合わせの上端実測オフセット(-3.913894px)までHUDへ付いてくる。
- **新しい寒色グレーの面トークンを新設する**（却下）: 依頼の語「グレー」に字面どおり応えられるが、面色パレットに2系統目が生まれ §5 と他HUDとの統一が崩れる。半透明ネイビーは世界が透けた結果として暗い青灰＝「グレーっぽい」に着地する。
- **面幅を内容幅追従（fit-content）にする**、または**本文幅を378pxへ詰める**（却下）: 右側の空白は減るが、前者は目標の入れ替わりで面幅が毎回変わり、後者は長文目標の行数増と幅・折返しのe2e契約引き直しを招く。

## Consequences

- **§1・§8.14 の改訂が必須**。あわせて §8.14 の「アニメーションは追加しない」条項は目標HUD側については維持する（面の出入りは演出しない）。
- **e2e契約の更新が必須**。`e2e/tests/challenge/hudLayout.spec.ts` の1本目はテスト名が「進行中チャレンジを内部キーや**カード面なしで**表示する」で、`background-color: rgba(0, 0, 0, 0)` / `borderWidth: 0px` / `boxShadow: none` を検証している。面付き後の値へ更新し、テスト名も改める。`animationName: "none"` は目標HUD側では維持する。
- 「見出し → `FadeRule` → 目標一覧」の構成と短い罫線（176px）は面付き後も維持する。面は階層の代わりではなく器であるため。（出所: agent前提）
- 面はメニュー中（インベントリ・研究・建築・チャレンジ一覧・ポーズ）も同一レイアウトで出す。§8.14 の「HUD自身は画面状態を参照して切り替えない」を崩さない。`--menu-upper-safe-area` は面込みの高さを確保する必要がある。（出所: agent前提）
- `variant="hud"` は将来の他HUD（装備HUD等）へ面を広げる入口になる。広げる判断は都度裁定とし、この ADR は目標HUDのみを許可する。
