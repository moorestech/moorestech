# ADR 0106: 軌道へ運ぶ積荷は、発射台と宇宙エレベーター拠点ごとにプレイヤーが選ぶ

- Status: Accepted
- Date: 2026-11-21
- Related: ADR 0091（軌道到着の処理を発射台と拠点で共有する。到着の処理は変えない）、ADR 0092（ケーブルプールと拠点ごとの接続。変えない）、ADR 0102（ICチップをそのまま軌道へ運ぶ。積荷表は変えない）
- Supersedes: ADR 0091 の「発射台は届いた積荷で打ち上げ内容を自動で選ぶ」に当たる記述、`.decisions/2026-10-23-発射台は届いた積荷で打ち上げ内容を自動で選ぶ.md`、`.decisions/2026-11-18-軌道エレベーターの入口の混在詰まりは直さず、ロード時に戻せない積荷は出口へ退避し無理なら消す.md` のうち「入口の混在詰まりは何もしない」（ロード時の退避の決まりは覆さない）

## Context

ユーザーの依頼（2026-11-19、逐語）:

```
ロケットのUIに必要な部材の透かしを入れる

ロケットのペイロードに何を入れたら何が返ってくるのか明示する
```

「積荷の6枠に透かしを出し、枠の下に打ち上げ成果を並べる」画面案に対し、ユーザーは次の赤を入れた（2026-11-19、逐語）:「積荷の種類をレシピ設定みたいに選択できるようにして そうじゃないと、何が必要で、何がどうなるのかきちんと認識できない」。

確認した事実（2026-11-19〜20、コードとマスタの読み。詳細は `../moorestech_logs/harness/ui-clarity-kgfsp/elevator-base-and-unlock-facts.md`）:

- 発射台の枠は 資材3・積荷6（積荷表 `orbitalPayloads` の1行につき1枠）・出力4。積荷表にある品は常に受け取り、資材が揃い1便ぶんあり成果が出力に入りきる最初の積荷を巡回で選ぶ（`RocketLaunchPadCargoLoader`）。選択の状態は持たない。
- 拠点の入口は1枠で、ICチップLv1〜5 のどれでも入る。入口に入っている品が運ぶ種類になる。選択の状態は持たない（`SpaceElevatorBaseInventoryComponent`）。
- 積荷表: ICチップLv1〜5 ×20 → 計算データ 20／40／80／160／320。グラフェンケーブル ×1000 → 出力なし（ケーブルプールが 1000 増える）。拠点はケーブルを運べない。
- 建造を始めた便の積荷と資材は段階（`BuildingStage` など）が `RocketCargo` として持ち、入れ口の中身や巡回位置に依存しない。
- 機械のレシピ選択（そろえる先の前例）: 未選択は搬入を受けず稼働しない。選択はプロトコル `va:machineRecipeSelection` で送り、サーバーが未解放の選択を拒否する。選択状態はブロック状態で届く。選び直しで合わなくなった入力品は操作者のインベントリへ返し、入りきらないぶんは枠に残す。ブループリントで選択を複製する。型は機械レシピ専用で、積荷にはそのまま使えない。
- 発射台も拠点もブループリント設定（`IBlockBlueprintSettings`）を持たない。
- 用語: 用語集の正は「積荷」「打ち上げ成果」「ケーブルプール」。依頼の「ペイロード」は「積荷」のこと。

## Decision

### 1. 発射台の積荷はプレイヤーが選ぶ

- 発射台は、積荷表のどの種類を運ぶかをプレイヤーが選ぶ。届いた積荷から自動で選ぶ動き（巡回）は廃止する。
  - 出所: ユーザー裁定 2026-11-19 原文「ロケットのペイロードに何を入れたら何が返ってくるのか明示する」→ 画面案への赤「積荷の種類をレシピ設定みたいに選択できるようにして そうじゃないと、何が必要で、何がどうなるのかきちんと認識できない」
- 選ぶ一覧の1行は、積むものと返るものの対（「ICチップLv2 ×20 → 計算データ ×40」）。グラフェンケーブルは「グラフェンケーブル ×1000 → ケーブルプール +1000」と1便の効果だけ書く。プールの今の数は発射台に出さない（拠点の画面にある）。
  - 出所: ユーザー裁定 2026-11-20 問い「グラフェンケーブルの成果は、発射台の画面にどこまで書きますか」→ 選択「A. 1便の効果だけ (「ケーブルプール +1000」。今の数は拠点の画面で見る)」
- 選んだ後の画面は、選んだ積荷と成果の見出し・資材3枠・選んだ積荷の1枠・状態と進み・出力4枠。見出しを押すと選び直せる。資材と積荷の枠は、空なら入れるアイテムの透かし（薄い絵と必要な数）、入り始めたら「持っている数／必要な数」を出す。
  - 出所（透かし）: ユーザー裁定 2026-11-19 原文「ロケットのUIに必要な部材の透かしを入れる」
  - 出所（画面の並び・透かしの見せ方）: agent前提（機械の画面の前例 `SelectedRecipeHeader`・`MachineSlotContents`。2枚目の画面案に描き、2026-11-20 に「そのまま通す項目」として提示し、異論なし）

### 2. 積荷を選んでいない発射台は何も受け取らない

- 未選択の発射台は、資材も積荷も受け取らず、建造もしない。開くと積荷を選ぶ画面になる。
  - 出所: ユーザー裁定 2026-11-20 問い「積荷を選んでいない発射台は、どう動きますか」→ 選択「A. 何も受け取らない (機械と同じ。開くと積荷を選ぶ画面)」
- 選んだ後は、資材と選んだ種類の積荷だけを受け取る。ほかの種類はベルトで届いても受け取らない（ベルトに残る）。
  - 出所: agent前提（機械の前例。2026-11-20 に「そのまま通す項目」として提示し、異論なし）
- 未選択の発射台・拠点の画面は、積荷の一覧だけを出す。出力の枠・状態・電力の状態・ケーブルプールの行は選ぶまで出さない（接続済みの拠点でも同じ）。選ぶまでは出力を手で取り出せない。
  - 出所: ユーザー裁定 2026-11-21 問い「積荷を選んでいない発射台・拠点は、一覧だけを出して、出力の枠や状態は選ぶまで出さない形でよいですか」→ 選択「A. 一覧だけ (機械と同じ。選ぶまでは出力を手で取り出せず、状態・電力の状態・ケーブルプールの数も見えない)」
- 一度選んだ積荷を「未選択」へ戻す操作は作らない。別の種類への変更だけ。
  - 出所: agent前提（機械の画面に解除の操作が無い。同上の提示で異論なし）
- 初打ち上げの決まり（ワールドで最初の1回は建造と発射をボタンで行う）は変えない。積荷を選ぶ手順がその前に入る。
  - 出所: agent前提（同上の提示で異論なし）

### 3. 一覧には解放した種類だけを出す

- 積荷を選ぶ一覧には、研究で解放した種類だけを出す。
  - 出所: ユーザー裁定 2026-11-20 問い「積荷を選ぶ一覧に、まだ研究で解放していない種類も出しますか」→ 選択「C. 解放した種類だけ出す (機械と同じ)」
- サーバーも未解放の種類の選択を拒否する。ブループリントの貼り付けで未解放の種類が来たら、未選択のまま置く。セーブからの復元では解放を見ない。
  - 出所: agent前提（機械の前例 `MachineRecipeSelectionUtil.ValidateSelection`・`MachineRecipeBlueprintSettingsComponent`・`MachineSaveRestorer`）
- 「解放した種類」は、アイテムの解放状態で決める（レベル別に分かれていてクライアントへ同期済みの状態）。マスタ（研究）を直し、ICチップLv2〜5 のアイテム解放を研究「品質モジュールLv1〜4」にも付ける。研究「速度モジュールLv1〜4」に付いている今の解放は外さない。ICチップLv2〜5 がレシピ一覧に出る時期も同じだけ早くなる。
  - 出所: ユーザー裁定 2026-11-21 問い「「解放した種類」を、何で決めますか」→ 選択「A. 作れるようになる研究で解放する (ICチップLv2〜5 の解放を「品質モジュールLv1〜4」の研究にも付ける)」
  - 「速度モジュール」側の解放を外さないのは、選択肢の文言「にも付ける」の読み（出所: agent前提）。
- 同じ研究に、途中のアイテムの解放もそろえて付ける。研究「品質モジュールLvN」（N は 1〜4）に ICチップLv(N+1)・シリコンダイLv(N+1)・品質モジュールLvN、研究「品質モジュールLv5」に品質モジュールLv5。今の研究「速度モジュールLvN」が持つ組み合わせと同じ。
  - 出所: ユーザー裁定 2026-11-21 問い「研究「品質モジュールLv1〜4」で、レシピ一覧に早く出すアイテムをどこまでにしますか」→ 選択「B. 途中のアイテムもそろえて出す (シリコンダイLv2〜5 と品質モジュールLv1〜5 の解放も、品質モジュールの研究に付ける)」
- 既に解放済みのアイテムをもう一度解放しても「解放されました」の通知を出さない（同じアイテムを2本の研究が解放するようになるため）。
  - 出所: agent前提（ブループリントの解放 `BlueprintUnlockStateHolder` の前例。2026-11-21 に「そのまま通す項目」として提示し、異論なし）

### 4. 選び直しても今の1便はそのまま打ち上げる

- 建造中・建造済みの便があるときに積荷を選び直しても、その1便は元の積荷のまま打ち上げる。次の便から新しい種類になる。積み込み済みの積荷と資材は返さない。
  - 出所: ユーザー裁定 2026-11-20 問い「建造中・建造済みのロケットがあるときに積荷を選び直したら、どうしますか。」→ 選択「B. 今の1便はそのまま打ち上げ、次の便から切り替える」補足「「打ち上げた」んだから、資材は返さないべきでしょ。普通に」
  - 「資材は返さない」は選び直しのときの話として読む。発射台を撤去したときの返却の決まりには広げない（出所: agent前提）。
- 選択の値は選び直した時点で変わり、その時点から新しい種類を受け取り、前の種類は受け取らない。進行中の便は段階が持つ積荷のまま進む。画面は今の便の積荷と成果を出し、その下に「次の便から ◯◯」を1行出す。
  - 出所: agent前提（2枚目の画面案 B の絵。2026-11-20 に「そのまま通す項目」として提示し、異論なし）
- 選び直したとき、まだ積んでいない前の種類の積荷は、選んだ人のインベントリへ返す。入りきらないぶんは枠に残り、画面に出て取り出せる。
  - 出所: ユーザー裁定 2026-11-20 問い「選び直したとき、枠に残っている前の種類の積荷はどうしますか」→ 選択「A. 選んだ人のインベントリへ返す (入らないぶんは枠に残る。機械と同じ)」

### 5. 選択の送り方・届け方・複製

- 「積荷の選択を受ける部品」の口を `Game.Block.Interface` に1つ足し、発射台と拠点が実装する。選択は1つのプロトコルで両方へ送り、操作した人のインベントリを返却先として渡す。選択の状態はブロック状態で届ける。発射台の待ち理由に「積荷を選んでいない」を足す。
  - 出所: agent前提（機械の前例「プロトコル＋ブロック状態」。汎用の口は積荷の語彙だけを持ち、発射台・拠点の事情は各実装が持つ）
- ブループリントで発射台・拠点を複製すると、選んだ積荷も複製する。
  - 出所: agent前提（機械の前例。2026-11-20 に「そのまま通す項目」として提示し、異論なし）

### 6. セーブ

- 発射台のセーブに「選んだ積荷」の項目が増える。巡回位置（`nextPayloadIndex`）は書かなくなり、読まなくなる。セーブの版（`WorldSaveAllInfo.CurrentVersion` = 12）は上げず、変換ステップもテストも足さない。AGENTS.md「セーブ形式を変える PR は版上げ・ステップ・テストを同梱」の例外とする。
  - 出所: ユーザー裁定 2026-11-20 画面案への赤「現在ワールドに発射台がないのでマイグレーション不要」→ 問い「「マイグレーション不要」は、セーブの版も上げず、規則の例外にする意味でよいですか」→ 選択「A. 版を上げない (変換の処理もテストも足さない)」
- 項目の無い発射台のセーブを読んだら、未選択として読み込み、開発者向けのログに1行出す。
  - 出所: agent前提（2026-11-20 の同じ問いに事実として添えて提示）

### 7. 宇宙エレベーター拠点も選ぶ方式にそろえる

- 拠点も、運ぶ積荷（ICチップLv1〜5 のどれか）をプレイヤーが選ぶ。
  - 出所: ユーザー裁定 2026-11-20 問い「宇宙エレベーター拠点も、積荷を選ぶ方式にしますか」→ 選択「B. 拠点も選ぶ方式にそろえる」
- 細部は発射台と同じにする: 未選択は何も受け取らない／一覧は解放した種類だけ／昇降中の1便はそのまま運び次の便から切り替える／選び直しの余りは選んだ人へ返す／ブループリントで複製する／一覧の行は積むものと返るものの対。
  - 出所: agent前提（上の選択の「そろえる」。個別には聞いていない）
- 拠点を選ぶ方式にすることで、2026-11-18 の裁定のうち「入口1枠に別レベルの ICチップが混ざって拠点が止まる件は何もしない」を覆す（拠点が運ぶのは選んだ1種類だけになり、棄却案だった「1拠点1種に絞る」と同じ結果になる）。同じ裁定の「ロード時に戻せない積荷は出口へ退避し、無理なら消す」は変えない。
  - 出所: ユーザー裁定 2026-11-21 問い「拠点を選ぶ方式にすると、11月18日の決定を覆します。それでよいですか」→ 選択「A. 覆してよい (拠点も選ぶ方式にする)」
- 拠点のセーブに「選んだ積荷」の項目が増える。セーブの版は上げず、変換ステップもテストも足さない（6 と同じ例外）。項目の無い拠点は未選択として読み込み、開発者向けのログに1行出す。入口の中身はそのまま残って取り出せる。
  - 出所: ユーザー裁定 2026-11-21 問い「拠点のセーブに項目が増えます。こちらも版を上げなくてよいですか」→ 選択「A. 版を上げない (拠点は未選択で読み込む)」
  - 出所（ログ1行）: agent前提（6 の発射台と同じ）
- 拠点で選び直したとき、前の種類は選んだ人のインベントリへ返し、入りきらないぶんは入口に残る。選び直しは成立する。入口は1枠なので、残りを取り出すまで新しい種類は入らず、入口の詰まりの表示が出る。今の詰まりの表示は「運べない品が入口にある」ときだけ出るので、「選んでいない種類が入口に残っている」も同じ表示に載せる（残りが1便ぶんあっても昇らせない）。
  - 出所: ユーザー裁定 2026-11-21 問い「拠点で選び直したとき、前の種類を返しきれなかったらどうしますか」→ 選択「A. 発射台と同じ (選び直しは成立。残りを取り出すまで新しい種類は入らず、詰まりの表示が出る)」
- まだ接続していない拠点は、積荷を選んでから接続する。未選択の拠点を開くと、接続済みかどうかにかかわらず積荷を選ぶ画面になる。
  - 出所: ユーザー裁定 2026-11-21 問い「まだ接続していない拠点で、積荷の選択と接続はどちらが先ですか」→ 選択「A. 選んでから接続 (開くと積荷を選ぶ画面。発射台・機械と同じ開き方)」
- 接続した後の拠点の画面の「ケーブルのプール」の行は変えない。選んだ後の拠点の画面にも、選んだ積荷の必要な数と成果を出す（発射台と同じ）。
  - 出所: agent前提（2026-11-20 の確認シート04 に「そのまま通す項目」として提示し、異論なし。黙認なのでユーザー裁定ではない）

## Considered Options

- 積荷の6枠に透かしを出し、枠の下に打ち上げ成果を並べる／文字の表にして積荷の下に置く（2026-11-19 に提示。ユーザーはどちらも選ばず、選択式を指示した）
- 選び直したら建造を取り消して資材と積荷を返す（2026-11-20 に提示。ユーザーは「今の1便はそのまま」を選択）
- 未選択の発射台が資材だけ受け取る／選ぶまでは今までどおり自動で選ぶ（2026-11-20 に提示。ユーザーは「何も受け取らない」を選択）
- 6種類を最初から全部出して選べる／全部見せるが解放まで選べない（2026-11-20 に提示。ユーザーは「解放した種類だけ」を選択）
- 余りを返さず枠に残す／全部返せるときだけ選び直せる（2026-11-20 に提示。ユーザーは「選んだ人へ返す」を選択）
- 発射台にもケーブルプールの今の数と必要な数を出す（2026-11-20 に提示。ユーザーは「1便の効果だけ」を選択）
- 発射台だけ変え、拠点は今のまま（2026-11-20 に提示。ユーザーは「拠点も選ぶ方式にそろえる」を選択）
- セーブの版を 13 に上げ、何も変えない変換とテストを足す（2026-11-20 に提示。ユーザーは「版を上げない」を選択）
- 拠点は今のままにする（発射台だけ選ぶ方式）（2026-11-21 に提示。ユーザーは「覆してよい」を選択）
- 拠点について版を 13 に上げ、変換で拠点の入口に入っている種類を選んだ状態にする（2026-11-21 に提示。ユーザーは「版を上げない」を選択）
- 「解放した種類」を今の解放のまま使う（「速度モジュールLv1〜4」の研究で一覧に出る）／別の決め方にする（2026-11-21 に提示。ユーザーは「作れるようになる研究で解放する」を選択）
- 拠点では全部返せるときだけ選び直せる（2026-11-21 に提示。ユーザーは「発射台と同じ」を選択）
- 未接続の拠点で順序は自由／接続してから選ぶ（2026-11-21 に提示。ユーザーは「選んでから接続」を選択）

## Consequences

- 発射台1台で複数の種類を順に打ち上げることはできなくなる。種類ごとに発射台を分けるか、選び直す。
- 拠点1つで複数のレベルを順に運ぶこともできなくなる。並行して運ぶには拠点をレベルの数だけ置き、それぞれ接続する（接続1回にケーブルプールの 1000 本）。
