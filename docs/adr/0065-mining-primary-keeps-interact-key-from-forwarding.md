# 0065. 採掘対象が主対象のフレームは F を近傍候補へ転送しない

日付: 2026-09-20
状態: 採択（暫定ガード。採掘FSMを単押し側と対称化する構造改修 bd moorestech-99c8 が入れば、このガードは FSM 側のキー宣言へ置き換わる）

## Context

技術負債監査 F0154。照準レイが2m内の何にも当たらず近傍フォールバックで主対象が決まり、2m内に採掘対象（小石・木・露頭）と開けるブロック／車両が両方あるとき、F 1回で2つの動作が走っていた。

- 単押し取得: 小石が取得され、同フレームで隣の石窯の UI も開く。
- 長押し採掘: ツールチップもハイライトも木なのに、F を押した瞬間に石窯が開き採掘は破棄される。

原因は `InteractController.ManualUpdate` が採掘対象を `target as ITapInteractable`（= null）として `TapInteractionDriver.Step` へ渡すこと。駆動側からは「主対象は F に応じない」と見え、PR #1302 レビュー F05 案A の「主対象が応じないキーは応じる候補へ回す」経路が F を石窯へ回していた。裁定 [[2026-08-30-インタラクト対象は照準優先で無ければ近傍最寄りを1件選ぶ.md]] 決定4（ハイライトとヒントは常に1件）と、表示／実行が食い違う。

## Decision

- **主対象が採掘対象（`IMiningTargetObject`）のフレームは、F（`Playable.Interact`）を近傍候補へ転送しない。** 表示中の1件だけが F に反応する。石窯を開きたいときは石窯を見る。
  出所: ユーザー裁定 2026-09-20 質問「主対象が採掘対象のとき、同じキーを近傍へ転送するかどうか」→ 提示した推奨「A: 主対象が IMiningTargetObject のフレームは Interact キーの候補転送を止める」に対し原文「あなたのおすすめでok」
  棄却案: なし（B「採掘側が使うキーを宣言し、被るキーだけ止める」は A と実質同じになると併記して提示し、下の「F だけ止める」で B の形に確定した）

- **止めるのは F だけ。E（乗車）など別キーの転送は、採掘対象がハイライト中でも維持する。** 長押し採掘の途中で E を押したら乗車し、画面遷移で採掘は中断される。
  出所: ユーザー裁定 2026-09-20 質問「小石・木・露頭がハイライトされている間、別キーのE（乗車）は近傍の車両へ転送したままにしますか？」→ 選択「Fだけ止める」
  棄却案: 全キーの転送を止める（木の隣に停めた車両に乗りにくくなる）

- **道具不足・手掘り不可で今は掘れない採掘対象が主対象でも、F は転送しない。** 判定は主対象の種類だけで決まり、駆動側は採掘可否を知らない。
  出所: ユーザー裁定 2026-09-20 質問「『今は掘れない』理由がツールチップに出ている採掘対象がハイライト中にFを押した場合も、近傍の石窯・車両へは転送しませんか？」→ 選択「転送しない」
  棄却案: 掘れないときは転送する（症状2と同じ表示／実行の食い違いがこの場合だけ残り、駆動側が採掘可否まで知る必要が出る）

- **`InteractController.Disable()` は現状維持。** 画面遷移時に採掘FSMを Idle まで回し、完了済み（`MiningCompleteState`）なら `SendAttack` を送る。F の転送を止めれば「勝手に石窯が開く」経路が消え、残るのはプレイヤー自身が F と別キーを同フレームで押した場合と、長押し完了直後のフレームで画面遷移した場合だけで、どちらも結果を届けるのが正しい。
  出所: ユーザー裁定 2026-09-20 質問「Q2（UI遷移でDisableされたら採掘完了をキャンセル扱いにする）の私の推奨を取り下げたい…どちらにしますか？」→ 選択「現状維持」
  棄却案: キャンセル扱いにする（掘り終えた採掘結果が捨てられる）

- **構造改修ではなく暫定ガードで今直す。** 根治（採掘FSMを `IHoldInteractable` として対称化し、採掘側も同じキー宣言の仕組みに乗せる）は bd moorestech-99c8 で追跡し、本症状を 99c8 へ追記する。
  出所: ユーザー裁定 2026-09-20 提示した推奨「暫定ガードを今入れて 99c8 に症状を追記」に対し原文「あなたのおすすめでok」
  棄却案: 99c8 の構造改修で根治する（改修が大きく、通常プレイで踏むバグの修正が遅れる）

- **F0156／F0157（照準ヒット時に近傍走査をしない）は現状を正とする。** 照準先が2m内の開けないブロックなら近傍フォールバックせず、照準ヒット中は別キーの候補転送も効かない。照準を向け直せば解決するため変更しない。
  出所: ユーザー裁定 2026-09-20 提示した推奨「F0156／F0157 は、現状を正として .decisions に1行残すだけ」に対し原文「あなたのおすすめでok」
  棄却案: 照準の有無に関わらず候補を保持し Primary だけ照準優先にする

- 実装形: `TapInteractionDriver.Step` に「主対象が長押しで使うキーの一覧」を引数で渡し、駆動側はそのキーを「主対象が応じるキー」と同じ扱いにして転送対象から外す。一覧は `InteractController` が主対象の種類を見て渡す（採掘対象なら F、それ以外は空）。駆動側は採掘という語彙を知らない。
  出所: agent前提（AGENTS.md「汎用基盤にドメイン語彙を持ち込まない」「基盤には値をプッシュする」。`InteractController` は既に `MiningControllerContext` を直接持つ司令塔で、種類の判断をここに置くのが既存の文脈に揃う）

## Consequences

- 採掘対象がハイライト中は、F で隣の石窯・車両インベントリが開かなくなる。開くには対象へ照準を向ける。
- 掘れない採掘対象がハイライト中の F は何も起こさない（理由のツールチップが出たまま）。
- `InteractController` が採掘の使うキーを名指しする箇所が1つ増える。99c8 の対称化で FSM 側の宣言へ移す。
