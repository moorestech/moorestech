# スキットの座標はスポーン地点基準の相対座標とする

スキットJSON（cameraWarp / camerawork / characterTransform / controlSkitBackground）の位置は
ワールド絶対座標で焼き込まれており、マップ自動生成でスポーン高さが変わる・templateモードでスポーンが別地点になるたびに
演出が地形からずれていた（[[2026-08-20-スキットのスポーン追従は当面固定座標の焼き直しで凌ぐ]] で一度は焼き直しで凌いだ）。
スキットJSONの位置は例外なく「スポーン地点（`InitialHandshakeResponse.MapLayout.Spawn` のXYZそのもの）からの相対座標」とし、
実行時に `StoryContext` へ登録した原点を4種の位置コマンドが常に加算する。JSONに絶対/相対フラグは持たせない。
地形の傾斜・起伏の吸収（スポーン周辺の平坦化等）は本決定の範囲外で、起動して実地形を見てから別タスクで扱う。

出所: ユーザー裁定 2026-08-22（原点「スポーン地点そのもの XYZ」／適用範囲「4種すべて常に原点加算」／傾斜「今回は相対化のみ。起動して見てから別タスク」）

## Considered Options

- 原点をXZのみスポーン・Yはワールド絶対のまま — マスタの生成パラメータでスポーンYが動くと再発するため棄却（ユーザー裁定 2026-08-22）
- 原点Yをクライアントで地形サンプリングして実測 — spawn.Yは生成時の地形高さと同値で、実装が増えるだけのため棄却（同上）
- コマンドごとの relative フラグ — 同一スキット内に2座標系が混在しフラグ忘れが事故になる。現時点で絶対座標の需要が無いため棄却（同上）
- 船・キャラのYを実行時に地面へスナップ／スポーン周辺の平坦化ステージ — 傾斜対策として提示し、本タスクでは採らず別タスクへ送ると裁定（同上）

## Consequences

- デバッグ用シーン（SkitTester）のようにハンドシェイクが無い文脈では原点ゼロで再生する（agent前提）
- 既存の 100_start_game.json は 8/20 焼き直し時の基準 (500, 15.6462908, 500) を全位置から引いて相対値へ機械的に変換する
