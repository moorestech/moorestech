# 通知は stage の背面レイヤーへ置き、全画面UIの裏に回す

ゲーム内通知（`NotificationHost`・画面左端縦中央）は Mantine `Portal`（body直下）へ描かれ `z-index: var(--z-portal-toast)` = 300 を持つため、インベントリ画面をはじめとする全画面UIの上に常に被さっていた。通知は「今起きたことの控えめな報告」であり、プレイヤーが画面を開いて操作している最中はUIの裏へ回るべきなので、通知を全画面UI・常駐HUDの下へ沈める。

適用範囲は特定画面ではなく全画面UI全般（インベントリ・ブロックインベントリ・研究・ビルドメニュー・チャレンジ・ポーズ・スキット・モーダル）とする。

出所: ユーザー裁定 2026-08-18（Q1「重なり順で裏（インベントリに隠れる）」／Q2「全画面UI全般に同じ扱い」）

## 決定

`NotificationHost` を `Portal` から `.viewport` 直下（`.backdrop` と `.stage` の間）へ移し、`.stage` より下の層に置く。通知自身は `position: fixed` のまま実ピクセル寸法を保つ。

これは ADR 0013 の二分法に対する第三の所属先であり、**背面viewport族**（実画面へ位置が追従し、stage拡縮に内容寸法も追従せず、stage 全体の背面に沈む層）として宣言する。stage族/viewport族と同じく、以後この層へ置く要素は実装前に所属を宣言する。

`.viewport` / `.stage` / `.backdrop` の層序はこれまで App.module.css の生値（0 と 1）だったが、通知が外部から参照するため `--z-viewport-*` トークンへ昇格させ、`zLayerTokens.test.ts` で `viewport-behind-stage < viewport-stage` を固定する（ADR 0013「stage内部の前後関係はトークンで明示」の延長）。

出所: ユーザー裁定 2026-08-18（Q「viewport直下・stage全体の裏（見た目維持）」）／トークン昇格は agent前提（ADR 0013 の DOM順依存をやめる方針の適用）

## Considered Options

- **トースト層の z を下げるだけ**（却下・実現不能）: `.viewport` が `position: fixed` でスタッキングコンテキストを作るため、body直下 Portal の通知は z をいくら下げても `.viewport`（z-index: auto）より前に描かれる。負値にすると `.viewport` のヴィネット背景の裏へ完全に消える。層を下げるには描画位置の移設が必須。
- **`.viewportOverlay`（常駐HUD族）へ移し `--z-stage-screen` 未満にする**（却下）: 常駐HUD（ホットバー・装備・採掘ゲージ）との前後関係を保てる一方、通知の文字サイズが `--ui-scale` 追従になり現行の見た目が変わる。見た目維持を優先。
  出所: ユーザー裁定 2026-08-18（移設先の選択で本案を却下）
- **画面が開いている間だけ通知を非表示にする**（不採用・未検討で棄却）: 「裏に回る」ならパネル外へはみ出た通知は読めるが、非表示だと取得ログが完全に失われる。

## Consequences

- 通知は `.backdrop`（ディム）より上・`.stage` より下に立つため、画面を開いている間はパネルの外側に出ている部分だけが暗転した世界の上に読める。
- 通知は常駐HUD（ホットバー・装備HUD・採掘ゲージ・クロスヘア）の裏にも回る。位置（左端縦中央）が離れているため実害はない見込みだが、将来左端縦中央へHUDを足すと通知が隠れる。
- `ToastHost`（右下・ブリッジのエラー/契約違反通知）は `--z-portal-toast` のまま最前面に残す。障害表出は何を開いていても見えるべき系統として、ゲーム内通知とは層序を分ける。
  出所: ユーザー裁定 2026-08-18（Q「Toastは前面のまま」）
- `--z-portal-toast` の利用者は `ToastHost` のみになる。`zLayerTokens.test.ts` の tooltip < toast の関係は Toast 側の要件として維持する。
