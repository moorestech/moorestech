# 削除ツールは選択を積み上げてF長押しで確定し、Shift+クリック2点の箱で範囲選択する

削除ツールの「左ドラッグでなぞり、離した瞬間に消える」挙動をやめ、なぞり選択と箱選択で対象を選択集合へ積み上げてから F キーの長押しでまとめて撤去する方式（Satisfactory の解体に近い感触）へ変える。箱選択は Shift+左クリックで始点セル、次の左クリックで終点セルを指す2点 AABB で、BP コピーと同じセル解決（1x1 設置と同じヒット面の外側セル）と Q/E の高さオフセットを使う。箱は破壊カテゴリーを問わず、一部でも入るブロック・レール・列車車両を全て入れ、接続線は箱では選ばず端点ブロックの撤去に巻き込まれて消える。選択が空のときの F 長押しはホバー中の1件を消す。選択の個別除外は作らず、ESC／パネル外右短押しの全解除だけを持つ。

## Considered Options

- 範囲指定: なぞり選択を廃止して2点直方体だけにする／画面上の矩形ドラッグ（RTS 風） — 棄却。採択: なぞり維持＋Shift+クリック2点の直方体。
  出所: ユーザー裁定 2026-10-15 原文「範囲削除機能を作りたい。削除機能の中に入れる。削除システム自体を変更して、選択をしてから、そのあと何らかのキーを長押しして削除を確定させる。みたいな感じ、satsifactoryみたいな感じ」→ 選択「なぞり維持＋Shift+クリック2点の直方体」
- 確定キー: 左クリック長押し（Satisfactory と同じ）／Delete キー長押し — 棄却。採択: F 長押し。左クリックは選択専用。
  出所: ユーザー裁定 2026-10-16 原文「何らかのキーを長押しして削除を確定させる」→ 選択「F 長押し」
- 選択が空の F 長押し: 必ず先に選択する — 棄却。採択: ホバー中の1件を暗黙の選択として消す。選択が1件以上あればホバーは含めない。
  出所: ユーザー裁定 2026-10-16 選択「ホバー1件を削除する」
- 箱の中身: 箱もカテゴリー固定に従う／箱はブロックだけ — 棄却。採択: カテゴリーを問わず箱内の全部（接続線は箱で選ばない）。なぞりの「同じカテゴリーだけ」の固定はなぞり同士の間だけで効き、箱の影響を受けない。
  出所: ユーザー裁定 2026-10-16 選択「カテゴリーを問わず箱内の全部」
- 個別除外: Ctrl+左ドラッグで外す／選択済みをクリックでトグル — 棄却。採択: 追加のみ。ESC／右短押しの全解除だけ（負債: 大量選択から1件だけ残したいときは選び直し）。
  出所: ユーザー裁定 2026-10-16 選択「個別除外は無し。ESCで全解除のみ」
- 長押しの満了時間は選択件数に応じて伸ばす／agent 提示の 0.5 秒 — 棄却。採択: 誤操作防止の確認として件数に関係なく一定の 2 秒（クライアントの定数。採掘の進捗と同じく `Time.deltaTime` 累積）。
  出所: ユーザー裁定 2026-10-16 選択「件数に関係なく一定時間」＋原文「Fの秒数は2秒」
- 長押しの進捗表示は採掘と同じ画面固定の進捗バー（ProgressBarState）。
  出所: agent前提（採掘の F 長押し前例。別の進捗 UI を増やさない）
- 進捗は F を離す・選択集合が変わる・（空選択時）ホバー対象が変わる・ESC のいずれでも 0 に戻り、選択は残る。
  出所: agent前提（MiningProgressState が対象変化で Focus へ戻る前例）
- 選択件数は選択がある間カーソルツールチップへ常時出す。箱の終点待ち中は箱に入る件数も同じ経路で出し、0 件の終点クリックは追加せず理由をツールチップとログへ残す。
  出所: agent前提（BP コピーの範囲内ブロック数表示と 0 件拒否の裁定 `.decisions/2026-10-08-BPコピーは終点選択中に範囲内ブロック数を出し0個なら確定を拒む.md` と同型）
- 箱の終点待ち中は左クリックを終点確定に使い、なぞり選択は受け付けない。Q/E は箱の始点・終点どちらのセル高さにも効く（BP コピーと同じ）。ESC の段階は「終点待ちの箱を畳む → 選択の全解除 → モード終了」。
  出所: agent前提（BlueprintCopySystem.TryCancelInProgressOperation と DeleteObjectState の二段階 ESC（ADR 0046）の合成）
- 箱の境界: ブロックは占有セルが全部箱内のものだけ／レールは両端点（または片方の端点）が箱内の edge だけ — 棄却。採択: ブロックは占有セルが1つでも交差すれば丸ごと（BlueprintCopyTargetRule と同じ）、レール edge は曲線上の点が1つでも箱内なら丸ごと（両端が箱外でも横切れば消える）。
  出所: ユーザー裁定 2026-10-16 選択「占有セルが1つでも箱に入れば対象」「レールの途中が箱に触れれば対象」
- 列車車両は車両位置が箱内なら対象。接続線は箱の判定対象にしない。
  出所: agent前提（車両は点で位置を持つ最小の規則／接続線の除外はユーザー裁定「カテゴリーを問わず箱内の全部」の選択肢文に含まれていた）
- 箱内でもカメラから見えている対象だけ選ぶ — 棄却。採択: 遮蔽を問わず箱内を全部選ぶ。判定は位置と AABB だけでレイキャストは使わず、隠れた対象はツールチップの選択件数で確かめる。
  出所: ユーザー裁定 2026-10-16 選択「遮蔽に関係なく箱内を全部選ぶ」
- 選択後に箱内へ入った対象や動いた車両: 長押し満了時に箱内を再判定する — 棄却。採択: 選択は対象の集合で箱の形は保持せず、選択時に取り込んだ対象を固定する。後から箱内に入った対象は含めず、選んだ車両は箱外へ動いても消え、選択後に他要因で消えた対象は確定時に読み飛ばす。
  出所: ユーザー裁定 2026-10-16 選択「選択時に取り込んだ対象を固定」
- 一部が撤去できないとき: 1件でも消せなければ選択全体を消さない（対象の列を全件検証してからまとめて撤去する一括撤去プロトコルを新設） — 棄却。採択: 消せる対象だけ消し、残った対象はワールドに残して拒否理由（インベントリ満杯・車両が載ったレール等）をツールチップとログへ出す。削除要求は対象ごとの個別送信のままで、1 回の確定で消えた分が 1 つの Undo バッチ。
  出所: ユーザー裁定 2026-10-16 選択「消せる対象だけ消し、残った対象と理由を表示」
- 箱の Q/E 高さは削除ツール専用のオフセットを持つ — 棄却。採択: 設置モードと同じ `PlacementHeightOffset`（DI シングルトン・HUD に高さが出る）を BP コピーと同じく共用し、箱を畳む・モード離脱で地表へ戻す。
  出所: ユーザー裁定 2026-10-16 選択「共用し、削除モード離脱・箱クリアで地表へ戻す」
- 選択済みとホバーの表示はどちらも赤プレビューで区別しない。Satisfactory の選択上限（50）は設けない。
  出所: agent前提（既存の SetRemovePreviewing を流用。上限を要する根拠が無い）

## 呼び出し側の線引き

- `DeleteObjectState` は毎フレーム削除サービスを駆動し、モード遷移だけを判断する。キー検知・照準・選択・長押し進捗の中身を知らない。
- 削除サービスは入力（左クリック／Shift+左クリック／F 長押し／Q/E）を検知し、選択モデルへ「この対象を足せ」「全解除」「確定」を指示する。進捗バーとツールチップへ値をプッシュする。
- 選択モデル（現 DragDeleteSelection）は入力を知らない。対象の追加・重複排除・なぞりカテゴリー固定・確定時の Undo 記録だけを持つ。
- 箱の解決は「AABB を受け取り、そこに入る IDeleteTarget の列を返す」1 本の問い合わせとし、ブロック／レール／車両の判定はその内部に閉じる。呼び出し側は結果を選択モデルへ足すだけで、種類ごとの分岐を書かない。

## Consequences

- クライアント: 削除サービスに「選択を保持する」「F 長押しで確定する」「箱選択」の 3 状態が入る。BP コピーのセル解決・高さオフセット・範囲ビジュアライザを削除側でも使えるよう共通の置き場へ移す。キーヒントに「Shift+左クリック 範囲選択」「Q/E 高さ」「F（長押し） 削除」を足し、「左ドラッグ まとめて選択」は残す。
- サーバー: 変更なし。
- CONTEXT.md: 「削除ツール」「破壊カテゴリー」を改め、「なぞり選択」「箱選択」「削除の確定」を足す。
- 関連裁定: `.decisions/2026-10-16-削除ツール*.md` 一式。前提となる裁定: ADR 0076、`.decisions/2026-10-04-削除ツール*.md`、`.decisions/2026-10-08-BPコピー*.md`。

## レビュー反映の委任既定

ユーザーの推奨案実行委任により、agent既定として既存対象別応答の結果通知を追加する。新しいユーザー裁定ではない。個別要求・サーバー無変更を維持し、成功分だけを1つのUndoへ確定する。ホバーから独立した結果表示で拒否と未確認を伝える。車両は対象ID付き応答がないため直列要求とtick完了後のID不在確認を使い、未確認中の後続車両要求は保留する。表示体の一時破棄を成功としない。

選択モデルがストローク・ホバー可否・確定・取消手順を所有する。選択変更はUniRxで長押しへ通知し、長押しAdvanceはキー状態と時間のみ扱う。

箱のレール交差は64個の点への近似を廃止し、連続Bezierと半開セル箱の交差で判定する。係数と構成参照はownerの形状・構成寿命で保持し、対象集合そのものは毎フレーム再解決する。これらは承認済みの交差要件を満たすためのagent実装既定である。

UI境界判定はstateが1回評価し、右短押し・スポイト・削除へ共有する。箱の終点待ちでカーソルが面を失った場合は最後の有効箱を保持して件数を再解決し、面未検出の理由を表示して確定を拒否する。
