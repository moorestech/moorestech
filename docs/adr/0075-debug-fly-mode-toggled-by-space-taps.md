# 0075. デバッグ用フライモードはスペース連打で入退し、既存の操作には手を入れない

日付: 2026-10-01
状態: 採択

## Context

広いワールドを検証で移動するために、地形を無視して空中を素早く移動できるデバッグ機能が欲しい（ユーザー依頼 2026-10-01 原文「フライモードデバッグが欲しい。フラモードになると飛べて、走りの2倍の速度で飛べる、シフトを推すとさらに3倍（つまり6倍）の速度で飛べる。スペースを4回連続で発動。スペースを2回で解除。WASD + 高度はQ、E」）。

調査で確認した事実:

- プレイヤー移動は `ThirdPersonController`（StarterAssets 由来・独立 asmdef）が重力・ジャンプ・接地判定・移動ロックを持つ。PlayerAvater.prefab の値は MoveSpeed=3.5、SprintSpeed=7.5（Shift=Sprint）。
- Q/E は既存操作と重なっている。建築モードでは設置高さの下げ/上げ（`CommonBlockPlaceDragState.UpdateHeightOffsetByInput`）、E は `Playable.Ride`（列車への乗車）に使われている。
- デバッグ機能は「デバッグシートの `AddBoolWithSave` トグル＋`DebugParameters` 参照」が前例（FreeBlockPlacement 等）。デバッグシートは配布ビルドにも入っている。
- サーバーの `va:playerCoordinate` はクライアント座標を検証せずにそのまま受け取る。

## Decision

- **デバッグシートの Fly Mode トグル（既定オフ・保存あり）がオンのときだけ、スペース4連打でフライモードに入る。** 配布ビルドでも、シートからオンにすれば使える。
  出所: ユーザー裁定 2026-10-01 原文「スペースを4回連続で発動」→ 選択「デバッグシートのトグル (推奨)」。棄却: 常に有効／エディタ・開発ビルド限定（[[2026-10-01-フライモードはデバッグシートのトグルがオンのときだけスペース4連打で入れる]]）

- **フライ中の速度は SprintSpeed の2倍、Shift 押しで SprintSpeed の6倍とする。** 現在の値ではそれぞれ 15 m/s と 45 m/s。
  出所: ユーザー裁定 2026-10-01 原文「走りの2倍の速度で飛べる、シフトを推すとさらに3倍（つまり6倍）の速度で飛べる」→ 選択「Shift押しの走り 7.5 m/s (推奨)」。棄却: MoveSpeed 3.5 を基準にする（[[2026-10-01-フライ速度の基準はShift走りのSprintSpeed]]）

- **Q/E による上下の速度は、水平の速度と同じにする。**
  出所: ユーザー裁定 2026-10-01 原文「WASD + 高度はQ、E」→ 選択「水平と同じ (推奨)」。棄却: 水平より遅くする（[[2026-10-01-フライの上下速度は水平と同じ]]）

- **フライ中も、地形・ブロック・列車との当たり判定は維持する（すり抜けない）。**
  出所: ユーザー裁定 2026-10-01 選択「通常どおり衝突する (推奨)」。棄却: すべてすり抜ける（[[2026-10-01-フライ中も地形ブロック列車と通常どおり衝突する]]）

- **Q/E の既存の用途（建築の設置高さ・E による乗車）のコードは改変しない。** フライ側は Q/E を読んで高度を変えるだけにする。そのため、建築中に E を押すと上昇と同時に設置高さも+1され、列車を狙って E を押すと上昇と同時に乗車も起きる。これは許容する。
  出所: ユーザー裁定 2026-10-01 原文「WASD + 高度はQ、E」→ 自由記述「デバッグモードのものだからプロダクションの影響を最小限にする」→ 復唱「建築の設置高さや乗車のコードには一切手を入れず、フライ側がQ/Eを読んで高度を変えるだけ」→ 選択「その解釈でよい」。棄却: フライ中は Q/E を高度専用にする／建築・乗車を優先する（[[2026-10-01-フライ中のQEは既存の設置高さと乗車に手を入れず同時に効かせる]]）

- **着地してもフライモードは解除しない。解除はスペース2連打だけ。**
  出所: ユーザー裁定 2026-10-01 原文「スペースを2回で解除」→ 選択「フライのまま維持 (推奨)」。棄却: 着地で自動解除（[[2026-10-01-フライは着地しても維持し解除はスペース2連打だけ]]）

- **連打は、スペースの押下間隔が0.3秒以内なら「連続」と数え、0.3秒を超えたら数え直す。** 発動の4連打と解除の2連打で同じ間隔を使う。
  出所: ユーザー裁定 2026-10-01 原文「スペースを4回連続で発動。スペースを2回で解除」→ 選択「押下間隔 0.3秒以内 (推奨)」。棄却: 0.5秒以内（[[2026-10-01-フライの発動解除の連打判定は押下間隔0.3秒以内]]）

以下は、ユーザーの委任（2026-10-01 原文「残りの質問はいい感じに決めといて」、[[2026-10-01-フライモードの残りの設計判断はagentに委任]]）を受けて agent が決めた事項。

- **Q で下降、E で上昇する。**
  出所: agent前提（建築モードの Q=設置高さを下げる／E=上げると同じ向き）
- **WASD はカメラの水平の向きに沿って動かし、カメラの上下の傾きは無視する。高さは Q/E だけで変える。** キャラクターの向きの回転と Ctrl によるカメラ角の固定は、通常移動と同じ処理を使う。
  出所: agent前提（原文が「WASD + 高度はQ、E」と高度の操作を Q/E に分けているため）
- **フライ中は重力とジャンプを止める。入った瞬間に縦方向の速度を0にし、その場で浮く。解除すると、縦速度0から通常の重力で落下する。** 落下の扱いは通常のジャンプ後と同じ。y<-50 の落下復帰（地表・スポーン地点へ戻す）は、フライ中も解除後もそのまま働く。
  出所: agent前提（重力を残すとホバーできない。落下復帰は通常処理の流用でプロダクションへの影響を増やさないため）
- **発動前の連打で、1回目のスペースは通常どおりジャンプする。** 空中の2〜4回目は、今と同じく何も起きない。フライ中のスペースはジャンプを起こさない。
  出所: agent前提（Jump の既存処理に手を入れないため）
- **移動を止めている間（UI表示中の移動ロック・列車乗車中）は、連打を数えず、フライ中の移動も止める。** 列車を降りたときにフライ中だった場合は、フライのまま再開する。
  出所: agent前提（移動ロックの意味を「プレイヤーを動かさない」で揃える。乗車追従が姿勢を上書きしている間に動かすと競合するため）
- **加減速は使わず、キーを押している間は目標速度で動き、離すとその場で止まる。**
  出所: agent前提（デバッグ移動では位置合わせのしやすさを優先する）
- **フライ中の状態はセーブせず、ゲームを起動した直後は常に通常移動から始まる。デバッグシートのトグルをオフにしても飛行中のフライは解除せず、スペース2連打での解除だけを受け付ける。**
  出所: agent前提（トグルの毎フレーム監視を避け、解除経路をひとつにする）
- **マルチプレイでも、各クライアントが自分のトグルで使える。サーバー側の変更はしない。**
  出所: agent前提（座標同期は既存の `va:playerCoordinate` がそのまま運ぶ。サーバーは座標を検証していない）
- **フライ中を示すHUDは出さない。フライの入り・解除は開発者ログ（Debug.Log）に出す。** アニメーションは、フライの入り・解除の瞬間に Animator のジャンプ・落下の姿勢を下ろす。飛行中はそれらを更新しない（移動速度の値だけが既存どおり流れる）。
  出所: agent前提（プロダクションのUIに手を入れないため）

## Consequences

- 通常移動のコードパスは、フライ中でない限り変わらない。`ThirdPersonController` には「フライ状態と上下入力を外から受け取る口」だけを足す。連打の判定と、デバッグトグルの参照は `Client.Game` 側に置く（基盤にデバッグの語彙を持ち込まない）。
- 建築中・列車の近くで Q/E を押すと、フライの上下と既存の操作が同時に起きる。デバッグ専用の割り切りとして受け入れる。
- 配布ビルドのテスターも、シートからオンにすれば飛べる。サーバーは位置を検証しないので、飛んだ位置へそのまま同期される。
