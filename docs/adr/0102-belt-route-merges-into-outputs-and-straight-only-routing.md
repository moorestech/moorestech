# ADR 0102: ベルト経路は出力口の前を避けず合流し、経路設置は直線ベルトだけにする

- Status: Accepted
- Date: 2026-11-18
- Related: ADR 0097（2クリック設置。本ADRが「既存の出力口の前を途中で使わない」「分岐器手持ちの経路」「手持ちが坂でも直線と同じ」「終点は直線固定」「終点の向き」を置き換える）、ADR 0100（重み付き探索の機構は変えない。「変えないもの」の一部・囲まれ判定の終点手前の高さ・世界の入力辺は本ADRが置き換える）、ADR 0083（合流マスの分岐器モデル。変えない）、ADR 0050（坂ベルトの単体設置。坂のドラッグの形を本ADRが置き換える）、ADR 0055（ベルト張替え。未実装）
- Supersedes: ADR 0097 の該当項（上記）

## Context

ADR 0097 の経路探索は「既存ラインを勝手につなぎ替えない」ために、既存の出力口（機械の搬出口・ベルトの末端・分岐器の分岐先）が向いているセルを経路の途中で使わなかった。機械の搬出口の並びに沿ってベルトを引くと、そこを避けて遠回りする。ユーザーはこれを避けないでほしいと依頼した。あわせて、分岐器・坂を手持ちにしたときの設置方法、ブロックの入口・出口の面を狙ったときの向き、始点・終点の坂を決め直した。

確認した事実（2026-11-18、コードとマスタの読み）:

- 接続（どの出力口がどの受け手へ繋がっているか）: 出力口の辺が向くセルは1つだけで、そのセルが空いているならその出力口は今どこにも繋がっていない、と読んだ。出力口の前にベルトを置いて既存の接続が付け替わる配置は、サーバーの接続実装（`BeltEdgeConnectionResolver` ほか）を読んだ範囲では見つかっていない。これは「反例が見つからなかった」であって、付け替わらないことの証明ではない（原因: 推測。根拠はコードの読みだけで、実行して確かめていない。全配置の網羅もしていない）。実装時に搬送テスト `RoutePassingASplitterExitKeepsTheExistingLineFed` で1配置を実測する。
- 荷物の配分: 出口を複数持つブロック（分岐器、出口が2つある駅・発射台）では、空いていた出口の前にベルトが来ると、既に繋がっているラインへ全部流れていた荷物が新しいベルトにも分かれ、既存ラインへ届く量が減る。機械・チェストは接続先を順番に回して入れる（`ConnectingInventoryListPriorityInsertItemService`、コードの読み）。これは起きる前提で、依頼の「分岐コンベアの分岐先も避けない」の帰結として受け入れる。
- 水平の直線ベルトは入口が背面・左右の3面、出口が正面の1面（`blocks.json` の `inventoryConnectors`）。出力口の前を通ったセルは 2入力1出力の合流マスになる。出口は1つなので 2入力2出力にはならない。
- 坂ベルトの入口は背面の1面だけ。出力口の前のセルが坂になったときは、横から向いている出力は流れ込まない。
- `moorestech_master/server_v8` の全ブロックで、同じ面に入口と出口が同居する例は無い。狙った面が出力口かどうかは一意に決まる。
- 始点はブロックの面を見ずに R の向きだけで決まっていた。終点はどの側面に当てても「ブロックへ差し込む向き」で、出力口の面に当てると出力口と正面衝突する向きになっていた。

## Decision

### 1. 経路設置は直線ベルトだけ。分岐器・坂は単発設置

- ビルドメニューで選んだブロックが「ベルトファミリーの直線ブロックで、かつ分岐器ではない」ときだけ経路設置（`BeltConveyorPlaceSystem`）に入る。分岐器・上り坂・下り坂は通常ブロックと同じ単発設置（`CommonBlockPlaceSystem`）に入る。
  - 出所: ユーザー裁定 2026-11-18 原文「分岐コンベア、登りコンベア等は他ブロックと同じように単発設置で良い」
- 坂・分岐器を手持ちにした左ドラッグも通常ブロックと同じ（同じ高さに横一列のドラッグ列）。ADR 0050 の「毎セル+1段の階段」は置き換える。出所: 上の原文の字義（「他ブロックと同じように」）。ドラッグ列まで含むかを個別には尋ねていない。
- 分岐器手持ちの経路（全セル分岐器・曲がりは出口側）は無くなる。`BeltRouteQuery.TurnByOutput`、`BeltConveyorHoldingBlock.IsSplitter`、分岐器の使わない出口の受け手を見る規則（`FeedsForeignInput`）と、それだけが読んでいた `IBeltRouteWorld.InputFaceBits` を削除する。出所: agent前提（上の裁定の帰結。経路に分岐器が入らなくなるので読み手が居なくなる）。
- 直線ベルトを手持ちにした経路の途中に坂が入る動き（探索がセル種別を決める）は残す。出所: agent前提（依頼は手持ちが分岐器・坂のときの話で、直線手持ちの経路は依頼外）。

### 2. 既存の出力口の前を避けない

- 経路の途中セルが既存の出力口（機械の搬出口・ベルトの末端・分岐器の分岐先）の前に来てもよい。そのセルが水平の直線ベルトなら合流マス（2入力1出力）になり、見た目は ADR 0083 の合流マス描画に切り替わる。
  - 出所: ユーザー裁定 2026-11-18 原文「ブロックのアウトプットスロット に並べるように置くとそこを避ける仕様になっています。それをさけないようにしてほしい。全例。分岐コンベアの分岐先も今さけるようになっているけど避けないようにして」
  - 出所: ユーザー裁定 2026-11-18 原文「2入力2出力になったりしてしまうことがあるので、そのときは合流化を優先し、2入力１出力に化ける」「設置後に2入力2出力にばけられないじゃんってはなし。1入力、1出力は機械の出入り口を想定。」（機械の出口から機械の入口へ引く経路が途中で別の出力口の前を通ると、そのセルは合流になる、という確認）
- 残す規則（出所: agent前提。2026-11-18 に「全例に含めず残すつもり。違えば言ってください」と提示し、異論は出ていない。黙認なのでユーザー裁定ではない）:
  - 終点自身の前のセル（終点が流す先）は経路の途中で使わない。使うと終点が自分の経路へ流れ込む輪になる。実装上は「終点自身の出口の辺を、途中セルの入口の面が受けない」検査として残す。
  - Ctrl 分岐で、分岐器の使わない出口の隣に受け手があるときは分岐不可にする。
  - 既存の坂の真上・自分の坂の真上を空ける規則。

### 3. 始点で出力口の面を狙ったらブロックから離れる向き、終点で狙ったら R の向き

- カーソルがブロックの側面に当たっていて、その面が出力口（カーソルのセルの高さで、そのブロックからカーソルのセルへ向く出力の辺がある）のとき:
  - 始点は、ベルトの向きを「ブロックから離れる向き」にする。その出力を受けて経路が始まる。出所: ユーザー裁定 2026-11-18 原文「ブロックの入口、出口にフォーカスしたときは、「そこからアウトプットする　インプットする、これについては多分考慮漏れあるのでまずは考えて」。離れる向きにする案は 2026-11-18 に表で提示し、異論なし（黙認。明示の採択ではない）。
  - 終点は R の向き（ブロックへ差し込む向きにはしない）。出所: ユーザー裁定 2026-11-18 原文「終点が出力面にかぶったらそりゃ今までどおりr回転しかなくない？そうしないと絶対経路なしにならない？」。agent が一度「終点も離れる向き」を agent前提として提示し、この回答で覆った。
  - 始点のセルをもう一度クリックする単発設置は、今までどおり終点と同じ判定を使う（出力口の面なら R の向き）。出所: agent前提（ADR 0097 の「向きと可否の判定は終点と同じ」のまま）。
- 出力口でない側面:
  - 始点は従来どおり R の向き。入力口の面に当てても R の向きのまま。出所: ユーザー裁定 2026-11-18 原文「2 juuraidoori」「R」「deかいてん」（質問「始点を入力口の面に当てたときはどうしますか」への回答）。
  - 終点は従来どおりブロックへ差し込む向き。出所: agent前提（ADR 0097 のまま）。
- 天面・底面・地面に当たったときは従来どおり R の向き。

### 4. 終点は下り坂に化けてよい

- 終点のセルは直線か下り坂。下り坂の終点は1つ上の高さから入り、終点の向きへ終点の高さで出る。坂は曲がれないので、手前のセルの出る向きが終点の向きと同じときだけ。終点の真上のセルは空いていること（既存ブロックが無い・始点でない・自分の経路が通らない）。
  - 出所: ユーザー裁定 2026-11-18 原文「後追加しよう、終点始点は　斜めコンベアに化けてもいい　つまり今は終点が斜めを許可していません」
- 始点は今までどおり直線か上り坂。
- 始点の下り坂・終点の上り坂は作らない。出所: ユーザー裁定 2026-11-18 原文「始点の下りと終点ののぼりは、そのとおり、おけ」（agent の提示「始点の下り坂・終点の上り坂は作らない」への回答）。根拠: (a) 始点の下り坂は直線と同じ高さへ出るのにコストが高く、終点の上り坂は直線と同じ高さから入るのにコストが高いので、探索が選ぶことが無い。(b) 始点の下り坂は入口が1つ上の高さ、終点の上り坂は出口が1つ上の高さになり、始点・終点のセルの高さにある機械の搬出口・搬入口と繋がらなくなる。
- 始点のセルをもう一度クリックする単発設置は直線のまま。

## Considered Options

- 始点を入力口の面に当てたとき、流れを逆にして終点→始点へ引く: 2026-11-18 に提示。端点規則の作り直しが大きい。ユーザー裁定で不採用（「従来どおり」「R で回転」）。
- 終点を出力口の面に当てたとき、ブロックから離れる向きにする: 2026-11-18 に提示。ユーザー裁定で不採用（R の向き）。

## Consequences

- 分岐器など出口を複数持つブロックの空いた出口の前を経路が通ると、そのブロックから既存ラインへ届く量が減る（新しい経路と分け合う）。
- 出力口の前を通る経路は、置いた瞬間に既存の宙に浮いた出力を受け始める。意図せず合流させたくないときは、利用者が経路を置いたあとでベルトを撤去するか、終点・始点を別のセルにして引き直す。
- 分岐器だけを並べた経路を一度に置く手段は無くなる（1個ずつか、通常ブロックと同じドラッグ列で置く）。
- 未実装の ADR 0055（張替え）は「手持ちが坂や分岐器でも `BeltConveyorPlaceSystem` に入る」前提で書かれている。張替えを実装するときは、坂・分岐器手持ちが通常設置へ入る本ADRの振り分けに合わせて 0055 を見直す（本ADRでは 0055 を書き換えない）。
- 囲まれ判定（ADR 0100）の「終点の手前は同じ高さか1つ下だけ」は、下り坂の終点が1つ上から入るので「高さ差±1以内」に変わる。
- 坂を手持ちにして2クリックで経路を引く操作は無くなる（直線を手持ちにする）。
- 参照ソルバ突き合わせ・ランダム試験の問い合わせ生成から分岐器手持ちを外す。終点の種別は直線か下りを許す形に検査を変える。
- 独立質問の消し込み（moores-grill-with-docs §1.7）は実施していない。個人スキル `codex-audit` が作業マシンの `~/.agents/skills/` に無く実行できなかった。ユーザーへ 2026-11-18 に省略の可否を尋ね、回答は「3 意味不明」。平易に説明し直したうえで省略して進めた（省略の明示の承認は得ていない）。
