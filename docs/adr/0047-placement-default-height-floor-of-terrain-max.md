# ADR 0047: ブロック設置の既定Yは地形最高点を含むセルにする

- Status: Accepted
- Date: 2026-08-30
- Supersedes: ADR 0037 の「設置セルYを地形最高点を上回る最初のセルにする」決定（フットプリント最高点プローブとドラッグの地形追従は維持）

## Context

ADR 0037 で設置Yを「占有範囲の地形最高点を**上回る**最初のセル」にしたが、実プレイでは既定（手動オフセット0）が
大きく浮き、手動で `-1` した状態がちょうど地形に沿う。

`PlacementGroundCellResolver.ResolveCellY`
（`moorestech_client/Assets/Scripts/Client.Game/InGame/BlockSystem/PlaceSystem/Ground/PlacementGroundCellResolver.cs:31`）は

```csharp
return Mathf.CeilToInt(groundMaxHeight - IntegerGroundTolerance) + heightOffset;
```

で、上方バイアスが二段重なっている。

1. `GroundHeightProbe.TryGetFootprintMaxGroundHeight` が占有セル4隅の**最高点**を基準に取る
2. その上でさらに切り上げる

地形高さは `HeightmapStage`（ブレンド→ブラー→スロープ平滑）を通った連続値で、整数へ量子化されていない。
よって 2 だけで常に 0〜1 セル浮き、斜面ではカーソル直下と最高角の差が上乗せされて1セル近くに達する。
`IntegerGroundTolerance = 0.001f` は「地表がちょうど整数のとき浮かせない」ためのもので、この浮きには効かない。

ブロックのモデル原点Yはセル座標Yそのもの（`BlockDirection.GetBlockModelOriginPos` は全方向で addPos.y = 0）なので、
セルYがそのまま底面の高さになる。座標系側のズレではない。

## Decision

**既定の設置セルYを「地形最高点を含むセル」にする。**

- `CeilToInt` を `FloorToInt` 相当へ変える。フットプリントの最高角が最大1セル沈む
- **通常ブロック設置から地形重なりゲートを外す。** 1段下げると必ず地形へ食い込むため、
  `PlacementCellReasonReporter.ApplyGroundOverlapsAndReport` による `Placeable = false` と
  `AddBlockedByTerrain` を通常設置の経路から落とす。地形の中に完全に潜る位置でも設置できるようになる
- 適用範囲は通常ブロック設置（`CommonBlockPlaceSystem` の単体設置＋ドラッグ範囲設置）のみ
- フットプリント最高点プローブとドラッグの階段状地形追従（ADR 0037）は維持する
- 手動オフセット（Q/E の `HeightOffset`）は基準に加算する形のまま。基準が1下がるので同じ操作で1低い位置になる

出所: ユーザー裁定 2026-08-30 原文「いまの高さ-1をデフォルトの高さとする」
／原文「そもそも、いま-1がちょうど地形に沿うようになってて、0がすごく浮いた状態になってておかしい」
→ 選択「地形最高点を含むセルへ (floor)」「通常設置からゲートを外す」「通常ブロック設置だけ」

裁定記録: `.decisions/2026-08-30-ブロック設置の既定高さは地形最高点を含むセルにする.md`

## Considered Options

### 1. 四捨五入（地形最高点に一番近いセル）

浮きも沈みも最大0.5セルに収まり、ADR 0037 の「ほとんど埋まらないようにしたい」とも正面衝突しない。
ただし地表の端数が 0.5 を超えるケースでは「いまの高さ-1」にならない。

見送り理由: agent前提。選択肢として提示したがユーザーは実測（`-1` が沿う）を優先したため採らなかった。この案への裁定は取っていない。

### 2. 一律 -1（棄却）

文字どおり現在値から常に1引く案。地表がちょうど整数の平地でもブロックが丸1セル埋まる。
floor なら平地は接地のまま変わらないため、そちらを採った。

棄却理由: ユーザー裁定 2026-08-30 選択「地形最高点を含むセルへ (floor)」。

### 3. 論理セルは据え置き、見た目だけ下げる（棄却）

ADR 0037 の Considered Options 1 と同じ案。積み重ね時のレイ面スナップとベルト継ぎ目の段差が再発する。

### 4. 地形重なりゲートを深さ判定へ緩める（棄却）

「触れたら不可」をやめ「基準セルより深く沈んだら不可」にする案。意図した1段の沈みは通し、崖に突き刺さる配置だけ弾ける。

棄却理由: ユーザー裁定 2026-08-30 選択「通常設置からゲートを外す」。判定を単純に保つことを優先した。

## Consequences

- 平地（地表が整数ちょうど）の設置高さは変わらない。変わるのは端数のある地表と斜面
- 斜面では最高角が最大1セル沈み、低い側の隙間は1セル分縮む
- 通常設置では地形を理由にした設置不可が無くなる。**崖の中・地下に完全に潜って見えないブロックも設置できる**。
  採掘機やベルトが見えないまま稼働しうるのは意図した割り切り
- 「地形に埋まっています」のツールチップ文言（`PlacementFeedback.AddBlockedByTerrain`）は
  電柱・レール・歯車ポールで引き続き使うため残す
- `PlacementBlockCause.GroundNotFound`（地表そのものが見つからない）は通常設置でも維持する
- ADR 0037 の「埋まるくらいなら浮かせる」は撤回。「浮くくらいなら埋める」が新しい正になる
