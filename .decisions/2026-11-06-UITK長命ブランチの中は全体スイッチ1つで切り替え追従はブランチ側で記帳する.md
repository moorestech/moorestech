# UITK 長命ブランチの中は全体スイッチ 1 つで切り替え、Web への追従は長命ブランチ側で記帳して優先する

決定:
- 長命ブランチの中でも、画面ごとに Web と UITK を振り分ける所有表は使わない。「全部 Web／全部 UITK」の 1 つのデバッグスイッチに置き換える。UITK にしている間、UITK 側にまだ無い画面は使えない。
- 追従ゲート G1 と追従台帳は master から外し、長命ブランチへ移す。master の Web 開発者は UITK を意識しない。長命ブランチへ master を取り込むたびに、その回に入った Web の差分を長命ブランチ側で記帳する。
- Web の更新を追いかける作業と未移植画面の実装が両立しないときは、移し終えた画面の追従を優先し、その分だけ残り画面の完成を延ばす。
- 切替前のビルドはどこにも配らない（テスターにもオーナー向け staging にも）。確認は Unity Editor の中だけ。切替 PR は配布物から CEF を消すので、その PR の中でだけ Windows/Mac ビルドと検証機の通し検証を回す。
棄却案: 長命ブランチの中は段階 1 の画面別の所有表を使い続ける／G1 を master に残し、Web の新画面を足す人がその場で台帳に行を足す／未移植画面の実装を優先し、追従差分は台帳に積んで全画面がそろってから解消する／全部そろってから別の Steam ブランチで希望テスターに先行配布する／段階の区切りでオーナーが staging ビルドを目視する／途中段階から別 Steam ブランチで配る／切替 PR でもビルド検証をしない
帰結: 段階 1 の所有表・委譲・Editor 限定の上書きは全体スイッチへ作り直しになる。切替前に配布環境で UITK に触れるのは切替 PR の検証だけになる。
