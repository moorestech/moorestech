# 分岐と合流のbufferは先頭を回収したtickに後続を満額進める

日付: 2026-10-18
文脈: スループット回帰テスト（ADR 0084）で、直線＋分岐マスが畳まれた多マスの分岐segmentが 5776 tick に 2〜6 個欠けた。原因は実測: 段階1で先頭を出口でクランプしてから回収するため、密着した後続が超過分の進行量を失う（121 tick ごとに着荷間隔 20→21）。後続のいない1マス分岐と、超過分を持ち越す通常segment境界では欠けない。
決定: `BeltBufferedSegment.CollectForBuffer` を「buffer が空で先頭がこの tick で出口に届くなら先頭を回収し、後続は `Advance(true)` で満額進める。満杯のときだけクランプする」に変える。出所: ユーザー裁定 2026-10-18「F1は Core を『buffer が空なら先頭の超過分を回収に使い、後続は満額進める』に直す方向で修正を」
棄却案: 現状値を B（特性値）にピン止めする。
理由: 割り切る整数速度は出口にちょうど着く十分条件ではなく（進入距離で位相がずれる）、buffer の回収規則が通常segmentの持ち越しと非対称だった。参照実装 README §1tickの順序 1. と異なるので、README はユーザーが更新する。
