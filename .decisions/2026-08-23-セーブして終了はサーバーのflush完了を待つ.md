# セーブして終了はサーバーのflush完了を待つ

決定（2026-08-23 ユーザー裁定 / moores-code-review run 2026-08-23-1930 D1）:
`SaveAndQuitPresenter` の固定2秒待ちをやめ、既存 `Client.Game.Common.GameShutdownEvent` に完了集約
（`RegisterShutdownTask(UniTask)` / `FireGameShutdownAsync()`）を足して、サーバー `ServerStarter.ShutdownAsync()`
のセーブflush完了を await してから `Application.Quit()` する。待ち上限はサーバー側 `SaveFlushWaitFrameLimit`(600) に一本化。
待ち順序も「セーブ要求→flush完了待ち→Disconnect→Quit」へ入れ替える。新規クラスは作らない。

棄却案:
- 固定待ちを12秒へ延長 / サーバー側 `SaveFlushWaitFrameLimit` を短縮 — 正常系でも毎回待たされ出展の回転が落ちる、
  または flush 上限をクライアントUI都合で削ることになり依存方向が逆転する
- 現状維持（固定2秒） — 低fps・大規模ワールドで最後のセーブが無言で欠落する。R6は通常モードにも及ぶ唯一の正規終了経路

理由: 症状が「最終セーブの無言喪失」で不可逆かつ全プレイヤーに効くため。副次的に、2秒窓で切断済みソケットへの送信が
無言破棄される／赤字の切断表示が出うる問題も順序入れ替えで同時に解消する。
