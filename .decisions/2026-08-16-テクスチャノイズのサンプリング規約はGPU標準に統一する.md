決定: Task 14 で復元した placementNoise のテクスチャサンプリングは、移植元 MM の `Texture2D.GetPixelBilinear`（実測で `uv*size` 原点）ではなく **GPU 標準規約（テクセル中心基準 `uv*size-0.5` + Clamp）** を採用する。移植の忠実性最優先の原則に対する意図的な逸脱として扱い、逸脱理由を `ManagedNoise.GetPixelBilinear` 直上のコメントに明記する。補間核（重み・近傍の取り方・チャンネル抽出）が移植元と同一であることは Unity 実機との格子照合テストで固定する。

棄却案: `uv*size` 原点へ寄せて移植元とピクセル一致させる案（計画が本文で与えたテスト値「2x2中央=0.5」を書き換える必要があり、そのテストは最近傍退化を検出できなくなる）。スキーマに規約選択キーを足してマスタで切り替えられるようにする案。

理由: 忠実性の原則は「観測可能な結果を変えない」ためのものだが、この規約差で見た目が変わるアセットが**MM側40件・moorestech側180件のどちらにも1枚も存在しない**（全て未設定）ため、守るべき対象が無い。`uv*size` は Unity の CPU API 固有のズレであってシェーダ・他エンジンは全て中心基準であり、新規に書くサーバー側コードへ欠陥を写経することになる。また `uv*size` は UV 上端の半テクセルが到達不能になり、マスクを地形いっぱいに引き伸ばす用途で不本意。加えて計画が指定したテストが MM 規約下では「バイリニアか最近傍か」を区別できない検査に成り下がる。規約選択キー案は利用箇所0件の機構に分岐を増やすもので YAGNI に反する。唯一の反対材料は「将来 MM の Inspector でマスクを作り込み PNG をそのまま持ち込んでピクセル一致させたい」ワークフローだが、MM は凍結済みの移植元でマスクは1枚も存在しない。
