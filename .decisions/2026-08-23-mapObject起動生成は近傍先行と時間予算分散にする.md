# mapObject起動生成は近傍先行と時間予算分散にする

決定（ユーザー裁定 2026-08-23）:
- 起動待機はPlayerPos中心・半径150mの近傍のみ。残りはゲーム開始後にPlayerPosからの距離順で後着生成
- フレーム分散は個数固定(100個)を廃止し時間予算制（近傍=ローディング中16ms/フレーム・後着4ms/フレーム）
- 未生成個体宛の破壊/HPイベントはinstanceId台帳に最新状態を保留し、生成時にhandshakeスナップショットより優先適用
- 全量完了の待機は正規API（WaitForAllInstantiatedAsync）として公開し、テスト・プレイテストDSLはそれを待つ
- 実装はfeature/nearest-search-kd-treeブランチ起点（Register→dirtyが後着追加を吸収）
- 露頭(Outcrop)は対象外・現状維持
- Initialize内GetComponentsInChildren走査は計測し支配的なら是正（スコープ内）
- 時間予算計測のStopwatchは「実時間API禁止」規約の適用外（サーバーゲームロジックでなくクライアント描画分散のため）

棄却案:
- 近傍中心をMapLayout.Spawnにする — 遠出セーブ復帰で足元未生成のまま開始するため棄却
- 後着をLayout配列順 — 近い所が数十秒空きうるため棄却
- 未生成宛イベントを現状どおり捨てる — 後着窓が分単位に伸び古いスナップショットで復活して見えるため棄却
- 全期間同予算16ms — ゲーム開始直後の操作感が落ちるため棄却（誤選択を即時訂正、推奨案採択）
- 個数固定のまま近傍先行のみ — 短縮効果が半減するため棄却
- master起点/k-dマージ待ち — 同一生成ループの確実なコンフリクト/待ちのため棄却
- 露頭も近傍先行化 — k-d側「露頭は完了時1回構築」を崩す割に効果が薄い（1,775件≈35フレーム）ため棄却
- 全量待機APIを作らずテストを近傍内個体に限定 — テストワールド配置依存になるため棄却
