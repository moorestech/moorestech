# 通知背面e2eのピクセル比較は不透明マスで行う

裁定日: 2026-08-18 / 出所: ユーザー裁定

## 決定

通知が `.stage` 背面にいることを確かめる e2e のピクセル比較は、**アイテム入りスロット（`rgb(254 254 254)` の完全不透明面）** を重なり先に固定し、その領域で before/after の完全一致を要求する。
比較は同一実行内の before（通知なし）/ after（通知あり）であり、保存ベースラインとの比較ではない。

plan の R1 受け入れ基準の文言「`main-grid` 全体の描画が通知の有無で変化しない」は、この形へ改める。

## 理由

moorestech の UI 面は意図的に半透明（`.slot` = `rgb(50 52 67 / 50%)`、`--surface-navy` = `rgb(10 14 27 / 80%)`。世界が透ける設計 / webui-design）。
そのため通知が**背面にいるまま**でも空きスロット越しに合成されて薄く透け、grid 全体での完全一致は原理的に成立しない。
一方、通知が前面へ回れば不透明マスの画素は必ず変化するため、不透明領域に限った一致要求でも「背面にいる」の検出力は落ちない。

## 棄却した案

- **grid 全体を残し差分に閾値を設ける** — 閾値の根拠が経験値になり、将来 flaky 化する。
- **ピクセル比較自体を廃止し z 値と DOM 位置だけで固定する** — 実描画結果を見る検証が消え、実挙動の証拠が弱くなる。
- **スロット・パネル面を不透明化して plan の文言どおり成立させる** — 「世界が透ける」意匠を全画面で変えることになり、色・装飾を変更しないという本 plan のスコープを大きく超える。
