決定: 日次フルビルドの対象は Client Windows/macOS + Server Windows/macOS の4ジョブとし、Linux dedicated server は戻さない。build.yml:141 の「Linux はランナーの容量が足りないためクライアントビルドは除外」というコメントは実態と食い違うため、CEFネイティブランタイム不在が理由である旨へ修正する（[[2026-08-02-Linuxビルド入口は意図的失敗として残す]]）。
棄却案:
- Linux server を復活させ free-disk-space で容量問題を検証する（「全PFが通る」が初めて事実になるが、Linuxが直らない場合に赤い日次が常態化し、無人修復パイプラインを毎晩空振りさせる）
- Linux server だけ週次の別ワークフローで回す（日次の安定は保てるが層が1つ増える）
- CEFのLinuxランタイムを用意してクライアントLinuxまで解く（CIの範囲を超えクライアントの依存関係に踏み込む規模）
理由: 今回の変更の主眼はCIの粒度再設計であり、4ヶ月止まっているLinuxの復旧を同時に抱えると、無人修復ループの初期安定を最優先すべき時期に恒常的な赤を持ち込む。Linux復活は独立したタスクとして分離する。
