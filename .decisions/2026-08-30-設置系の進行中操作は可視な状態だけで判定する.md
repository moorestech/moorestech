# 設置系の進行中操作は可視な状態だけで判定する

- 日付: 2026-08-30（moores-code-review C4 の裁定）
- 関連: docs/adr/0046-right-short-press-closes-ui-and-build-mode.md（「起点/選択があればそれだけ解除」）

## 症状

`IPlaceSystem.TryCancelInProgressOperation()` の「進行中操作」の定義が設置系4種でバラバラだった。
歯車ポールを設置した直後の応答待ち（数百ms）に右短押しすると、電線なら「起点解除だけでモードに留まる」ところを
歯車・線路は建築モードごと GameScreen へ抜ける。BPコピーは名前入力中の右短押しで入力途中の名前ごと閉じる。
さらに電線は false を返す経路でも `_sourceBlock = null` と `Invalidate()` を無条件実行しており、
「false＝解除したものが無い」という interface のコメント契約と食い違っていた。

## 決定

**可視な状態だけを「進行中操作」とする。** 電線から `IsAwaitingResponse` を落とし、false を返す経路の副作用も
早期returnで消して他3実装と同形にする。`IPlaceSystem` の契約コメントも実装に合わせる。
BPコピーの名前入力待ちは現状維持（モードごと閉じる。`Disable()` が後始末する）。

## 棄却案

- **応答待ちも進行中に数える**: 4系統すべてを `状態 != null || sender.IsAwaitingResponse` に揃え、
  BPコピーは `_isAwaitingName` も数える。送信中の取り消しができるようになるが、線路に
  `TrainRailPierRequestSender` 相当の切り出しが必要でPRが大きくなる。「目に見えているものがあればそれを消す」
  という一貫規則のほうが挙動として説明しやすい。

## 帰結

「見えない応答待ちだけで true を返し、右短押しが可視の変化なく握り潰される」現象も同時に消える。
