# PlayMode検証を保留したまま最終レビューまで進める

- 日付: 2026-08-23
- 文脈: plan `docs/superpowers/plans/2026-08-23-mapobject-near-field-instantiation.md` Task 5〜7 / bd: moorestech-4z88

## 決定

`uloop run-tests` がPlayMode遷移テストのフィルタに対してだけ即座に "Domain Reload in progress" を返し、テストが起動すらしない固着が解けないため、**PlayMode検証を保留したまま Task 6・Task 7（最終ブランチレビュー）へ進む**。PlayMode検証は別タスクとして起票し、Editorが落ち着いた時点で行う。

## 棄却した案

- 他worktreeのUnity Editor 2本（nearest-search-kd-tree・hpbar-overlay）を閉じてリソース競合を解消してから再試行する案 — k-d treeセッションが平行作業中であり、そちらを止めることになるため
- ブランチはそのままに新規worktreeを切り、クリーンなLibraryで検証し直す案 — 作成に3分強かかるうえ、Editor状態起因である確証がない

## 理由

実装本体は完了しており（Task 5 `ef6b3dcf3` はレビュー時点で26/26 PASS、Spec ✅、プロダクションコードは全レビュー観点 ✅）、その後のfix `936aa7a30` は**テストコードのみの変更**である。fixは `uloop compile` Error 0 / Warning 0 と EditMode単体テスト 13/13 PASS で検証済み。

未検証なのはPlayMode遷移テスト2本の実行結果のみであり、ここで止めるより最終レビューまで通してPRの形にする方が価値が高い。

## 固着の再現条件（申し送り）

- 同一Editor・同一時刻に EditMode単体テスト（13件）は正常完走する
- PlayMode遷移テストのフィルタだけが2秒で "Domain Reload in progress" を返す
- PlayModeに入った形跡（`UserSettings/UnityMcpSettings.json` の `.bak` 退避）が出ない＝テストが起動していない
- Editorクリーン再起動4回・`uloop fix`・`control-play-mode --action Stop`・長時間放置・compileを挟む/挟まない のいずれでも再現
