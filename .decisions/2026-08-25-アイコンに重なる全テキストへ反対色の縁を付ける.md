# アイコンに重なる全テキストへ反対色の縁を付ける

決定: Web UI でアイコンの上に重なるテキスト5系統（`ItemSlot .count` 個数バッジ／`RecipeBox .materialCount` 所持・必要／`research .consumeCount` 消費数／`FluidSlot .amount` 液体量／`HotbarPanel .num` キー番号）すべてに縁取りを付ける。縁の色は文字色の反対色（黒文字には白縁・白文字には黒縁）とし、**太さは全系統で1つに揃える**。文字色そのものは現状維持（黒文字系は黒のまま・白文字系は白のまま）。

棄却案:
- 黒文字系（ItemSlot個数・所持/必要）だけ白縁を強化し、白文字系は据え置く（症状箇所は直るが「黒文字＋極薄白縁」「白文字＋黒縁」「1方向ぼかし影」の3様式混在が残る）
- `ItemSlot` の個数バッジ1箇所だけ直す（レシピ画面の所持/必要・研究の消費数に同じ症状が残る）
- 白文字系も縁を白へ揃えて「全部白縁」に統一する（明るいアイコン上で白文字＋白縁が同化して逆に読めなくなる）

理由: 黒っぽいアイコンの上で黒い数量が沈む症状の根治には縁が要るが、白文字に白縁を付けても縁が文字と同化して視認性は上がらない。「背景の反対色の縁で文字を浮かせる」を原則に据えると、太さ1つ＋色2つで5系統を1様式に畳める。なお `--count-text: #111` の2026-08-17裁定は「バッジが出るのは明色面のみが前提」と書かれていたが、その前提が黒いアイコンで崩れたのが今回の症状であり、文字色は据え置いたまま縁で解く。
