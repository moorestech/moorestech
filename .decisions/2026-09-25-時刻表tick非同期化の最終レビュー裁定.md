# 時刻表tick非同期化の最終レビュー裁定

決定: PR #1415 改訂（時刻表・自動運転フラグの tick 非同期化）の moores-code-review 最終レビューで出た設計判断 D1〜D6 を次のとおり裁定する。
- D1 A: 時刻表の取得状態（読み込み中／取得不可／取得済み）を判別共用体で UI まで運び、表示を分ける。
- D2 A: クライアントの時刻表データストアは通信形（MessagePack）でなくドメイン型 `TrainTimetableSnapshot` で保持する（`ToModel()` を使う。前例 TrainUnitClientCache）。
- D3 A: `TrainUnitClientCache` に列車単位の適用通知を戻し、開いている時刻表タブは連結・分割で列車IDが変わったら再配信・再取得する（既存 Train コードの改修を伴う）。
- D4 A: 時刻表の取得は「時刻表タブを選んだとき」に Web UI が送るアクションで始める（列車インベントリを開いただけでは取得しない）。取得状態のリセットはサブインベントリの開閉から行う。
- D5 B: tick 内で自動運転が OFF になった経路の走行状態は、master と同じくハッシュ不一致→再同期に任せる（追加の snapshot 通知はしない）。
- D6 A: 時刻表の取得をテストで差し替えられる境界を設け、要求回数・重複抑止・閉じた後の再要求・失敗時の再要求を EditMode テストで守る。配線全体は unityプレイ録画テスト1本で守る。

棄却案: D1 B（状態フィールドの並置）／D2 B（通信形のまま保持し ToModel 削除）／D3 B（publish 毎の再解決）・C（別issue）／D4 B（取得起点は列車インベントリ表示のままで裁定文言を修正）／D5 A（tick 内の自動運転変化で走行 snapshot も送る）／D6 B（録画テストのみ）。

理由: ユーザー発言「D5はB、他はA」（2026-09-25）。選択肢は moores-code-review の design.md（runs/2026-09-25-1300-pr1415-fix）をそのまま平文で提示した。
