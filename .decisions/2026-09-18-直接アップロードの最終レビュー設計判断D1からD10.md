# 直接アップロード（ADR 0064）最終レビューの設計判断 D1〜D10

出所: ユーザー裁定 2026-09-18（moores-code-review 最終ブランチレビュー design.md の D1〜D10 に対し、すべて推奨案を選択）。詳細: moorestech_logs/harness/moores-code-review/runs/2026-09-18-1745/design.md・integrated.md。

- D1 件数上限128: 宣言を優先度順（manifest/world/snapshots → logs 等 → frames/）にし、必須群が上限に掛かった箱は Sent にせず箱固有の恒久失敗。静止画 fps を下げて上限内に収める。棄却: 上限引き上げ／frames のアーカイブ化。
- D2 2xx の契約違反応答: PlaytestApiResultKind.MalformedResponse を新設（Retryable・走行は止めない）。complete は {ready:true} を型検証。棄却: 恒久失敗扱い／現状維持。
- D3 送信後に分かる 4xx: 署名付き PUT の 4xx（403 除く）はそのパスだけ skipped にして prepare からやり直す。棄却: 箱単位のまま ADR 追記。
- D4 403/設定漏れ: (1) Worker は R2 設定の空値で 500 server-misconfigured (2) 署名付き PUT の 403 は R2 の Code で分け期限切れ系だけ Retryable (3) LocalUnreadableFile は箱固有の恒久失敗。棄却: 空値検査のみ／走行跨ぎカウンタ／403 再発で Unauthorized。
- D5 失敗段階: enum PlaytestUploadStage＋factory、判定は PlaytestUploadFailurePolicy.Decide 一本。棄却: factory のみ。
- D6 DECLARED: write-once。同じ path+bytes 集合なら再署名、違えば 409 declaration-conflict、クライアントは恒久失敗として数える。棄却: 差し替え時に旧キー削除／現状維持。
- D7 原本の差し替え: 署名に If-None-Match: * を含め、再 prepare は宣言どおりの長さで既存のファイルに URL を出さない。書き込み直前に ACK を再確認。棄却: sha256 署名／現状維持。
- D8 アイドル期限: 独自 HttpContent が固定長チャンクを書き出すたびに期限を延ばし、本文送信後は応答待ち用の期限に切り替える。棄却: 実機確認に委ねる。
- D9 worldDefinition: 再生側が manifest の worldDefinition を読んで分岐し、中身との食い違いを理由付き Reject。値は enum {Full, GeneratedWorldJsonOnly, NotCaptured}。棄却: enum 化のみ／現状維持。
- D10 ReplayCheck 以外の消費者: prepare-run.sh と bug-report-auto-fix は resolver で地形付きワールドを実体化してから起動する（plan の「消費者は現状無い」は誤りだった）。棄却: 範囲外を裁定で確定。
- 本体判断（設問外）: D11 worldId 導出の共有化は plan の非目標どおり別 PR。D12 10 ファイル規約はアップロード関連の新規 TS を src/uploads/ へ移す（ファイル分割は設問対象外の規約）。
