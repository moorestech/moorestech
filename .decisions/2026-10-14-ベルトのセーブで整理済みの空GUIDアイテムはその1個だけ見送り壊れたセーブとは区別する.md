# ベルトのセーブで整理済みの空GUIDアイテムはその1個だけ見送り壊れたセーブとは区別する

日付: 2026-10-14
文脈: mod を外したワールドをロードすると、欠損マスタの整理（MissingItemReferenceCleaner）がベルトの保存要素 `{itemGuid, entryDirection, distanceToExit}` の itemGuid を空GUIDに書き換える。ロード側（BeltTransportLoadedStateConverter）は空GUIDを「読めない値」として block を壊れた扱いにし、同じ segment のアイテムを全て捨てて LogError を出していた。直線20マスに mod アイテム1個と鉄19個が載っていれば20個全部が消える。旧ブランチ（codex/belt-segment-*、削除済み）は該当1個だけを見送っていた。

決定: ロード側で空GUIDを「整理で種類を消された印」として読み、その1個（走行中・buffer・内部segment のいずれでも）だけ見送って block は壊れた扱いにしない。残りのアイテムと同じ segment の他 block のアイテムは復元する。見送った個数はロード1回につき情報ログ1行で残す（LogError ではない）。解釈できない GUID・範囲外の方向や距離・null 要素は従来どおり壊れたセーブとして segment ごと捨てる。セーブ形式は変えない（版6のまま）。出所: 旧ブランチのギャップレビュー 2026-10-14、ユーザー「今の打ち直したほうがいいかな」→実施指示。
棄却案: 整理側（pruner）でベルト要素を個別に null にする（ロード側の null 要素は壊れた扱いなので結局ロード側も変えることになり二重になる）。空GUIDも壊れた扱いのまま放置する（通常の mod 削除で segment 全体が消え、方針「ログは本当の異常時だけ」にも反する）。
理由: 整理は意図した削除であり異常ではない。影響を削除された個体に限定するのが整理の約束（他セクションでも1件ずつ空にしている）と揃う。
