# PR #1255 F05（台帳digestのクライアント一致）は生成2回の実装では入れない

決定: #1316 から #1255 F05（案B）の実装を外し、残る5件（#1255 F02 / #1258 F02+F05 / #1260 F05 / #1271 F07）だけをマージする。F05 は「探索で原点を確定させたうえで Generate を1回だけ回す」形に畳み直す設計課題として積み直す。

棄却案: 案Bの実装のまま入れる。ワールド作成時に MapGenerationPipeline.Generate を丸ごと2回回すため、クライアント起動が BlockIconImagePhotographer の破棄と競合して MissingReferenceException で失敗する（実測: 同一テストが緑PRの34.8秒に対し245〜316秒でタイムアウト、シャード全体で6分47秒→11分49秒、同エラーの出現は #1316 で1回・#1317 で0回）。

棄却案: 案A（別鍵で自前焼きした台帳を退避する）へ戻す。2026-09-04の裁定で一度棄却した設計へ後退することになり、digestのfail-closed一致という当初の狙いも取り下げになる。

理由: 裁定の意図（記録するdigestがクライアントの再生成経路のdigestと構造的に一致する）は正しいが、それを「全パイプラインをもう1回回す」で実現したのが誤り。意図を保ったままコストゼロにできる余地（探索→原点確定→生成1回）が残っているため、実装だけを差し戻して設計をやり直す。
