# 木のシャフトitemは削除しブロックは残す

決定日: 2026-08-30
出所: ユーザー裁定 2026-08-30 原文「木のシャフトのitemsと関連依存を全部消す」「サクッとやりたい」→ 選択「アイテムのみ削除、ブロックは全部残す」

## 決定

v8マスタから item `24a63965-fc83-4eff-b0b0-00e264d23c1f`（木のシャフト）とその参照を削除する。
木のシャフト系ブロック（`3dda0801` 木のシャフト / `0ab4b8c3` 木の縦シャフト / `b1bddbd5` 木のシャフトボックス）は残す。

削除対象:
- items.json の item エントリ
- craftRecipes.json のレシピ `98b86740-6bb2-4e7a-9d5f-6c845c1692b8`（当itemが唯一の生成物）
- research.json 原始研究7 (`0d76f2e5`) の `unlockItemRecipeView` アクション（当item 1件のみのため丸ごと）
- localization.csv の `item.24a63965-….name` 行
- .mooreseditor/nodeGraph.v1.json の当itemノード

差し替え:
- 研究ノード「軸の変更」(`e47ec0e1`) と「原始研究7」(`0d76f2e5`) の `graphViewSettings.IconItem` を `ef4223f8`（木の棒）へ。
  出所: ユーザー裁定 2026-08-30（選択肢「両方とも木の棒」を採択）。`IconItem` はスキーマ上必須（`VanillaSchema/ref/graphViewSettings.yml` にoptional指定なし・itemsへのforeignKey）のため空欄にできない。

## 根拠

v8のblocksスキーマには `itemGuid` が無く、ブロックとアイテムは構造的に無関係。木のシャフトブロックは
設置コスト（木の棒＋砕いた石材）で建ち、当itemを一切経由しない。当itemはどのクラフト材料・機械レシピ材料・
ブロック設置コストにも使われておらず、クラフトで作れるだけの完全なデッドアイテムだった。
よって削除してもゲーム進行・歯車伝達の実プレイ経路は変わらない。

## 棄却案

- **木のシャフト系ブロックごと廃止する** — 却下。ブロックは原始研究7で解放され、風車→シャフト→粉砕機の
  歯車チェーン経路とプレイテストシナリオ `placement-guided-tutorials.cs` で現役。歯車伝達の設計変更に
  なり波及が大きい。ユーザーの依頼は「items」の削除であり範囲外。

## 明示的に触らないもの（agent前提）

- 旧マスタ server_v5〜v7 の木のシャフトitem — 触らない。ロードされるのは v8 のみで、旧版はセーブ互換用の凍結資産。
- 研究ノード説明文「木のシャフトと歯車を組み…」とチャレンジsummaryの「木のシャフト」 — 触らない。
  どちらも残す**ブロック**を指す文言であり、item削除後も正しい。
  出所: agent前提（ブロック名として文言が成立するため）
