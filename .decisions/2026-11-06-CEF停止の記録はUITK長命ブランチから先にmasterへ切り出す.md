# CEF 停止の記録は UITK 長命ブランチから先に master へ切り出す。最終検証中の Web 更新は取り込んで再検証し、レーンは agent が長命ブランチへ取り込む

決定:
- 長命ブランチに入っている「CEF 停止の記録」（バグ報告に Web ホスト起動の成否・CEF の生存・最後の WS 受信からの秒数を載せる／Web 無応答時は Web 側の入力排他の値を無視して Esc が塞がらないようにする）を、別 PR で先に master へ入れる。切替の日に CEF と一緒に消える。
- 切替 PR の最終検証中に master へ Web の更新が入ったら、取り込んで追従し、影響箇所を再検証してから切り替える。切替の日はその分延びる。
- 段階 2〜5 の各レーンは、moores-code-review を通したうえで agent が長命ブランチ feature/uitk へマージする。master への切替 PR のマージはユーザーが行う。
棄却案: CEF 停止の記録を長命ブランチに置いたままにする／最終検証の数日だけ master への Web の変更を止める／レーンごとに feature/uitk 向けの PR にしてユーザーがマージする
理由: CEF 停止の記録は UITK の画面ではなく今の Web の世界の改善で、テスターの UI 全停止の報告に今から原因の値が載る。
