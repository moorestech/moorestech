# ビルドメニューの素材不足判定はホストで行い、財布の残りは不足としない

日付: 2026-08-28
関連ADR: docs/adr/0041-build-menu-material-shortage-tooltip.md

## 決定

- **不足判定はホスト(C#)で行い、DTOへ結果を載せる**。Web は受け取った結果を書式化するだけ。
  棄却案: Web側で `Topics.inventory` を購読し `buildOwnedCounts` で突き合わせる（recipe/research と同型・ホスト無変更）
  理由: 財布・所持の算術を `ConstructionWalletQuery` 側へ閉じる裁定 [[2026-08-22-財布システムは指示を返すサービスとしてカプセル化する.md]] / [[2026-08-23-クライアントの財布窓口は問い合わせ専用の共有クラスへ集約する.md]] に従う。書式はWeb側が持つ（[[2026-08-19-カーソルツールチップの書式はWeb側が持つ.md]]）ため、判定=ホスト・書式=Web の分割になる。
- **財布制ブロックは残り設置数 ≥ 1 なら不足なしとする**。残り0のときだけ1セット分の必要素材と所持を突き合わせる。
  棄却案: 残りがあっても次の1セットを買えないなら予告として不足を出す
  理由: 「今この場で1個置けるか」を問う。設置時カーソルtooltipの `ConstructionMaterialShortageReporter` と同じ局面判定。
- **詳細サイドバーの赤表現も同じ判定を使う**。残りがある間は `0/5` でも黒字・白枠のままにする。
  棄却案: サイドバーは所持<必要をそのまま赤で示す（素材の事実に正直）
  理由: 不足の定義をホストの1本に固定し、ツールチップと赤表現が食い違わないようにする。
- **所持数もホストが配信する**（`BuildMenuRequiredItemDto` に `Held` と `Lacking` を追加）。
  棄却案: `Lacking` だけ載せ、表示数値は Web が `Topics.inventory` から取る（線に二重に流さない）
  理由: 別トピックの到着差で「赤枠なのに 5/5」のような食い違いが見え得る。表示と判定を同一スナップショットから出す。
- **`FreeBlockPlacement` デバッグON時は `Lacking` を常に false にする**。
  棄却案: デバッグ中でも実所持で判定して不足を出す
  理由: `ConstructionMaterialShortageReporter` が同条件でコスト判定をスキップしており、表示と実際の設置可否を一致させる。
