# 歯車機械も液体タンクに対応させ、機械の配管接続を共通化する

決定: タンク項目（inputTankCount・outputTankCount・innerTankCapacity・fluidInventoryConnectors）は機械共通の IMachineParam に置き、電気・歯車・清浄室機械の3種とも持つ。タンクがあれば配管コネクタと液体インベントリを付ける処理は BlockTemplateUtil.AddMachineFluidComponents に1つだけ置き、3種のテンプレートから呼ぶ。moorestech_master の歯車機械 JSON にはタンク0の欄を書き戻す。D12（歯車機械に配管の繋がらないタンクが生える）は、歯車機械にも配管接続を付けることで解消する
棄却案: スキーマに定数を持たせる interfacePropertyConstants（PR #1565 の D12 実装）／タンク項目を IMachineFluidTankParam に分けて歯車機械は実装せずコード側で0とみなす（PR #1572 の初版）
理由: ユーザー回答（2026-11-02）。機械の入れ物と液体の仕組みは共通層にあり、歯車機械に無かったのは配管部品を付ける数行だけで、設計上の理由は記録に無い（2025-06-03 の 16af56f7af で電気機械だけに付けたまま）。抜けを埋めれば3種が同じ作りになり、例外の分岐が要らなくなる
