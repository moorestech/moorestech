# ベルトの設置不可原因はenumで運び網羅する

2026-08-22 裁定（moores-code-review C4）。

## 決定

`PlaceInfo` に `PlacementBlockCause`（None / ExistingBlock / ImpossibleOverpass / SlopeBlockMissing）を持たせ、`PlacementCellReasonReporter` の switch で網羅する。立体交差不能・坂ブロック欠落には専用のローカライズキーを与える。

## 棄却した案

- **平行配列で受ける**（`bool[] overpassInfeasible` を返してベルト側で合成）。`PlaceInfo` を汚さないが、`_currentPlaceInfos` と並走する平行配列が増え Reporter の引数が bool 2本になる。
- **誤断言だけ止める**（重複と確定したときだけ行を出し、他は無言）。キー追加不要だが、立体交差・坂の失敗時に理由が出ないままになる。
- **現状維持**（何の理由でも「設置位置が埋まっています」と出す）。

## 理由

3原因を畳んだ `Placeable` の bool だけを見て重複理由に流用していたため、立体交差が作れない・坂ブロックが無いケースでも「設置位置が埋まっています」と誤った理由を断言していた。enum を運べば生成側→運搬型→消費側が1本で通り、将来の原因追加をコンパイラが検出できる。表示専用フィールドが共有型に増えるコストは受け入れる。

なお理由行はカーソル下の1セルについてのみ出る（連続設置全体の可否判定は存在しない）。本裁定の網羅もカーソルセルの原因に対するもの。
