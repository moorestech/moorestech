# ツリーのノード押下もパンにし、閾値未満の解放だけを選択とする

日付: 2026-08-26

## 決定

- 研究・チャレンジの共通 `TreeView` は、ノードカード上の押下でもパンを開始する。押下点からの移動が5px未満のまま離した時だけ、その押下点のノードを選択する（前例: `features/recipe/panels/useDragScroll.ts` + `shared/pointerGesture/dragThreshold.ts`）。
- 選択のINは `TreeView` の `onNodeTap(node)` へ一本化し、`ResearchNodeCard` の `onClick` は撤去する。
- 閾値は実画面px（`clientX/Y` の生の差分）で測る。UI拡縮率・ツリーのズーム倍率では換算しない。
- ノード解決の印は `TreeView` が自前で付ける `data-tree-node-id` に一本化し、`nodeTargetSelector` prop と `data-research-node` / `data-challenge-node` は撤去する。チャレンジツリーもノードを掴んでパンできるようになる。

## 棄却案

- ノード上はパン不可のまま、別のパン手段（ホイール・キー操作・専用ハンドル）を足す — 研究ツリーはノードが密で掴める空背景が乏しいという原因に触れない。
- ノードのドラッグをノード移動など別機能へ割り当てる — 今回望まれているのはツリーを動かすこと。
- 押下点のDOMをそのまま `onTap(target)` で渡す — 呼び出し側でDOM文字列からのID再抽出が必要になる。
- カードの `onClick` を残し、ドラッグ時だけ直後のclickを潰す — 選択のINが2系統残り、ポインタ捕捉によるclickのリターゲットを自分で逆に辿る必要がある。
- 閾値をCSS px換算後に測る — UI拡大時に実画面7.5px動かさないとドラッグにならず、掴み心地が拡縮率で変わる。
- チャレンジツリーだけ現状維持 — 共通部品に振る舞い分岐のフラグが増える。

## 理由

研究ツリーはノードが密で、パン可能な空背景が実質残らない。チャレンジツリーに至ってはクリック先が無いのにパンだけ塞がれていた。掴み操作とクリック選択の両立は同repo内に前例（レシピ一覧のドラッグスクロール）があり、閾値・判定関数をそのまま再利用できる。
