# ベルト経路のテストは利用者が見る挙動を守るものだけ残す

決定: ベルト2クリック設置の PR に残すテストは、経路の規則（`BeltRoutePlannerBasicTest`）、経路の形の不変条件（`BeltRouteRandomizedSearchTest`）、経路の存在と最短性（`BeltRouteReferenceCrossCheckTest`）、置いた経路に荷物が流れること（`BeltRouteConveyanceTest`）、実入力での2クリックの流れ（`BeltRouteWiringTest`）の5本だけにする。内部の助手や診断のためのテストは消す: 優先順の順列が相異なることだけを見る `BeltRouteStepPriorityTest`、組み直しの余裕の内部挙動を構築配置で見る `BeltRouteRecoveryCorridorLayoutTest`（余裕ありで既知の穴が消えることは突き合わせが見る）、分岐化の不具合調査のために書いた `BeltBranchReplaceReplayTest`（本番マスタで最初のセルが曲がる分岐の先頭が歯車網から切れることを「現状」として固定していた。修正は別 PR でその修正のテストを持つ）。
棄却案: 診断テストを残して修正時に書き換える（不具合を固定するテストが PR に入るのは誤解を生む）。
理由: ユーザー裁定 2026-11-07 原文「そもそもだけどムダなテスト消してもらっていい？本当に必要なテストなんですかね？」。残した5本は手元で合計約 0.6 秒（暖機込み約 1 秒）。
