# 列車配置の可否は理由enum一本から導出する

2026-08-22 裁定（moores-code-review C9(b)）。

## 決定

`TrainCarPlacementHit.IsPlaceable => BlockReason == TrainCarPlacementBlockReason.None;` とし、ctor 引数の `isPlaceable` を削除する。成功と失敗理由を1つの enum で表し、可否はそこから導出する。

## 棄却した案

- **可/不可の判別可能な2形へ分ける**（enum から `None` を削り `Placeable(...)` / `Blocked(reason)` の静的ファクトリへ。前例 `BlueprintRequest`）。不可時にレール位置等が意味を持たないことまで型で言えるが、`TryBuildRailPosition` の out 引数7本の組み替えが要り、本PRの非目標（列車系の掘り下げ）に近づく。

## 理由

可否 bool と理由 enum を独立フィールドで並置していたため、「不可なのに理由None」「可なのに理由あり」という矛盾値が将来作れてしまう。導出にすれば矛盾が表現不能になり、変更も小さい。
