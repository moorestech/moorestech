## 決定

1. **D1 keyControl の旧uGUI残骸** … prefab の uGUI 実体を撤去する（`uloop execute-dynamic-code` で子GameObject `Text (TMP)` を削除し SerializeField 参照も外す）。
   - 棄却: `Awake` の `SetActive(false)` と GatedRoot 分類を復帰させる案（使わない uGUI 実体と分類ルールを保守し続けることになる）／このPRでは触らない案。
2. **D2 keyName 必須化とマスタ未更新** … schema の `default: Tab` を削除して必須のまま維持し、マスタ側の keyControl 2件へ keyName を先に追記する（順序逆転または同時マージを保証）。
   - 棄却: 該当2件の tutorialType 再分類／schema 変更をマスタPRへ移送／現状のままマージし順序で回避。
   - 理由: 設計原則「変更の波及を恐れない」。ADR 0022 Decision 6 の PR 順序は運用側で調整する。
3. **D3 キーヒント様式** … 既存共有部品 `LocalizedShortcutHint` へ寄せる。
   - 棄却: インライン実装のまま「文言に `{shortcut}` を書かない」規約を明文化する案（将来の書き手に依存するため）。
4. **D5 subState 未考慮** … 現状維持（`state` 単独判定）とし、subState 非対応である旨を注記する。
   - 棄却: `screenForUiState(state, subState)` へ寄せる案。ADR 0022/R2 が `state` を名指ししており、実マスタに `uiState: TrainHUDScreen` は0件。
5. **D4 uiState の語彙検証** … schema options を正本とし、`UIStateEnum`（Debug除く）との集合一致を assert する EditMode テストを1本置く。
   - 棄却: Web 側を `z.enum` へ狭める案（既存 `UiStateDataSchema.state: z.string()` の意図的に緩い前例とこのtopicだけ方針が割れる）／両方やる案／現状維持。
6. **D6 CSSキーヒント様式の3重化** … このPRで共通トークンへ引き上げる（`tokens.css` の共通トークンか共通クラス1つへ。床位置は `--hotbar-floor-offset` を1本置く）。既存2ファイルも触るのでPR-Aの範囲が広がることを受容する。
   - 棄却: 別PRへ送る案／新規側を生値へ戻す案。
7. **D7 ラベル有無判定の置き場所** … store 内1箇所へ集約する（`AddOutlineHighlight(anchorId, labelText, tutorialGuid)`。引数名は中立の `labelText`）。
   - 棄却: 2箇所複製のまま PR-B まで先送りする案。
8. **D10 union 描画振り分け** … `isAnchoredElement` 型ガードで列挙前にフィルタし、react key 導出を共有ヘルパへ上げる。
   - 棄却: `TutorialOverlay` へ統合（webui-design §8.17 に抵触）／union から keyControl を分離（ADR 0022 の「unionへ足す」規約に反する）。
