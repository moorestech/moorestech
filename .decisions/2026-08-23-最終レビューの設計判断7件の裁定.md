## D1. 後着生成とスキットの世界オブジェクト非活性ウィンドウの調停 → 案A

**決定**: 世界オブジェクトが非活性の間は後着生成を止め、活性復帰で再開する（生成を活性状態に従属させる）。

**棄却案**: 案B `MapObjectGameObject.cs:95,158` の `GetComponentsInChildren<T>()` を `(true)` へ揃える／案C 生成と初期化を分離し活性復帰時にまとめて初期化。

**理由**: 症状は「開幕スキット中に後着生成された木/岩が、スキット明け以降セッション中ずっと採掘もフォーカスもできない（ログも出ない）」「同窓で生成された破壊済み個体はコライダーと見た目が残る」。案Bは最小差分だが「非活性でも初期化が成立する」不文律を全prefabの将来の子へ課す。案Cは「生成済み未初期化」の第3状態を増やす。案Aは非活性下で生成される個体自体を無くすので症状が根本から消える。代償は長いスキット中に後着が進まないことだが許容する。

## D2. 後着完了という新しい可変状態の上位への通知 → 案A

**決定**: datastore が `IReadOnlyReactiveProperty<bool>` で後着完了を公開し、`MapObjectPin` が購読する。未完了中は `LogError` もラッチ更新も行わない。

**棄却案**: 案B `SearchNearestMapObject` を結果variant化（`MapObjectNearestSearchResultType` + out）／案C `ApplyInitialTutorials()` を全量完了後へ移す。

**理由**: 症状は「チュートリアル対象の木が150m圏外にしか無いワールドで起動すると嘘の LogError を出し、ラッチにより以後同guidの本物の欠落も二度と報告されない。後着到達までピンは前回座標に留まり誤座標をWeb UIへ配信し続ける」。6系統一致の最高確度指摘。案AはAGENTS.md「状態変化の検知は購読で。UniRxの変化通知をSubscribeする」と前例一致。案Cは「起動を待たせない」R1/R2と正面衝突。

## D3. 後着生成の開始点 → 案A

**決定**: `GameInitializedEvent.OnGameInitialized.Take(1)` を完了ソースへ接続し、`InstantiateBackgroundAsync` が「近傍完了」と「ゲーム開始」の双方を待つ。前例 `DebugEnvironmentController.cs:68`。

**棄却案**: 案B `MainGameInitializationFinalizer` から `StartBackgroundInstantiation()` を明示的に押す（前例 `OutcropGameObjectDatastore.StartOutcropInstantiation()`）／現状維持。

**理由**: 現状は後着が `Construct` 内で即起動され、露頭生成・列車スナップショット適用・チュートリアル適用の最中に4ms/フレームを奪ってローディング時間を伸ばす。ADR 0030のR2「残りはゲーム開始後に生成」という設計境界が成立していない。

## D4. R4配線のテストseam → 案A

**決定**: `MapObjectPendingStateApplier.Apply(MapObjectGameObject, MapObjectPendingState)` を切り出し、EditModeテストから入口起動する。`Map/MapObject/` が10ファイル上限に達するため `Pending/` サブディレクトリ分割を併用する。

**棄却案**: 案B PlayModeで遠方個体へ破壊イベントを注入して全量完走を待つ。

**理由**: R4（未生成個体宛の破壊/HPイベントの保留と優先適用）は `TryConsume` ブロックを削除しても未生成分岐を `return` にしても全テストが緑で、配線がまったく検証されていない。壊れると遠方個体がプレイヤー到達前に破壊された場合に破壊前スナップショットが適用され、破壊済みのはずの木が復活する。案Bは「実機テストは近傍待機で完結させる」裁定（[[2026-08-23-実機テストは全量生成を待たず近傍待機で完結させる.md]]）と衝突し、実行に30分超かかる。

## D5. `CountWithinRadius` のソート済み前提の型表現 → 案B

**決定**: `SortNearFieldFirst(layouts, origin)` → `NearFieldOrder{ Entries, NearFieldCount }` の1呼び出しへ畳み、`CountWithinRadius` を private 化する。C3で半径定数を同クラスへ集約済みなので半径引数も畳む。

**棄却案**: 案A `readonly struct SortedLayoutEntries` を `Sort` の戻り型にする／現状維持。

**理由**: 未ソートListを渡すと先頭が遠方だった時点で `nearFieldCount = 0` になり、プレイヤー周囲に1個も無い状態でローディングが明ける。例外もログも出ず、近傍先行という機能そのものが無音で無効化される。案Bは呼び出し元が2行→1行になり、誤用の余地が型から消える。

## D6. mapObject登録簿の所有 → 案B

**決定**: `_allMapObjects` ＋ `_nearestSearcher` を包む `MapObjectRegistry`（`TryRegister` / `TryGet` / `MarkDirty`）を新設し、datastore と instantiator の双方がその型を持つ。

**棄却案**: 案A `bool TryInstantiate(layout, out MapObjectGameObject)` にして登録・索引・台帳消費を datastore 側1箇所へ戻す／現状維持。

**理由**: 現状は生の `Dictionary` と索引を協力オブジェクトへ渡し双方が書き換えている。登録の不変条件（TryAdd重複検出→保留適用→`Register`）が Instantiator 側にしか無く型が守らない。後日 `Register` を保留適用より前へ動かすと、破壊済み個体が dirty 無しで索引に載り、破壊済みの岩に採掘レイが吸われる。案Bは不変条件が型に入る。ファイル数増は D4 の `Pending/` 分割と併せて調整する。

**注意**: R6により `MapObjectNearestSearcher.cs` および `NearestSearch/` 配下には差分を出さない。`MapObjectRegistry` はそれらを**包む**だけで、索引側の実装は変更しない。

## D7. 後着中のAddressable同期ロード → 案A

**決定**: `InstantiateFromLayoutAsync(layout, CancellationToken)` ＋ `ResolvePrefabOrNullAsync` へ変え、`AddressableLoader.LoadAsyncDefault` を待つ。

**棄却案**: 案B 後着開始前に登場guidを一度だけprewarmしループ本体は同期のまま保つ／現状維持。

**理由**: `AddressableLoader.LoadDefault` が `WaitForCompletion()` でメインスレッドを同期ブロックし、後着中に初出現guidが来ると数十〜数百msのヒッチがプレイ中に露出する。4ms予算はロードの**後**にしか判定されないため止められない。CTを受ける `LoadAsyncDefault` が既存なのに鎖が切れている。案Aは破棄で鎖の端まで止まる利点もある。代償は近傍待機の解除がロード時間ぶん遅れること。
