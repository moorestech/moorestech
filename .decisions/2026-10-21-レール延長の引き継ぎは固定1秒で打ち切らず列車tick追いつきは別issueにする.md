# レール延長の引き継ぎは固定1秒で打ち切らず、列車tick追いつきは別issueにする

- 決定: 橋脚つきレール延長の次の起点の解決（PlacedPierConnectAreaResolver）から固定1秒の打ち切りを撤去し、持ち替え・再選択でキャンセルされるまで待つ。起動直後にクライアント列車tickが遅れてノード反映が数秒遅れる問題は、この PR では直さず GitHub issue に詳細レポートとしてまとめる。
- 出所: ユーザー裁定 2026-10-21 原文「1秒待ちの撤去　←これだけ実施して。tickの追いつき改善について詳細レポートをまとめてgithubのissueを作っておいて」
- 棄却案: 「駅から伸ばすパターンの最適化」— 実測でサーバー処理は1〜13msで駅起点に特有の遅れが無く、対象から外した（ユーザーも撤去のみの実施を選択）。
- 理由: 遅れの本体はクライアント側のtick揃え反映（2〜5秒）。固定1秒だとこれを超えたとき起点が捨てられ、2本目のプレビューが出なくなる。
