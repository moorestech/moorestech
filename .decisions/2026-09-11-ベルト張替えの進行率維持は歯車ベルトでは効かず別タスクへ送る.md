# ベルト張替えの進行率維持は歯車ベルトでは効かず、今回のPRでは直さない

2026-09-11 ユーザー裁定。ADR 0055 / plan 2026-09-10-belt-conveyor-replace-placement の R11 に関する裁定。

## 事実

R11 は「搬送中アイテムは進行率維持で新ブロックへ引き継ぐ」と規定しているが、**実ゲームでは効かない**。

- 実マスタのベルトは全て歯車ベルト。`GearBeltConveyorComponent.Update` は稼働率0のとき
  `SetTicksOfItemEnterToExit(uint.MaxValue)` を設定する。
- 張替えで新ブロックを設置した直後、まだ `Update` が回っていないため搬送時間は停止中扱い。
  `BeltConveyorTransitCarryOver.Restore` は停止中のベルトでは進行率を保存できず入口スロットへ置く。
- その後に動力が入ると `VanillaBeltConveyorInventoryItem.ResetTicksOnSpeedRecovery` が
  `RemainingTicks = newTotalTicks` で進捗を0へ戻す。

結果として「張替えは搬送品を失わない」は成立するが、「進行率を維持する」は実運用で成立しない。

## 決定

**今回のPRではそのままにする。** 「張替えは搬送品を失わないが進捗はリセットされる」を現時点の仕様とし、
ADR 0055 と plan の R11 にその旨を明記する。進行率維持の実装は別タスクへ送る。

- 棄却1: `ResetTicksOnSpeedRecovery` を「復元時に渡された進行率を覚えて `RemainingTicks = rate * newTotalTicks` にする」へ変更する
  → R11 が実際に効くようになるが、張替えと無関係な既存の「停止→復帰」挙動全体に影響が及ぶ。
    張替えのPRでベルトの基本挙動を変えるのはスコープ外
- 棄却2: 設置直後ではなく歯車ネットワークから搬送時間が確定した後に復元する
  → 復元待ちの中間状態をサーバーに持つことになり、B2「事前検証で失敗経路を消す・部分状態を残さない」裁定と衝突する
