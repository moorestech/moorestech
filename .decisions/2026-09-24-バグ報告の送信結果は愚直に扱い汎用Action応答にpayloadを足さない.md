# バグ報告の送信結果は愚直に扱い汎用Action応答にpayloadを足さない

決定: 送信成功トーストの欠損は、送信を押した時点で画面が持っていた確保状態（pause_menu topic の bugReport.missing）から作る。汎用Action応答への payload 追加と action 毎の応答スキーマ登録表は取り消す。書き出し中に起きた欠損は manifest にだけ残す。到達しなくなった `submitted` / `already_submitted` は削除し、再送時の箱の重複と、ポーズを閉じた後の成功で走る確保1回は許容する。

棄却案:
- 汎用Action応答 payload＋zod登録表で送った箱の欠損を正確に返す（実装済みだったが撤回）
- 送信IDでC#側が再送の重複を拒否する
- ポーズが開いている間だけ確保し直す
- 確保世代の持ち主一本化・画面名の正本一本化・Capture/Server の namespace 整理

理由: ユーザー裁定 2026-09-24「変に複雑化してない？愚直な実装でいいんだけど」→「じゃあそれで」。欠損トーストの正確さのためにレビュー差し戻しで基盤変更が積み上がり、要件に対して過剰だった。
