決定: moorestech repo の `.agents/skills` には、個人スキル（`~/.agents/skills`・`~/.claude/skills`・`~/.codex/skills`）と同じ名前のスキルを置かない。moorestech固有の内容を持つものは `moores-` 接頭辞へ改名し（subagent-driven-development → moores-subagent-driven-development。呼び出し元も全て更新）、個人版とほぼ同じ写し（codex-audit・domain-modeling・grilling・postmortem）は repo から削除して個人版に任せる。衝突は `.dev-hooks/skill-name-collision-check.mjs` を SessionStart で走らせて機械で検知する。uloop-launch だけは `uloop skills install` が両側を再生成する配布物なので削除せず、検知の対象外とする。
棄却案: 同名のまま併存させる（[[2026-08-18-同名スキルのrepo版とユーザー版は併存させる]]。この裁定で覆す）。codex-audit・postmortem の repo コピーを残して全体同期する（[[2026-09-29-create-infographic-lightはグローバル一本化しcodex-auditとpostmortemは全体同期する]] のうち repo コピー保持の部分をこの裁定で覆す）。個人版を削除して repo 版を正とする（他プロジェクトから汎用版が使えなくなる）。
理由: 8/18の裁定は「moorestech内ではproject skillが優先される」という前提に立っていたが、Claude Code は同名なら個人版を優先する（公式 https://code.claude.com/docs/en/skills#resolve-skills-that-share-a-name）。実際に repo 版 writing-plans の検査フックは一度も動いておらず（[[2026-10-06-writing-plansのproject版をmoores-writing-plansへ改名する]]）、同名の repo 版は読まれない死蔵コピーか、読まれる版が環境で変わる不確定要因にしかならない。個人スキルは repo 外にあり CI から見えないため、検知はローカルのセッション開始時に行う。
