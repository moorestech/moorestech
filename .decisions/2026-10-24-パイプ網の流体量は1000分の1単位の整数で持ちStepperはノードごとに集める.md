# パイプ網の流体量は 1000 分の 1 単位の整数で持ち、Stepper はノードごとに集める

決定: パイプ網（網の配列・Stepper・差分と全量のメッセージ・ハッシュ・パイプのセーブ・クライアントのコピー）の流体量を 1/1000 単位の `long` にする。機械のタンク・`FluidStack`・レシピ・UI は double のまま、境界で単位を変換する（機械→パイプは切り捨てて端数を機械に残す、パイプ→機械はノードが引く量を切り上げて増える側に丸めない）。Stepper は面から両端へ足し込む形をやめ、ノードごとに接続面を集めて自分だけ書く形にし、各フェーズをノード範囲で呼べる関数にする。実行は直列のまま。異種流体が同じ tick に同じ空ノードへ入るときは面の番号が小さい方を採る（今と同じ）。セーブは版 7 へ上げ、`amount`/`velocity` を `amountMilli`/`velocityMilli` に変換する。今の PR（fix/train-client-tick-slack-pacing）に足す。
棄却案: 今のブランチの上に新しいブランチを切る／ゲーム全体の流体量を整数化する／1 単位 = 1/1,000,000（64 ビットに収まらない積が出る）／異種流体は流量が大きい方・どちらも通さない／今回から複数スレッドで実行する。
理由: 整数なら加算順で結果が変わらず、サーバーとクライアントの一致が計算順に依存しなくなる。ノードごとの gather なら範囲を分けて回せる。128 ビット整数が無い API レベルなので、充填率差 × 容量の積が 64 ビットに収まる単位（ミリ）を選ぶ。
出所: ユーザー裁定 2026-10-24 原文「流体についてdoubleから整数化への許可が早速オリました。この並列化可能な状態への変更を追加したい」。AskUserQuestion 5 問の回答: 「今の PR に足す」「パイプ網だけ」「1/1000（ミリ）」「面の番号が小さい方を通す（今と同じ）」「構造だけ並列可能にし、実行は直列のまま」。境界の丸め・定数の整数比・比例縮小の有理数化・gather の相の分け方・セーブのキー名は agent 前提（ADR 0090 に根拠）。
リンク: ADR 0090、ADR 0088（棄却案「先に固定小数点へ」を採る）、ADR 0089、`.decisions/2026-10-22-パイプの流体状態は境界の出入りだけを差分で送りクライアントが同じ計算を回す.md`

追記 2026-10-24: 単位は同日の後続裁定で 1/1,000,000,000 に変更し、セーブのキーは `amountNano`/`velocityNano`、容量比と比例縮小の掛け割りは自前の 128 ビット途中値（`FluidMulDiv`）で求める形になった。gather・直列実行・異種流体の規則・境界の丸めの向き・版 7 はそのまま。→ `.decisions/2026-10-24-パイプ網の流体量は10億分の1単位にし動けない量は毎tick空にして容量比は128ビットで正確に求める.md`
