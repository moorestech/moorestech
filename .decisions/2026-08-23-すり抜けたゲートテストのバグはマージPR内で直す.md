# すり抜けたゲートテストのバグはマージ PR 内で直す

- 日付: 2026-08-23（PR #1232 の master コンフリクト解消時のユーザー裁定）
- 決定: `TileVisualBakerGateTest` の引数取り違え3件を本マージ PR 内で修正する。`CreateBaker(generateTexture, generateDetail, generateHeightmap)` に対し `DetailGenerationIsOff` は `(true, false, true)`、`TextureGenerationIsOff` の2件は `(false, true, true)` が正
- 棄却案: (a) マージのスコープ外として bd に別 issue を立て、赤のまま push (b) 修正に加えてポストモーテムを起こす
- 理由: マージ由来ではなく本 PR に元からあるバグだが、テスト名とアサーションから意図が一意に決まる3行の機械的修正であり、ブランチを緑にしてから push できる。分離する利得より、赤いまま渡す不利益が大きい
- 背景: 本 PR の CI は master ピン起因（bd moorestech-hvwb）でテスト job が動いておらず、3件の恒常失敗が素通りしていた。`(true, true, false)` は heightmap off、`(true, false, true)` は texture on なので、マージの有無に関わらず落ちる
