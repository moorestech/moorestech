# 配布ビルドの検証機起動・ピン照合・master準備・branch欄の裁定

2026-09-17 ユーザー裁定（plan E 最終レビュー moores-code-review の設計判断、AskUserQuestion で推奨案を選択）。

決定:

1. 検証機の smoke は `steam.exe -applaunch 1958160 --playtestSmoke ...` で Steam 経由起動する。
2. strict ビルドのピンずれ照合元はコミット済みのピン（`git show HEAD:.moorestech-external-revisions.json`）。
3. release-playtest.sh はビルド前に、同梱元 master data の HEAD とピンを突き合わせ、ずれていれば理由を出して止まる（合わせるのは人）。
4. build-info.json の branch 欄には配布元 ref（master 等）をスクリプトから渡して焼く。

同日の前段裁定: build-info.json は既存 BuildOrigin.BuildInfo を唯一の型とし、キーを masterDataCommit へ改名、builtAt は UTC、失敗は strict 時のみ（ADR 0059 追記）。

棄却案:

- 1: exe 直接起動＋検証機だけ steam_appid.txt を置く（テスターと起動経路が違う検証になる）。
- 2: 作業ツリーのピンがHEADと違えば strict で拒否（照合元は作業ツリーのまま）。
- 3: moores-wt を改修し worktree ごとにピン専用 master を自動配置／ビルド入口に master の場所を env で渡す。
- 4: 一時ブランチ名のまま焼き、共有契約 §1 の例を実態に合わせて改訂する。

理由:

配布物の出所表示と通し検証が「テスターと同じ経路・実際に同梱したもの」を指すことを優先し、無人工程の改修範囲（moores-wt 等）は最小に留めた。
