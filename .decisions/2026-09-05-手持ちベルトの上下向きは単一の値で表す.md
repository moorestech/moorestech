# 手持ちベルトの直線/上り/下りは単一の値で表す

決定: `BeltConveyorHoldingBlock` の `IsSlopeSelected`(bool) を廃止し、上下向きの値だけを真実の源にする。併せて `BeltConveyorSlopePathBuilder.Build` の `yStep` を3値網羅の switch にし、`Horizontal` を明示的に弾く。

棄却案: 坂専用の2値型 `enum BeltSlopeGrade { Up, Down }` を切って `Build` へ渡す。`Horizontal` を型として渡せなくなり3値潰しが構造的に起こり得なくなるが、`PlaceInfo.VerticalDirection` への変換が1箇所増える。採用案で不整合値そのものが作れなくなるため、追加の型は現時点では過剰。

棄却案: `StraightHoldingBlock` / `SlopeHoldingBlock` へ variant 分割する。教科書的に最も安全だが、今回の依頼は構造変更を求めておらず過剰。

理由: bool とセンチネル enum の二重符号化は `(IsSlopeSelected=true, SlopeDirection=Horizontal)` という到達可能な不整合値を作り、`yStep` が3値を2分岐に潰しているため `Horizontal` が渡ると無言で「下り」になる。「上り」を選んだ列が毎セル地面へ潜って1個も置けなくなり、検出点はどこにも無い。
