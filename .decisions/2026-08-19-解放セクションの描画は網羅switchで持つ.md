# 解放セクションの描画は網羅switchで持つ

決定: `SECTIONS` のルックアップ表は純データ（sectionId / labelKey / testId / wrapInSlotsRow）だけを持ち、描画は `renderUnlockEntry` の網羅 `switch` ＋ `default` の `never` 代入へ移す。グルーピングキーはDOMの目印である `testId` ではなく `sectionId` を明示フィールドとして持つ

棄却案: 表を保ったまま mapped type で種別と描画を型レベルで結ぶ（表の一覧性は保てるが、ディスパッチ1箇所にキャストかジェネリックヘルパの抜け道が要る）

理由: 表に描画関数を持たせると型システムが「この行はこの種別」を追跡できず、6箇所すべてが実行時の手書きガード頼みになる。種別追加時にコピペ元のガード行を書き換え忘れると、型エラーゼロのまま「ラベルだけ出て中身が空のセクション」が黙って描画される。リポジトリ既存の同型（`selectableTarget` / `plannedAction`）も網羅switch形で前例一致する
