# PlayMode検証は #1219 をローカル一時マージで行いPRには含めない

2026-08-23 ユーザー裁定。

## 決定
`feature/tutorial-equip-challenge-and-pin-fixes` の PlayMode 録画テスト(Task 4 Step 3)は、
code PR #1219 (`feature/object-scatter-spawn-bands`) を**ローカルへ一時マージした状態**で実施し、
検証後にその一時マージは破棄する。本ブランチのコミット・PRには #1219 を含めない。

## 経緯
マスタrepo master は既に PR #28 で `objectConfig.entries` を距離帯 `bands` へ移行済みだが、
対のコード側スキーマ (`VanillaSchema/mapGenerate/biomeObjectConfig.yml`) は未マージの code PR #1219 にしか無い。
このためマスタrepo master tip をピンした瞬間に
`algorithmParam.grassland.objectConfig.entries[0].density` でマスタロードが落ちる。
旧ピンへ戻すと今度は Task 1 のスキーマに旧データが追いつかず落ちるため、前後どちらにも逃げ場が無い。
本ブランチ固有の問題ではなく、コードrepoとマスタrepoの取り込み順序に起因する既存の構造問題。

## 棄却した案
- **#1219 を先にマージしてから続行**: 順序として正しくCIも通るが、他PRのマージ判断を本タスクが握ることになる
- **Step 3 を保留して Task 5 へ進む**: PlayMode 未検証のまま PR を出すことになる
- **#1219 を本PRへ同梱**: 無関係な変更が混ざりPRの責務が崩れる

## 帰結
- 本PRの CI はマスタロード段で赤になる前提。#1219 マージ後に緑化する
- 検証状態と実マージ状態が一致しない点は残存リスクとして PR 本文に明記する
