決定: GitHub Actionsのキャッシュ枠10GBは、PRで回るジョブ（EditMode Test・PF別コンパイル）に配分し、日次フルビルドはキャッシュを使わずコールドで回す。
棄却案:
- PF別コンパイルをWin/Mac1ジョブに畳んでターゲット切替で回しキャッシュ系統を半減させる（枠に余裕は出るが、切替のたびにPF固有アセットの再インポートが走りPRのフィードバックが遅くなる）
- Mac miniにself-hosted runnerを立ててLibraryを永続化（枠制限から完全に解放されるが、CIが自宅サーバー常駐に依存し、既存のUnity Editor群・cmuxワークスペースとマシン資源を争う。public repoでのself-hosted runnerはセキュリティ検討も要る）
- Cloudflare R2等の外部S3互換ストレージをキャッシュバックエンドにする（容量制限は外れるが転送量と鍵管理が増え、CIが外部サービス依存になる）
理由: 素直に全系統へキャッシュを張ると約23GBで上限10GBに入らない。日次は深夜に無人で回るため所要時間がコストにならないという既決裁定（[[2026-08-21-日次ビルド失敗は専用ラベルIssueから無人修復パイプラインを深夜に回す]]）と整合し、速度が意味を持つPR側へ枠を寄せる。
帰結: 修復エージェントがラベルで起こす検証ビルドもコールドになる。並列化しても1回あたり1時間弱かかる前提で無人ループを設計する必要がある。
