# 独立レビューの散文ガードは終了コード判定のスクリプトへ置き換える

日付: 2026-09-13
出所: ユーザー裁定 指示ファイル剪定監査（PRレビュー系）の裁定3点のうち3。質問「pr-independent-review の散文ガード（〜してはいけない・必ず確認）をスクリプトの終了コードで機械判定する形へ置き換えるか」→ 選択「やる。第1波と同時に着手し、PRはスタックにして第1波マージ後は第2波だけの diff になるようにする」

## 決定
- 散文で書かれた安全装置（$CANON をメイン worktree にしない・$ORIGIN で gh pr checkout しない・共用 worktree にしない・[ADR:] 引用前の PR diff 自己変更確認・レビューのみで対応完了ラベルを付けない）は、スクリプトが exit 0 以外で拒否する形にし、SKILL.md 側は「実行して非0なら abort.json を書いて中止」の1行にする
- スクリプトには既存 tests/ と同様に pytest を付ける。前例は同スキルの scripts/unattended-gate.py
- 第1波（重複集約・陳腐化修正）と第2波（本裁定＋Step 3.5 の merge-tree 化）は別PRとし、第2波は第1波ブランチ上に積む

## 棄却案
- やらない: 散文ガードが同一規則の再掲と事故経緯の堆積の主因であり、削減が頭打ちになる
- 第1波に混ぜる: 文章整理と新規スクリプト＋テストが1PRに混在し、回帰確認の切り分けができない
