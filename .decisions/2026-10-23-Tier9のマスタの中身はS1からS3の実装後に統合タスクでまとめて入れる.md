# Tier9 のマスタの中身は S1〜S3 の実装後に統合タスクでまとめて入れる

決定: S1〜S3 の各 PR は、コード・スキーマ・テスト用データと、スキーマ変更でゲームの読み込みに要る最小限の moorestech_master 変更（例: 積荷表の空配列）だけを入れる。GPU・GPU衛星・積荷表の行・発射台の値・レシピ・研究と解放先・バランス・ビルドメニューの「宇宙」・スタックテーブルの修正といったマスタの中身は、S1〜S3 の実装がそろってから別の統合タスクで1回にまとめて入れる。ループ全体の unityプレイ録画テストも統合タスクで撮る（マスタに発射台が無いと実ゲームで置けないため、S2 の録画テストはそちらへ移す）。
棄却案: 各セッションが自分の PR でマスタの中身まで入れ、他セッションのアイテムは S1 待ち・取り込み・先行 push で解決する。
理由: ユーザー発言「マスタはタスク全体の実装が終わった時に全体でまとめて入れるのが良いんじゃないの？どうせ他にもデッドロック的なタスクがあるんじゃないの？」。実際にマスタだけで6件のセッション間依存がある（GPU衛星のレシピ←S1 の GPU、研究の解放先←S1 のモジュール、ロケット技術の前提←S1 の研究、積荷表のケーブル行と軌道エレベーター研究←S2、スタックテーブル7件の重複修正、ビルドメニュー「宇宙」の共有）。
明示引用: 提案「S2 の PR はコード・スキーマ・テスト用データと、読み込みに必要な最小限の master 変更だけにし、master の中身と録画プレイテストは S1〜S3 がそろった後の統合タスクでまとめて行う」→ 回答「1 ok」
