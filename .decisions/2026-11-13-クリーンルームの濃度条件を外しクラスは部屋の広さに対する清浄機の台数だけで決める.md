# クリーンルームの濃度条件を外し、クラスは部屋の広さに対する清浄機の台数だけで決める

決定: クラスの条件から不純物の濃度を外す。クラスは「部屋の広さ（空きセル数）に対する清浄機の台数」＝換気回数だけで決める。
棄却案: 濃度の条件を残す（ハッチの搬送量が極端に増えたときの歯止めとして。agent が一度提示）
理由: 濃度の条件は実質効いていない（今のワールドの部屋は清浄機2台で濃度約13〜15、クラスCの上限は200）。フィルター消費を清浄機1台ごとの一定にしたので、不純物の量はフィルター消費とも無関係になり、プレイヤーにとって意味のない数字になる。
明示引用: agent 提示「濃度の条件は外して、クラスを「部屋の広さに対する清浄機の台数」だけで決める形に単純化するのをすすめます。」→ ユーザー原文「←それでok」
決定（範囲）: 濃度と一緒に、汚染流入（部屋の体積・壁面積・ハッチやパイプの数・稼働機械・ハッチ搬送量）の仕組みも消す。セーブの不純物量も不要になるので、セーブ形式の変更（マイグレーション）込みで実装する。
明示引用（範囲）: agent 質問「(1) 濃度と一緒に、ハッチ数・機械の稼働・壁面積などによる汚染流入の仕組みも消してよいか。(2) フィルター消費の変更と濃度の削除を、セーブ形式の変更込みで実装に進めてよいか。」→ ユーザー原文「1,2両方ok」
