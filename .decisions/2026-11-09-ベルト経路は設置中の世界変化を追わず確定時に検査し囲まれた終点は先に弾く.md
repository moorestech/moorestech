# ベルト経路は設置中の世界変化を追わず確定時に検査し、囲まれた終点は先に弾く

決定: (1) 始点を決めた後にブロックが置かれた・撤去されても、世界の作り直しも再探索もしない。終点をクリックした瞬間に世界を読み直して経路の全セル（分岐なら分岐器の向きと出口も）が置けるか検査し、置けなければ送らずに理由行を出して始点選びからやり直す。(2) 本探索の前に終点から空きセルを小さく塗りつぶし（上限 512 セル）、先に尽きたら「入れない終点」として即経路なしにする。利用者向けの理由行は「経路が見つかりません」のまま。(3) 端点セルの判定は `BeltRouteCellJudge.Judge` の1本にし、設置システムが本番の世界を1つ持って始点確定前も同じ判定を通す（`BeltRouteCellCheck` は削除）。(4) 経路の途中セルは建築射程の外へ出てよい（始点と終点だけ射程内）。(5) 組み立て失敗時の追加探索が回数で止まる件、本番の世界（占有・辺の写し取り）を通るテストが無い件、辺の書き込み先 interface の「坂の真上」を分岐判定の入れ物が空実装で受け流している件は現状のまま。
棄却案: (1) 探索が触った範囲の外接箱と交わるブロック変化だけ作り直して再探索（推奨として提示）／始点・終点の周りの球だけ見る／世界を共有して改訂番号が同じなら飛ばす。(2) 展開数の上限を距離に比例させる／現状のまま。(3) 2本のまま ADR に理由を書く。(4) 全セルを射程で確かめて外れたら「遠すぎます」（推奨として提示）。(5) 追加探索を予算に届くまで続ける（推奨として提示）／失敗時だけ重みなしで探し直す。本番の世界のテストをブロック列差し込みで足す（推奨として提示）／写し取りを static に切り出してテスト。空実装は interface から「坂の真上」を外す（推奨として提示）／interface を2つに分ける。
理由: ユーザー裁定 2026-11-09 AskUserQuestion。(1) 原文「自分が設置操作中にブロックがかわったらの話？であれば再探索しなくていいものとします。そのかわり自分が設置するときに本当におけるか検査してだめならブロック、最初からやりなおし、これでどう」→ 読み上げ確認に「合っている」。(2) 選択「終点の周りを先に小さく調べる（推奨）」。(3) 選択「1本にする（推奨）」。(4) 選択「途中セルは射程外でもよい」。(5) 選択「現状のまま」「テストは足さない」、空実装は解説の後に原文「ok 3」（分岐判定に坂の真上は関係なく、将来見るなら入れ物へメソッドを足す必要があり気づける）。moores-code-review（2026-11-09-1240-belt-route-unbounded）の設計判断 D1〜D4・D6〜D8。
