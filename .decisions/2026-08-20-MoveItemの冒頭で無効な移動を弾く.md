# MoveItemの冒頭で無効な移動を弾く

決定: `LocalPlayerInventoryController.MoveItem` 本体の冒頭に2つのガードを置く。(a)`count <= 0` または移動元が空なら return（空の移動元×count=0でswap分岐が成立し、行先スタックを空スロットへ吸い出す穴を塞ぐ）。(b)移動先が非空かつ別IDかつ部分移動なら return（確定no-opの送信自体を止める）。(b)を本体へ引き上げた結果、`SetInventory()` 内の `count != fromInvItem.Count` は到達不能になるため削除。

棄却案:
- 吸い出しだけ塞ぐ（アイテム消失は防げるが、別IDスロットの右ドラッグで確定no-opのパケットが最大45本飛ぶ問題が残る）
- `TryMoveItem` の `denyReason` へ `incompatible_partial_move` を載せて集約（「成功したが何も起きていない」を呼び出し元が区別できるようになるが、`error_codes.json` の既存ドリフトに触れる）
- 現状維持（サーバーも同条件でno-opのため実害は今ゼロ。ただし `MoveItem` はpublicで、countを素通しする呼び出し元が生えた瞬間に装備が消える）

理由: ユーザー裁定 2026-08-20。`SetInventory()` はローカル関数なので、そこからの return では送信（`SendMoveItemData`）が止まらない。症状の本体は「ローカル無反映のままパケットを送り、しかも成功応答を返す」ことなので、判定は本体側に置く必要がある。
