# 正常終了の印は終了パイプライン自身が保険として書く

決定: エディタのPlay停止は、初期化途中でもゲート応答待ちでも例外なく正常終了として印を書く。責任は `GameShutdownEvent` が持ち、`Application.quitting` を購読して誰も意思表明していなければ自分で `UnawaitableExit` を発火する。シーン上のオブジェクト（`SaveAndQuitPresenter`）の生存に依存しない。ゲートの仕組み自体と配布ビルドの挙動は据え置き。

棄却案:
- エディタでは異常終了ゲートを丸ごと出さない → エディタで踏んだクラッシュの報告をゲート経由で拾う道も消えるため棄却
- ゲートで起動を止めるのをやめて後から聞く → テスターが通知を無視して報告が取れなくなるため棄却
- エディタ専用フック（ExitingPlayMode）で書く → 配布ビルド側に同じ穴が残るため棄却
- SaveAndQuitPresenter の NRE を直すだけ → MainGameシーン読込前の停止は Presenter 自体が居らず直らないため棄却

理由: ユーザー裁定 2026-09-21 原文「プレイを停止しただけなのにこれが出るのうざい」。実測では `SaveAndQuitPresenter.Disconnect()` の `VanillaApi` NRE で `FireGameShutdown` に到達せず clean 印が書かれていなかった。ゲート応答待ちで停止すると同じNREが再発して無限に繰り返す。

付随の裁定:
- `SaveAndQuitPresenter` の NRE は同PRで直す。他の未初期化NRE（`UIStateControl` 等）は別タスクのまま
- 手元に残った未応答の `pending_crash_report` は偽のクラッシュなので答えずに削除する
- 検証は保険の分岐のEditModeテスト＋実機Playの目視の2本立て
